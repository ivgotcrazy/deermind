## 评审：E01-08 业务投影职责补修（重建接口重构）

用户原则（重要，后续以此为准）：公共底座与投影解耦，事件与投影的关系由业务层自己定义。底座不得预设「一事件一行」「主键=scope」这类形状。

实际落地（已核实）：
- `foundation/system/projections/rebuild.py` 已删除，拆成 `records.py`（只操作 runtime 控制记录）+ `receipts.py`（按 projector/generation/event 防重）。
- 业务侧新增 `product/accounts/projections.py`：`TABLES`（五表顺序、key、可更新列）、`rows_for(event)`、`apply_account_events(connection, events, generation, targets)`。一条事件可产多行多表。
- `product/accounts/rebuild.py`：`AccountRebuilder` 负责选范围、建 LIKE 副本、重放核对、原子替换。`_finish` 先 DELETE 范围内多余从表行，再 upsert，再逐列 `to_jsonb` diff。
- 迁移 `0009_projection_ownership` 给 `runtime.projection_rebuilds` 加 `target_relations jsonb`。
- 事件保存不再自动投影；`save.py:99` 与 `transactions.py:94` 在同一事务显式调 `apply_account_events`。
- 文档已同步：DECISIONS §120、System_Foundation_Design §2.6「E01-08补修」、Delivery_Plan v0.78、`src/m1/deploy/environments/local-wsl/E01-08-ownership.md`。
- 测试 19 项，新增多行多表、多表失败回滚、多余行清理、旧记录不可续、临时故障续做。

遗留（非阻塞，已在评审中指出）：
1. 副本表名 `product.rb_{32hex}_student_guardian_relations` = 62 字符，PG 上限 63，余量 1；超长会静默截断。
2. `projections.py:40` 用 `next(iter(model.model_fields))` 当主键，属隐式约定。
3. `_verify` 不可分批（`max_events` 只作用于 `_checkpoint`），是重建停写时长的真正决定项。
4. `records.py` 里 generation=1 硬编码两处（`:193`、`:202`）。
5. `save.py` 直调 `store.append` 再手动投影，`manage.py` 走 `append_account_event` 封装，同一业务两种写法。
