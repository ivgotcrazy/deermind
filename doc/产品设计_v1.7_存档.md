## 2. 产品定位与设计原则

### 2.1 产品定位

- **形态**：私人工具，唯一核心用户是创始人的女儿（2026 秋季升入六年级）。
- **本质**：**掌握度驱动的 AI 高效辅导助手**——以"输入 → 模型 → 输出 → 反馈"学习引擎为骨架，**以聊天为核心互动**；错题闭环只是最重要的技能之一，而非唯一主线。
- **核心价值（减负）**：掌握即止、能不用就不用——用最少时间把不牢的知识点学牢，把时间还给孩子。
- **使用场景**：每天放学后 15–30 分钟，随时可插入提问，可中断恢复。

### 2.2 设计原则（继承概念文档五条红线）

1. **减负（红线〇）**：掌握即止——模型判定已掌握就不再安排，主动提示"这个已经会了，不用再花时间"；产品成功 = 帮孩子用最少时间达到掌握，而非占用更多时间。
2. **家长零强制投入**：默认零录入、零操作即可良好运转；家长各项功能独立开关、想看就看、想录入就录入，全凭自愿（不做参与度分档）。
3. **教育结论必须严谨**：禁止"一次做对 = 已掌握"；掌握度必须是时间维度上的状态机；讲解绑定教材来源。
4. **低风险技术优先**：费曼用"结构化自述 + 要点核对"，不赌 LLM 主观评判；变式用"三不变一变 + 自检清单"。
5. **信任输入假设（有效运行的基础）**：充分信任所有输入都是真实的——孩子如实作答与反馈、错题真实、家长录入可靠；不设防作弊机制；若输入失真，由归因对话/检验/间隔复习交叉验证逐步自我修正。

### 2.3 本版已确认的关键决策

| 决策项 | 结论 |

| 科学策略（v1.6） | 遗忘曲线 → 间隔复习（1/3/7/14 天）；费曼学习法 → 重要知识点"讲给小鹿听"（结构化自述 + 要点核对） |

| 记忆体系 | 所有对话全量持久化，定期提炼为结构化记忆（事实/偏好/状态），支撑"越用越懂"（v1.2） |

## 3. 用户与使用场景

### 3.1 用户

| 角色 | 说明 | 参与方式 |
|---|---|---|
| 女儿（核心） | 六年级，放学后 15–30 分钟，聊天为主 | 每日使用（由"需要"驱动，非强制） |
| 妈妈/爸爸（间接） | 低频查看与可选录入 | 功能独立开关、想看就看、想录入就录入，零强制 |
| 管理员=创始人（运营） | 维护内容与配置、监控成本与数据质量 | 通过 Web 后台访问，不接触孩子/家长日常界面 |

### 3.2 核心闭环主流程（学习引擎，孩子端）

```
女儿与小鹿聊天（随时插入提问，语音/文字）
  → 意图路由 / 技能调度（映射到 6 项技能，注入空间/进度/掌握度/记忆上下文）
  → 掌握度模型更新（任何一次作答/提问/反馈都更新）
  → 输出：讲解 / 讲题 / 检验 / 练习 / 复习 / 错题闭环 / 读题训练 / 今日规划
  → 反馈：做对 / 做错 / 提问 / 讲解后反馈 → 再次成为输入（闭环）
  → 减负：掌握即止——已掌握主动提示"这个已经会了，不用再花时间"
```

**错题闭环（作为重点技能之一，非唯一主线）**：

```
拍照错题 → OCR 归类 → 归因对话（粗心/概念不清/审题失误/思路混乱）
  → 针对性处理（讲解 / 检查提示 / 读题训练）
  → 变式验收（三不变一变 + 一句话思路）→ 短期掌握
  → 间隔复习（1/3/7/14 天）→ 长期掌握 → 错题画像沉淀
```

#### J1 家长创建学习空间（一次性配置）

- **用户**：妈妈/爸爸
- **目标**：为女儿建立"六年级上学期数学"学习空间，绑定教材，让系统拥有学习范围
- **主流程（用户视角）**：
  1. 打开家长端 App → 进入"学习空间"
  2. 新建空间：填写名称"学校·六年级上册数学"、选择类型（学校/辅导班）、学期
  3. 选择教材：从系统内置列表选择（人教版/北师大版），或上传辅导班教材（PDF/图片 → OCR 提取目录）
  4. 确认知识点清单与当前进度（可选：不确定则留给 J2 摸底）
  5. 完成 → 孩子端出现该空间入口，系统可在其内辅导
- **关键界面要素**：空间列表卡片、新建空间表单、教材选择器、上传导入进度条、知识点清单确认页
- **涉及功能**：US-15、US-16（部分）、§5.10
- **分支/异常**：上传 OCR 识别失败 → 手动上传目录；同一空间可绑多本教材；学期中报辅导班 → 再建一个空间

#### J2 学生首次进入学习空间（摸底/冷启动）

- **用户**：女儿
- **目标**：让 Agent 知道她学到哪、水平如何，建立初始画像
- **主流程（用户视角）**：
  1. 首页出现"学校·六上数学"空间 → 点击进入
  2. 小鹿打招呼 + 摸底对话："这学期我们学分数乘法，你学到哪了？先做两道题试试？"
  3. 完成 3–5 道摸底题 → 生成初始薄弱点画像（三色）
  4. 小鹿建议："要不要把上周的错题拍给我看看？"
- **关键界面要素**：空间切换、小鹿形象对话、摸底进度、初始画像页
- **涉及功能**：US-16、US-18、§5.10
- **分支/异常**：女儿不想测 → 跳过摸底，从日常错题逐步积累；进度不确定 → 标记"待摸底"

#### J3 学生每日学习（聊天优先，核心旅程）

- **用户**：女儿
- **目标**：放学后 15–30 分钟，通过对话把今天要学的/不牢的知识点解决掉（最省时）
- **主流程（用户视角）**：
  1. 打开 App → 首页 = **今日任务卡 + 大对话区**（待复习 + 待学知识点 + 已掌握减负提示）
  2. 小鹿主动引导："今天想先复习分数乘法，还是先看看今天课上到哪？"（女儿可回答、可提问、可发语音）
  3. 女儿说"这道题不会"（拍照/描述）→ 讲题技能：归因 → 讲解 → 练习
  4. 女儿说"考考我" → 检验技能；说"我不懂分数乘法" → 讲知识点技能；拍错题 → 错题闭环
  5. 任一作答/提问都更新掌握度；今日任务完成或已掌握 → 小鹿提示"这个已经会了，今天可以休息啦"
  6. 25 分钟到时 → 休息 5 分钟
- **关键界面要素**：今日任务卡片、大对话区（气泡、语音输入、快捷技能按钮）、拍照/裁剪、识别确认、归因对话、讲解卡（朗读按钮）、答题卡、变式页、一句话思路输入、休息引导
- **涉及功能**：US-1~9、US-21、US-22、§5.1–5.9、§8
- **分支/异常**：超进度题 → 软提醒"提前学/先放着"；OCR 失败 → 手动输入；意图未命中 → 友好澄清；中途中断 → 下次进入恢复

#### J4 学生检验与费曼自述（掌握度确认）

- **用户**：女儿
- **目标**：通过客观检验与"讲给小鹿听"确认掌握情况（含减负判定）
- **主流程（用户视角）**：
  1. 女儿说"考考我" → 检验技能：3–5 道客观题（填空/选择/判断）自动判定
  2. 通过 → 小鹿鼓励并更新掌握度；重要知识点触发费曼
  3. 费曼：小鹿分步引导"用自己的话讲讲分数乘法的规则" → 孩子分步骤自述
  4. Agent 按关键要点清单逐条核对 → 全部覆盖 → "你已经掌握了这个知识点，可以不用再花时间啦"；有遗漏 → 只指出缺哪条 + 补讲
- **关键界面要素**：检验答题卡（客观题）、费曼引导气泡（逐步）、要点核对反馈卡（逐条打勾）
- **涉及功能**：US-4、US-5、US-11、§5.4、§8.7
- **分支/异常**：孩子不想讲 → 不强求，改客观检验；要点核对不通过 → 补讲缺条后重讲一次

#### J5 学生间隔复习与掌握即止（掌握度推进 + 减负）

- **用户**：女儿
- **目标**：按遗忘曲线 1/3/7/14 天复习，把"短期掌握"推进为"长期掌握"，并体会"会了就停"
- **主流程（用户视角）**：
  1. 收到复习提醒（放学时段）→ 进入"复习"（或在对话中完成）
  2. 逐题作答 → 判定通过/失败
  3. 1/3/7 三次间隔全部通过 → 该知识点变"长期掌握"（画像黄→绿），小鹿祝贺
  4. 已长期掌握的知识点不再安排复习；再次出现时小鹿提示"这个已经会了，不用再花时间"
  5. 失败 → 回到讲解换角度，重排复习计划
- **关键界面要素**：复习任务列表、答题页、掌握度变化反馈（鼓励）、"已掌握·无需再学"提示卡
- **涉及功能**：US-8、US-11、§5.8、§6.1
- **分支/异常**：错过复习日 → 顺延并保留记录；不打扰（家长零强制投入）

#### J6 家长日常跟进（日报/周报/告警，功能开关）

- **用户**：妈妈/爸爸
- **目标**：用最少时间了解孩子学情，收到异常提醒
- **主流程（用户视角）**：
  1. 打开家长端 App → "今日"（开关，默认开）：今天学了什么、完成几个知识点、有无异常
  2. 异常告警（开关）如同一知识点连续失败 → 点开看建议
  3. 周日 → 周报（默认开）：掌握率变化、重点错因、下周建议
  4. 只看周报即可，其余零操作
- **关键界面要素**：今日卡片、异常列表、周报图表页
- **涉及功能**：US-13、US-14、US-15、§5.10
- **分支/异常**：各项功能独立开关，想看就看、想关就关，不做参与度分档

#### J7 家长可选录入与深度查看

- **用户**：妈妈/爸爸
- **目标**：补充系统不知道的信息（评语/观察/教材），让辅导更精准
- **主流程（用户视角）**：
  1. 家长端 App → "家长录入"（开关）
  2. 录老师评语（孩子不可见）："老师说女儿分数应用题常漏条件"
  3. 录观察："她口算还行，一到大题就慌"
  4. 上传补充教材（辅导班讲义）
  5. 系统纳入记忆与画像 → 后续辅导体现（如多鼓励、多练读题）
  6. 开启"错题详情"（开关）可查看错题内容与归因
- **关键界面要素**：录入表单（评语/观察/教材）、上传页、错题详情列表、记忆列表（可查看/删除）
- **涉及功能**：US-16、US-17、US-23、§5.10、§8.12
- **分支/异常**：不录入不影响产品运转（红线）；记忆可删

#### J8 家长设置与数据管理

- **用户**：妈妈/爸爸
- **目标**：控制防沉迷、功能开关、数据主权
- **主流程（用户视角）**：设置每日时长 → 开关各功能（日报/告警/错题详情/录入）→ 查看/删除记忆 → 一键导出/删除全部数据
- **关键界面要素**：设置页（功能开关列表）、导出/删除确认弹窗
- **涉及功能**：US-18、US-19、§5.11、§8.12（家长控制）
- **分支/异常**：删除为不可逆操作（二次确认）

#### J9 管理员 Web 后台（运营与维护）

- **用户**：创始人（管理员）
- **目标**：维护内容与规则、监控成本与数据质量，让孩子/家长端保持简洁

- **关键界面要素**：侧边栏导航、统计卡片与图表、内容管理表格、规则编辑页（版本化）、操作日志
- **涉及功能**：US-25~29、§5.13

```
┌─ 首页（今日任务引导 + 大对话区）

│    · 讲题（拍照/描述 → 归因 → 讲解 → 练习）
│    · 检验（客观题 + 费曼结构化自述）
```

```
┌─ 今日（日报，开关，默认开）：今日学习、完成知识点、有无异常
```

## 5. 核心功能需求

### 5.1 聊天与意图路由（P0，核心交互主通道）

- **功能描述**：孩子端以聊天为主通道，小鹿接受文字/语音提问，通过**意图路由 / 技能调度**把聊天内容映射到 6 项技能（讲知识点/讲题/复习/检验/错题闭环/读题训练），并注入上下文（学习空间、进度、掌握度、记忆）。
- **输入/输出**：
  - 输入：文字、语音（ASR 转写）、拍照（触发错题闭环/讲题）。
  - 输出：聊天回应；或唤起对应技能流程（对话内展开或跳转结构化页）。
- **意图分类**（MVP 6 项技能 + 兜底）：
  | 意图 | 示例 | 路由到 |
  |---|---|---|
  | 讲知识点 | "我不懂分数乘法" | 讲知识点技能 |
  | 讲题 | "这题不会" / 拍题 | 讲题技能（含归因） |
  | 复习 | "帮我复习下分数" | 复习技能 |
  | 检验 | "考考我" | 检验技能 |
  | 错题闭环 | 拍错题照片 | 错题闭环技能 |
  | 读题训练 | "应用题读不懂" | 读题训练技能 |
  | 掌握/规划查询 | "今天学什么" | 今日规划 / 画像 |
  | 无关话题 | 闲聊/娱乐 | 聊天边界规则（友好拉回） |
  | 兜底 | 意图不明 | 友好澄清 + 引导回学习 |
- **交互**：识别到技能意图 → 对话内展开（或轻量跳转）；未命中 → 澄清；边界外 → 拉回。
- **验收标准**：意图识别正确率 ≥ 90%（离线测试集）；6 项技能均可经聊天触发；兜底不打断对话。

### 5.2 讲知识点（P0）

- **触发**：聊天"我不懂 X / 讲讲 X"。
- **内容要求**：
  - 绑定教材/教辅原文来源（RAG 引用，展示"来源：人教版六上 Pxx"）；
  - 苏格拉底式、用孩子能听懂的语言；
  - 支持多角度讲解（同一概念至少 2 种讲法，供换角度回溯）；
  - 篇幅控制：单次讲解正文 ≤ 300 字或 ≤ 3 分钟朗读（适配儿童注意力）。
- **TTS**：默认朗读（柔和女声/童声），可静音切换为文字；朗读失败自动降级为文字。
- **验收标准**：讲解后检验首答正确率 ≥ 70%；讲解内容必须带教材来源引用；无来源的内容标记"补充说明"。

### 5.3 讲题与归因对话（P0，核心创新）

- **触发**：聊天"这题我不会"（拍照/描述）。
- **错误类型（四分类）**：
  | 类型 | 定义 | 典型信号 |
  |---|---|---|
  | 粗心（程序性失误） | 概念/方法对，仅计算、抄写、符号、步骤跳跃错误 | 能说出正确思路；换数字会做；错在"最后一步" |
  | 概念不清 | 知识点本身未掌握 | 说不清考什么；换数字仍错；方法不对 |
  | 审题失误 | 漏条件、看错单位/要求/数字 | 复述题意有遗漏；圈不出关键条件 |
  | 思路混乱 | 知道概念但不知从何下手、步骤逻辑断裂 | 卡在中间；讲不清为什么这么做 |
- **追问规则**：最多 3 个追问，采用决策树（见 §8.3），命中任一判定即停止并给出归因。
- **处理分支**：概念不清 → 讲知识点 + 练习；粗心 → 检查习惯提示 → 直接变式；审题失误 → 读题训练；思路混乱 → 引导式讲思路（§8.6）。
- **验收标准**：归因对话 ≤ 5 轮完成；验证期（家长抽查）归因一致率 ≥ 80%；每次归因写入错题记录（供家长"错题详情"复核）。

### 5.4 检验与费曼自述（P0）

- **客观检验（"考考我"）**：
  - 来源：预置题库 + LLM 按知识点生成客观题（填空/选择/判断）；
  - 数量：3–5 道；自动判定，结果写入掌握度；
  - 通过 → 更新掌握度；重要知识点触发费曼。
- **费曼学习法（"讲给小鹿听"）**：
  - 适用：重要知识点/原理（分数乘法规则、单位换算规律等）；
  - 流程：小鹿分步引导 → 孩子用自己的话讲（语音 ASR 或文字）→ **要点核对**：Agent 按该知识点关键要点清单逐条比对，给出"通过/未通过 + 缺哪条"；
  - 全部覆盖 → 判定掌握（配合其他信号）；有遗漏 → 补讲缺条后重讲一次；
  - **不赌 LLM 主观深度评判**：用客观要点比对替代自由文本评判（低风险技术优先）。
- **验收标准**：客观题判定正确率 100%（可校验）；费曼要点清单覆盖核心知识（人工维护）；核对结果可追溯。

### 5.5 错题拍照与 OCR（P0）

- **功能描述**：女儿拍摄错题照片（或从相册选择），OCR 识别题目文本，自动归类到知识点，留存原图。
- **输入/输出**：
  - 输入：单张或多张照片（≤3 张），支持裁剪。
  - 输出：题目文本（可编辑）、识别置信度、归属知识点（可修正）、原图 URL。
- **交互**：拍照 → "识别中…" → 展示识别文本与题目预览 → 女儿确认或修正 → 进入归因对话。
- **去重**：相同题图/相近文本重复录入时，提示"这道题之前录过"，可选"作为新错题"或"回到原记录"。
- **验收标准**：打印体/手写体（工整）错题识别文字准确率 ≥ 90%（可编辑兜底）；从拍照到进入归因对话 ≤ 5s；识别失败（低置信度）时提供"手动输入题目"兜底。

### 5.6 错题闭环处理（归因 → 讲解 → 练习 → 变式验收）（P0）

- **归因**：见 §5.3。
- **基础练习**：来源 = 预置题库（每知识点 5–10 道基础题，人工录入+校验）；数量 3–5 道；全对 → 进入变式；有错 → 返回讲解（换角度）后再练，最多 2 轮。
- **变式验收**：
  - 变式题由 LLM 按"三不变一变"生成（不变 = 核心知识点、解题逻辑、难度；一变 = 情境/数字/表述，至少两处以上）；
  - 生成后自检（规则校验 + LLM 自评，见 §8.5），不合格重生成（≤2 次）；
  - 判定：做对 + 一句话思路（语音或文字）→ **短期掌握**；任一项不达标 → 回到讲解换角度。
- **验收标准**：变式题与知识点绑定一致率 100%（规则校验）；变式验收后进入间隔复习闭环的转化率 ≥ 90%；进入变式的知识点最终"长期掌握"比例 ≥ 70%。

### 5.7 读题训练（应用题专项，P0）

- **触发**：归因 = 审题失误，或聊天"应用题读不懂"。
- **三步流程**：
  1. **圈关键信息**：Agent 引导女儿在题干中圈出已知条件、隐藏条件、所求目标；
  2. **复述题意**：女儿用自己的话复述"求什么、给了哪些条件"（Agent 只确认、不评判）；
  3. **数量关系建模**：Agent 引导说出"条件与问题的关系"（如总价=单价×数量），再重做原题。
- **判读逻辑**：训练后重做原题或变式，连续 2 次通过 → 确认"读题类"并进入变式验收；仍失败 → 切换检查"概念不清"。
- **验收标准**：读题类错题训练后重做通过率 ≥ 80%。

### 5.8 间隔复习调度（P0）

- **计划**：知识点达到"短期掌握"后自动生成复习计划：第 1 / 3 / 7 / 14 天。
- **判定**：
  - 通过第 1、3、7 天三次复习 → **长期掌握**；
  - 任一次失败 → 回退"学习中"，重新讲解并重排复习计划；
  - 长期掌握后，第 14 天巩固抽查；30 天抽查失败 → 回退"学习中"（疑似遗忘）。
- **减负语义**：长期掌握后不再安排；再次出现时提示"已经会了，不用再花时间"（§8.9）。
- **提醒**：孩子端 App 内通知（放学时段）；不强制、不打扰（家长零强制投入）。
- **验收标准**：间隔复习通过率 ≥ 80%；复习计划生成正确率 100%（自动校验）。

### 5.9 系统主动能力（P0）

- **摸底（冷启动）**：首次进入空间建立初始画像（3–5 道摸底题；可跳过）。
- **今日规划**：依据掌握度生成"今天该学什么"（最省时方案：待复习 + 待学薄弱点），展示在首页任务卡，可一键开聊。
- **主动提醒**：间隔复习到点、异常薄弱（同一知识点连续失败）提醒。
- **掌握即止提示**：模型判定已掌握（短期/长期）→ 主动提示"这个已经会了，不用再花时间"，不再安排学习任务。
- **验收标准**：今日规划依据掌握度生成（可测）；已掌握知识点不再出现在任务卡（可测）；有明确"已掌握"话术。

### 5.10 家长端（独立 Flutter App，功能可开关，P0）

- **功能清单（各项独立开关）**：
  | 功能 | 默认 | 说明 |
  |---|---|---|
  | 日报（今日） | 开 | 当天学习了什么、完成几个知识点、有无异常 |
  | 周报 | 开 | 本周学习、掌握率变化、重点错因、下周建议（周日生成） |
  | 异常告警 | 关 | 同一知识点连续失败 → 建议 |
  | 错题详情 | 关 | 错题内容与归因（P1 增强） |
  | 家长录入 | 关 | 老师评语（孩子不可见）/ 观察 / 补充教材 |
- **推送（P1）**：App 本地通知（日报/周报提醒）；微信推送（订阅消息/服务号）推迟到小程序阶段（需备案/认证，见 §13 R1）。
- **验收标准**：日报/周报生成及时（每日 21:00 前 / 每周日）；家长零操作即可查看；任意功能关闭不影响孩子端独立运转；录入不影响孩子端运转。

### 5.11 防沉迷与家长控制（P0）

- 单次会话最长 25 分钟强制休息 5 分钟（倒计时 + 休息引导页）；
- 每日总时长可由家长设置（默认 30 分钟）；
- 达到阈值后孩子端锁定，需家长解锁或次日恢复；
- 家长端可随时查看/调整。

### 5.12 学习空间与进度对齐（基础模型，P0）

**学习空间（Learning Space）是产品的基础模型元素**——一个按学期/任务隔离的上下文容器，系统在该空间内进行辅导。

- **创建**：家长（一次性配置）创建"学习空间"，如"学校·六年级上册数学"；学期中报辅导班可再建"辅导班·学而思数学"等空间。一个空间包含：绑定教材（系统内置或上传导入，可多个）、当前进度、录入材料。
- **教材绑定**：教材库 = 系统内置（人教版/北师大版等）+ 家长上传（辅导班教辅）。空间内至少绑定 1 本教材。
- **进度维护（学生为主）**：
  - Agent 每次会话自然询问"今天学到哪了？"（10 秒级）；
  - 拍照测验/错题时自动推断进度；
  - 家长仅在异常时一次性校准（如换教材）。
- **范围护栏（核心约束）**：
  - **知识点的存在性必须来自空间内教材的范围**（系统不能凭空教教材外知识点）；
  - **讲解内容以教材为权威、可生成式多角度展开**（因材施教，不拘泥原文）；
  - 超出当前进度 → **软提醒 + 分支引导**，不硬阻断：分支 A「提前学」（更新进度）/ 分支 B「先放着」（挂起）。
- **进度与掌握度的关系**：进度范围按空间隔离（学校空间未学到≠辅导班空间未学到）；知识点掌握度全局统一（跨空间共享）。
- **验收标准**：创建空间、绑定/上传教材流程可用（一次性配置）；超进度题必触发软提醒（可测）；软提醒不阻断操作（可测）；讲解内容不越出知识点边界（人工抽检）。

### 5.13 后台管理系统（Web，管理员，P0）

- **定位**：创始人的运营与维护台（数据/内容/规则/治理），让孩子与家长端保持简洁。
- **数据看板**：掌握度分布、会话统计、薄弱点 Top、LLM/OCR/ASR/TTS 用量与月度熔断状态、异常告警列表。
- **内容管理**：知识点（本体/前置依赖）、教材与目录映射、题库（基础/变式/复习）、费曼要点清单——增删改查，发布后孩子端生效。
- **规则配置（版本化）**：归因决策树、变式自检清单、系统提示词版本、家长功能开关默认值；支持预览与回滚。
- **数据治理**：错题、记忆、对话记录可检索/查看/修正/删除，修正留痕（操作日志）；掌握度状态可手动校正（异常兜底）。
- **系统设置**：管理员账号（MVP 单账号）、月度预算与熔断阈值、操作日志。
- **验收标准**：核心内容可在后台完成维护并生效（可测）；成本与熔断状态实时可见；数据修正留痕可追溯；后台与孩子/家长端物理隔离。

## 6. 教育模型与状态机

### 6.1 掌握度状态机

```
未接触 → 学习中 → 短期掌握 → 长期掌握
            ↑         │         │
            └─────────┴─────────┘（复习失败 → 回退学习中）
```

| 状态 | 进入条件 | 离开条件 |
|---|---|---|
| 未接触 | 知识点首次纳入 | 进入讲解或练习 |
| 学习中 | 进入讲解/练习/复习失败 | 变式验收通过（做对+一句话思路） |
| 短期掌握 | 变式验收通过（当天） | 1/3/7 天三次复习全部通过 → 长期掌握；任一失败 → 回退学习中 |
| 长期掌握 | 1/3/7 复习通过 | 14/30 天巩固抽查失败 → 回退学习中（疑似遗忘） |

- **掌握度分值**（用于画像）：长期掌握=1.0；短期掌握=0.7；学习中=0.3~0.6（按通过练习比例）；未接触=0。
- **减负语义**：长期掌握 = 真正学会，不再安排学习与复习；已掌握知识点再次出现时，Agent 主动提示"这个已经会了，不用再花时间"（§8.9）。

### 6.2 归因分类判定标准

见 §5.2 表格；归因必须可追溯（记录追问问答，供复核）。

### 6.3 知识点与前置依赖

- **本体**：知识点 = 领域（算术/代数/几何/应用）+ 年级 + 名称 + 描述 + 前置依赖列表。
- **教材映射**：知识点 ↔ 人教版目录 ↔ 北师大版目录 ↔ 辅导班专题（多对多）。
- **前置依赖规则**：A 是 B 的前置（如"分数意义" → "分数乘法"）；诊断 B 薄弱时检查 A。

### 6.4 学习空间 × 进度 × 掌握度（v1.2）

- **进度（scope）**：按空间隔离——每个学习空间有自己的教材集与"当前进度"（学到哪章哪节）。
- **掌握度（mastery）**：全局统一——同一知识点跨空间共享掌握度（学校空间学过分数乘法，辅导班空间也视为已学）。
- **超进度判定**：基于"当前对话所在空间"的进度范围；知识点"是否学过"基于全局掌握度记录。
- **范围冲突处理**：辅导班超前教"分数除法"而学校空间未到——辅导班空间进度覆盖该知识点，学校空间不覆盖；两空间均可辅导，掌握度共享。

## 8. Agent 行为设计

### 8.1 系统提示词框架（孩子端）

```
角色：小鹿，一位耐心的六年级数学老师
语气：鼓励、不评判、儿童友好
核心原则：
1. 聊天是主通道：先听懂孩子想干什么（意图路由），再决定用哪项技能
2. 先归因后讲解，不直接给答案
3. 讲解绑定教材来源；无来源内容标注"补充说明"
4. 苏格拉底式引导，让孩子自己说出思路
5. 每次讲解 ≤300 字或 ≤3 分钟朗读
6. 孩子回答错误时："没关系，我们来看看哪里卡住了"
7. 信任所有输入都是真实的，不质疑、不设防作弊
8. 掌握即止：判定已掌握时主动说"这个已经会了，不用再花时间"
9. 聊天边界：学习范围内畅聊；无关话题简单回应并友好拉回
禁止：贬低、打击、一次性抛出大量概念、直接报答案、扩展无关话题
```

- 提示词版本化存储（便于迭代回归测试）。

### 8.2 意图路由与技能调度规则

- **路由输入**：当前消息（文字/ASR 文本）+ 会话上下文（空间、进度、掌握度、记忆、最近技能）。
- **判定顺序**：
  1. 拍照 → 错题闭环 / 讲题（按是否已 OCR/确认题目区分）；
  2. 显式技能词（"讲讲/考考我/帮我复习/这题不会/读不懂/拍错题"）→ 对应技能；
  3. 知识/题目内容 → 讲知识点 / 讲题；
  4. 规划/掌握查询（"今天学什么/我哪里弱"）→ 今日规划 / 画像；
  5. 无关话题 → 聊天边界（§8.10）；
  6. 兜底 → 友好澄清："你是想让我讲个知识点，还是看看这道题？"
- **技能注入上下文**：每个技能执行时注入 学习空间 + 当前进度 + 该知识点掌握度 + 相关记忆。
- **中断与恢复**：技能流程可被打断（孩子插入新问题），先处理新意图，再问"还要继续刚才的题吗？"
- **验收**：意图路由可离线回归测试；正确率 ≥ 90%（见 §5.1）。

### 8.3 归因追问决策树（2–3 问）

```
Q1（判概念）: "这道题考的是哪个知识点？/ 你能先讲讲你当时是怎么想的吗？"
   → 说不出/说错 → 概念不清
   → 能说对思路 → 进 Q2
Q2（判读题）: "你能把题目里给了哪些条件、要求什么，用自己的话说一遍吗？"
   → 复述遗漏/错 → 审题失误
   → 复述正确 → 进 Q3
Q3（判粗心/思路）: "如果数字换成小数/分数，你还知道怎么做吗？"
   → 会做 → 粗心（程序性失误）
   → 不会/不确定 → 思路混乱
```

### 8.4 讲解规则

- 先给出"这个问题考什么"，再讲方法，最后给 1 个例子；
- 多角度：至少准备 2 种讲法（例：分数的意义用"分饼"与"数轴"两种讲法）；
- 讲解结束引导："现在你能试着做一道类似的题吗？"

### 8.5 变式生成规则（三不变一变 + 自检）

```
约束：
· 不变：核心知识点、解题逻辑、难度层级
· 一变：情境 / 数字 / 表述方式（至少改变两处以上，避免仅换数字）
自检清单（LLM 生成后执行，全部通过才下发）：
1. 是否仍考核同一知识点？
2. 解题逻辑是否与原型一致？
3. 难度是否相当（步数、计算量相近）？
4. 是否有两处以上变化（情境/数字/表述）？
5. 答案是否唯一且可校验？
不合格 → 重生成（≤2 次），仍不合格 → 使用预置变式或标记人工待审
```

### 8.6 软性讲思路规则

- 场景：变式验收后"用一句话说说你怎么想的"。
- 处理：语音录入（ASR 转写）或文字；**不深度评判对错**，仅做记录 + 简单鼓励（"思路不错/我们再练练"）；
- 目的：自我解释训练（self-explanation），培养元认知；深度评判推迟 V1（"小老师模式"）。

### 8.7 检验与费曼核对规则

- **客观检验**：LLM/题库生成 3–5 道客观题；逐题判定；答错 → 记录到对应知识点，回到讲解换角度。
- **费曼触发**：重要知识点（预置清单标记）在"检验通过"或"变式通过"后触发一次。
- **结构化自述**：小鹿分步引导，一次只问一个环节（如"先说说规则""再说一个例子"），孩子语音/文字作答。
- **要点核对（替代主观评判）**：
  - 每个重要知识点维护一份**关键要点清单**（人工编写，进 `feynman_checklist`）；
  - Agent 把孩子的自述与要点逐条比对：覆盖 → 该条打勾；遗漏/错误 → 记缺失；
  - 全部覆盖 → "通过，这个知识点你已经会了，不用再花时间啦"（可触发掌握即止）；
  - 有缺失 → 只指出缺哪条 + 补讲，不展开自由深度评判。
- **不强求**：孩子不想讲 → 改为客观检验；每次自述 ≤ 3 分钟。

### 8.8 读题训练规则

- 圈信息：Agent 逐句引导，"这句话里哪个是条件？哪个是要我们求的？"
- 复述：女儿用自己的话说一遍题目（Agent 只确认、纠偏、不评判）；
- 数量关系："这些条件和问题之间是什么关系？能写成算式吗？"
- 完成后再重做原题，按 §5.7 判读。

### 8.9 主动引导与掌握即止规则

- **主动发起（不是被动问答）**：Agent 在对话中主动建议学什么、主动出题检验、到点提醒复习、发现薄弱主动讲解；防止"孩子不问就没用"。
- **主动引导话术**：开场"今天想先复习还是学新的？"；空档期"要不要考考自己？"
- **掌握即止（减负核心）**：
  - 状态机判定某知识点已掌握（短期/长期）→ 不再安排任务；
  - 孩子再问已掌握内容 → 主动提示"这个已经会了，不用再花时间"；孩子仍想巩固 → 尊重，给一道轻量检验即可；
  - 长期掌握且无遗忘迹象 → 不进入复习计划。
- **信任输入**：对孩子的作答/反馈不做真实性怀疑，按如实记录更新模型；模型偏差由归因对话、检验、间隔复习交叉验证修正。

### 8.10 聊天边界规则（不是通用聊天）

- **允许**：当前空间范围内的知识讲解、题目、方法、复习、检验，及基于教材范围的延伸。
- **无关话题**（闲聊/娱乐）：**友好拉回**——简单回应（1 句）后引导回学习："这个有意思！不过我们先看看这道分数乘法题？"
- **不扩展**：不主动延伸无关话题、不进入开放式闲聊；不硬拒、不评判孩子的话题。
- **边界失效兜底**：若孩子持续偏离，温和结束本轮："那我们下次再聊，先做两道题吧？"

### 8.11 学习空间与进度对齐规则

- **上下文注入**：每次会话注入"当前空间"信息（教材、当前进度、已学知识点范围）。
- **进度询问**：会话开场自然询问"今天学到哪了？"；拍照错题时按题目知识点推断进度并请确认。
- **范围判定**：题目 → 知识点 → 判定其是否在当前空间进度范围内。
- **超进度软提醒（不硬阻断）**：
  - 分支 A「提前学」→ 将该知识点纳入空间进度（标记超前学习），正常进入闭环；
  - 分支 B「先放着」→ 题目挂起到"待学清单"，不进入闭环。
- **讲解范围约束**：知识点存在性必须来自空间教材；讲解内容可多角度展开，但不得越出该知识点边界。
- **记忆注入**：系统提示词携带当前用户相关记忆（偏好/状态/事实），支撑个性化。

### 8.12 记忆提炼规则

- **全量留存**：所有对话（含 ASR 文本）持久化保存，作为事实数据，不删减（家长可一键删除全部）。
- **提炼节奏**：每日定时 + 会话结束触发，从新增对话中提炼记忆条目。
- **记忆分层**：
  - 事实型（factive）：学过哪些章节、错题归因、测验结果、进度变化；
  - 偏好型（preference）：讲解风格偏好、激励方式、畏难点（如应用题）、兴趣点；
  - 状态型（state）：当前进度、当前薄弱点、近期情绪/信心。
- **质量控制**：每条记忆带来源（session）、置信度与时间；低置信度不进提示词上下文；记忆可去重、可过期（时间衰减）。
- **家长控制**：家长可查看全部记忆并删除（与数据导出/删除一致）。
- **验收**：每日提炼任务成功执行；记忆在后续会话中被引用（抽样验证）。

## 9. 非功能需求

### 9.1 性能

| 场景 | 目标 |
|---|---|
| 聊天响应（单条） | ≤ 3s（流式） |
| 意图路由 | ≤ 500ms（随聊天响应内） |
| 拍照→OCR 完成 | ≤ 3s |
| 归因对话响应（单条） | ≤ 3s |
| 讲解生成（首字） | ≤ 5s（建议流式输出） |
| 变式题生成 | ≤ 8s（含自检） |
| TTS 返回首段音频 | ≤ 3s |
| 日报/周报生成 | 每日 21:00 前 / 每周日 |

### 9.2 防沉迷

- 单次 25 分钟强制休息 5 分钟；每日总时长家长可设（默认 30 分钟）；超时锁定，家长解锁或次日恢复。

### 9.3 隐私与安全

- 数据加密传输（HTTPS/TLS）与存储（敏感字段加密）；
- 最小必要收集：仅收集女儿学习所需数据；语音仅用于 ASR，按需留存，支持删除；
- 未成年人保护：监护人（家长）知情同意；数据导出/删除一键完成；
- 孩子端不可见家长录入的老师评语/观察。

### 9.4 成本控制

- 模型：DeepSeek API（低成本优先）；
- OCR/ASR/TTS：按量付费，设月度预算上限（建议首月 ≤ ¥50），超限熔断降级（关闭 TTS/ASR，改文字）；
- 图片/音频：对象存储，定期清理非必要副本。

### 9.5 兼容性与可用性

- 孩子端：独立 App，Android 8.0+（MVP 侧载 APK），iOS 后续（TestFlight）；平板优先响应式（手机亦可），大触控目标；
- 家长端：独立 App，Android 侧载 APK / iOS 后续 TestFlight；手机优先响应式，平板/桌面自动扩展；
- 管理员后台：Web（PC 浏览器为主，Chrome/Edge 现代版本）；
- 孩子端/家长端均支持手机与 Pad，布局按断点重排（详见 §4.3）；
- 弱网/断网：文字为主流程可降级，语音/朗读降级为文字。

### 9.6 可维护性

- 提示词版本化 + 规则可配置化（归因决策树、变式自检清单、复习排期、熔断阈值）——配置统一收敛到后台（§5.13）；
- 模块化：拍照/OCR、归因、讲解、变式、复习、家长端、后台各自独立模块；
- 埋点完整（见 §12），便于验证期迭代。

## 10. 技术架构

### 10.1 总览

```
[孩子端 Flutter App（平板优先，聊天优先）]   [家长端 Flutter App（手机优先）]   [管理员 Web 后台（PC 浏览器）]
        （三端共享后端）
                        │
       └─────────── 后端 API（轻量云服务器 2C4G）──────────┘
                        │
      ┌─────────────────┼─────────────────┐
  DeepSeek API      OCR / ASR / TTS      PostgreSQL + 对象存储
   （LLM 引擎）        （腾讯云/讯飞）        （业务数据 / 图片音频）
        │
   核心运行时：意图路由 / 技能调度 + 掌握度引擎（状态机/图谱/记忆）
        │
   轻量 RAG（BM25 检索教材/教辅片段，MVP 不引入向量库）
```

### 10.2 前端（三端）

- **孩子端 `app_child` + 家长端 `app_parent`（Flutter）**：单仓双入口，共享 core 包与主题令牌；Android 侧载 APK 起步，不上应用商店；关键依赖：相机拍照（`camera`）、录音（`record`）、音频播放（`just_audio`/`audioplayers`）、状态管理（`Riverpod` 或 `Provider`）、本地缓存（`drift`/`sqflite`）、本地通知（`flutter_local_notifications`）；本地重运算预留 MethodChannel。
- **管理员后台 `admin_web`（Web）**：Vue3 + Vite + TypeScript + Element Plus（沿用原型技术栈），PC 浏览器访问；提供看板、内容管理、规则配置、数据治理页面。

### 10.3 后端（轻量云）

- 轻量云服务器（2C4G，约 ¥50–80/月）；
- API 框架：FastAPI（Python）或 Node.js；REST + 少量流式（SSE）接口；
- 鉴权：孩子端设备绑定；家长端独立 App（打开即用，无 PIN，可选启动锁按需添加）；管理员后台独立账号登录（MVP 单账号，强密码 + HTTPS + 登录日志）；微信登录/openid 推迟到小程序阶段（R1）。

### 10.4 OCR / ASR / TTS

- OCR：腾讯云 OCR（错题识别）；
- ASR：腾讯云/讯飞语音识别（普通话，儿童友好设置）；
- TTS：腾讯云/讯飞 TTS（柔和女声/童声）；
- 全部按量付费，带月度熔断（§9.4）。

### 10.5 RAG 与知识库（无向量库的落地实现）

**结论：MVP 不引入向量数据库**——因为语义层由 LLM 意图路由承担，检索退化为"知识点锚定的结构化查找 + BM25 兜底"，不需要向量检索。具体实现：

- **离线建库（一次性）**：
  - 教材解析：人教/北师大/教辅 PDF → 按"章-节-知识点"切分为教材片段（chunk），每片段挂元数据：知识点 ID、教材版本、章节、页码、标题；
  - 建两类索引：**知识点锚点表**（知识点 ID → 片段列表，结构化主路径）+ **BM25 倒排索引**（片段全文，关键词兜底，`rank_bm25` / PG 全文检索）；
  - 片段存 PostgreSQL，BM25 索引内存加载（单教材几十万字符，2C4G 毫秒级）。
- **查询链路（每次讲解/讲题）**：
  1. 意图路由（LLM）把问句归一为 技能 + 知识点 ID（结构化输出）；
  2. **主路径**：知识点锚点表直接取该知识点教材片段（含页码）→ 注入提示词 → 讲解标注"来源：人教版六上 Pxx"；
  3. **兜底路径**：路由置信度低或未命中锚点 → 问句关键词跑 BM25 召回 top-3 → LLM 结合上下文选用（LLM 即重排器）；
  4. 每次检索 1–3 个片段、低频率，延迟可忽略（远小于 LLM 生成时间）。
- **同义词问题的处理**：中文"同义不同词"（孩子说"分数除法咋做"，教材写"除以一个数等于乘它的倒数"）——语义匹配放在"问句→知识点"这一跳（LLM 意图路由），而非"问句→原文"；辅以小型同义词/术语词典（人工维护，几十条）。
- **可选增强（不引入向量库基础设施）**：离线把教材片段向量化（几千片段 × 几百维 ≈ 几十 MB，numpy/文件存储），查询时问句向量化后内存余弦 top-k——自托管伪向量检索，毫秒级；后期可平滑迁移到真向量库。
- **升级阈值**：语料 > 100 万字符 / 需跨学科跨文档语义召回 / 多用户规模化时，再引入向量数据库（PG `pgvector` 扩展或独立向量库）。

### 10.6 数据库

- PostgreSQL 或 MySQL；对象存储（COS/OSS）存图片音频；
- 日报/周报与记忆提炼由每日定时任务聚合生成。

## 11. 里程碑与迭代计划

| 阶段 | 周期 | 目标 | 交付物 |
|---|---|---|---|
| 0 对话原型 | 第 1–2 周 | 聊天 + 意图路由跑通 | 大对话区 + 意图路由/技能调度 + 讲知识点/讲题（文字）+ 学习空间创建/教材绑定 |

## 12. 指标与埋点

### 12.1 核心指标（对齐概念文档）

| 指标 | 目标 | 数据来源 |
|---|---|---|
| 同知识点再犯率下降（间隔复习通过率） | ≥ 80% | 状态机 |

| 归因准确率（验证期家长抽查） | ≥ 80% | 家长复核 |
| 讲解后检验首答正确率 | ≥ 70% | 自动统计 |
| 读题训练后重做通过率 | ≥ 80% | 自动统计 |
| 费曼要点核对通过率 | ≥ 70% | feynman_checklist |
| 单次会话时长 | 15–30 分钟（不追求更长） | 会话统计 |
| 家长每周耗时 | ≤ 5 分钟 | 埋点 |
| 每周使用天数 | ≥ 4 天（由"需要"驱动，不作首要标准） | 埋点 |

## 13. 风险与开放问题

| # | 风险/问题 | 说明 | 应对/决策 |
|---|---|---|---|
| R1 | 微信小程序需备案 | 小程序发布必须完成备案（2023 年起强制），个人主体周期长；服务号推送另需企业认证（约 ¥300/年） | MVP 家长端用独立家长端 App 查看日报/周报（无 PIN），无需微信；小程序与微信推送推迟到后期（P2） |
| R2 | 学校实际教材版本待确认 | 已支持人教/北师大双版本，但女儿学校实际用哪个需在"一次性配置"时确认 | 知识点版本无关 + 目录映射，配置时选定 |
| R3 | ASR/TTS 增加成本与网络依赖 | 语音方案比纯文字贵、且依赖网络 | 设月度熔断；弱网降级为文字 |
| R4 | LLM 讲解/变式幻觉 | 讲解错误被孩子内化；变式不合规 | 讲解绑定教材来源；变式自检清单 + 预置兜底；间隔复习暴露错误 |
| R5 | 归因准确率不足 | 影响辅导方向 | 验证期家长抽查校准；归因可追溯 |
| R6 | 孩子不愿主动使用 / 不知道问什么 | 产品依赖孩子每日使用 | 小鹿形象 + 短节奏 + 可中断；Agent 主动发起（建议/检验/提醒）+ 今日任务卡引导；验证期观察并快速迭代 |
| R7 | 成本超支 | LLM+OCR+ASR+TTS 按量计费 | 月度预算 + 熔断降级 |
| R8 | 数据隐私（未成年人） | 语音、错题、画像均为敏感数据 | 最小收集、加密、家长控制导出删除、监护人同意 |
| R9 | 讲出思路的深度评判（V1） | 儿童 ASR + 评判准确率 | MVP 软性版本，V1 再上"小老师模式" |
| R10 | 大陆轻量云域名需 ICP 备案 | 大陆云厂商对未备案域名默认不放行 80/443 访问；个人主体备案约 1–2 周 | MVP 后端若用大陆云，尽早提交域名 ICP 备案；或改用香港/海外轻量服务器（免备案，延迟略高）跳过备案 |
| R11 | 记忆/对话数据规模与隐私 | 全量对话+记忆包含大量个人信息，随时间增长 | 文本为主（成本可控）；家长可查看/删除；记忆最小化进入上下文；符合未成年人数据保护 |
| R12 | 聊天被当"答案机器"或越界闲聊 | 影响学习效果与减负 | 先归因后讲解、限制直接给答案；意图路由 + 聊天边界规则（友好拉回）；验证期观察话术 |
| R13 | 费曼自述评判不可靠 | 影响掌握度判定 | 结构化自述 + 要点清单核对（客观比对），不赌 LLM 主观深度评判；要点清单人工维护 |
| R14 | 管理员后台安全与误操作 | 后台可改数据，误操作影响孩子端 | MVP 单管理员账号 + 强密码 + HTTPS + 登录/操作日志；数据修正留痕；删除二次确认；配置版本化可回滚 |
