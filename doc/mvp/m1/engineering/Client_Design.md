## 1. 客户端范围与已定框架

前端采用Vue 3＋TypeScript＋Vite，见[登记§61](../../DECISIONS.md#61-m1代码组织与前后端框架)。在同一仓库的`src/m1/clients/`维护一个前端工程，学生和管理员分别设入口、页面及状态，共享内容渲染和基础组件；顶层组织见[总体§5.1](System_Design.md#51-已确认的源码组织)。入口分开不代替后端权限校验。

正式前端在src/m1/clients重新实现，按已确认业务合同接入后端。旧原型的布局、颜色、动效和组件实现不直接迁入；可参考已确认流程、内容样例和异常场景。模拟响应、硬编码概率及演示状态不进入生产逻辑。

基础组件采用[shadcn-vue](https://www.shadcn-vue.com/docs/introduction)，样式采用Tailwind CSS。两端共享颜色、字体、间距、圆角和状态变量，组件按需引入shared/ui；学生端偏重阅读与对话，管理员端偏重核对与处理。具体依赖版本按实施计划Q01接收，不因本次选型一并批准。

### 1.1 视觉设计与样板评审

“专注阅读”保留为视觉方向参考；用户认为当前[样板](../design/visual-sample/reading-focus/README.md)未达到预期，暂不继续打磨，不视为界面验收通过。正式前端先按E01—E07的小增量落实工程结构，视觉及交互优化后续再评审；Q12不再作为页面实现前置，见[实施计划§3](Delivery_Plan.md#3-待确认清单)。

当前重点是§2的两端入口、功能模块与依赖边界，基础组件和内容渲染复用，局部/共享状态的归属，以及OpenAPI、WS和错误处理接线。样式通过共用变量和组件维护，便于后续调整；不为尚未确定的视觉方案增加抽象层。旧原型与本次样板代码均不直接作为正式工程基础。

各功能增量仍须保证长中文、公式/图表、题目与答题区可用，正确显示空态、处理中、失败和恢复。键盘操作、焦点、可读性及已确认的业务流程照常验证；后置的是视觉与体验打磨，不是基本可用性或业务正确性。

开发辅助采用frontend-design、shadcn-vue和Playwright skills，来源见[登记§102](../../DECISIONS.md#102-正式前端重新设计与工具选择)。skills不进入运行环境，也不代替业务合同、浏览器验证和用户评审。组件展厅、其他设计工具和渲染库在需要时再接收，不作为本次新增必选依赖。

## 2. 页面、组件与状态组织

E01-11使用生成合同封装登录、会话、使用条件和确认请求。确认响应丢失或返回未声明响应时，先查原收据；查到已提交结果才刷新页面。未查到或查询失败时保留当前页面内的原request_id及正文，显示“查询本次确认结果”和“用原请求重试”，不自动重发、不让新决定覆盖未明请求。切换身份销毁该页面状态；刷新页面仍以服务端使用条件为准，不建立离线写队列。

保留学生聊天＋教材＋活动目录的单页行为和管理员业务能力，重新设计页面结构、布局与样式，不按每个Space另建前端应用。活动目录回看不改变当前活动，教材浏览不限制聊天；回复仍先检查保存再整条展示。管理员教材修正仍通过助手对话完成。工程目录按总体既定src/m1/clients组织，完整树见§2.1；组件按以下责任拆分：

| 单元 | 唯一职责 |
| --- | --- |
| AuthState | 当前账号、角色、登录会话诊断ID、使用条件和CSRF值；不保存密码或Cookie原值 |
| ConnectionManager | 一条当前标签页WS、连接状态、watch及重连；不决定业务是否成功 |
| RequestTracker | 稳定request_id、发送正文依据及未知／已受理状态；补读原收据，不建立待发送消息队列 |
| ResourceViews | 按账号＋资源保存服务端视图、修订及查询代次；不自行计算活动、概率或目标结果 |
| DraftStore | 当前标签页的未发送内容，按账号、资源和题目／导入隔离；明确不等于已提交原文 |
| ContentRenderer | 两端共用文字、公式、图表及答题区渲染，合同见§3.1 |

学生活动目录只定位消息，教材浏览只改变展示状态。管理员解析候选、领域入库和章节关联分别持有各自收据。是否使用独立状态管理库留在前端依赖评审；不为上述单元默认增加后端服务。

### 2.2 业务功能与Vue组件

以`admin/features/materials/`为例：

```text
materials/
├── pages/                       # 路由页面与页面级装配
├── components/                  # 教材列表、助手、候选卡片等专用组件
├── composables/                 # useMaterialAssistant等交互流程
├── state.ts                     # 本功能的响应式状态与清理
├── api.ts                       # 调用生成客户端并映射视图
├── types.ts                     # 仅本地视图类型，不复制HTTP DTO
└── index.ts                     # 有跨功能复用需求时才提供公开出口
```

组件采用Vue单文件组件、Composition API及`<script setup lang="ts">`，props/emits使用明确类型。页面组合业务组件；组件通过props/emits交互，复杂异步流程放composable。状态仅本组件使用时留在组件，不为所有字段建全局store。跨功能只调用明确出口；管理员和学生不互相导入实现，确实复用的能力提升到shared。

按[Vue TypeScript建议](https://vuejs.org/guide/typescript/overview.html)使用`vue-tsc`独立检查；Vite构建成功不代表类型通过。路由与全局状态库的具体接线仍待依赖评审；若采用Vue Router/Pinia，分别落入既定router和功能状态位置，不额外建立第二套状态源。shadcn-vue和Tailwind CSS的具体版本，以及公式和图形渲染库的选择仍待接收。

### 2.3 状态所有权与生命周期

| 状态 | 位置 | 更新和清理 |
| --- | --- | --- |
| 登录身份与auth_epoch | shared/auth | 会话核验后更新；退出/换账号清空受保护视图和旧请求影响 |
| WebSocket与受理跟踪 | shared/realtime | 每标签页一份连接；未知受理查原收据，不自动重发写请求 |
| 服务端业务视图 | 各feature/state或composable | 按账号、空间/教材和结果依据保存；晚到旧响应不覆盖新视图 |
| 输入草稿 | chat或materials功能 | 按账号和资源隔离；忙时保留；退出和换账号按§5清理 |
| 展开、选中、历史定位 | 所属组件或空间页面 | 不改变活动运行状态，不将浏览书页当成聊天范围 |
| 共享内容渲染输入 | shared/content的props | 只渲染服务端已授权内容，不自行补答案或计算目标达成 |

`shared`不维护全部业务的巨型store。管理员教材助手与学生聊天分别维护各自收据和草稿，只复用通信机制。页面离开释放watch、AbortController、定时补读及Object URL；不因此取消已受理后台工作。重新挂载从服务端视图恢复，不能仅凭浏览器缓存恢复活动或概率。

### 2.4 HTTP与WebSocket接线

组件→功能composable→功能api.ts→shared/api/client.ts配置的生成客户端；生成代码不手改。完整OpenAPI约定见[API§7](API_and_Message_Design.md#7-openapi与可执行合同)。传输DTO复用生成类型，本地types.ts只表达UI状态；将未知JSON强制断言成类型不能替代接口与消息校验。

HTTP生成客户端负责普通请求的序列化；当前会话、CSRF、统一错误和AbortSignal由手写适配注入。受理不明按既有RequestTracker查询，不能增加通用POST自动重试。WS的command/changed/error由其公开版本Schema生成类型，HTTP与WS共用业务输入类型；内部NATS信封、私有FactRecord和后台执行权限不进入浏览器生成目录。 事件页只使用R05/R06的EventSummaryView/EventDetailView；visibility=partial表示授权裁剪，不能按内部完整事件Schema校验或自行补读隐藏字段。运行时校验WS消息的必要字段和版本，不信任TypeScript类型断言。

服务器通知先经shared/realtime，再由所属功能按权限补读视图。教材修正、活动动作和评价判断仍由服务端作出。页面上的隐藏和前端路由守卫只是交互限制，服务端逐次授权。

### 2.5 两入口构建与浏览器测试

Vite显式构建`admin/index.html`与`student/index.html`，各自引用对应main.ts；开发代理和正式部署统一使用`/api/m1`与`/ws`。同一镜像提供两个入口，前端依赖和共享资源保持同版。路由刷新回退应限定到所属入口，API错误不得被静态页面回退吞掉。依据[Vite多页面构建](https://vite.dev/guide/build.html#multi-page-app)。具体路由模式沿接线评审确认。

测试分为纯函数/composable、组件、浏览器主流程，参照[Vue测试指南](https://vuejs.org/guide/scaling-up/testing.html)。重点检查公式图表原义、先关检测轮再提示、草稿与停止、账号切换、通知遗漏补读和目标→Evidence→原始事件追溯。各层路径、环境与实际结果归[源码组织§7](Source_Organization.md#7-测试目录与执行边界)，不以组件mock测试冒充真实后端验收。

## 3. 学生对话与多模态交互

设计讲解内容块、公式图表、题目卡片、答题区和活动路径的渲染与操作接口。说明活动定位、展开收起、明确引用书页、提交和求助怎样调用后端及呈现反馈。普通查询、保存、作答和明确活动控制通过API或消息进入相应处理器；需要AI业务的自然语言输入由公共底座派发Operation。客户端都只发送稳定请求身份、资源范围、内容和必要引用；客户端不指定Operation、结束检测轮或提交掌握结论。现有入口由服务端直接映射；聊天含义由学习助手处理。完整例子见[总体求助时序](System_Design.md#45-从求助请求到前端回显)，业务字段沿所属模块，通用信封见公共运行§5.3。

学生端遵循[Interaction输入合同](Interaction_Space_Design.md#24-输入消息与活动引用)：忙时不受理新消息并保留草稿；教材浏览、历史查询和停止本次回复仍可用。正式回复先检查保存再整条显示，不将模型流式候选展示给学生。后端是活动和评价状态的唯一依据，本轮不修改原型。

运行状态沿[公共运行§3.3](System_Foundation_Design.md#33-operationrun与步骤记录)：自动重试显示原请求仍在处理；重试耗尽显示失败和允许操作。获准恢复保留原请求／消息位置，新尝试不显示成学生又发了一条消息。停止后的重连只补读，不自动重发或恢复。WebSocket通知仅提示收据／消息可读，不能把NATS确认当作回复完成。

### 3.1 统一内容的读取与渲染

内容数据合同只在[Domain§1.4](Domain_Space_Design.md#14-文字公式图表的统一内容结构)维护；两端共享按类型渲染的组件，不另设计一套前端题面数据。服务端先按权限返回题面、参考或辅助内容，前端隐藏不能替代内容裁剪。

| 内容 | 客户端处理 |
| --- | --- |
| 文字与作答空白 | 按有序段落展示，转义文本；空白不附服务端未授权答案 |
| 公式与原演算 | 表达树派生MathML；保留括号、运算顺序、约分书写标记和辨错题原错误，不自动改正确 |
| 表格与统计图 | 从同一数据表读取值、单位和标签；未知、待填、缺失与0分别展示；关键数值未知时不编造图形 |
| 几何图 | 按白名单对象及明确关系生成SVG；布局仅为示意，不添加圆心、平行、等边等未经输入说明的条件 |
| 缺口与不支持内容 | 明确说明缺少什么，管理员可回到教材助手继续对话；不靠空白或原图替代完整解析成功 |

重排、缩放及同数据的表图切换不调用LLM、不修改领域对象。新增提示、解释或辅助图读取各自内容引用，不能覆盖原题；缓存与历史定位使用确切内容引用／对象版本，不能混用“同ID最新版”。不执行模型提供的任意HTML、脚本或原始SVG。

E02-02 在领域详情接入共用渲染组件，读取 D04 返回的说明和覆盖范围。浏览器使用从集群回读的四例正文验证各用途的展示。[交付与复验](../../../../src/m1/deploy/environments/local-wsl/E02-02-rich-content.md)

### 3.2 输入草稿与整条回复

| 情况 | 客户端行为 |
| --- | --- |
| 发送前 | 为该次输入固定request_id；草稿按账号、空间及题目引用缓存，不当作已提交消息 |
| 正在处理 | 显示处理提示；busy拒绝的新输入仍保留草稿，不自动排队。浏览历史／教材不变更当前活动 |
| 受理结果未知 | 按原request_id补查／重发，收到受理收据后才标为已发送；不能换ID重复发 |
| 收到澄清问题 | 本次处理结束，恢复输入；补充使用新request_id并引用原问题，不重试旧工作 |
| 回复提交完成 | 按message_id、message_seq去重插入整条正式消息，渲染富文本、题卡及答题区；未保存候选不显示 |
| 停止本次回复 | 发送target_input_id，按服务端返回显示stopped或already_committed；不撤回答案、不取消评价、不擅自重开检测轮 |
| 刷新／重连 | 先读服务端当前位置和消息，再还原本地草稿；已关闭轮的草稿保留可查，不能作为旧轮补交 |

聊天内转入检测准备仍跟踪原工作；只在题单准备完成后显示确认入口，不把供题完成当成已开测。停止／恢复沿原收据执行，见Interaction§4.1。

讲解中的例题和练习沿原聊天请求显示，不显示检测题单确认；只有正式检测走题单确认。等待超时按Interaction§6.3的正式收尾结果结束处理提示，保留已保存内容和未完成原因；客户端计时到期只能标明状态待核对，不能自行清除服务端busy。迟到供题或评价通知只刷新允许读取的记录，不自动插入旧活动回复。

多个标签页共享服务端busy判定，本地按钮不是并发锁。答案在答题区保存成功后，显示提交卡片和原submission_ref；不另发一条同义聊天答案。

显示回执引用正式资源及part_id，只用于显示追溯；缺失、重复或迟到均不发起评价补算。浏览器不生成教学机会身份、不更新概率。客户端显示情况与服务端已正式提供记录可以不同，重连通过补读对齐；不将“已提供”展示成“学生已阅读”。

### 3.3 主动任务的卡片与响应

只展示服务端已正式提供的任务卡片，客户端不按概率或时间自建提醒。任务卡片引用task_id及revision；接受／暂缓／拒绝由服务端核对。检测轮尚未关闭或后续独立轮仍需保护时不插入提示；后台已有pending建议不等于必须立即显示。

点击接受返回关联活动／题单准备状态；准备完成仍须确认开测。历史卡片补读当前状态，已接受、失效或过期修订的按钮不能重复启动。暂缓／拒绝失败保留原状态并提示，不在浏览器先当作处理成功。技术恢复引用原任务及执行，不要求学生新建任务。

## 4. 管理员业务操作接入

给出教材助手、领域、评价定义、目标及学习空间等已定页面的请求、结果和操作状态。处理候选核对、选择关联、保存失败及冲突提示，说明哪些展示可以直接引用公共组件。

领域入库展示服务端返回的匹配依据与`matched|mismatch|unresolved`，不把技术失败显示成内容不匹配。保存请求可能先等待AI检查再提交；只有收到已保存对象版本及结果，才显示入库成功。刷新或回执丢失先查同请求结果，不能重新分配请求身份重复保存。`version_conflict`保留当前输入并提示重新读取，不自动覆盖；软删除与新关联限制由服务端执行。上述接线沿已有按钮和流程，不增加审批页面。

活动配置保存携带expected_revision，冲突保留本地草稿并重新读取；成功后返回新config_ref。编辑规则影响新采用配置，当前活动仍显示其固定依据。节点界面只显示本层规则／策略，继承生效由服务端解析；本批不修改原型或新增规则编程器。

### 4.1 教材助手及内容交接

请求、状态及错误码唯一合同见[Product§3—4.1](Product_Application_Design.md#3-教材助手与内容准备)。本节只定义客户端如何使用，不在浏览器重做入库判断。

| 情况 | 客户端行为 |
| --- | --- |
| 上传材料 | 先选Domain，再按文件登记上传；一次选择整册，显示各文件成功／失败，失败只重传该文件。查询到ready才使用原收据，不以本地选中或进度100%代替保存成功 |
| 发送消息 | 保存request_id和草稿，发送原文及明确选择的固定引用；浏览章节不自动成为本轮引用。明确“解析整本”无需逐页发送 |
| 同教材助手忙 | `assistant_busy`表示未受理；保留草稿和引用，不伪造已发送消息、不自动排队。结束后由管理员发送；不同教材互不占用 |
| 已受理、回执未知或断线 | 202后按请求补取进度；回执丢失以同request_id重发取得原收据，不能换ID重复发消息。断线不终止服务端工作 |
| 处理中／needs_input／失败 | 进度不显示为已解析完成；needs_input呈现具体问题并允许下一条消息；失败保留原记录和草稿，不显示内容不符合 |
| 核对候选 | 显示原件、解析内容及改动对照，公式图表按统一内容渲染；采用、拒绝和继续对话，不增加手工正文编辑器 |
| 采用冲突 | 只显示服务器报告的相关内容变化，回到助手继续核对；不因另一章更新自动丢弃本章候选，不在前端合并 |
| 提交领域 | KC、题目、参考分别选择，参考显示父题；202只显示已提交，取得Domain收据才显示领域已受理。超时保留原提交，不自动再发 |
| 章节关联 | 主列表方法只读；弹框确认发送add／update／remove，取消无写入。显示服务端保存修订，已失效引用或冲突需重新选择 |

采用候选、Domain已入库、章节已保存、课程已应用分别使用各自收据，不共用“完成”布尔值。候选按batch_ref、内容按CandidateRef、Domain内容按ObjectRef缓存；当前投影更新后不以新正文覆盖历史核对记录。助手历史通过消息seq续取，事件通知不作为聊天正文。

导入删除后关闭发送和采用操作；晚到通知不得恢复已经删除的列表项。仅收到连接中断不能判定删除或失败。草稿隔离到账号及导入，切换账号不得显示前一个人的未发送内容；本地保存方式在客户端存储设计中落实。本批只补接线设计，不改变现行mock页面或截图。

定义读写沿[Evaluation§1.4—1.5](Evaluation_Space_Design.md#14-保存与删除判据)，目标载荷沿[§4.4](Evaluation_Space_Design.md#44-目标结果载荷)。界面保持已有判据卡片、方法页签和目标内Evidence列表。

## 5. 网络、异步结果与展示回执

### 5.1 登录与账号切换

启动先GET /auth/session，不凭本地角色标记进入学习数据。登录会话采用[Product§2.5—2.7](Product_Application_Design.md#25-密码与登录会话)，浏览器不保存session_token。未登录进入登录页；缺使用确认时只显示允许的确认流程，不加载真实学习记录。

用户已确认同一浏览器配置共用账号。收到账号切换或退出信号时，所有标签页关闭旧WS、撤销旧订阅、清空视图和旧账号草稿，再核对服务端身份。标签页通过BroadcastChannel传递“身份可能变化”提示，不广播凭据或学习正文；不依赖广播授予身份。恢复焦点、接口401及WS鉴权失败也重新核验，防止遗漏本地提示。

每次身份建立或失效递增本地auth_epoch。查询、通知处理和草稿恢复绑定该代次；旧代次的迟到响应丢弃。普通API携X-Expected-Session，WS hello携已核验session_id；session_changed先清空旧视图再核对身份，不能把新Cookie下取得的数据混进旧账号页面。切换前已受理的后台工作继续属于原账号，不能显示在新账号下。需要同时操作学生和管理员时用不同浏览器配置，不在同一标签页临时改角色。

E01-09实现采用共享AuthGate与内存身份状态。Cookie由服务端设置；不持久化session_token或csrf_token。标签页通过BroadcastChannel通知身份变化，不传账号或秘密；不支持时使用只含变化信号的storage事件。重新取身份前清空旧视图，取消旧读取，并用递增代次丢弃迟到响应。返回前台再次向服务端核验，连接失败显示无法确认身份，不假装退出或保留旧业务视图。写请求失败不自动重发，改查服务端登录状态。

登录与退出使用浏览器Web Locks串行协调同一浏览器的认证写入；服务端仍检查Cookie、X-Expected-Session及CSRF，不以页面锁作为授权依据。学生/管理员入口共用身份，角色不符只显示正确入口；E01-10接线前不推定学生已完成使用确认。

API类型由openapi-typescript 7.13.0生成到contracts/generated/http/schema.d.ts，登录代码只引用生成类型。先运行server侧export-openapi.py，再运行clients的generate:api；check.sh核对两份生成物，不手改Schema或生成类型。该接线不提前实现E01-11的通用收据与请求封装。

### 5.2 请求状态与草稿

请求处理沿[公共运行§5.3—5.5](System_Foundation_Design.md#53-websocket连接与命令)，学生和教材助手的输入通过WS；管理保存、查询和文件上传用既有HTTPS入口。不新增SSE，也不将模型token作为可见回复。

| 状态 | 客户端操作 |
| --- | --- |
| draft | 用户尚未发送；只存本地内容，无后台工作 |
| sending／unknown | 已发送但受理不明；锁住这条原请求的ID和正文，允许补查，不把它当未发送自动新建 |
| accepted | 服务端已持久受理；清除已发送草稿，保留请求和对应消息引用，显示处理状态 |
| completed | 补取正式结果；若还有关联执行，继续显示其状态。内容为needs_input时显示问题并允许下一条输入，不假装活动已完成 |
| rejected | 明确未受理，例如busy；保留草稿，用户下一次发送生成新request_id，不自动排队 |
| failed／cancelled | 表示后台执行结果；保留已完成提交，显式恢复或停止按服务端允许动作处理，不自动重发原消息 |

业务收据的补查统一使用[公共收据R04](contracts/Runtime_Protocols.md#r04)，按原action、资源及request_id取结果，不选择模块收据路径。业务状态和后台执行状态分别显示：答案已提交、反馈仍生成中可以同时成立，反馈失败不撤销答案。HTTP与WS错误均读取error对象；WS另看acceptance决定是否先补查，不根据retryable自行改请求身份。

业务接入时提供 R04 登记的所有者动作名，另用 WS 动作名发送。查询回执沿用原资源和请求编号。连接暂不可用时，已授权的 HTTP 读取仍可核对结果。

本地使用sessionStorage保存当前标签页草稿和待核对请求，键包含account_id、resource_ref及适用的题目／导入引用；Cookie、密码、完整服务端对话和模型候选不入此存储。刷新可恢复，退出／切换清除；本批不承诺关闭浏览器后的草稿恢复或跨设备同步。存储不可用时退为内存并明确提示，发送状态不能因此伪装成已保存。

unknown先查原request_id。没有收据时显示“发送结果未确认”，用户选择重试仍用原ID和正文；不可把草稿修改后挂在原ID上。明确busy／参数拒绝的请求允许回到可编辑草稿。新输入和已发送内容分别维护，查询回包不能清空后来输入的新草稿。

### 5.3 watch、消息补取和迟到结果

每个已登录标签页维护一条WS，进入页面后订阅当前资源的必要视图，离开时撤下。先watch_ready，再取得当前状态和消息；期间changed只置待刷新标记，读完后合并补查。浏览器不订阅NATS subject或任意事件类型。

消息按message_id／seq去重，分别使用学生对话和教材助手的游标；scope_event_seq只用于事件页。服务端给出本次消息上界，补齐该界内分页后才推进游标。查询失败保留上次内容并显示状态，不将错误当空历史。

当前活动、busy、目标结果和候选状态按正式视图更新，不只靠“来了新消息”推断。请求旧、资源已离开或auth_epoch变化时不覆盖当前视图；同视图查询串行合并，旧依据的目标结果只按历史展示。若用户正在看历史，新增消息不强制滚到末尾，保留现有活动定位行为。

页面可见时按有限同步周期补读已订阅视图；有未完成请求一并查收据。恢复焦点和重连立即补读；后台标签页暂停周期请求，回到前台再同步。频率沿基础设施§4.5 S06；同资源只保留一个在途查询，失败退避，通知合并；有未完成请求时不再叠加普通周期查询。这个只读动作不调用open_learning_space，不产生新的进入事件或保持检测。

### 5.4 断线、停止与到期

断线标明“连接中断，正在重连”，保留草稿；不把已受理解析或评价改成失败。重连采用有限退避及上限，超过上限提供手动重连；次数和间隔采用已确认的[基础设施§4.5 S07](Infrastructure_and_Deployment_Design.md#45-首轮入口与执行参数建议)。重新登录仍为同账号时查回原请求；账号变了先清空隔离。

停止指令发出后以原target_input_id和request_id补查停止收据。停止响应未知时不自行宣布已停止，也不自动恢复生成；若正式回复已提交则展示already_committed。停止只针对本次回复，不撤回答案或取消Evaluation。

输入预检沿[运行协议的共同动作计量](contracts/Runtime_Protocols.md#动作与授权视图)，同时检查实际WS消息UTF-8字节；服务端做同样的业务校验。HTTP通用正文限额不扩大这些动作的输入上限。超限提示保留原文，不截断后发送；文件走已有HTTPS上传，不塞进WS正文。上传并发和时限沿基础设施§4.5 U01–U04；已成功文件不随某个文件超时重传。

WS超大帧、协议错误、慢连接或服务端重启均可能关闭连接，后续按相同补取流程恢复；不通过更换请求身份“解决”发送失败。登录到期清空受保护视图并显示需重新登录，原账号草稿暂存且不展示；重新核实为同账号才恢复，明确退出或换账号则清除。后台工作仍受其执行授权约束。

### 5.5 呈现回执

正式内容渲染后按part_id发送已有record_presentation；重复／迟到只用于追溯，不改变教学机会或评价资格。消息已接收、已渲染和学生已作答分开表示。客户端不能把补读旧消息变成新学习事实，也不能用“没收到浏览器回执”把服务端计算结果清空。

## 6. 本地数据、权限与设备行为

客户端接入遵循[总体§6.6.1](System_Design.md#661-最小调用授权矩阵)，不凭持有引用或隐藏按钮代替服务端授权。答题区已提交内容由Interaction保存原文，不能要求同时存在聊天消息才能追溯。等待到期、执行失败及仍可查询的既有结果分别展示；是否可重试按服务端授权和所属模块校验，不自行新建输入绕过去重。

登录信息、草稿及查询缓存按§5隔离和清理；本地文件选择不视为上传成功。多模态上传及授权读取见[基础设施§2.3—2.4](Infrastructure_and_Deployment_Design.md#23-文件对象与上传合同)；Blob显示绑定当前身份代次，切换或离开资源时释放Object URL，不缓存裸文件地址。页面隐藏不等于学生退出活动，关闭重开只恢复服务端已保存内容，不承诺找回本地草稿。保留实际展示所需的回执，不建设学习计时、补记或离线教学能力。

## 7. 客户端验证与交付

制定两端浏览器的兼容、渲染、输入、恢复和权限检查案例，记录实际浏览器版本与窗口条件。明确Web构建、部署地址及与真实后端联调的接收条件；mock检查与正式业务验收分开，图文与交互规格对应维护。

等待指标由本文定义用户可见的起止，公共运行区分受理、执行及回传；双方按[实施计划§4.4](Delivery_Plan.md#44-量化验收的提出与确认)在详细设计评审时提出阈值建议。检测题单就绪先展示摘要，学生确认作为下一条输入才开始首轮；不能因后台供题完成自动显示首轮答题区。具体协议及组件接线待审。
