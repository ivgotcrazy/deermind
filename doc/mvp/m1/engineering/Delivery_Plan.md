## 1. 设计接收与依赖

[总体主流程审阅](System_Design.md#72-总体架构问题清单)已明确主要模块协作、数据与事件交接、AI取材及结果返回的边界。已有Operation草案保留，暂不深入操作步骤、接口字段和物理存储。总体问题形成确认结论或获认可的受限验证安排后，才继续下述模块接收；本清单不授权启动编码。

非功能质量问题集中登记在[总体§6.3](System_Design.md#63-非功能质量属性待讨论清单)。主流程边界、恢复目标及[四点保障方案](System_Design.md#65-已确认的恢复保障方案)已确认，资源不足按总体§1.3直接报错，不安排专门优先级调度；权限与模型外发职责已按[总体§6.6](System_Design.md#66-已确认的读取工具与越权边界)确认，允许短暂停机和具备备份恢复能力已确认，日志与事件的可观测边界按[总体§6.7](System_Design.md#67-已确认的日志与事件记录)落实，消息／事件分存及总体收口检查见[总体§3.2.1](System_Design.md#321-聊天消息与空间事件分开存储)和[§7.2.2](System_Design.md#722-总体收口检查2026-11-13)；代码组织及前后端框架已按[登记§61](../../DECISIONS.md#61-m1代码组织与前后端框架)确认；初期文件存储已按[登记§62](../../DECISIONS.md#62-m1初期文件存储与同节点部署)确认；模型API接入已按[登记§63](../../DECISIONS.md#63-m1模型api统一接入与agent配置)确认；教材Agent解析与对话修正已确认不单独接入OCR；具体模型及量化验收安排仍待确认，详细提交合同、表结构及重试参数随后设计。已有质量约束、E01–E07实现顺序及接收检查保持，本轮未授权编码。

每项实现工作引用[Operation总目录](README.md#5-m1-operation总目录)中的名称和责任章节。进入实现前核对：

- 调用者、权限、输入输出及正常分支已明确，传输Schema有唯一来源。
- 需要持久化的Step、事实事件、幂等身份、失败恢复和提交边界已定义。
- 跨Space输入与结果名称对应，等待释放资源，重试不重复业务效果。
- 已确定本工作项所需的存储、调度、模型与客户端适配；未决项明确阻塞哪一步。
- 至少有正常、非法输入、重复提交及关键中断恢复案例，期望结果来自合同。

当前业务Operation及共用机制是待审草案，传输Schema、表约束和技术选型尚未全部落实，不因总目录齐全就宣布各模块可直接开工。用户审阅关键合同，Codex据此逐项实现和验证。

正式实现沿[总体§5.1](System_Design.md#51-已确认的源码组织)组织：后端Python＋FastAPI，API和Worker共用模块；前端Vue 3＋TypeScript＋Vite，一个工程两个入口。E01承接启动与共用模块装配，客户端增量在同一前端工程中接线；不重新比较已定框架，不直接复制原型mock作为正式实现。

## 2. 必要技术验证

Temporal＋Pydantic AI＋NATS JetStream＋PostgreSQL及Kubernetes生产部署方向已定，不另设独立选型PoC。按已定方案继续总体设计，版本、资源和部署参数待确认。

[总体V01–V08](System_Design.md#73-技术验证的范围与完成条件)保留为设计及实现检查入口；V03／V04／V07的重复投递、早到通知、进程中断和恢复检查纳入E01及后续接线测试，不作为开始设计的门槛。其他语义、数值、容量与浏览器验收沿既定范围进行，测试条件和实际证据在对应实现工作中记录。本批未执行运行测试。

V01采用[总体§1.3](System_Design.md#13-已确认的试用与容量验证假设)的输入：首批总人数上限100人，首轮验证10名学生同时学习，并有管理员同期导入教材。10人不转换为固定LLM并发数；请求节奏、测试时长、模型限额、资源配置和通过阈值在试验前提出并确认。资源不足场景按最新决定检查：明确返回错误及提示，已受理输入和已完成结果仍保留；不设置教学优先、资源预留或教材降速的验收要求。本轮未执行容量或资源不足测试。

V05／V06的权限验收区分两层：底座拒绝跨空间资料引用和未授权工具，所属Operation拒绝违反业务规则的动作。覆盖教材指令不能扩权、合法候选保存、独立检测求助的先后顺序，以及拒绝后的明确反馈与允许部分接续；不把权限通过当作语义正确，也不新增权限管理页面。还须核对外发内容由Operation组织、未配置模型服务不能调用，以及服务凭据不进入提示词、客户端或普通记录；不安排材料标记或内容审查机制。以上均为后续实现验收项，本轮未执行。

V07按[总体§6.4](System_Design.md#64-已确认的恢复目标)验收停机后的任务接续及数据库、教材原件的备份恢复，不以持续不中断为M1门槛。实际恢复时长、备份恢复结果和可能损失范围须有证据；指标与配置在详细设计确认，不预填通过。

文件存储按[总体§5.3](System_Design.md#53-文件存储与初期部署)接入。E01实现统一文件访问与文件系统适配；初期API、Worker在同一节点挂载同一个local-path PVC。V07检查API写入后Worker可读、进程重启后文件仍可读及原件备份恢复；不以此宣称节点故障可自动跨节点接续。共享存储或对象存储后续按需接入，初期不同时建设多套适配或迁移平台。

日志与事件在E01建立共同记录及关联方式，E02—E07按业务补齐。验收须从某学习空间查询并筛选事件，再定位相关Operation、模型／工具调用日志和结果；失败记录应让人看清失败位置与原因。日志完整性、可读性与事件查询单独检查，不以存在日志文件代替通过，也不把技术日志当作正式事件。具体字段、级别及查询条件先设计审阅，不新增监控后台。

聊天与事件分存的验收归V06／V08：消息历史显示原文，空间事件按范围查询，Evidence沿来源事件及引用取得授权原始内容；同一消息关联多个事实不产生重复聊天记录。V03／V07继续检查提交中断及备份恢复后正文、事件与关联均可追溯。字段和具体用例随后设计，本轮未执行。

模型API按[总体§6.1.1](System_Design.md#611-模型api接入边界)由AI底座统一接入，E01承接受控连接及按Agent配置；不建设模型推理平台。E02／E04／E05分别核对教材助手、学习助手与证据解释的输入输出能力；各类Agent共用模型时，仍分别检查上下文和工具权限。具体供应商、型号与配置合同先审阅；E02按[总体§6.1.2](System_Design.md#612-教材agent解析与对话修正)验证教材Agent解析、按提示修正、核对及采用，不安排独立OCR接入。先用既有代表样例检查补漏、公式、解法拆分和局部修改范围，再按既定计划完成整册验收；API接通不作为教材、教学或证据解释的语义验收通过。

## 3. 增量实现安排

按[已确认实施顺序](../../DECISIONS.md#27-m1主流程简化与工程实施顺序)展开基础运行、内容与建模、评价定义与课程选用、学习活动、评价反馈、主动任务和整册验证。每项写明依赖、可并行部分、可使用的结果与退出条件；数值纯函数可先用结构化案例验证，再接语义解释和真实事件。

当前范围以[浏览器交付与学习用时功能后置决定](../../DECISIONS.md#34-mvp浏览器交付与学习用时功能后置)修订：不安排原生客户端、平板真机适配或学习用时统计／提醒工作。事件时间、延迟保持检测及后台执行的超时与成本记录仍属于主流程。

| 实现增量 | Operation与公共合同 | 接收结果 |
| --- | --- | --- |
| E01 基础运行 | 最小账号与授权；公共路由及预定义Operation派发；PostgreSQL业务持久化；NATS事件与Temporal／Worker执行、Pydantic AI接线；文件隔离与文件系统适配；API／Worker同节点local-path＋PVC及Kubernetes部署 | 可创建原身份、受理并恢复一个含AI步骤的有限Operation；事件可关联执行，越权和重复被正确处理 |
| E02 内容与建模 | 产品业务教材操作、Domain维护／入库、章节关联 | 原件→助手候选→管理员采用→领域实例与模板→章节采用，各自可追溯 |
| E03 评价定义与课程选用 | `manage_claim`、目标维护、`apply_course`、`open_learning_space` | 可用组合对试用学生开放，采用范围与方法适用来源准确 |
| E04 学习活动 | 活动配置、消息存储与事件关联、输入、控制、呈现、检测准备、作答；Domain供题 | 一条持续对话内完成讲解／答疑／检测，消息历史与空间事件各自可查；求助先结束独立轮，生成题检查保存后使用 |
| E05 评价反馈 | 三类评价处理及依据查询、Interaction结果接续 | 数值纯函数先用固定结构化输入验证，再接LLM解释；等待、部分结果、重复和恢复均覆盖 |
| E06 主动任务 | `check_proactive_task`、`respond_proactive_task`及已有活动入口 | 进入空间检查保持条件；无离线保持作业；同一依据不重复建任务，暂缓／拒绝和必要性重查有效 |
| E07 整册与交付 | 全部适用Operation、授权查询及真实语义验证 | 指定教材整册可用，浏览器主流程通过，质量与限制有实测证据 |

每项可拆实现任务，但不把每个内部函数都做成独立后台任务。E05的纯函数测试可在E04接线前开展；涉及真实评价接续的集成验收依赖E04事实事件。

## 4. 既有资产判断

接入前逐项核对原型、内容提取试验、spike 和 architecture validation 的用途。登记可参考的结构或测试、必须适配的内容、仅供历史比较的结果；旧工程文档只用于参考，不直接迁入新设计。mock 数据、预写响应和硬编码概率不能作为生产算法。

## 5. 验证与结果记录

将确定性单元测试、接口与事务集成测试、客户端交互测试、真实语义质量验证分别映射到[验证计划](../validation/Validation_Plan.md)的对象和指标。说明输入、预期结果、执行方式和证据位置；质量校准和学习效果另取真实证据，不以工程测试代替。

| 层次 | Operation验证重点 | 结果记录 |
| --- | --- | --- |
| 确定性函数 | 关系／Schema校验、资格、参数、数值更新、目标派生 | 固定输入、精确输出及边界断言；不能用模型回答作为数值期望值 |
| 接线与故障 | 受理后未派发、请求去重、执行恢复、业务提交后发布失败、NATS到Temporal交接中断、早到／重复通知及陈旧执行 | 按Operation及故障位置核对输入可查、交接可补、业务生效次数和结果可读；无法继续明确失败；区分消息承接和业务完成 |
| 浏览器 | 真实提交／呈现、刷新恢复、目标→Evidence→来源查询 | 对应交互规格的截图、请求与结果引用；区分生成和实际呈现 |
| 语义质量 | 解析、模板归类、供题正确性、教学与证据解释 | 保存输入、提示与工具、候选、人工核对及错误类型；工程通过不替代语义验收 |

预测校准和学习效果按验证计划另取真实学习资料，不因上述四层通过就宣称有效。本轮只补设计和未来验证入口，未执行这些工程测试。

## 6. 部署与交付

交付同一Vue＋TypeScript＋Vite工程的管理员和学生入口、共用Python后端模块的FastAPI入口与Worker启动入口，以及Temporal、NATS JetStream、PostgreSQL的运行配置；Pydantic AI依赖随应用交付。分别提供本地开发启动说明与Kubernetes生产部署说明，具体配置及数据初始化按基础设施设计确认。逐项检查浏览器访问、主流程、失败恢复及备份恢复；记录验收所用浏览器版本和窗口条件，真实后端验收不能以现有mock替代。实际结果在交付时记录，不在目录稿预填通过。
