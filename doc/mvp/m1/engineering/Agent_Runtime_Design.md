**职责。** 定义共用AI运行机制，说明Agent任务如何执行、等待、恢复和结束，以及如何安全调用模型和业务工具。

**输入。** [AI Native 架构原则 v0.6](../../../top/DeerMind_AI_Native_Architecture_Principles_v0.6.md)、[PRD v0.23 §4、§6](../PRD.md)、[活动与评价详规 v0.22](../design/Content_and_Model_Reference.md)；共同设计输入为[总体架构](Engineering_Design.md)、[业务运行机制](Business_Flow_Design.md)和[上下文设计](Context_and_Memory_Design.md)。

**预期输出与接收者。** 执行生命周期、调度与等待恢复协议、工具调用及提交机制、关键故障处理表和框架验证要求；供业务流程、接口设计与后续运行代码使用。

**边界。** 学习活动与Agent运行实例分别建模；通用执行机制不代替活动蓝图、评价算法或教学决策。共享执行器及持久恢复为待论证方向，尚未选定框架或部署方案。

下列章节只约定需要回答的问题与交付形态，尚未形成设计正文。互引的工程文档也处于大纲阶段，是交叉完善的分工，不是已经成立的输入合同。共同范围、唯一维护位置和推进顺序见[工程入口](README.md)。

## 1. Agent定义、运行实例与执行器

待设计：区分职责定义、一次执行的身份和进度、承担执行的资源，并说明其与学习空间、活动森林及检测轮的关系。

预期产出：术语与关系图；不将运行任务与Domain TaskTemplate混为一物。

## 2. 执行生命周期

待设计：说明启动、执行、等待、恢复、完成、失败与取消的条件、责任和结果，以及哪些边界可以保存进度。

预期产出：运行状态图、状态转移与恢复边界表；字段统一交[数据与接口](Data_and_Interface_Design.md)。

## 3. 共享执行与资源调度

待设计：分析执行器复用、任务隔离、优先级、模型调用限流及背压；区分本地执行资源与远端模型并发。

预期产出：调度方案及取舍、资源控制规则；不预设微服务或通用调度平台。

## 4. 任务依赖、通知与恢复

待设计：以教学等待本轮评价说明依赖登记、结果保存、通知、恢复与取消；处理通知重复／丢失及结果迟到。

预期产出：等待恢复时序图、依赖协议及当前活动变化后的处理约束；与[上下文刷新](Context_and_Memory_Design.md)对照。

## 5. 模型、工具与业务提交

待设计：说明推理协议如何落实为模型请求、结构化结果、工具权限、校验与提交，并保留实际调用和展示依据。

预期产出：调用生命周期图及工具执行合同；不由LLM输出自行授予权限。

## 6. 必要故障与一致性控制

待设计：明确超时、停止、重试、进程中断和重复执行的责任；区分失败请求、已成功工具效果与可继续任务。

预期产出：故障处理表及幂等／排他要求；与[数据与接口](Data_and_Interface_Design.md)的提交机制互相核对。

## 7. 框架选择与最小验证

待设计：提出需要对比的框架能力和有限验证场景，验证跨任务等待、恢复、隔离与不重复提交；结果未取得前不宣称可用。

预期产出：候选对比与验证规格，实际执行由[实施计划](Delivery_Plan.md)安排。
