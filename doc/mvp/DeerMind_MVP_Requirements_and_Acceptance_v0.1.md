# DeerMind MVP Requirements & Acceptance v0.1

**状态：需求与验收覆盖基线已冻结；随 G3 PASS 交付 Phase 4，尚无执行结果。冻结日期：2026-10-09。**

## 1. 文档职责与适用方式

本文把[产品定义](DeerMind_MVP_Definition_v0.1.md)的用户问题与范围转换为可实现、可验收的行为合同，覆盖学习者、家长和后台管理员。R01–R24 是需求，P01–P02、M01–M06 是支持角色任务，A01–A78 是必须覆盖的行为与边界示例；N、D 编号回指产品依据与决定。质量统计与价值观察由[验证方案](DeerMind_MVP_Validation_Plan_v0.1.md)统一规定。

产品行为及关键权限已经确定，表中后续工作是 Phase 4 的交互、领域、数据与授权设计，或 Phase 5 的实现与参数设计，不笼统视为 Definition 待决。页面布局、数据库字段和算法没有在此冻结；细化不能删减五个场景、改动质量门槛或扩大权限。A 示例为合成材料，既非孩子真实记录，也非完整的冻结评测样本；G3 通过不表示 A 已执行或通过。

## 3. 学习流程、检测与题目管理

各流程描述用户意图、输入、响应和结果，不强制所有会话走完全部环节，也不要求孩子为获取更多证据而继续作答。具体页面与异常衔接在 Phase 4 形成。

| 场景 | 进入与处理过程 | 本次可获得的结果 | 后续衔接与关键边界 |
| --- | --- | --- | --- |
| 错题再学习（R01） | 在所属空间上传或打开错题 → 取得可用题目与原始作答 → 请求某一步帮助、讲解或再次作答 | 题目与原始表现被保留；获得适用于当前请求的解释，或得到本次作答反馈 | 可选相关任务或以后复习；原题订正、提示后完成和独立新作答不能合并成同一种表现。题源能力见 R22，分类方式和具体选题条件待定 |
| 试卷回顾（R02） | 导入已完成试卷 → 对应题目、作答和可取得的批改 → 提供有依据的回顾 → 选择具体题目继续 | 能分清有支持的优势、待检查问题和材料缺口，并回到题目核对 | 错题可进入再学习，正确题存在具体理解疑点时可邀请验证；空白、照片缺失和确实答错分别处理。成绩与全域掌握不等同 |
| 主动讲解（R03） | 从知识名称、当前题目或教材内容提出请求 → 必要时澄清对象或卡点 → 先给简明、分步骤解释 → 按需继续互动 | 能取得与问题相关的解释，帮助内容和来源可追溯；允许请求仅提示或更详细 | 已确认先解释、再互动，无需先通过测验；讲完可结束或自愿尝试任务，额外任务与邀请的具体安排待定 |
| 主动章节自测（R04） | 在当前空间教材中选择一章、多章、一节或多节 → 根据有效目标、映射和检测规则形成题单 → 展示本次范围、题数与参考用时，必要时协商分次 → 孩子选择开始 → 作答 → 完成或主动结束后统一反馈 | 知道本次范围、实际取得的证据及仍不能判断的部分；过程中不自动加题，不提前展示对错与解法，不因完成题单就宣称全面掌握 | 可主动结束或求助转学习；未做部分保留未检测，未决可另邀补测。映射缺口或无适用题目需说明，R01、R05 无需先选章节；具体规则、用时估计及异常处理待细化 |
| 理解疑点验证（R05） | 系统识别具体疑点 → 解释验证目的并邀请 → 孩子接受后完成有区分作用的任务 → 根据表现回应 | 疑点获得支持、被削弱或仍未解决；需要时提供相应解释 | 提示“还需要了解”不能先写成“你没有掌握”。不接受邀请不成为能力反证；口头表达不流畅也不能单独等同数学理解不足 |

明确求讲解时先简明分步解释，必要时用图示；仅在对象或卡点确有歧义时澄清。“仅提示”请求不因默认方式而变成完整解答。学习练习逐题反馈，独立自测或复测完成或主动结束后统一反馈。多题检测中途请求提示或讲解时，结束本次检测并转教学，保留已有作答，未做题标为未检测；不把余题自动接续为同一次独立检测。输入核对、识别更正及技术恢复本身不触发教学切换。实际展示前不能登记为已接受帮助，之后另开检测、重新作答或新会话也不抹去相关暴露。外部测评若有适用约束，不能用自主切换规则越权。

主动章节自测通过本空间教材选择章、节及其组合，选中父子节点或共享对象时合并去重。教材范围只是入口，实际检测还依赖有效 Target、Task、Solution、KC、Claim 与证据规则；章节中出现的全部 KC 不自动成为必测项目。Phase 4 准备检查责任、适用条件、可观察表现、覆盖关系和参考依据，沿用现有审核发布流程，不增加通用语义模型编辑平台。

题单在开始前形成：合并有效检测要求，选择或生成适用题，核对缺口，展示实际范围、题数及参考用时，由孩子决定开始。题量来自题单及覆盖，不是 KC 数量乘固定系数或无依据的模型数字。映射或适用题不足如实说明，范围过大协商缩小或分次；正常作答不自动追加题目，结束后仍未决可另邀补测，由孩子选择。参考用时不是强制倒计时。未作部分保留未检测，技术中断不伪装成主动结束或不会。首版不要求运行中自适应换题或自动提前结束。

适用历史可减少重复检测，但须区分本次表现、历史支持和未覆盖范围。历史题可作为候选，是否值得重测以及选原题、变式还是原生题，由 Policy 依据当前 Belief、相关 Evidence、目标、帮助与接触、时间和负担决定。新反证可修正旧判断，曾答对或听过讲解不直接免测；缺少证据不直接命令重测。新编号、改数字、连续答对不能机械累计独立证据，原题重做也不一律无效。检测后只有 Evaluation 按实际表现形成新的能力认识。具体适用性、充分性和复习计算模型由 Phase 5 设计。

R22 同时支持教材原题、变式和原生题。原生题无须种子，可以引出计算、解释、比较、判断或纠错等正式模型支持的表现，不承诺全网独创。选题先明确练习或证据目的，再检查数学有效性、目标适用性、图文一致、合理负担及可核查解法；开放任务容许多种正确回答，教材例解不是唯一合法解法。已审核模型与获准规则内自动生成、校验及使用，无须逐题人工审批；无法核验先不使用，正式语义变化经 R20 处理。具体领域与检查依据由 Phase 4 准备，不能用一句可读题面代替适用性验证。

R23 保存所有完整生成候选，包括未选用和核验失败的候选；未形成完整题目只记录生成失败。纲内上传新题也须入库，缺映射时保留题目与未决，不编造关系。题目档案、版本、质量状态与每次使用分别管理；生成、合格、展示、作答和当前可复用不是同一状态。

| 信息 | 需要表达的信息与用途 |
| --- | --- |
| 题目身份与内容 | 稳定编号、版本、题面及图示、可用解法或判定依据；内容记录存在不等于正式模型已批准 |
| 任务与知识关系 | 引用适用的 Task Family、Target、Solution、KC 与版本，区分本次主要检查对象和支撑知识；题目关联的全部 KC 不自动成为这次实际检验的 KC |
| 变式维度 | 记录改变了哪些数值、条件、表示、情境或作答要求，哪些任务要求保持不变，以及预期检查什么差异；原生题记录所选择条件与模型依据，不编造母题 |
| 来源与生成依据 | 原题、一个或多个参考题、生成要求、模型与规则版本及核验结果；仅有相似性不冒充实际派生关系 |
| 质量与使用范围 | 待核验、合格、需复核或停用及依据，适用目标和课程空间；曾通过校验不代表在模型变化后仍自动适用 |
| 每次实际使用 | 关联学习者、活动、准确题目版本、实际展示、提示或解法暴露、作答、评价依据及版本；从既有事件和执行记录追溯，不另建可改写运行事实的来源 |

变式描述复用 Task Variables 等适用关系，说明哪些条件变化、哪些任务责任不变及预期差异。不能为数值变化新建 KC 或 Task Family，也不能仅凭相似性伪造派生关系；从计算转解释等责任变化需检查正式模型是否支持。难度和预期诊断价值可为估计或待验证，少量个人表现不成为稳定测量参数。稳定编号不编码全部语义，修订保留旧版与实际使用，不把历史改成使用了修正后的题。

合格、适用且未停用的题仅在本空间复用，不建设跨两空间共享题库。去重不得丢失生成与使用记录，语义相似不等于同题；具体去重和未使用候选的存储策略由工程评估，不把保存全部候选扩大为保存全部原始模型请求。已提交学习材料及实际学习记录继续按 R24 保留，后台在现有内容和模型职责内追溯来源、质量和使用。

知识超纲、纲内新题及模型缺口按产品定义 §6 处理，并由 A75–A78 验收。已有 Task 未登记不是拒绝纲内求助的理由；当前帮助需要校验但不一律等待人工补模，正式掌握判断不能使用未经批准的关系。普通新实例复用，真实缺口进入 Evolution。Phase 4 必须把当前帮助、入库、评价和后续模型变更的衔接设计成完整路径。

[ETS 的 ECD 研究](https://www.ets.org/research/policy_research_reports/publications/report/2018/jzuw.html)为目标、证据与任务的对应提供方法参考；[题目模型研究](https://www.ets.org/research/policy_research_reports/publications/report/2006/hska.html)支持用任务变量与约束组织变式。这些资料不证明本项目的标记、出题和选题质量。首版采用开测前组卷，是为了控制运行中计划变更与停止判断的复杂度；相关取舍可参照[计算机测评设计报告](https://www.ets.org/Media/Research/pdf/CBT-2011.pdf)，但不据此宣称统计精度或已测工期。资料核对日期：2026-10-09。

| R09 作答分析触发与默认反馈 | 手写作答由孩子点击提交或求助后触发语义分析，语音按 R10 点击发送后进入学习处理；学习练习逐题反馈，独立自测或复测完成或主动结束后统一反馈，中途求助可转教学 | 未触发时不发起学习判断与教学反馈；提交和求助分别保留，内部评价不冒充已展示帮助，反馈不提前泄露检测题的对错或解法，未做不等于不会；语音预览转写不构成正式作答 | D03、D05：具体反馈内容、界面和恢复行为；必要保存与预览处理不等同于触发学习判断 |
| R10 双向语音 | 学习者主动开始、结束录音，录完可查看或修改识别文字、取消或重录，点击发送后进入学习处理；语音提问或求助默认播放回复并显示文字、公式和图示，文字或手写输入默认展示、可选择播放；已发送录音关联转写和实际发送内容保存，可回听核查 | 指定 App 完成录音、预览、发送与回复；自测语音作答遵循 R09 的统一反馈；可停止或重听，失败可通过文字继续；取消或重录淘汰的录音不入学习历史，临时文件按规则清理；保存不扩大访问权，重听不产生新的独立作答 | 保留与删除遵循 R24；D04、D05、D07：删除与临时文件清理规则、相关依据及排障访问细节；具体界面、识别播放技术和质量门槛在相应阶段明确 |

教材接收多页 PDF、成组扫描图片，错题与试卷接收拍照、图片和 PDF；印刷文字、公式、表格、几何图、手写答案与过程均属支持类别，须保留跨页题目、图表、作答和来源关系。不是只保存附件即算支持。格式、文件页数边界、内容复杂度与代表性样例由 Phase 4 确定，不默认承诺任意材料均能正确处理。

教材识别后经管理员核查发布；日常上传默认自动处理，手写在提交或求助后分析，关键数字或条件不确定只确认局部，不要求逐题审批。其余有依据的部分继续处理，未决不记为答错，确认过程不泄露测验答案。未标疑材料也可有误，原件必须可核对、更正并处理受影响判断。无答案教材可导入，候选解法注明系统生成、校验后经章节审核；未核验解法不用于相应讲解与判断，也不堵住其他就绪内容。教材审核不变成每次日常求助的人工预审。

语音由孩子主动开始、停止录制，预览转写后可修改、取消、重录或发送；预览转写不触发正式作答、评价或教学回复，也不强制逐字确认。已发送原录音、转写、修改与实际发送内容关联保存，不能用修改文字覆盖原录音。同次输入不重复计为独立作答，转写错误不归为知识错误。未界面删除时可回听和提出异议；取消或重录淘汰的临时录音按工程清理规则处理，不入学习历史。不要求持续监听或全双工对话。

语音求助默认播放并展示，文字或手写默认展示、可选择播放；独立测验仍统一反馈。停止只结束播放，不撤回已提交输入或已展示文字帮助。生成、文字呈现、音频开始和完成、主动重听分别记录，不推定已经听懂；重听不重评原作答。识别失败可转文字，播放失败可看原回复，状态不明时按 R13 核对后继续。家长和管理员对录音的访问分别受 R15、R17、R18、R24 限制。

学生端指定 HUAWEI MatePad Pro MRR-W29 与手写笔，家长使用手机，两端系统 HarmonyOS 4.2.0，分别交付 Android APK；后台为电脑 Web。Phase 4 补齐手机型号、笔、系统构建和浏览器，Phase 5 实测安装升级、输入权限、连续书写与手掌误触、滚动、拍照、语音和公式图表阅读等体验。不能由 HarmonyOS 名称推断 Android API，核心流程不依赖额外安装 Google Play 服务；不以桌面接口或 APK 可安装替代实机任务验证，也不改为网页前置试验。

日常异议先复核，不因孩子或家长说有误就改写事实，也不凭第二个模型同意宣称解决。现有规则与权限内可确认的记录错误，由相应 owner 自动更正并处理实际依赖；未决、冲突、正式模型修改及学生端已删资料维护交唯一管理员。已知失效依据停止当前使用，局部更正不重置无关记录，修复待完成或失败如实表达，历史展示与帮助保留。

更正若实质改变此前已展示的讲解、判题或掌握结论，须在产品内主动告知受影响且当前有权查看的用户，说明原问题、更正及仍待处理部分；纯排版和未展示候选修正不造成无意义打扰。通知生成不等于实际呈现或理解，按影响和权限选择对象，不广播所有家长、不泄露其他家长对话、不向撤权账号展示，也不恢复学生已删原件或重放旧教学。具体提报、等待与通知界面由 Phase 4 设计，复核及依赖实现由 Phase 5 落实。

R24 的删除作用于相应用户界面：无需管理员审批，无回收站或恢复入口，列表、搜索、详情、旧链接及新回复不直接重现该条目，重装也不恢复。内部历史、帮助、Evidence 和 Belief 保留，按有效性及当前授权继续使用；围绕相同知识提供其他适用任务不受条目删除禁止。家长仍可在相关判断依据内只读查看学生已删资料，不能恢复或编辑；发现错误走后台例外。家长删除自己的交流不删除孩子资料或撤销已完成维护。

上传资料的删除单位是原始资料：独立上传的一题可单独删除；整份试卷按整卷删除，同步隐藏原卷、关联错题入口和原作答，不支持只删除其中一道题。从卷内错题进入删除时，先明确将删除其所属整卷，不能用“删除这道错题”的提示执行整卷删除。关联讲解和判断页遵守同一原件显示限制，后台继续分析、重试或更正不得重新展示被删资料。其他独立资料或之后独立发生的练习不连带删除，但不能借它们重新展示被删原件；删除不等于更正判题，也不撤回实际发生的帮助。

家长咨询以整段会话为删除对象，不提供单条消息删除；会话中的提问、回复及其展示入口一并移除，新回复不得经摘要或检索重现被删交流。删除咨询不删除孩子资料，也不撤销已经提交的独立后台事项。事项仍可按既有权限处理和告知结果，但事项页与通知不能成为恢复整段私人咨询的入口；后台已合法取得的事项材料继续受具体用途及访问权限约束。

删除界面明确说明用户不可恢复而内部记录保留，不声称物理销毁，也不扩大原有数据用途。已提交照片、笔迹、录音和学习记录随档案保留，不以固定天数自动清除；完整物理删除与关联处置、数据使用授权撤回功能均留后续。首版仍按当前角色、空间权限及已确认范围使用数据，亲子解绑后的访问限制继续执行。临时未发送录音不混入此保留规则。其他学生资料的删除粒度、关联显示及首次告知与确认继续在 Phase 4 设计，存储备份在 Phase 5 落实。

断网时保护已写内容和待提交材料，区分本地保存、服务端接收、处理与展示。没有响应不代表未接收，恢复先核对原提交：处理中继续等待，已完成取得原结果，确需重试只处理原提交的未完成步骤，不建立新作答或重复评价。技术尝试与学习表现分别计数；身份、空间、授权及主动结束状态仍生效。首版不承诺完整离线教学与评价，保存位置、寿命、自动或手动重试、超时和上限在工程设计明确。

展示回执丢失时区分已经发生与未知，不补造“未帮助”或“已帮助”；恢复不自动重播已播放或状态未明的旧音频，主动重听仍可用。测验不能借恢复提前泄露答案。批量试卷与教材已被服务端接收后可离页处理、返回查看原任务；上传未完成或接收未知如实标明，教材处理完成仍不代替核查发布。普通单题时延从原始客户端提交计算，重试不重置，30 秒是交付目标而非自动取消时限。

R14 的具体复习决策模型在 Phase 5 基于理论、规则与经验确定：应明确适用假设、输入输出、参数、计算与语义推理分工、验证及失效处理。Phase 4 先准备交互、正式领域关系和代表性材料。Evaluation 提供 Belief 与 Evidence，Policy 决定建议、暂缓或不建议；时间流逝可触发重新评估而非直接命令复习，拒绝不成为能力反证，理由反映实际依据。此处不预选固定间隔、遗忘公式或模型组合，不新增核心 Space、绕过 Policy 的执行器或产品外通知渠道。

## 6. 家长、管理员与账号流程

| 流程 | 进入、操作与结果 | 关键边界与后续设计责任 |
| --- | --- | --- |
| P01 家长了解并支持学习 | 登录家长 App → 在获授权孩子中选择当前孩子与课程空间 → 查看近期情况、困难或未决 → 查看相关题目、作答与判断依据并提出疑问 → 之后回看进展 | 孩子选择与多对多关联已确认，切换不串用其他孩子的数据；按空间查看概况与依据，不默认浏览全部历史；相关上下文和信息频率待定，不生成跨空间掌握推断 |
| P02 家长询问与理解判断 | 在所属空间针对判断询问 → 系统按授权依据说明 → 可继续询问或管理自身交流；既往结果被实质更正时按 R12 取得相关告知 | 对孩子资料只读，家长输入不直接成为修改指令。普通资料更正在学生端，已删资料纠错交后台且不恢复条目；提报与通知形式在 Phase 4 细化，通知遵守各自对话边界和当前授权。首版不提供家长独立上传或修改学习资料 |
| M01 管理员准备内容与使用条件 | 进入后台 → 创建学习者和家长账号、建立明确关联并按权限准备空间 → 导入教材 → 对照原件核对章节与题目 → 分批确认开放 → 查看内容与领域映射各自状态；后续可维护关联及按核实流程重置用户凭据 | 后台开户、多对多关联维护及恢复分工已确认；核实和具体交互由 D04 明确，内容覆盖仍待 D02；各关系单独授权，账号与关联变更保留学习档案，章节确认不自动批准领域模型，正式模型维护见 M04 |
| M02 管理员处理运行或质量问题 | 从具体审核、复核、失败任务或已删资料事项进入 → 按 R17 查看相关原件与依据 → 经既定流程处理 → 核查更新结果及 R12 所需更正告知，保留记录 | 同一管理员独立完成，无第二人审批；已删资料维护不恢复学生展示，不能直接手改掌握或以家长身份取得管理权限。告知反映已修复与待处理内容；提报、事项关联、自动条件和通知交互继续设计 |
| M03 管理员配置模型并查看用量 | 进入模型连接配置 → 设置或修正连接 → 获知配置的可用状态 → 查看调用及用量情况 | 配置与用量查看已确认；可用状态的检查方式、生效范围、用量与费用口径、失败后的处理和回退由 D04、D07 及后续技术设计明确；不承诺配置变更自动重算历史评价 |
| M04 管理员维护模型与映射 | 从章节、题目、具体线索或模型对象进入 → 按建设或演化目的取得评估、候选与检查材料 → 管理员查看和修改，核查疑点、样例及影响 → 批准明确范围并按治理规则提交和启用 → 检查后续使用与依赖维护结果 | 教材建模按章节组织审核，基础演化按 §7.1 处理；同一管理员可完成修改、审核与发布，未决可保留，无须修改可结束。最低领域参考由 Phase 4 按 D09 准备；AI 不自批结构语义变更，人工兼任不合并授权和 owner 提交责任 |
| M05 管理员追查判断 | 从疑似错误判断进入 → 查看授权范围内的材料、观察与依据 → 找到引用模型及版本 → 定位来源、映射、评价或运行问题 → 转入对应维护流程 | 使用正式记录的输入输出、来源、规则版本、校验及可审计说明，不要求模型内部思维过程；能查到原因不自动赋予发布修改的权限 |
| M06 管理员交付其他语义模型版本 | 查看当前与候选版本的来源、差异和验证资料 → 检查授权及适用范围 → 经相应 owner 提交和受控启用 → 查看结果、影响及必要恢复 | 覆盖评价、交互和推理规则的版本交付；候选如何准备或进入系统待设计，不增加任意在线语义编辑器，也不绕过正式提交与版本合同 |

部署初始化首个管理员，后台创建学生和家长账号，暂不开放自助注册。三类账号分别以账号名密码登录，孩子无须手机号；两个 App 可保持有效登录，退出或失效后重认证，后台单独登录。账号、稳定档案、亲子关系和管理授权分别表达，共享实现不能共享会话权限。

首批人员的身份、亲子关系和找回账号，由项目发起人以管理员身份在系统外人工核实本人和关系，再在后台记录对象、核实方式、结果、操作范围及时间，执行相应操作。首版不新增证件上传或自动身份认证，不要求第二人审批；核实未完成时不凭账号名称或家长陈述直接绑定、重置。

首次使用由项目发起人以家长身份确认对应孩子学习数据的用途、可见范围、保留方式及实际外部模型服务，记录当时说明的版本、范围与确认；孩子端用简明说明确认愿意使用。两项必要确认完成前，不启动真实学习资料的接收与分析。家长授权、孩子参与意愿、管理员核实和登录状态分别记录，不以家长代点或账号已建推定孩子愿意使用。以后每次打开不重复确认；相关用途、可见范围或服务范围改变时重新检查，超出原授权的部分在取得相应确认前不启用。关联家长的只读权限不自动赋予替孩子授权的身份。

MVP 不提供学习数据使用授权撤回功能，家长端入口、管理员代办及其配套处理和验收均留后续。本次范围取舍不取消首次授权、当前权限与用途范围检查，也不影响亲子关联解除、退出当前学习活动或既定界面删除；这些操作各按原有含义执行，不能互相替代。

后台维护多对多亲子关联，每段关系分别授权和解除，双方能查看当前关联。家长选择当前孩子及空间，检索和推理上下文不串用；多家长仍指向同一学习者档案，解绑一段不影响其他有效关系。保持登录不绕过撤权，首批只有一组真实关系不成为一对一硬编码。

家长可查看授权的概况及相关依据，对学生资料只读；各自对话默认不向孩子或其他家长共享。访问接口、搜索、引用、总结和模型上下文均执行同一边界；共同获准查看同一学习事实不等于共享提问。首版家长任务分配、目标修改及专门线下表现录入暂缓，咨询和接口不能绕过此执行范围。

家长在咨询中转述的线下表现，首版只用于家长咨询，不形成更新孩子掌握判断的正式学习 Evidence。保存了家长这段陈述，不等于观察到孩子做出相应表现；摘要、后续检索与上下文复用也不能改变来源及用途。基于转述的建议须保留“按所描述情况”的条件，不另写无依据的能力结论。对已有系统记录或判断提出异议仍走 R12 的合法复核路径，核实后的原材料与正式更正按原合同处理，不因这项限制停止纠错。

普通资料录入和更正在学生端，家长不得直接修改、删除或恢复。管理员针对具体教材审核、学习质量复核或故障读取相关原件、识别、讲解与判断依据，包含事项所需原录音和学生端已删资料；身份、对象、空间、操作由服务端检查，读取与修改关联事项、用途和结果，不授予无关资料通读权。单人可兼任修改、审核和发布，但不能直接填掌握程度或借家长会话行使管理权。

学生或家长凭据恢复由管理员按上述人工核实方式记录后重置，继续关联原档案及历史；管理员有独立恢复方式，亲子关系不是恢复管理权的凭证。不以直接改库代替已纳入的界面流程，不要求第二位管理员。关联告知与后台记录交互由 Phase 4 展开；密码、会话、管理员恢复、签名更新和技术实现由 Phase 5 决定，不预设永久登录或数值期限。

## 7. 模型与教材映射管理

下表定义必须能够追溯或维护的信息，界面布局和操作编排由 Phase 4 设计。Learning Space 与教材映射完整维护，其他语义模型受控版本交付；M03 的模型服务连接配置与这里的语义模型管理分开。

| 对象层 | 可查看的信息 | 维护方式与边界 |
| --- | --- | --- |
| 教材与来源 | 原件、页码、章节、题目、例解、识别内容、核对状态和内容版本 | 校对来源与结构，按已确认方式分批开放；教材答案与 AI 生成解法分开，原始来源不静默覆盖 |
| Learning Space | Target、Task Family / Instance、Solution Strategy 及必要分解、KC 与知识支撑关系、适用条件、来源、版本和未决项 | 已确认 AI 起草候选，管理员查看、修改并检查疑点与代表性样例；正式定义及关系改变经验证与治理授权，由 Learning owner 提交，再在限定范围启用 |
| 教材到领域的映射 | 内容与任务实例的对应、任务归类、可用解法、知识支撑和目标关联；正向及反向引用 | 纠正错配、提出新增或替代对象、保留未决；不把每段正文都变成 Task，不把每个步骤都变成 KC |
| 学习者运行判断 | 实际输入与帮助、Observation、Evidence、Belief、适用条件、引用版本、当前有效性和依赖 | 按权限追溯、提出异议并走 owner 更正或重算，不直接填掌握程度；记录修正与正式模型改版分开处理 |
| 评价、交互和推理规则 | 评价规则、交互策略、Reasoning Protocol 的当前版本、适用范围、验证依据、异常及关联问题 | 已确认提供查看、追溯与受控版本交付；能够检查候选来源、差异、验证、授权、启用及恢复，不建设每类模型的通用在线编辑器；具体交付方式待设计 |

各功能满足自身条件后开放，不把全部 KC 关系齐备设为共同前置，也不以一次章节批准执行所有学习行为。以下讲解条件区分教材预置内容与日常求助，避免将教材发布审核扩大为在线题目逐题人工预审；正式模型变更仍受治理约束。

| 功能 | 已确认的开放依据 | 缺口如何影响使用 |
| --- | --- | --- |
| 浏览教材与题目 | 相应原材料、识别内容及题目对应已核对开放 | 不依赖完整领域映射；没有答案不妨碍浏览，未核对部分保留状态 |
| 讲解题目或知识内容 | 对应内容与解释依据适用，教材预置解法经校验与章节审核，日常求助解法经适用的运行校验 | 局部 KC 关系缺失不自动关闭讲解；不使用待核验解法，不给每道上传新题增加人工预审；讲解发生不计为已掌握 |
| 当次作答反馈 | 当题要求、有效解法及判定规则明确，实际作答与帮助情况可用于相应判断 | 可对有依据的部分给出当次反馈；材料或标准不足保留未决，不将一次对错直接升级为能力结论 |
| 任务或知识点掌握判断 | 对应正式领域对象、适用 Claim 及评价规则有效，作答与帮助记录能够形成相应证据 | 仅更新有足够依据的命题；Task 判断和 KC 判断分别处理，未建立的关系不被编造成结论，模型缺口不计作能力不足 |

Task 与 KC 判断各受相应 Claim 约束，未决 KC 关系不妨碍其他有充分依据的 Claim。[Learning Space Design](../concept-design/DeerMind_Learning_Space_Design_v1.1.md) §5–§7 的任务与策略关系可以多对多：同题多解不一定检验同一组 KC，正文概念可关联知识和适用任务而不必强制建题。UNKNOWN、部分理解和未确认映射须保留，不以凑图谱完整度替代正确性。

教材建模按章节由 AI 起草候选、来源、验证材料与未决，管理员可查看、修改全部候选，核查疑点及代表性未标疑样例后批准明确范围。抽查不等于全部正确，未确认关系不能随整章批准生效。流程遵循候选与验证 → 人工治理授权 → 对应 owner 提交 → 限定启用 → 影响检查，见[Governance Runtime](../system-design/DeerMind_Evolution_Governance_Runtime_Design_v1.0.md) §6–§7；一个人兼任不合并这些责任。不把手工逐题建模或逐关系审批设为默认工作量。

发布前可查差异、基础版本、作用空间、验证依据、未决风险及依赖影响。知识和判断依据变化按实际语义检查，版面修正不自动全量重算，任务归类或解释变化可能影响 Evidence/Belief，仅 Target 标准变化通常检查 Target Assessment，见[Evaluation Space Design](../concept-design/DeerMind_Evaluation_Space_Design_v1.1.md) §7.3、§7.9。已知失效停止当前使用，未完成及失败可见；校内改版不静默影响校外。

回退仅在授权范围恢复未来使用版本，旧执行与题目版本保留，既有错误结果仍需维护，不重放旧教学。合成例：题目“原价 200 元，八折后付多少”若错归“求优惠金额”，参考 40 可能使正确答案 160 被误判；应核对原件、任务和解法，修订映射并处理其依赖判断，而非直接把学习者掌握标记改好。该例不构成教材范围承诺。

| 维护任务 | 开始时的情况 | 完成时应有的结果 |
| --- | --- | --- |
| 初始建模与映射 | 已核对教材中的题目或内容尚无适用的正式关系 | 系统提出可建立或复用的对象与候选关系；管理员可查看、修改和核查样例，批准明确范围后经适用流程启用，并回查来源、版本和功能可用条件 |
| 修正已使用的映射 | 某关系存在已确认问题，已有判断引用旧版本 | 能定位影响、修订和启用、检查相关结果的替代；不影响的记录保留，待处理或失败明确显示 |
| 恢复与回退 | 新版本启用后不满足预期，或替代计算失败 | 能在获授权范围内处理未来使用版本，并列出历史结果的剩余维护工作；不抹去事实，不误称全部恢复 |
| 交付其他语义模型 | 评价、交互或推理规则已有候选版本及验证资料 | 能查看差异、检查授权和范围、由对应 owner 提交及启用，并追溯结果与必要恢复；不依赖任意改写数据库 |

纲内新题暴露的覆盖缺口按 A78 进入基础领域演化；普通实例无须新建 Issue。缺口评估、候选验证、人工授权、owner 提交和启用可追溯，失败不启用、成功不改写先前事实。其他语义模型仍通过现有受控交付承担修订，不扩张为所有模型的在线编辑平台。

### 7.1 基础领域演化的最小行为合同

R20 承担人工主导、AI 辅助的真实领域演化。首版对 KC、Task Family、Solution 和教材映射的必要新增及局部修正完成下列路径；Target 的既有维护、标准变化后的影响处理及其他模型的受控交付仍按 R19–R21、A21、A22 执行，不因基础演化聚焦而删除。新增对象也须检查依赖和适用性，不能仅因操作名是“新增”就推定没有影响。

| 环节 | 必要输入与处理 | 结果与责任边界 |
| --- | --- | --- |
| 发起与取材 | 管理员提出具体需要，或选择处理已保存的题目、运行失败与覆盖线索；关联本空间的原材料、所用模型版本、实际结果和预期行为 | 形成可追溯的待评估材料，记录目的、范围与当前授权；线索不直接成为已证实的 System Issue，不建立第二份可改写的事实历史 |
| 评估与解释 | AI 按语义规则检查已有模型、实际输入和参考要求，区分现有对象可复用、识别/匹配/单次推理错误与真实领域缺口；保留相关替代解释、支持与反对依据 | 可得出不需改变模型、确有范围有限的问题、依据不足或需转交其他维护。System Assessment 与 Hypothesis 的结论、理由和不确定性可区分；不能把第一个合理解释写成已确认原因 |
| 候选准备 | 基于可说明的需要起草新增或局部修订，引用准确基础版本，列出定义、条件、来源、实例、解法或知识关系、预期效果与影响；管理员可修改 | Hypothesis 解释原因，Revision Candidate 表达具体修改，两者不混用。候选没有正式效力，不因新题出现就新增 KC，不将修改模型当成修改学习者 Belief |
| 有限验证 | 围绕问题与候选预先确定参考材料、区分性案例、相关旧案例、方法、通过/否定/未决依据及停止条件；执行后保存版本、实际输出、人工介入与限制 | 分别说明原因获得何种支持、候选是否达到预期及是否出现副作用。使用可核查领域材料、规则与 LLM 辅助及人工复核，不以生成模型再次同意或人工批准充当验证成功 |
| 审核与生效 | 管理员检查完整候选差异、验证、未决和影响，批准明确版本及范围；相应 owner 校验后提交，再在授权范围启用 | 修改、审核和发布可由同一人完成，但批准、提交和启用结果分别留痕；未经批准、基础已变、检查或发布失败均不得冒充生效 |
| 生效后检查与维护 | 在后续实际运行中核查适用对象、引用版本及预期结果；检查受影响的既有判断，必要时触发既有更正、恢复或获授权回退 | 记录改动是否实际被采用以及效果、失败或仍需观察之处；生效不自动关闭全部问题，回退不删除历史或代替依赖修复，不重放旧教学 |

初次教材建模仍从领域建设入口起草对象与参考材料，共用候选、检查、审核和发布能力；不为新章节或每个新对象虚构旧模型缺陷。问题驱动与建设/理论来源的目的、依据和适用检查须明确，符合既有[Evolution 合法入口](../concept-design/DeerMind_Evolution_Space_Design_v1.1.md#32-两类合法入口)及治理合同。不存在的 Issue、原因证据或运行效果不得为补齐流程而伪造，具体记录映射在详细设计中落实。

学生当下求助与后台维护分别推进。当前能够核验的纲内帮助仍须提供，题目与实际使用保存；后台排队、未决或验证失败不成为常规拒绝理由，也不授权使用候选关系形成正式掌握结论。已批准自动处置条件内的普通记录更正沿用 R12，不将每次识别纠正都升级为领域演化。

首版不要求持续自动发现所有问题、开放式搜索原因、通用实验编排、跨模型自动修订或大规模多版本平台。后台可以按一项维护事项呈现上述过程，不必让每个语义对象对应独立页面或服务；信息、责任、版本和非成功结果仍须可区分。复杂原因无法确认时可保留未决，管理员意见也不自动成为事实；不得为减少步骤而删除相关反证、必需检查或授权。

Phase 4 将此合同落实到后台及学生端衔接、首批变更情形、独立参考、审核材料与生效后检查要求；Phase 5 设计数据与接口、LLM 任务及上下文、验证执行、版本依赖与恢复，估算实际增量并限定运行次数或时间。若特定变更只能靠扩大首版范围或削弱合同实现，提出具体冲突讨论，不静默增加通用平台。完成标准由验证方案 V10–V11 统一维护，不将详细设计留到编码时临时决定。

## 8. 验收覆盖示例

以下 A01–A78 覆盖正常行为、权限、失败与边界。Phase 4 补齐真实支持范围与参考材料，Phase 5/6 转成相应测试与验收；不得把全部示例的文档存在当成质量合格，也不得删去不利路径后声称完整覆盖。

| 示例 | 输入或触发 | 预期行为与应防止的错误 | 关联需求 |
| --- | --- | --- | --- |
| A01 手写后求助 | 孩子写到一半，尚未提交；随后选择求助 | 求助前不自动给教学判断。求助后的解释记录其帮助条件，后续成功不能无条件记为独立完成 | R08、R09、R11 |
| A02 上传材料局部不清楚 | 孩子上传错题或整份试卷，一处关键数字有歧义，无法确定原题或作答 | 指出有疑问的局部并请求确认，不强制重核整份材料；先澄清再作依赖该内容的评价，不把读不清记为算错，其他有依据的内容继续分析并标明未决范围；识别确认不借机泄露测验答案 | R01、R02、R08、R09、R11、R12 |
| A03 有具体理解疑点 | 作答正确，但现有材料不足以支持对原理理解的结论 | 可以提出针对疑点的验证邀请；不能因为材料不足断言不会，也不能因为答对直接断言充分理解 | R04、R05、R11 |
| A04 切换课程空间 | 校内空间有一条相关错题记录，校外空间发起自测 | 校外不引用该记录选题、评价或说明理由；这不等同于假定孩子现实中没有学过相关内容 | R06 |
| A05 更正后处理失败 | 已确认某识别结果错误，依赖它的评价重算失败 | 原始记录和更正保留，受影响判断不再以当前有效结论使用，失败状态可辨；不自动重放旧教学行动 | R12、R13 |
| A06 讲解结束 | 系统已提供解释，孩子暂时没有继续作答 | 保留解释已发生这一事实；没有新的能力表现时不生成“已学会”的结论，也不把退出直接当作不会 | R03、R04、R11 |
| A07 明确请求讲解 | 对象清楚，孩子要求讲解一个知识点，没有先完成测试 | 按 D03 方式先给简明、分步骤解释，按需配图和互动；只有实际需要时澄清，不以完成强制测验为前置条件 | R03 |
| A08 自主自测中求讲解 | 本次允许自主切换，多题自测中孩子在独立尝试后请求提示或讲解，尚有题未做，帮助还未展示；另覆盖仅做识别确认或技术恢复 | 请求教学帮助时结束本次自测并进入教学，保留已有作答，未做题标为未检测；开测说明与求助入口表达这一后果。识别确认及技术恢复不机械触发结束；实际展示前不记录为已获得帮助，之后另开检测仍保留相关暴露，不把余题自动续作同一次独立检测 | R04、R09、R11、R13 |
| A09 主动学习教材 | 孩子按章节打开所属空间已确认内容，选中例题或练习 | 对应能力就绪时可请求讲解或开始作答，不必先由系统排到该章节；待核验解法不用于相应讲解或判断，正式学习判断还需满足领域映射及证据条件 | R03、R07、R19 |
| A10 一开始只要提示 | 孩子明确要求“只给提示，不要完整解答” | 响应当前请求的提示范围，不套用默认讲解方式先给完整解答；已展示内容保留真实帮助记录 | R03、R09、R11 |
| A11 家长查看学习情况 | 家长进入授权的课程空间查看一项判断 | 能看到概况及相关题目、作答和判断依据，区分未知和问题，并可提出疑问；不扩展成全部原始记录浏览，也不静默引用另一空间的数据 | R06、R15、R18 |
| A12 管理员处理导入失败 | 后台教材任务失败，管理员检查并重试 | 能辨认失败与处理结果；失败内容不被宣布可用，重试不静默覆盖来源或重复发布；恢复后仍按章节核对确认再开放 | R07、R13、R17 |
| A13 家长询问不取得修改权 | 家长询问判断原因，或在交流中说“把识别的 1 改成 7”，并尝试调用资料修改接口 | 可解释授权范围内的依据，但不能将家长话语作为已授权资料更正执行指令，修改请求在服务端被拒绝；普通资料更正引导到学生端，已删资料维护按 A62；不因家长陈述直接改能力结论 | R11、R12、R15、R17、R18 |
| A14 同一人的两种账号 | 同一人持有家长和管理员账号，先以家长账号请求后台管理功能，再以管理员账号独立登录执行获授权操作 | 家长账号的请求被服务端拒绝，不因同一人另有管理员账号而继承权限；管理员独立登录后仍受作用范围限制，操作记录可区分，独立后台不自动授予任意学习记录读取权 | R15、R17、R18 |
| A15 模型连接配置不可用 | 授权管理员配置的模型连接不能正常服务 | 后台能展示可检查的失败状态，允许修正并获知后续结果；不把配置提交成功冒充模型可用。用量按已约定口径展示，不凭空把未知费用记为零 | R13、R16、R17、R18 |
| A16 局部 KC 关系未决 | 题目、适用解法与判定依据已确认发布，作答可判断，但部分 KC 关系仍未决 | 浏览、讲解及有依据的当次反馈可用；不依据未决关系更新相应 KC 判断，不把模型缺口当作能力不足；其他 Claim 按各自正式条件与证据判断，未决关系不随整章批准变为有效 | R03、R04、R07、R11、R19–R21 |
| A17 同题多解 | 一题有两种有效策略，知识支撑不完全相同 | 能查看多个策略及依据；不把教材唯一例解当作唯一有效策略，不把结构关系自动解释为实际作答使用全部 KC | R11、R19 |
| A18 映射修改影响已有判断 | 已用于评价的任务映射发现归类错误 | 能查旧映射与引用；按验证及授权流程提交、启用修订；失效结果退出当前使用，新解释保留事实与版本关系，不重置无关记录 | R12、R19–R21 |
| A19 候选未授权或基础改变 | 候选在旧版本完成验证，但未授权，或授权绑定的基础已变化 | 不静默启用为当前模型，说明待授权或冲突并按要求重新检查，不绕过 owner 提交 | R18、R20 |
| A20 回退后仍有受影响结果 | 新版本已经用于判断，之后恢复先前获授权版本 | 展示未来使用版本及还需处理的历史结果；不将回退宣称为全部修复，不删除曾发生的执行，也不重放教学行动 | R12、R13、R20、R21 |
| A21 仅目标标准变化 | Target 达标标准调整，Task、Claim 和 Evidence 语义未改变 | 检查 Target Assessment 及其使用的影响，不把标准变化直接当作能力变化或自动重算全部 Belief | R20、R21 |
| A22 其他语义模型版本交付 | 管理员收到评价、交互或推理规则的候选版本及验证资料 | 能查看当前与候选差异、来源及作用范围，经授权和相应 owner 提交、启用；未授权、基础冲突及交付失败不被掩盖，不要求通用在线编辑器 | R18、R20、R21 |
| A23 建立初始领域关系 | 已确认的教材内容没有适用映射，需要复用或建立正式对象，初期只有一名管理员 | 系统起草候选及依据，同一获授权管理员可查看、修改全部候选并核查代表性样例，明确批准范围后发布，无需第二人或第二个管理员账号；保留各步依据与结果，未标疑题目也纳入检查，不为凑覆盖率编造 KC，不把章节确认当成模型批准 | R07、R18–R21 |
| A24 可确认的记录错误 | 复核可凭原始材料确认一处识别或记录错误，修正符合已批准自动处置条件且无需改正式模型 | 相应 owner 自动更正，保留原件、更正依据及记录，处理实际受影响判断；不要求逐次人工审核，依赖修复失败不冒称全部完成 | R11–R13、R18 |
| A25 自动复核不能解决 | 材料仍不清楚、依据冲突，或发现需要修改正式模型或映射 | 转交后台并保留材料、复核依据及未决原因；不把再次模型同意当成已正确解决，不借自动纠错发布模型修改；已确认失效的结果停止当前使用，尚未确认错误的争议不直接改成能力结论 | R12、R17–R21 |
| A26 无答案教材发布 | 导入的章节没有附答案或解析，系统能生成候选解法与校验依据 | 不因缺少答案拒绝导入；候选注明系统生成来源，经管理员检查疑点、代表性题目并批准明确范围后发布，不冒称原书答案或仅凭模型一致直接发布 | R07、R19、R20 |

| A66 服务器已收到但客户端未知 | 服务器已接受作答，确认响应在网络中断时丢失；分别覆盖仍处理中与已完成结果的情况 | 客户端表示状态待核对，不能宣称未提交或已完成；联网后先核对原提交，继续等待或取得原结果，不新建重复作答或重复评价；需要重试的未完成步骤仍关联原提交，保留尝试记录及成本 | R09、R11、R13、R16 |
| A67 反馈展示后断网 | 文字已展示或讲解已播放，展示回执尚未同步即断网；另覆盖播放状态无法确认和独立自测尚未允许反馈 | 核对生成、展示与播放状态，不抹去已发生帮助，不把未知当作未展示；恢复不自动重播已播放或状态未明的旧音频，主动重听仍可用；不因恢复重评作答，也不提前透露测验对错或解法 | R04、R09–R11、R13 |
| A68 普通单题求助等待 | 在预定支持范围内，从学生端提交单题求助，记录必要识别、理解、评价、决策、校验及讲解实际呈现 | 至少 90% 的预定普通单题求助在提交后 30 秒内取得可用讲解；状态文字、未校验或未实际呈现的结果不算达标。保留全链路时延、超时、失败、澄清和重试，不只统计模型生成时间；从原始提交计时，条件在实测前明确，超时不自动取消或新建重复请求 | R03、R08–R10、R13、R16 |
| A69 批量处理、返回与错题归集 | 分别提交整份试卷与教材导入任务，服务器接收后离开，处理期间及完成后返回；另覆盖接收未知、确认错题及未决题、后续复核和已删条目的重处理 | 已接收任务继续后台处理，返回可看原任务进度或结果，不重复导入或评价；上传未完成或接收未知按 R13 恢复。试卷确认错题自动归集并保留原卷来源，不混入未作答、识别不清或争议，不重复累计 Evidence；更正同步更新相关错题状态，重处理不恢复已界面删除条目。教材完成仍须核查发布，保持角色、空间和串行规则 | R01、R02、R07、R11–R13、R16–R19、R24 |
| A70 同一孩子的家长对话隔离 | 两位家长各自与系统交流，分别查看孩子同一学习判断；再尝试搜索、访问对方对话链接、直接调用接口或要求系统总结对方交流 | 双方按各自授权取得孩子情况及相关依据，但不能因关联同一孩子而读取、修改或删除对方对话；服务端拒绝越权，检索和模型上下文不混入对方交流，新回复及引用不披露对方对话。双方依据同一获准学习事实得到相似回答不算串用，验证应检查实际来源与上下文 | R11、R15、R18、R24 |
| A71 管理员按事项查看与维护 | 唯一管理员处理教材审核、学习质量复核或具体故障，查看所需原件、识别、讲解和判断依据；另尝试读取无关对象、以家长会话访问或直接修改掌握结论 | 相关读取可由同一管理员独立完成，含事项所需原录音或学生端已删资料，无第二人审批。服务端校验身份、对象、空间及操作，访问和修改关联事项并记录用途与结果；越权读取、家长会话代用及直接改掌握结论被拒绝，更正仅由既定 owner 按校验流程完成，学生端删除状态不变 | R12、R17–R21、R24 |
| A72 家长咨询与扩展功能边界 | 家长询问如何支持孩子，要求布置任务或修改目标，转述线下表现，或尝试专门的表现录入；另覆盖指出既有系统记录错误 | 查看、追溯、咨询与自身交流管理正常可用；支持建议不派发学生任务或修改正式目标。线下转述只用于家长咨询，不形成更新孩子掌握判断的正式学习 Evidence，不经摘要、检索或上下文复用冒充实际表现；对已有错误的合法复核继续可用。不能借对话绕过已暂缓范围，孩子自主自测及管理员正式维护按原职责继续 | R04、R11、R12、R15、R17–R19 |
| A73 实质更正主动告知 | 系统曾把正确作答判错，或已展示的讲解、掌握判断确认有误，后续完成更正；另覆盖部分依赖仍在修复 | 在产品内主动告知受影响且有权查看相应结果的学生或家长，说明原问题、更正内容、已更新和待处理结果，不只改后台或冒称全部恢复。可追溯更正与通知，生成说明不冒充已呈现；原展示和帮助保留，不自动重放旧讲解 | R11–R13、R15、R17、R18、R21 |
| A74 更正告知的影响与权限边界 | 分别发生纯排版调整、未展示候选被修正，以及实质更正涉及学生端已删条目、另一家长对话或已撤销的关联 | 无实质影响的排版措辞变更不主动打扰，不把未展示错误说成用户曾见；实质告知按当前权限及影响选择对象，不广播给所有家长，不恢复学生已删条目或向学生重新展示其隐藏原件。家长相关依据查看遵守 R24，不披露他人对话和无权资料；必要的当前判断变化仍可在授权范围说明 | R11–R13、R15、R18、R24 |
| A75 超纲判断与委婉拒绝 | 当前课程大纲已明确，题目确需范围外知识；另覆盖只是较难、课程内尚未学到的章节、示范解法超纲但可用纲内方法，以及范围判断依据不足的情况 | 用语义规则与 LLM 依据本空间大纲判断；确认超纲后简明、委婉说明当前不支持，不归因为孩子不会。课程内尚未学到也允许求助，按已有基础调整讲解，不按进度锁定；不能仅按题源、难度、缺少 Task 或某种解法判超纲。无学习记录不证明未学过；不确定先澄清或保留未决，不伪装确定拒绝，不自动扩展课程大纲 | R03、R06、R11、R19 |
| A76 纲内新题型获得帮助 | 上传教材未出现但知识在大纲内的新题型或组合题，覆盖现有模型可解释及确有局部覆盖缺口的情况 | 按请求提供经必要校验的帮助，不因题库无原题或模型未登记而常规拒绝，也不一律要求等管理员补模。题目入库，实际作答与帮助可追溯；具体处理失败如实记录，不冒称超纲，正式掌握判断只采用有效依据，未授权模型不直接启用 | R01–R04、R11、R19、R20、R23 |
| A77 上传新题入库与复用 | 纲内上传新题已用于讲解或作答，其中模型映射尚未完整；之后补齐或修正题目依据 | 保存原始来源、题面图示、空间、解法与校验状态、模型关系及未决，关联实际使用；后续能查到原题和当时版本，不能只留对话。入库不等于可复用，不因未映射丢弃或编造正式 Task/KC；合格且适用后按本空间规则复用，历史作答不被覆盖 | R01、R06、R11、R21、R23、R24 |
| A78 基础领域演化真实运行 | 管理员从运行线索或明确的模型维护需要进入，分别覆盖已有模型足够、非领域错误、KC/Task Family 等真实缺口，以及未决、候选验证失败和成功路径 | 评估保留原因与相关替代解释，普通实例不机械创建 Issue 或对象；真实 AI 辅助候选经有限参考与回归验证、单人审核、owner 提交和限定启用，检查后续实际使用及依赖影响。原因解释、候选、验证和批准分别可查；无须改模型可结束，未决可保留，失败不启用，不以预写结论或版本号变化冒充演化成功，不改写旧作答或重放教学 | R12、R18–R21、R23 |

## 9. 冻结与阶段交接

本规格随[产品定义 §11 的 G3 评审](DeerMind_MVP_Definition_v0.1.md#11-g3-评审与阶段完成条件)冻结，下一阶段为 Product & Domain Foundation。Phase 4 将 R、P、M、A 映射为三类角色流程、领域包、检测与变式材料、质量审查、数据和授权及初始评测集；Phase 5 据此形成实现任务、工程测试与复习决策模型；Phase 6 取得实际验收证据。尚未执行的项目不能写为通过。

工程质量按验证方案 §5 分项衡量，真实学习价值按 §4 的四周、8 个问题及同批即时/延后观察执行。每天全部活动共用 30 分钟，不因补测增加额度；用户负责收集反馈和决定处置，不增加专门暂停机制。具体样本、最低有效数量、环境、参考与有限试验参数在对应运行前冻结，不能看结果再改规则。

优先落实纲内新题当下帮助与后续模型完善的组合流程，明确哪些输出已有可核验依据、哪些正式判断仍待补齐。若无法在既定权限及语义责任内实现承诺，应带具体冲突回到 D02/D09 和相应系统设计讨论；不得一律等待人工、自动批准新模型或悄悄拒绝纲内题。其他影响范围、体验、责任或关键门槛的取舍同样重开讨论，阶段交接不授予实施者改变产品的权力。
