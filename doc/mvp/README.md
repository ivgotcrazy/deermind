## 3. 每类输出只维护一份

| 输出 | 位置与职责 | 创建／完善时机 |
| --- | --- | --- |
| 产品规格主文档 | `m1/PRD.md`：目标、范围、用户场景、全流程、功能规则、模型与数据含义、权限、AI责任及验收 | 按业务包与详细规格、原型同步迭代，保留完整产品图景 |
| 产品详细规格与原型 | `m1/design/`：分步操作、状态、截图、教材与模型对应、题目及评价标准；原型代码在`m1/prototype/`，旧代码按需复用 | 有范围草稿即交叉展开；具体操作和内容可以返回修改PRD，按包共同评审 |
| 工程设计与交付 | `m1/engineering/`：接口、存储、真实服务、运行恢复、实现计划与交付记录 | 当前已建立五份技术设计和一份实施计划大纲；后续按主流程交叉细化，不由工程补定核心需求 |
| 验证计划与报告 | `m1/validation/`：测量方法、样本、配置、停止条件；实际结果另成报告 | 计划在运行前形成；有真实执行后才建立结果报告 |
| 决定与待决 | `DECISIONS.md`：承接、变更、未决、阶段评审及版本记录 | 随需求推进维护；不另复制PRD正文 |

文件不必一开始全部创建。design已对齐领域、教材、评估、目标与 Interaction 活动模型的产品规则；四类活动蓝图、两层配置、学生固定流程及运行追溯已有当前截图，管理员证据及事件查询已有mock，真实评价链尚未完成。engineering已建立六份大纲，具体实现方案、技术验证和选型尚未展开；validation已有有限真实内容提取试验，实际结果按原报告保留。PRD主文档、详细规格和原型共同表达产品设计；工程设计属于工程阶段，负责定义技术机制；验证说明怎样获得和解释证据。模型定义以现行专项 Space 合同为权威，PRD说明其产品作用。本轮 Domain v1.5／Evaluation v1.9 与 M1-DEC-015／016／020／021 已同步；仍引用旧关系的概念／系统摘要属于待迁移基线，不可据此覆盖新合同，迁移范围见 M1-OPEN-04。

## 4. 历史与资产的使用规则

- 原MVP文档和截图整体进入[归档入口](archive/README.md)，不继续在旧正文中填新需求。已经确认的决定不会因归档自动失效，承接过程见DECISIONS。
- 当前M1原型在[独立目录](m1/prototype/README.md)，默认端口5182；[旧原型](../../src/mvp_prototype/README.md)保留为参考，默认端口5181。当前包含领域手动管理、教材助手持续对话、候选核对及采用、待入库处理、章节关联、Claim、目标管理、四类活动管理及学习空间追溯；学生默认打开独立活动森林示例，原有记录入口单独保留，均为mock，真实执行和评价按工作包推进。内容参考仍在[准备资产目录](../../src/mvp_foundation/README.md)，不把样例当作实际建模结果。
- 只有与当前M1需求有关且核对过的旧内容才迁入新PRD；不整篇复制旧文档后换名称。需要改变已确认决定时说明理由并讨论。
- 每次修改文档均升版并记录；旧冻结输入和真实运行结果不重算、不改判。当前图文设计发生修改时，文字、原型及截图仍需同步。

教材助手本轮已完成mock图文同步，当前版本及截图见[M1交互规格](m1/design/Interaction_Design.md#12-与教材导入-agent-对话核对和纠错)。[M1主流程检查](m1/README.md#6-主流程闭环检查2026-11-09)已按下述四项决定收束，工程接收输入纳入本轮大纲；不把对话原型当作真实Agent、整册建模或评价服务完成。

当前主流程规则已收束，见[登记§27](DECISIONS.md#27-m1主流程简化与工程实施顺序)：M1具备模板实时出题，Belief按方法与方面简化，提问不受阅读位置和目标章节限制，错误评价纠正后置M2。当前达标规则已由[登记§28](DECISIONS.md#28-m1全局达标阈值与工程阶段边界)统一为0.90，Evolution版本演进后置；当前已建立工程大纲，并按[登记§30](DECISIONS.md#30-m1工程大纲评审承接与产品规则对应)补齐评审承接及产品规则对应，下一步审阅后按[三轮设计安排](m1/engineering/README.md#5-三轮设计推进与完成判断)细化；E01—E07保留为未来实现顺序，原型与历史截图保持。
