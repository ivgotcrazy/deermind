本文件回答每次AI执行“取哪些信息、从哪里取、如何组织、缺少信息怎么办”。建议由 `foundation/context`提供ContextAssembler及摘要／索引机制，业务模块和Space提供各自用途的取材规则；数据库和模型适配不决定信息的业务资格。

首轮细化教材助手、学习助手及证据解释三个用途，重点核对“本轮作答怎样形成Evidence”与“评价返回后怎样继续教学”的输入区别。目标不是把全系统内容放入一个万能Context，也不建设独立学生画像库。模型具体容量、token预算和语义检索质量尚待有限验证。

输入为[AI Native原则](../../../../top/DeerMind_AI_Native_Architecture_Principles_v0.6.md)、[内容规格](../../../m1/design/Content_and_Model_Reference.md)和[交互规格](../../../m1/design/Interaction_Design.md)；执行机制引用[Agent运行框架](Agent_Runtime_Design.md)。本文维护上下文包及内部组装合同；业务实体、事件和HTTP字段以[数据与接口](Data_and_Interface_Design.md)为准，避免重复定义。

## 1. 记录、状态、摘要与执行进度

### 1.1 信息归属

| 信息 | 权威来源／维护方 | ContextAssembler怎样使用 |
| --- | --- | --- |
| 教材原件、解析候选、已采用内容 | 产品业务层materials；文件在技术存储 | 区分原页、候选与已采用内容；保留文件和页内出处 |
| TT／ST／KC／题目和解法实例 | Domain | 按明确引用或检索条件取得内容；参考解法不是学生实际使用方法 |
| 活动、轮次、消息与实际帮助 | Interaction，已发生事实通过全局事件留痕 | 当前状态用于动作许可；历史事实用于解释表现 |
| Claim、判据 | Evaluation | 为评价提供定义及本次采用依据 |
| Evidence、Belief、目标达成状态 | Evaluation | 学习决策可读有效结果；本次证据解释禁止读取旧概率和达标结论 |
| 目标定义、教材与方法采用关系 | 产品业务层targets／learning_spaces | 提供任务所需只读条件，不复制第二目标库 |
| 活动／教材对话摘要 | 所属Interaction或materials维护的派生记录 | 帮助恢复话题，原文可查；不能替代作答、帮助或能力依据 |
| 执行检查点 | foundation/execution | 恢复程序步骤，不能当成学习状态 |

共用底座提供存储与检索机制，内容所有权仍归原模块。学习空间中不维护一份独立的“总聊天记忆”来覆盖活动、事件和Belief。管理员教材助手的对话以导入任务为范围，不能和学生学习对话合并。

### 1.2 实际输入与出处

每次模型请求保存一个不可变的输入包记录，内容包括实际发送的公开消息／结构化数据、引用清单、裁剪记录、模型协议及请求参数；原件图片通过受控文件引用追溯。不得只保存“用了某教材”的说明，否则无法复核漏图、漏条件或是否受到旧判断影响。

输入包在技术存储中可使用文件加数据库引用，不在本轮要求新建通用向量库。敏感输入不写入普通控制台日志；管理员读取仍须权限检查。输入包不能包含密钥、系统未授权的其他空间资料或模型内部思维链。

## 2. 各类任务的上下文合同

### 2.1 ContextAssembler接口建议

建议公开操作为 `build_context(request) -> ContextPacket | ContextMissing`。调用方提供job_id、用途、授权范围和业务输入引用；业务取材提供者通过已定义查询接口返回资料，Assembler不直接读取其他模块内部表。

| ContextRequest字段 | 类型／必填 | 含义与检查 |
| --- | --- | --- |
| `job_id` | UUID，必填 | 程序产生的运行身份 |
| `purpose` | 枚举，必填 | `material_assistant`、`learning_assistant`或`evidence_interpreter`；不从学生文字决定权限 |
| `actor_scope` | 服务端授权结果，必填 | 执行身份及资源范围；教材任务使用import_id，学生任务使用space_id，不能仅信任请求体编号；授权字段交数据合同 |
| `input_ref` | SourceRef，必填 | 本次请求或评价处理等权威输入引用，引用结构按数据合同解析 |
| `protocol_ref` | 非空字符串，必填 | 所属模块注册的协议和输出Schema标识 |
| `checkpoint_ref` | SourceRef或null | 只用于恢复步骤，不能覆盖当前权限 |
| `budget_profile` | 非空字符串，必填 | 部署中已登记的模型能力及预算配置名，不能由LLM扩大 |

| ContextPacket字段 | 类型／必填 | 内容 |
| --- | --- | --- |
| `context_id`、`job_id` | UUID，必填 | 程序分配的输入包身份及运行任务引用 |
| `purpose`、`captured_at` | 上述用途枚举、UTC时间，必填 | 用途与组装时间 |
| `policy` | 结构化对象，必填 | 当前协议、活动定义引用、强制规则及可用动作；推荐策略另列 |
| `request` | SourcePayload，必填 | 当前请求或作答原文与权威引用 |
| `materials` | SourcePayload数组，可空 | 实际装入的内容块，标记其来源角色 |
| `source_manifest` | 来源记录数组，必填 | 原事件／对象／文件的当时引用、覆盖情况及缺失原因；必须能回查当时内容 |
| `allowed_tools` | 工具许可数组，可空 | 程序授权的工具及范围，网关再次校验；完整工具参数交运行协议细化 |
| `omissions` | 遗漏说明数组，可空 | 资料引用或查询条件及原因：无权限、与用途无关、超预算、缺失 |
| `usage_estimate` | 结构化计量对象，必填 | 输入估算、输出预留和估算方法；未知计量为null并说明原因，不能记零 |

SourcePayload包含`source_ref: SourceRef`、`role`与`body`。role只取`request`、`fact`、`reference`、`assessment`、`summary`或`tool_result`；body使用已有内容块结构，不另造纯文字教材格式。来源记录包含同一source_ref、`coverage`（complete／partial／unknown）、`reason`及必要的时间或事件范围。coverage描述本次查询实际覆盖，不允许把所有来源无条件标complete；原始引用和文件身份由数据合同维护。policy及工具许可的细项还须与各AgentSpec逐一补齐，本轮不据此宣称已具备全部可执行Schema。

ContextMissing至少返回缺少的必需来源、原因和业务可采取的动作，例如“需要更清晰原页”“本轮帮助事实未闭合”。必需输入不足不得悄悄删除后照常调用；可选内容缺失可以继续，但输出须受相应限制。数据及接口文档引用此内部输入包合同，不复制第二份字段表。

### 2.2 三类用途

| 用途 | 必需输入 | 可选输入 | 明确禁止／不足处理 |
| --- | --- | --- | --- |
| 教材助手 | 本次管理员请求、导入身份与领域引用、引用的原页／区域、采用内容与候选状态、允许修改范围 | 同次导入前后页、此前对话摘要、Domain检索返回的定义 | 不读学生Belief；不能把候选冒充入库；图表不足则请求补取来源，不能补造数值 |
| 学习助手 | 学生当前请求、活动及节点、采用的蓝图和两层规则、当前可执行动作、相关任务／方法内容 | 本空间有效Belief及依据摘要、目标要求、原文历史、明确引用的书页、推荐策略 | 不读取其他学习空间个人记录；目标范围不构成全部聊天白名单；未引用的当前书页不自动作为题目 |
| 证据解释 | 本次原始表现、题面、轮与提交、实际帮助及接触记录、采用的Claim／判据、候选方法及来源 | 支撑迁移／保持的既有接触与时间事实、必要子Task步骤、相关知识参考 | 不读取旧Belief概率、目标已达标标签或预测结论；不把总结代替原始表现；不足的方面返回unknown／skip依据 |

证据解释可读取目标涉及的实际条件，但不得得到“需要把学生判为达标”等指令。最终目标对照由Evaluation程序按真实Evidence与概率执行。Domain提供的参考解法不证明学生采用了该方法；模型必须从学生步骤中归因，只有答案不能自动更新两种方法。

### 2.3 “四分之一”的两份输入包

假设学生提交“120本增加四分之一，先算120÷4=30，再算120+30=150”，本次要求核对A方法。以下是用于接口评审的输入内容示例，编号是假设值，不是新的模型实体或实际记录。

| 输入部分 | Evidence解释任务 | 评价后的继续教学任务 |
| --- | --- | --- |
| 本轮事实 | 题面、原始提交、开始与结束、实际帮助记录及覆盖情况、此前接触事实 | 可以引用本轮表现和反馈，不重新解释已提交Evidence |
| 定义 | Task、方法A／B、Claim及独立／理解等判据 | 当前活动定义、节点允许动作、采用的方法及目标 |
| 个人状态 | 不提供旧概率、达标标签 | 提供本次Evaluation结果引用及当前有效状态，明确哪些方面仍未知 |
| 当前进度 | 保留本轮发生时的条件，不让后续聊天改写当时表现 | 重读当前活动／节点、暂停或切换情况 |
| 缺失处理 | 若没有可核对的帮助覆盖，独立方面不得默认为无帮助；没有解释机制，不自动给理解正证 | 只能利用有效结果决定下一步，不能把评价失败当能力不足 |

同一事件可能服务多个方面，但解释任务必须给出各方面的具体依据。学生答对不自动证明理解、迁移或保持；候选引用由程序校验，重复计权由Evaluation控制。父Task成功不能直接生成所有子Task的正证。

教学机会解释使用同类受限输入，但额外需要程序分配的稳定机会身份、实际展示、收束依据、Task／方法／方面责任及帮助性质。拆消息、暂停恢复或同一输出重试不生成新身份；机会是否合格仍需语义解释与程序核对，不能用“活动完成”替代。

## 3. 活动森林中的连续性

### 3.1 进入、子活动与返回

| 发生什么 | 取材及传递方式 |
| --- | --- |
| 新顶层活动 | 当前请求＋本空间必要历史＋该活动定义；不把全部历史活动铺入输入 |
| 进入子活动 | 子活动采用自己的蓝图、活动级／节点级规则与推荐策略；传入触发请求、父活动问题与返回位置 |
| 子活动结束 | 形成结果摘要和原消息引用，说明解决了什么、剩余问题、发生过哪些帮助；父活动重读自己配置 |
| 从暂停恢复 | 恢复活动身份和未完成目的，重查当前权限、节点和需要依赖的评价；不恢复过期动作许可 |
| 查阅历史／教材 | 导航本身不改变当前活动；只有明确引用历史片段或当前书页的请求才把它作为本次问题来源 |

子活动不自动继承父活动的局部规则或策略，但仍受系统约束。节点使用本活动的通用规则加本节点规则；推荐策略没有命中时可在许可动作内继续。两个蓝图的内容不能简单合并为一段系统提示。

### 3.2 检测上下文隔离

检测题面、学生提交、评分参考和未来题解须分别标识使用目的。参考答案可以提供给受限评价任务，不作为学生界面输入；学习助手在轮内只取得当前许可所需内容，不为“等待学生回答”提前生成可展示的提示。

中性技术处理、含糊请求澄清及实质求助采用当前活动规则。生成帮助前先由程序结束受影响检测轮，再重新组装轮后讲解上下文；不得沿用独立检测的动作许可。学生过去已见过的答案、图表或提示作为接触史保留，不因新题号／新活动号重置。

## 4. 检索、长度预算与多模态内容

### 4.1 取材次序

M1建议先按明确对象、活动、轮次和时间取材，再由受限工具补取必要资料，不先建设全域向量检索平台。

1. 先读取本次input_ref、当前权限及所用配置，定位不能缺失的题面、原始作答与规则。
2. 通过Domain公开查询取得相关模板、方法及必要子Task；教材书页只有被明确引用或为核对出处需要时加入。
3. 按用途读取本空间有关历史，排除禁止资料；迁移／保持所需历史不足要保留未知。
4. 长历史用带来源摘要提供导航，模型需要具体依据时再查询原文；不能用摘要证明作答或实际帮助。
5. 没有足够候选时允许请求进一步检索或澄清。检索质量不足是待验证项，不能靠“无结果”断言领域模型不存在。

教材供题方法按章节采用来源过滤，不能把一个章节的方法无条件开放到全书；同时学生的自然提问范围不被目标Task清单限制。取材范围、动作许可、评价适用条件是不同限制，不能统一成一个过滤器。

### 4.2 预算与裁剪

可用输入预算等于已配置模型上下文容量减去输出预留及协议开销，由ModelGateway报告能力、Assembler计算；供应商无法提供可靠图像／token估算时保留安全余量并验证。不在设计中假定所有模型拥有同样窗口。

建议裁剪顺序为：不相关历史 → 过长的已解决话题摘要 → 可按需检索的辅助内容。当前请求、强制规则、当前题面关键图表、证据原文及判断资格必需事实不能悄悄截断。必需内容超预算时拆分工作或返回ContextMissing，不能只保留前半题照常评分。具体输入／输出预留在选定模型后校准，属于接入前必须确认项。

多模态内容分别保留结构化文字、公式、表格数据、图形关系及必要原件引用。识别候选不自动等于原页真实含义；取材结果标明未识别区域、图形关系缺失及原页位置。题面与解法辅助图分开，不能为了“完整上下文”把解题提示拼入学生题面。图像无法访问时不能用纯文本摘要伪装为已核对。

## 5. 摘要生成与信息时效

摘要是可重建的辅助数据。建议由所属模块在活动收束、子活动返回，或历史长度触发压缩时委派摘要任务；教材对话采用同一机制但限定本次导入。

摘要记录至少保留所属空间／导入、活动引用、覆盖的消息或事件边界、来源引用、未解决问题及生成时间。自然语言总结不能写成“学生已掌握”等权威判断；如需提及评价，只引用Evaluation结果并注明来源。

组装时将摘要覆盖后的新消息补入；同一段消息不重复装入。摘要落后并不删除原记录。发现遗漏或与原文冲突时回查原文、跳过受影响摘要并重建，不能修改旧事实。摘要任务失败时可用有限原文或明确缩小范围继续；必需事实不足仍返回缺失。

首轮不建立自动长期记忆优化或人格画像。需要跨次影响教学的稳定事实必须有明确来源、所属模块和使用限制，不能把模型自己推测的偏好永久写成事实。具体摘要压缩阈值与保留长度须随模型预算实测，暂不作为产品配置项。

## 6. 并发与暂停恢复的刷新

| 数据 | 本轮Evidence解释 | 下一步教学恢复 |
| --- | --- | --- |
| 已提交题面、作答及当时定义 | 固定权威引用，不用后来编辑内容替代 | 需要引用过去题目时仍用原引用 |
| 实际帮助、接触史及发生时间 | 使用与本轮有关的事实，记录覆盖边界；迟到／未确认记录不得静默视为无帮助 | 读取当前可用事实，不把重复展示或新编号当新独立样本 |
| 当前活动、节点与前台可用性 | 不能改变历史表现的解释条件 | 必须重读；已切换／停止时旧任务不得推送继续 |
| 权限与账号／空间归属 | 每次取材及提交检查当前许可 | 重新检查，不沿用等待前授权 |
| Belief与目标状态 | 不送入本次证据解释；数值提交读取合法前序状态 | 读取所依赖结果及当前有效状态，不用缓存的旧概率 |
| 目标及教材采用 | 核对本轮当时采用依据，不无声迁移 | 按当前活动采用依据和后续动作要求读取，变更处理遵循业务规则 |

全局事件记录顺序不能当作现实发生顺序；须保留发生时间、记录时间和关联身份。单凭“读到了最大事件号”不能证明帮助事实完整。对实际展示未知、来源覆盖不全等情况，解释结果必须保留限制，不能按零帮助更新独立方面。

输入包保存的是当次所见资料。业务提交前再检查仍有效的权限、当前活动资格和Evaluation序列；输入包不是绕过提交检查的授权凭证。Evaluation采用同空间请求序号串行更新的建议见[运行§3](Agent_Runtime_Design.md#3-共享执行与资源调度)和数据合同；它解决提交先后，不自动解决语义归因准确性。

## 7. 隔离、调用留痕与效果验证

### 7.1 读取限制与模型指令

所有查询带服务端确定的actor_scope。即使用户或LLM知道另一个space_id，也不能读取该空间个人记录。Domain公共定义可以按权限复用，不等于跨空间复用个人Belief。

系统规则、当前用户请求、教材文字、检索结果和模型输出在输入包中分区表达；教材或题目中出现的“忽略规则”等文字属于待处理内容，不授予工具权限。工具网关再次验证范围；仅用自然语言提醒模型不要越权不构成权限实现。

证据解释的禁止字段不仅在初始输入中排除，后续工具查询也不得提供旧Belief、达标结论或含同类结论的学生摘要。学习助手可读这些有效结果用于选择教学，但不能将其反向作为本轮正证。

### 7.2 首轮验证案例

| 案例 | 应检查什么 |
| --- | --- |
| 同样作答，已有Belief不同 | Evidence任务输入不含旧概率与达标标签；算法阶段才读取前序概率 |
| 题面包含图表且文本不足 | 保留图表关系或返回缺失，不基于裁剪文本强行判断 |
| 子活动返回讲解 | 传回结果及未决问题，父活动采用自身规则，无错误继承 |
| 等待评价时学生切换活动 | 原始事实不变，继续任务刷新前台状态，不恢复旧活动 |
| 摘要写“学生已经会了” | 不作为证据；回查原文与Evaluation结果 |
| 教材内容含越权指令 | 内容可被分析，工具权限不扩大 |
| 帮助记录未知或迁移背景缺失 | 相应方面不能假定合格，保留原因及来源 |
| 读旧聊天或切教材章节 | 不重复评价旧答案，不改变当前活动或限制提问 |

这是验证规格，没有执行结果。检索命中率、摘要遗漏、图表覆盖、证据解释质量和预算适配还需与[验证计划](../../../m1/validation/Validation_Plan.md)核对；上下文结构合法不证明语义可靠。

后续必须补齐三类AgentSpec的最终提示协议与工具输入输出、选定模型的预算配置、教材批处理／跨页取材策略、首批整册的检索与摘要样本。不因首轮字段表已建立就宣称所有AI任务上下文已设计完成。
