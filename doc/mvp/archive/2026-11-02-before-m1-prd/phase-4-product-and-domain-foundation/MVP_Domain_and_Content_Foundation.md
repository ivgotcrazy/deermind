## 1. 领域范围与覆盖要求

**本轮内容交付范围。** 按 DEC-039，M1 必须从北师大版 **2026 年六年级上册数学教材**的真实扫描件完成导入和建模。用户已确认 M1 完成整册建模（DEC-040），OPEN-014 的范围选择已关闭；2026-11-02 已核到此前链接为北师大版六上数学及其完整印刷目录；用户随后按 DEC-041 指定以此前电子链接为 M1 工作源，版权页后补；本轮内容准备不再等待版次确认，完整原件及实际处理用途按 OPEN-002 的对应使用节点核对，详见 §1.1。整本批量导入能力必做，未建模的章节保持未就绪，不自动变成可评价内容。M2 再准备校外第二课程；下段与 §6 的旧书页、候选包仅说明历史准备情况。

**M1 从源材料到可用模型的输出。**

1. **来源与整理：** 保存整批扫描件和原页顺序，建立章／节、文本、公式、图、表和跨页引用；识别内容与原图可对照修正。图表参与题意和讲解，不能只保留 OCR 文本或摘要。
2. **领域定义：** 在数学 Domain 内形成所选范围的 TaskTemplate、适用 SolutionTemplate（含必要递归子方法）及 KC。Task 的知识关联由方法递归汇总；已就绪 KC 有可定位的任务／方法路径，不新建 KC Belief。
3. **课程与评价定义：** 章节引用领域子集及方法条件；每个 Task Claim 绑定一个模板版本和内部方面，学习目标配置要求及达标条件。目标要求、通用定义和个人判断分别归属，不合并成一份教材标签。
4. **可用教学及检测材料：** 准备原理、适用例子、必要图表、已核对的题目与合法解法／评分参考。先支持小型核对题库，记录实例、来源及使用；不以实时自动出题为 M1 必需条件。
5. **检查与应用：** 校验必要字段、关系、版本、方法条件和当前章节覆盖；管理员可直接修正保存并应用，学生随后能够选用。保存、应用与学生实际表现分别留痕，不要求逐题审批或独立审核发布中心。

允许 AI 辅助与管理员人工核对，不允许由工程师预写固定模型包替代可使用的导入建模流程。Phase 4 先交付真实输入样本、预期模型及核对参考，Phase 5 实现工具并用该流程产出正式内容；两者不互相等待，也不能把参考包当实际工具已运行。M1 的实际完成量按 Definition §5.2 为整册；可先打通“分数的应用”再逐章扩展，但其余章节不能整体留到 M2。

**整册建模完成清单。** 以已核验的原书目录及实际页码为底表，每章记录内容范围与来源、Task／Solution／KC 覆盖、章节方法条件、Task Claim 与目标要求、讲解依据及检测题参考、核对结论和剩余缺口。正文、例题、练习、复习与综合活动涉及的学习内容均需找到对应；目录等非教学页保留来源并说明性质，不强建任务。各章无阻塞教学或评价的建模缺口并已可应用，才满足整册交付。模型对象允许跨章节复用；清单衡量内容覆盖，不按模板数量或“一题一模板”验收。

整册建模可按章分批核对、保存和应用；过程中明确可用与未就绪章节。M1 的实际完成结果必须覆盖整册，不能以“后续继续补内容”作为全部完成的结论。目录清单按 DEC-041 选定的电子版推进；出版／印刷元数据待补，不改变当前工作来源，也不能据目录登记计算建模完成百分比。

M2 的完整课程扩展仍需两个相互隔离的课程空间，支持校内、校外各自获准的内容。教材按章、节分批准备和保存，不要求一次建完整学科；用户已确认校内使用北师大版数学六年级上册，校外为后续提供的内部教材（SRC-024）；SRC-025 已明确校内首批为第四单元“分数的应用”，在线来源及 49–56 页边界已核到。出版年／印次、参考和使用条件仍属 OPEN-002；2026-11-02 的全册来源核验及工作清单见下文，旧候选不能代替当前合同的全册准备。合成三角形例子继续用于交互走查，不视为该教材内容。

| 可用行为 | 必需材料与判断依据 | 缺少时怎样表达 |

**模型关系保持一致。** Task 定义学生要完成什么；Solution 定义怎样完成及其知识依据，Task 的 KC 只通过 Solution 递归汇总。Task Claim 绑定唯一模板版本，在内部维护独立、理解与解释、迁移、延迟保持方面；学习目标再选取要求和方法条件。教材目录不决定模板必须一章一个，也不决定每个 KC 新建一个个人状态。

**实践和操作内容不删掉，也不冒充已验证。** 测量、画图、构造、棋局、调查与方案表达仍需建模。M1 可用书页、纸上操作及结果／过程报告承载，不预设专用棋类引擎或实验仿真平台；具体输入能力随 M1 合同确认。没有实际过程依据时，只能判断已展示的分析与解释，真实操作、小组合作等表现保持未知。教材中的自评星级不能直接写入 Belief。此处不把“整册建模”改成“只做适合纯文字的题”。

## 2. 核心概念与领域规则

Domain Space 管理有明确身份和范围的 Domain；TaskTemplate、SolutionTemplate 和 KnowledgeComponent 均有明确的领域归属。当前后台已按领域组织三类对象，同名不构成跨领域引用依据，课程选择也不复制或改变领域定义。这里说明现有领域归属，不在本批引入跨领域自动复用机制。

Domain 定义共享的 TaskTemplate、SolutionTemplate 和 KnowledgeComponent；Learning Space 选择教材、范围和目标；Evaluation 定义 Task Claim 并维护个人 Belief。目标不改变领域定义，题目与参考方法也不是个人能力状态。

本节是本轮确认的 **MVP 对象关系与内容准备要求**（DEC-027、028）。[Domain v1.3](../../../../concept-design/DeerMind_Domain_Space_Design_v1.3.md) 的图 D-01 及正文仍允许 Task 直接关联 KC；本轮 MVP 已明确不采用这条直接关系。以下规则用于当前 MVP 交互和后续资产准备，上位概念图及相关引用尚待同步，见 OPEN-012。不能把旧图当作当前 Task 表单另设 KC 字段的依据。

### 2.1 Task、Solution 与 KC

**图 CONTENT-03　MVP 的任务、方法和知识关系**

```mermaid
flowchart TB
  T[TaskTemplate] -->|直接关联适用方法| S[SolutionTemplate]
  S -->|选定子方法，可递归| C[子 SolutionTemplate]
  S -->|直接引用| K[KnowledgeComponent]
  C -->|直接或继续递归引用| K
  K -->|有条件的先修等关系| K2[其他 KC]
```

箭头表示定义之间的引用，不表示学生已经掌握。图只展开一层子方法，递归可以继续；不在 Task 层平铺全部子方法，也不增加 Task → KC 的直接引用。

- Task 可以关联多种 Solution，方法说明各自适用条件；用哪种方法、是否要求多种方法分别覆盖，由课程与 Claim 条件明确。
- Solution 直接关联必要 KC；复杂方法还要说明子任务、子方法、输入输出和结果如何组合。不能只列一串步骤名称，却无法看出各步解决什么。
- Task 的 KC 集合等于其直接方法及递归子方法的 KC 并集。按 KC 身份去重，保留所有来源方法；若只选部分方法，则只对该子集汇总。
- KC 间的先修、构成或解释关系继续保留，但不把整张先修图自动展开为 Task 的必需 KC。具体方法需要哪些知识，须在方法中表达。
- 没有方法就没有可汇总的 KC。可编辑的未完成 Task 可以暂缺方法；用于完整教学或评价的 Task 至少有一个可用 Solution，其直接或递归知识依据应完整。缺失引用、未选子方法和循环必须显示缺口，不能把部分结果称为完整汇总。
- 知识并集表示这些方法覆盖哪些知识，不表示一次成功证明所有 KC 已掌握，也不建立个人 KC Claim／Belief。

通用递归设计中的子任务及方法选择仍需明确；当前 mock 直接保存选定的子方法引用，供查看和汇总使用。它不提前确定正式递归执行器或数据库结构。

KC 从自身反查任务及方法的合同、知识理解任务的覆盖要求见 [§2.5](#25-kc-的任务与方法对应关系)。反查使用同一套方法引用，不恢复 Task 直接挂 KC。

### 2.2 任务模板的结构化表达

本轮采用相同字段表达分数应用、几何面积和递归综合任务。语义描述必须明确，必要时附公式；不要求先实现一套通用数学语言，也不将自然语言字段包装成已经可执行的程序。

| 内容组 | 管理员填写什么 | 用途 |
| --- | --- | --- |
| 基本定义 | 名称、简述、完成目标、学习者责任、期望输出 | 区分要算出结果、解释关系或检查方案等任务责任 |
| 对象与参数 | 符号、名称、类型、已知／中间／输出角色、单位及取值条件 | 正向绑定数值或对象，反向识别题目中的量和角色 |
| 条件与关系 | 关系含义、可用表达式、给定与待推导条件 | 区分相同文字下不同的数量关系和求解目标 |
| 允许的变化 | 数值、情境、表述或表示方式的合法变化 | 明确哪些变式仍属于该模板 |
| 适用边界 | 不适用条件、排除情况、缺条件时的处理 | 避免只因关键词或公式相似就强行归类 |
| 方法关联 | 直接适用的 Solution 及适用条件 | 提供求解、讲解和 KC 汇总的路径 |

Solution 写清适用条件、参数及输入输出、推导步骤、分解与组合关系、子方法和知识依据。KC 写清认知内容、解释、适用边界及相关知识关系；只写一个名称不足以支持教学。

以下为当前交互用的三种例子，不代替 §6 的实际教材候选：

| 例子 | 任务的核心关系 | 方法及知识怎样体现 |
| --- | --- | --- |
| 分数应用 | 已知基准量与增加的分率，求增加后的量；分清基准与比较对象 | 分步求增加量再相加，或先求倍数再乘；各方法分别关联分率意义及所用运算知识 |
| 三角形面积 | 已知一组对应底和高，求面积；底高必须对应，单位条件明确 | 先确认底高对应，再代入面积关系；知识关联包括底高对应和面积公式，不能将任意边长当高 |
| 综合场地任务 | 长方形花园中的三角形花坛按比例扩建，求剩余草坪面积 | 主方法选定求增加后底长、求三角形面积等子方法，再组合面积结果；逐层汇总 KC，缺方法就显示依据缺口 |

### 2.3 实例生成与保存检查

具体题目在“实例”页管理，表格保留题目、参数、参考答案及解释、来源和当前模板关联。生成、导入、编辑共用保存检查：

1. 正向生成根据模板条件选择参数与情境，形成题目、参数绑定及参考解答；题目是否成立与答案是否正确分别检查。
2. 反向归类核对题目的已知、未知、关系、完成责任和边界，不只匹配词语、外观或一个相似算式。
3. 条件不成立、答案未通过检查、归类失败或仍不确定时，不能保存为该模板的已归类实例；保留输入和原因供修改。
4. 原始资料与正式实例分开：学生上传的纲内新题、未识别材料和待映射题可以先保留。不得因暂时没有匹配模板就删除资料或一律拒绝帮助（REQ-019）。管理员按需补齐；MVP 不因补齐映射而补算这类历史作答，新表现按适用定义解释。

当前页面用固定样例生成，导入为文本，检查结果由 mock 情境控制；没有真实生成、OCR 或语义反向归类引擎。自动生成、正式入库和正确分类仍需后续工程及语义验证，当前 UI 不能作为其通过证据。

### 2.4 Task Claim、教材与目标

[Evaluation §3.1](../../../../concept-design/DeerMind_Evaluation_Space_Design_v1.5.md#31-learner-state-model定义-deermind-可以相信什么) 定义 Task Claim：一个 Claim 绑定唯一 TaskTemplate 版本，描述适用范围、责任、帮助、方法及质量条件。独立完成、理解与解释、迁移、延迟保持是默认内部方面，有依据才裁剪或扩展，未测不是裁剪理由。KC 继续用于解释和教学，不产生个人 KC 状态。

后台在 Claim 内直接维护方面标准、证据要求、支持／反对／未决的解释规则及推断说明。个人 Belief 由实际表现及评价机制更新，不由管理员填写；修改 Claim 定义不覆盖已有个人判断。使用一种方法成功不能自动支持未使用方法，任选、指定和分别覆盖必须区分。

| 关联 | 应表达的含义 |
| --- | --- |
| 教材章节 → Task／Solution | 本章涉及哪些任务、允许其中哪些直接方法；KC 由这些方法递归汇总，映射保留教材来源 |
| LearningTarget → Claim／学习要求 | 在所选章节，要求哪些 Claim 的哪些方面达到什么标准，方法与支持条件是什么 |
| 个人 Learning Space → 教材／目标版本 | 学生采用的教材与目标版本；不保存长期章节范围，普通保存不更新当前引用，管理员明确应用后更新，旧活动保留原依据 |
| 个人 Belief → Claim 版本／方面 | 对该学生在该空间中的能力判断、证据与限制；与目标是否达成分别展示 |

章节方法不足以支持 Claim 条件时，保留准备缺口，不能悄悄降低标准。章、节统计按管理员维护的学习要求项计数，不用模板数、Claim 数、KC 数或四方面总数替换分母。

教学运行可按当次目标自动生成题目，检查通过后保存实例及来源再使用，不逐题等待管理员确认。检查包含题意完整、答案与方法成立、参数／范围和模板匹配；失败或未决不进入可用题库或检测。当前候选和检查为 mock，真实检查由工程接入；保存题目不生成学生表现。

### 2.5 KC 的任务与方法对应关系

每个作为已准备内容用于正式教学或评价的 KC，都应能追溯到至少一条具体的 `TaskTemplate → SolutionTemplate → KC` 路径；方法递归时保留中间子方法。对应关系须说明采用的对象版本、方法适用条件以及该 KC 在方法中承担什么作用。“有确定的对应”表示关系可以定位、解释和核对，不表示每个 KC 只有一个 Task 或一个 Solution，也不表示关系永不调整。

**历史依据与当前含义。** 旧 [Knowledge Model v0.2 §4.2](../../../../archive/DeerMind_Knowledge_Model_v0.2.md) 已要求 KC 的实际依据来自任务和问题解决过程，并明确同一 KC 可以参与多个任务和方法。它没有规定“一 KC 固定配一 Task、一 Solution”，也没有保证每个 KC 已有专门的基础检测任务。本文承接可追溯对应与多对多关系；旧文档中的个人 KC 状态不恢复为当前模型。

对应关系需要分清两个问题：

| 要回答的问题 | 所需依据 | 不能据此得出的结论 |
| --- | --- | --- |
| 这个知识在哪里被使用 | 适用 Task、选定 Solution 及子方法、引用该 KC 的具体作用 | 该任务已经充分检测了这个知识，或学生已掌握它 |
| 怎样针对这个知识取得理解或使用表现 | 任务明确要求学生完成辨认、解释、构造、操作等责任，参考方法及判断标准能够区分相应表现 | 所有相关复杂任务都会做，或其他未测方面也已通过 |

KC 的任务与方法反查由上述正向关系得到，不增加另一套独立可编辑的 Task–KC 关系。一个 KC 可被多个方法使用、参与多个任务；一个任务也可能涉及多个 KC。方法中引用某个 KC，只说明方法的知识依据，不能把所有引用关系都解释成“本题专门测这个 KC”。例如解释正比例时用到除法，不代表同时完成了除法能力的全面检测。

**知识理解可以成为任务本身。** 凡是课程需要针对某个 KC 教学并判断其理解或使用情况，都须准备能承担该目的的 Task、Solution、Task Claim 和相应判断依据，不必用复杂应用题间接代替。若现有任务已明确承担该责任，可以复用；若只在复杂方法中顺带使用该知识，则不能据此声称针对性检测已覆盖，应补充合适的基础任务。不能给每个 KC 自动生成名为“掌握此知识”的空 Task 或名为“讲解此知识”的空 Solution 来凑齐关系。

以下是说明关系的合成例子，不声称已纳入六上首批正式内容：

| 对象或责任 | 正比例关系示例 |
| --- | --- |
| KC | 正比例关系：在规定范围内，两个量的对应比值保持不变，表示为 `y = kx` |
| TaskTemplate | 给定若干对应量及比较范围，判断是否满足正比例关系，并说明依据；有限数据上的判断不自动证明未知范围也成立 |
| 具体任务 | 比较 A：`x = 1, 2, 3；y = 3, 6, 9` 与 B：`x = 1, 2, 3；y = 4, 5, 6`，分别判断给定对应值是否符合正比例关系，并解释 |
| Solution A | 分别计算并比较 `y/x`；A 均为3，B为4、2.5、2，因此给定数据中A符合、B不符合 |
| Solution B | 比较两个量是否按相同倍数变化；A随x变为2倍、3倍，y也变为2倍、3倍，B不满足；说明为何这种比较与固定比值一致 |
| Task Claim 与个人判断 | 声明绑定上述任务；按条件解释判断、理由等表现，在同一 Belief 内组织默认四方面。数值判断正确但理由不足时，理解与解释仍可待确认，不另建 KCBelief |
| 学习目标 | 选择该任务 Claim 的相关要求及达标标准；任务本身不决定所有课程都必须学到相同范围 |

**Solution 与教学策略的边界。** Solution 描述学习者怎样完成任务。学生通过画图、比较或解释完成一个知识理解任务，这些方法可以属于 Solution；系统先展示图、讲解，再依据回应安排练习和切换教法，则属于 Interaction 的教学蓝图、策略和规则。同一种图可以用于两种过程，但系统提供的帮助不是学生自己完成的表现，不能混为一条证据。

**建设状态与用途分开。** KC、Task 和 Solution 可以先建立草稿再补关系。没有适用路径的 KC 标为关系待补，不称为已完成的可用模型；已有使用路径、但缺少针对性任务时，说明目前只能定位知识使用，不能宣称该课程已经具备针对性的理解检测。辅助知识只需交代实际作用，不因被引用就为每名学生自动创建一个 Claim／Belief。关系缺口按具体用途限制评价承诺，不把它变成全部讲解和帮助的前置阻塞。


### 2.6 按比例增加的完整交互样例

本例是为检查产品逻辑而准备的合成内容，采用“教材管理示例”的 CH-INCREASE；不替代北师大版全章内容或冻结规范包。对应逐步操作和 F01–F18 截图见 [Product §3.11](MVP_Product_and_Interaction_Design.md#fraction-walkthrough)。

| 对象 | 具体定义及采用关系 |
| --- | --- |
| Domain | DOM-MATH，数学领域；不借用其他学生或其他 Learning Space 的个人记录 |
| TaskTemplate | fraction：已知原量 q>0 和相对原量的正增加比例 r，求最终量 t；Δ=q×r，t=q+Δ；连续量单位相同，离散数量需合法。数值、情境、合法表示可变；反求原量、把 r 的基准换成最终量不属于该完整任务 |
| Solution A | S1-A：先求 Δ，再求 t；其中 S0 求部分量，直接与递归知识依据由当前方法引用给出 |
| Solution B | S1-B：t=q×(1+r)，说明1与r以同一原量为基准；课程允许两法任选 |
| KC | K-REF 分数的参照量；K-PART 求一个量的几分之几；K-GROW 增加后的倍数关系。S1-A 经 S0 引用 K-PART，S1-B 引用 K-GROW；Task 汇总并去重，不能推断个人 KC 状态 |
| Task Claim | CLAIM-FRACTION，绑定 fraction；默认四方面分别有标准与证据要求，同一次表现的多方面解释仍保留同源关系 |
| LearningTarget | TARGET-MATH 的 REQ-F1–F4，对应该章四项要求；Claim 条件与课程目标均保留，目标变化不等于能力变化 |
| Learning Space | 学生采用 BOOK-MATH 与 TARGET-MATH；按次选择 CH-INCREASE，活动保存采用快照 |

例题为80米增加四分之一、结果100米；文字检测120本、结果150本；图示检测48米、结果60米。参数、答案、方法、检查结果与版本先保存再展示。已准备题可按适用条件复用；每次使用保留独立的目的、帮助和作答记录。生成候选、保存实例、实际展示和学生作答是不同事件。

**判断参考。** 下面是明确的预写输入输出，不是一套根据字符串估计能力的算法；工程接入后须用真实语义解释替换预设选择。

| 输入情境 | 当题结果 | 能力解释及目标结果 |
| --- | --- | --- |
| 文字题写120×1/4=30，再加120得150，并解释原量 | 正确 | 当堂理解有局部支持；刚接受几乎相同解释，不能确认稳定理解或独立达标 |
| 图示题只求48×1/4=12，并明确把12当总长 | 错误 | 对本次图示要求有局部反证，需加强；不将所有方面或KC判为不会 |
| 两题均用1+1/4并说明原量是一份 | 正确 | 方法B合法；保留解释和图示方面的局部支持，不因两题全对宣称整类任务、稳定迁移或持久掌握 |
| 仅填150或60，没有过程 | 数值正确 | 未表现解释，不断言理解，也不把不解释等同不会解释；图示理解仍缺依据 |
| 不属于预设的自由输入／含糊回答 | 待确认 | 不调用LLM，不使用关键词或默认正确结果；保存输入不新增正向能力结论 |
| 求助结束／未提交 | 未检测 | 先结束检测再讲解，未提交不判错；已提交部分原样保留 |
| 图示依据后被管理员作废 | 原判定可追溯、当前排除 | 撤回该题带来的解释，其他有效依据仍保留；本例无其他图示依据，回到待确认 |

本活动没有延迟表现。7天只是 Claim 原有的示例条件；不将立即重复作答当作延迟保持，也不在本批确定通用复测间隔。实际能力聚合、跨活动冲突和概率校准由工程基线及后续测量承接。

### 6.4 教学策略的依据与内容准备

## 7. 验收、依赖与后续扩展

以下是 CONTENT-001 逻辑交换合同，规定材料必须表达的含义，不冻结数据库或通用运行时 Schema。

| 记录类别 | 必备信息 |
| --- | --- |
| 交付清单 | 包标识、修订、源文件与校验信息、责任人、核对状态、适用范围、相容依赖与已知缺口 |
| 材料及章节引用 | 材料标识与版本、章/节内部位置、页码/图片区域、原文与修订来源、允许使用条件 |
| 领域对象 | Domain 身份与范围；Task、Solution、KC 的领域归属、稳定标识与版本、语义定义、适用条件、关系及所依赖的准确版本 |
| 映射 | 来源位置、目标引用、关系含义、适用条件、候选或已核查状态、依据及核对记录 |
| 目标与判断依据 | 语义所属层、目标／要求、唯一 TaskTemplate 版本及 Claim 版本／方面引用、表现与支持边界、正反例及 Evidence 方面归属、不能作出的结论、版本 |
| 问题与参考 | 原题、参数或来源、要求、图示、合法解法与判据、实际核对结果；候选生成及使用历史分别保留 |

当前 v1 候选仍是旧结构的 UTF-8 JSON 交换样例；以下字段和数量只说明已有资产，不表示新合同已接入。`asset_id/version/status/activation` 表达交付身份和效力；`source/material.inventory` 表达来源与位置；三个领域数组分别承载问题、方法和 KC；`target/claims/evidence_reference` 保留不同 owner；`original_problems/lesson_outline` 承载题目参考和讲解输入。全部内部正式引用带 `@版本`，本包均为 v1；定位 key、目标内部 requirement ID 不冒充新的 Domain 对象。

`verify.py` 检查 ID 唯一性、引用类型、版本存在、问题与方法双向适用、目标与 Claim 范围、来源页覆盖及案例引用，并用精确分数计算检查原创题、两路径等价和运次约束。逐题参考另检查 58 项数值、11 项图示比例关系、51 条定位对 21 组材料的覆盖及本地原页哈希；没有本地页图时报告未执行哈希对照，不声称重新读取了原图。字段存在与数值成立不证明语义分类正确，须结合 §6.3 的内容复核。G4 前据实际接收完善格式约束，Phase 5 再实现导入与运行，保留来源、版本与未知状态；本 JSON 不提前冻结数据库或 LLM 输出 Schema。

下一版资产交付须完成以下检查：

- 模板类型、范围、方法适用关系及映射按 TaskTemplate 合同逐项迁移；移除 Task 直接 KC 引用，补齐各方法和已选子方法的知识来源，再计算并核对汇总。保留旧身份关系，不假定字符串替换即兼容。
- 对每个拟用于正式教学或评价的 KC，核对至少一条适用 Task／Solution 路径和具体知识作用；对课程需要针对性检测的知识，另核对任务责任和判断参考。区分已有路径、针对性覆盖与关系待补，不将自动反查当作语义质量验证。
- 每个 Claim 绑定唯一模板并在内部定义方面；同一评价条件不按四维复制声明。逐项核对旧分维／多模板命题与新 Claim／方面的映射，移除独立 KC Claim，保留领域知识用途。
- 核对目标采用的 Claim／方面、裁剪／扩展依据、迁移与保持条件；Evidence 参考精确指向方面，给出局部未知、同源依赖、方法覆盖和跨任务边界。不将旧分数拼接冒充迁移，缺少定义与缺少证据分开报告。
- 重写受影响的 Evidence 参考、目标关联及验收案例；新包在版本、内容条件和授权未满足前不得正式使用。旧包与 G3 快照继续按原版本保留。
- 校验脚本与工程接入识别新状态类型及历史边界；现有 verify.py 的通过仅针对旧资产合同，不能用来宣布 Task-only 迁移通过。

这些是 OPEN-010 的接收条件。§6.5 已新增当前合同参考切片及检查，旧资产 JSON、脚本或其历史状态未覆盖；OPEN-012 另跟踪上位概念文档中的直接 Task–KC 关系同步。工程不得把旧包的脚本通过当作当前合同验收通过。

**按阶段验收。** M1/G4 接收实际教材、整册目录与内容范围、代表性模型／题目参考和逐章核对办法；不要求导入软件尚未实现时人工先做完整本模型。M1/G5 验证管理员实际完成整册导入、修正、建模、应用和逐章覆盖，以及学生使用路径。旧 v1 候选不符合新 Claim 合同，须按 OPEN-010 迁移当前需要的内容；无需先迁完全部历史实验。OPEN-012 在正式工程关系合同冻结前同步，OPEN-013 在真实教学采用前明确，不因分期自动关闭。校外材料及后置题库功能不阻塞 M1。
