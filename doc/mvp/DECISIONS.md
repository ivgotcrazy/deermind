## 17. Interaction 活动模型收束

**M1-DEC-013，2026-11-07。** 用户确认 M1 将学习过程建模为持续聊天中的、按时间排序的活动树。讲解、答疑和检测是三类学习活动，自由交谈是没有评价效力的极简兜底活动。三类学习活动都可作为顶层活动；父活动只在子活动有独立目标、过程和退出条件，且完成后需要回到原主线时创建。任一时刻只有一个活动叶节点进行，父活动保存进度后暂停，子活动结束时按返回规则恢复、结束或替换父活动。

**检测边界。** 检测活动可包含多个检测轮，原子性属于检测轮而非整项检测活动。轮中不能讲解、答疑或泄露方法；实质求助先结束当前轮，取消原题单尚未开始的轮次。检测活动随后可以创建关联该轮的讲解或答疑子活动。帮助后如需重新确认，必须使用新题建立新轮，不能恢复旧轮或将帮助后的表现倒灌为帮助前独立证据。检测活动既可为顶层，也可为讲解或答疑的子活动；相关轮后的讲解、答疑继续以该检测活动为父活动。

**范围与未完成部分。** M1 现有教学模型页面及14张截图只覆盖讲解蓝图和单轮走查，不代表答疑蓝图、检测活动／检测轮管理、活动树或管理员运行追溯页面已实现。本决定固化产品语义，不提前决定数据库、调用协议、上下文裁剪、LLM提示词或Evidence／Belief的工程算法；这些由工程设计在不违反本决定的前提下展开。

## 19. KC Task、复合 Task 与依赖更新合同

**M1-DEC-015，2026-11-08。** 用户确认以 Task 统一承载知识及复合能力，授权先同步文档，之后再讨论概率算法。本节补充 M1-DEC-007，并替代其中不区分 Task 角色的直接 KC 约定；保留 M1-DEC-010／011 的方法判据、四方面与目标分工。旧记录保留当时语境，不当作第二套现行规定。

- KC Task 的每个可用本层 Solution 直接引用同一个且唯一的核心 KC，可通过 Solution 调用其他 KC Task；不是必然无子任务的原子任务。
- 复合 Task 本层 Solution 不直接引用 KC，通过子 Task 组织求解；组合、选法与检查仍是父 Task 责任，不由子任务分数代替。
- Task 依赖由 Solution 的子 Task／子方法调用、条件及输入输出定义。KC 求解依赖从相关路径推导；旧 KC 先修注释不是另一套概率传播权威。
- 每个正式采用 KC 有对应 KC Task／Solution 可直接展示和检验；KC 可先保存待补齐。只维护 Task Claim／Belief，不新增 KC 或方法个人状态。
- 依赖必须参与适用 Evidence 的解释和推断。可归因过程与总结果间接支持分开，未用方法与受助步骤不冒充独立成功，父失败不推出所有孩子失败，子掌握不自动证明父组织能力。
- 父子判断保留共同来源，不重复计权；后验 Belief 不冒充新作答回流。Belief 采用概率性认识方向，命题、数值表示、算法、参数及校准按 M1-OPEN-09 继续讨论，本轮不锁定 BKT。

## 45. 公共运行底座路由与Operation执行边界

**M1-DEC-038，2026-11-13。** 用户确认先固化公共运行职责及路由／Operation执行边界，再讨论机制；职责与机制均属总体架构，不以职责已定代替可编码设计。保持Temporal＋Pydantic AI＋NATS JetStream＋PostgreSQL、Kubernetes及WebSocket选型。

- 公共底座负责接入、自己的路由函数、必要上下文准备与请求留痕、派发、运行保障和输出回传。目标Operation预定义；路由可借助AI，不能先执行Interaction函数代替公共路由。
- Operation归所属业务或Space，Worker在Temporal之上执行其业务编排。底座提供调度、等待恢复、授权及运行观测，不逐步决定教学或评价行为。回传按原请求、用户和空间关联，不再次使用AI判断接收人。
- 底座支持指定事件订阅及处理入口登记，成功、最终失败和超时分别可处理；消息送达不等于工作完成。注册形式、终态通知及恢复机制待讨论。
- 采用分层重试、全局协调。各层管理自身重试；下层执行与间隔预算服从上层剩余执行期限，累计消耗不因重试清零。停止等待不自动取消生产任务，期限和取消协议仍待定。
- 底座提供技术去重与可靠提交能力，各Space定义业务重复和共同生效边界。业务状态与事件怎样一起保存、通知失败如何补发、重复消费和并发怎样只生效一次，作为下一项机制讨论。
- M1只保留预置账号与统一发放、简单登录、固定学生／管理员角色、本人空间隔离及后台受限执行；必要使用确认保留。完整账号权限平台、复杂找回、完整亲子关系、自定义权限和单点登录后置，认证组件未定。
- M1保持检测等到学生再次进入学习空间时检查，离线时不做后台保持检查或提醒；暂缓后仍以再次进入为前提。执行超时和重试计时保留，已受理的后台工作可继续。

职责与求助时序见[总体§3.5／4.5](m1/engineering/System_Design.md#45-从求助请求到前端回显)，机制归属见[公共运行§7.2](m1/engineering/System_Foundation_Design.md#72-尚待落实的技术设计)。规则、向量、决策模型、LLM及澄清是可选路由手段，未确认M1组合；示意求助Operation名、传输字段、回调协议、Workflow／Activity映射、事务／待发记录及重连方案都不得据时序图擅自定案。
