所属阶段：Phase 3 — MVP Definition。文档目录与阶段关系见 [MVP 文档入口](../README.md)。

文档职责：回答为谁解决什么问题、为什么值得做，以及完整 MVP 的价值闭环和范围。需求决策表在本文维护。

输入输出与边界：输入为需求来源、已有能力和限制、历史决定及可用证据；输出为产品范围与价值假设。具体行为交给需求规格，指标口径交给验证方案，页面和技术方案在后续阶段展开。

## 1. 问题背景与依据

说明问题背景、已有替代方式及不足；区分事实、观察、理论或经验依据、逻辑推断和待验证假设，列出重要反证与信息缺口。

必备产出：来源证据索引，记录来源编号、类别、出处或原始材料位置、日期与版本、支持的判断及限制。用户陈述、直接观察、理论依据、经验推断与未验证假设分别标识；未取得材料标明缺失，不假设必须开展新的访谈或调研。原始材料不强制复制进正文，需可定位并说明访问条件。

## 2. 用户、角色与使用情境

定义受益者、使用者、决策者及运营支持角色，说明各自目标、动机、使用环境和约束，避免仅由某一种角色的意见推定其他角色的需求。

运营支持角色需说明内容建设、审核、发布、异常处置和持续维护由谁承担，以及人工投入的假设。无需在此设计后台页面，也不默认增加新的人员岗位。

## 3. 需求分析与决策表

从要解决的问题识别并比较候选需求，评估价值、频率或严重程度、替代方案、依赖、成本和不确定性。表项至少包含需求编号、角色与问题、来源与依据、期望结果、候选方案、优先级理由、纳入或后置决定、状态及后续验证。尚未确定活动与功能前，不把既有功能清单当成需求全集。

需求候选使用 NEED 编号，正式行为需求在需求规格使用 REQ 编号；两者的对应进入需求追溯主索引。取舍形成的决定通过共同登记册记录来源和有效状态，不把需求决策表复制成另一份跨阶段决定登记册。

## 4. 价值主张与关键假设

说明相对替代方式的价值，以及用户收益、使用意愿、实现可行性等关键假设；区分即时收益与需要长期观察的效果，列明可推翻假设的证据。

## 5. 完整 MVP 范围与能力边界

定义必须形成的价值闭环、纳入和排除的能力、适用条件与已知限制；关联已有系统能力及待补能力。区分完整 MVP 承诺与实施顺序，不用首个开发增量代替整体定义。

范围包括产品级 AI 行为的授权边界：系统可主动开展哪些类型的行动、何种行动需用户决定、哪些结果不能承诺、哪些情况必须停止或交由人工处置。具体可观察行为与验收统一交给需求规格；此处不设计模型调用或 Agent 实现。

## 6. 成功判据与验证责任

说明什么结果足以支持继续、调整或否定产品假设，哪些结果在开发、内部评估或真实使用阶段取得。指标、分母、阈值和采样办法引用验证方案，避免重复维护。

G3 必须明确最低可接受的产品目标与关键判据。后续允许校准的是有明确责任、依据和期限的测量细节，不能把全部成功标准交给实现结果决定；校准状态与审批依据由验证方案维护。

## 7. 约束、待决事项与范围变更

明确影响范围与可行性的前提，给出当前依据、允许的不确定性及后续细化边界。跨阶段决定、约束、待决事项与风险在[共同登记册](../MVP_Governance.md)维护，本章引用其编号并说明对产品定义的影响，不另建一套状态表。

| 范围级前提 | G3 前须说明 | 后续细化责任 |
| --- | --- | --- |
| 数据与权限 | 支持的角色及代理关系、主要可见与操作边界、必要数据用途和外部处理允许范围 | Phase 4 细化授权模型与流程，Phase 5 实现控制 |
| 内容与使用条件 | 必要内容的可得性、使用权利或限制、可覆盖范围、不可得时的替代及影响 | Phase 4 交付实际内容、来源和映射审查 |
| 成本与运营 | 主要资源与人工投入的量级、估算依据、维护责任及明显瓶颈；可用情景范围表达，不要求伪精确预算 | Phase 4 验证内容和运营准备，Phase 5 实测成本与容量 |
| 安全与适用约束 | 按目标人群和使用环境识别数据保护、AI 内容安全、外部或跨地域处理等范围约束及待核实条件 | Phase 4 落实流程与控制要求，Phase 5 实现并提供证据 |

未知的供应商、具体材料或实现参数可以保留后续节点，但足以否定核心范围的前提不能笼统写成“以后再定”。适用规则须有来源，不因大纲出现某项就推断具体法律义务、某服务的处理地域或新增产品功能。

## 8. 文档完成条件

- [ ] 问题来源、候选需求比较和价值假设可追溯，事实与推断清楚区分。
- [ ] 完整 MVP 范围、最低成功目标及范围级数据、内容、运营与安全前提明确。
- [ ] 相关历史决定已有承接引用，阻塞定义的取舍已解决，后置项有理由与节点。

评审时逐项补充状态（已满足／未满足／不适用及理由）、证据位置、实际判断人和日期；当前均未评审。阶段结论另见 [Gate 记录](../MVP_Gate_Reviews.md)。
