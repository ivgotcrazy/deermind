# MVP 验证方案

**状态：大纲草案，待评审；尚未填充项目正文。创建日期：2026-10-10。**

所属阶段：Phase 3 — MVP Definition。文档目录与阶段关系见 [MVP 文档入口](../README.md)。

文档职责：规定要验证哪些假设、如何取得证据，以及有限证据可以支持什么结论。指标与判定口径由本文统一维护。

输入输出与边界：输入为产品定义、需求规格及已有验证限制；输出为跨阶段验证设计。Phase 4 准备实际参考资产，Phase 5 开展工程验证，正式 Internal Alpha 与 Controlled Pilot 仍分别属于 Phase 6、7。

以下段落是各章的撰写要求，不是已确认的产品决定、技术方案或验证结果。

## 1. 验证问题与阶段责任

区分机制与实现正确性、AI 输出质量、端到端体验和实际用户价值；为每个问题指定证据类型、取得阶段及结论边界，说明对上阶段遗留问题的承接。

## 2. 指标与判定规则

为指标规定对象、分子分母、参考来源、支持条件、合格标准、失败分类及不确定性表达。阈值须有依据；范围通过不代表所有结果均已达标。

## 3. 样本、参考与评审方法

说明样本覆盖、选择偏差、参考答案或参考行为的形成与复核、分歧处理；区分开发样本、保留样本和实际使用观察，规定调整后如何保持结果可解释。

## 4. 验证执行与预算边界

规定有限批次、资源记录、停止条件、复测条件及实施问题、网络故障、判断质量和设计缺陷的分别处置。不得通过无止境调参替代结论，也不得用修复前的实现缺陷冒充最终能力限制。

## 5. 真实使用与价值观察

说明未来真实使用的目标、参与条件、可接受负担、基线或对照思路、观察窗口与反馈方式；解释短期表现、持续效果和可推广结论的区别。此处为方案，不代表已获试用准入。

## 6. 结果记录与问题处置

定义结果、版本、运行条件、失败与不确定性的记录方式，建立问题分级和重测责任；给出继续、调整、补证或重开设计的判定方式。

## 7. 报告结构与阶段交接

规定验证报告应包含对象和版本、方法与实际样本、结果与失败、偏差及限制、遗留责任和阶段判断；区分 Phase 5 工程证据、Phase 6 质量评估和 Phase 7 使用效果报告。

## 8. 文档完成条件

核心假设和需求都有合适的证据获取办法；指标可计算且参考可取得；预算与结束条件明确，不把尚未执行的验证标为通过。
