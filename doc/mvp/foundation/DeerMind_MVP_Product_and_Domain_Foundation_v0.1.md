## 1. 组合流程的目标与责任

孩子提交一道课程范围内的新题并求讲解时，系统应当回应她的问题，而不是要求她等待管理员建模。后台则根据保存的材料判断是否需要完善正式领域模型。这是两个相互关联、完成条件不同的过程：当次帮助以合格内容实际呈现为结果；领域维护以有依据的修改、授权生效及后续使用检查为结果。

讲解成功不能证明孩子已经掌握，后台发布新模型也不能补造过去的学习表现。题目是否入库、解法是否经过检查、是否已有正式任务归类、能支持哪些能力判断，分别记录。学生界面只表达与她有关的学习结果和限制，不要求她理解模型、版本或 Evolution 的内部术语。

同一会话继续严格串行处理学习请求。后台维护可以独立推进，但不能把未批准候选注入当前学习判断；每次正式提交和执行仍遵守当前权限、依赖有效性和版本一致性要求。维护完成不会自动重发已经结束的教学行动。

| 责任方 | 本流程负责什么 | 不能代替什么 |
| --- | --- | --- |
| 学习者 | 选择课程空间，提交题目与求助意图，必要时澄清材料，自主决定是否继续练习 | 不必先说出知识点或任务族名称，也不负责替后台完成领域建模 |
| Interaction 与 Reasoning Runtime | 理解请求，形成合法 Observation，依据获批规则检查讲解内容，由 Policy 决定行动并记录实际呈现 | 不直接写学习者掌握结论，不将生成的解题思路发布为正式领域模型 |
| Evaluation | 根据有效领域对象、Claim、实际表现及帮助条件形成 Evidence 和 Belief；必要时保留未决 | 不因缺少模型或材料而判孩子不会，不把讲解文字当成孩子的表现 |
| Evolution | 对管理员选取的线索评估问题、比较原因、准备并验证有限候选 | 不批准自己的修改，不把每道新题都认定为模型缺陷 |
| 管理员、Governance 与相应 owner | 管理员审核明确差异与验证材料，Governance 记录授权，相应 owner 检查并提交，运行系统限定启用 | 同一个人可完成管理操作，但审核、提交、生效及效果检查仍分别留痕 |
| 家长 | 在有效关联和授权内查看学习情况及相关依据，询问如何支持 | 不从家长端修改学生材料、批准模型或触发孩子必须完成的任务 |

## 2. 学生求助与题目保存

### 2.1 提交到讲解

学生从当前课程空间进入求助，可上传拍照、图片或 PDF，也可提交手写与语音。页面应持续显示当前课程，避免把校内与校外资料混在一次请求中。语音先转写预览，再由学生发送；输入尚未提交时不形成正式学习判断。

| 步骤 | 必要输入与处理 | 给学生的结果及保留的信息 |
| --- | --- | --- |
| 提交 | 当前学习者、课程空间、题面及图示、已有作答、讲解或仅提示等意图；原始作答并非每次求助都存在 | 接收后显示处理状态，保留原件与提交关联；不让孩子为获得讲解先补做一道题 |
| 理解与必要澄清 | 识别题面、同题跨页、作答对应和请求；只在影响后续判断的内容不清楚时询问 | 显示需要核对的局部，例如某个数字或图形条件；原材料与更正分别保存，不要求默认逐字确认 |
| 范围与依据检查 | 依据本课程已确认范围、题目实际要求和可用解法判断支持条件；同时检查现有模型适用性 | 纲内按求助继续；确认超纲后委婉拒绝；依据不足保持未决。范围结论和模型覆盖状态分别记录 |
| 保存与评价 | 保存题目档案，保留尚未确认的关系；仅对满足输入及规则条件的部分运行正式评价 | 有作答且可判定时可形成当次反馈；不适用的掌握判断保留缺口，已有其他有效判断不被一并清空 |
| 决策与呈现 | Policy 按本次请求及活动约束选择帮助；实际内容通过适用的数学、来源、支持边界及能力声明检查 | 明确求讲解时简明分步解释关键理由；仅提示时保留对应责任。生成、展示、播放及未知发生状态分别记录 |
| 收束与后续选择 | 保存当次作答、反馈、实际帮助及本轮结果；如有模型缺口，保存供管理员选择处理的线索 | 可离开、继续追问，或自愿接受合适的检查；不因后台存在待处理事项要求留在页面或完成额外测试 |

独立自测中途请求讲解，仍按既定规则结束相应独立诊断并转入教学；不能把求助前后表现合并成一次无帮助测验。实际帮助程度以展示及播放记录为依据，不能把一次点击求助等同于已经收到完整答案。

普通单题求助的 30 秒质量目标覆盖必要检查直到可用讲解实际呈现，不包含后台领域演化；30 秒不是自动取消时限。断网或接收状态不明时查询原提交，避免重复录入和评价，不自动重播。技术失败不能包装成超纲、孩子不会或正常的 Policy 不干预决定。

### 2.2 不同缺口下能提供的服务

| 当前情况 | 当下处理 | 对正式评价和后台的影响 |
| --- | --- | --- |
| 题目纲内，已有正式模型适用 | 按当前请求讲解或反馈，保存为本空间题目档案 | 按实际证据及 Claim 条件评价；普通新实例无须新建模型 Issue |
| 题目纲内，解法可核验，但任务归类或部分知识关系尚未确认 | 提供经过检查的讲解，保存题目和未确认关系，不要求逐题人工预审 | 只使用已成立的正式依据；相关掌握判断不足时保留未决，将真实覆盖线索留给后台 |
| 题目纲内，但当前不能可靠核验必要解法或关键条件 | 请求必要澄清，或如实说明本次尚不能可靠讲解，保留任务状态和失败依据 | 不将单次失败改记为超纲，也不能把这条异常路径变成所有未建模题的常规入口 |
| 范围依据不足 | 根据缺失材料澄清或保留范围未决 | 不以“没有匹配到 KC”代替超纲判断，不擅自扩大课程支持范围 |
| 已有充分依据确认超纲 | 简明说明当前课程支持边界，拒绝该题的学习帮助 | 不作能力不足判断，不把拒绝变成偷偷讲解超纲知识的入口 |

上述范围判断不以当前学习进度为界。课程内尚未学到的内容也允许求助，系统依据有效信息调整说明基础和解释方式；不能因本系统没有记录而断言孩子从未学过。是否学过、是否掌握及内容是否经过核验分别表达，不为实施这一决定额外要求孩子每日登记学校教学进度。

“能够核验”要求保存原题、可复核推导或解法、适用条件与检查结果。确定性计算可检查数值和形式一致性，数学与教学语义仍按规则及 LLM 处理；模型再次表示同意不独立证明正确。具体检查协议与准确率在工程和 Alpha 中验证，不能由本表承诺绝对正确。

### 2.3 讲解不必依赖完整的掌握判断

既有 [Interaction Runtime §3.3](../../system-design/DeerMind_Interaction_Decision_Runtime_Design_v1.0.md#33-decision-context)规定，Policy 的输入随目的确定，不是每次读取全部 Learner Belief。由此，本流程要求为“回应明确的单题讲解请求”准备经批准的输入与行动合同，而不是把完整能力诊断设为所有帮助的共同前置。

该合同必须取得有效请求、当前活动与帮助约束、范围依据、必要原材料、内容校验结果及当前授权。涉及纠正具体作答时，还必须取得该作答；不声称个性化能力诊断的讲解无需虚构一个掌握结论。若行动声称“你在某能力上薄弱”，或依赖某个 Belief 才能作出相应决策，则必须取得那个 current-valid 判断。

因此，本轮仍先完成合法理解及适用评价，再进行 Policy；Evaluation 没有适用命题、证据不足和处理故障分别表达。不能将这些情况统一伪装成评价成功。某个输入合同确实必需的评价结果无效时，该合同不能继续，也不能偷读旧结果；只可在已批准且自身前提成立的其他能力范围内处理。具体协议须在 Phase 5 固化并验证，遵守 [Runtime 的未决与故障合同](../../system-design/DeerMind_Interaction_Decision_Runtime_Design_v1.0.md#71-policy-non-resolution-与-runtime-failure-分离)。

本次讲解采用的经检查推导属于具体内容及运行依据，不自动成为正式 Solution Strategy。尚未归类的题目以题目档案保存，不冒充已经实例化的正式 Task Instance；确认适用关系或新模型获批后，再由相应 owner 建立正式关联。不能为了让链路跑通，临时创造一个包揽所有数学题的 Task Family、通用 KC 或新的掌握命题。

## 3. 题目档案与初始领域包

### 3.1 题目档案

题目档案是材料、版本、适用关系和使用记录的可追溯入口。它不是第二套规范任务模型，也不是可以覆盖原作答的可编辑日志。稳定题号只用于识别对象；针对什么知识、怎样变化和适合何种使用，通过可修订的描述表达，不把这些语义塞进不可更改的编码。

| 信息组 | 必须能回答的问题 | 条件与限制 |
| --- | --- | --- |
| 身份与来源 | 来自哪个空间、哪次上传或生成、哪个教材页或外部材料；当前与历史题面各是什么 | 上传题不冒充教材题或系统生成题；可关联同题档案，但不能因此丢失每次实际提交 |
| 内容与修订 | 题干、条件、图表、公式和子问是否完整；更正了什么、依据是什么 | 保留原件和局部修订；版面变化与题意变化分开 |
| 解法与检查 | 可用解法有哪些，来源与适用条件是什么，谁或何种规则检查了什么 | 原书答案、AI 推导及人工修正分别标明；未决解法不能因保存而取得教学资格 |
| 正式关系与缺口 | 已关联哪些 Task、Solution、KC、Target 和教材位置；引用何版本；什么尚不清楚 | 多解不强制共用一组 KC；没有正式关系时保留未决，不用自由文本候选替代规范身份 |
| 变式描述 | 若有原题，改了哪些条件、表示、责任或支持方式；预期检验什么 | 原生题不伪造母题；题号或数值变化不证明新的独立测量机会 |
| 功能可用性 | 可否浏览、讲解、作为练习或诊断材料，以及在什么条件下复用 | 保存、核验、授权开放和当次适用性分别记录；不压成一个“已通过”状态 |
| 实际使用与维护 | 谁在什么活动下见过、做过、获得何种实际帮助，引用哪些版本；有何纠错或演化事项 | 各次使用保持独立记录；旧题允许重测，由 Evidence、Belief 和目标决定是否合适；按空间和当前权限使用 |

学生查看自己的题目与学习记录，家长按已有相关依据权限只读查看；管理员在具体事项授权内查看模型关系、校验和影响。界面删除继续遵守 R24，不因后台维护恢复学生已经删除的条目，也不向其他空间或无权角色复制材料。

### 3.2 初始领域包的必需内容

领域包必须让工程实现知道“支持什么、按什么标准判断、使用哪些正式对象和参考”，而不是只交一份 KC 名单。两个课程空间分别准备和发布，章节进度、教材组织与正式 Task 身份分开。产品课程容器与架构 Learning Space 的完整映射及 authority mapping 仍由后续 Phase 4 设计完成。

| 组成 | 最低内容与相互关系 | 本轮状态 |
| --- | --- | --- |
| 课程范围与来源 | 教材版本、适用课程、已确认知识边界、可用材料与缺口；范围内外及未决参考 | 结构已明确；等待实际教材与范围确认。已确认不以学习进度判超纲，见 §2.2 |
| 教材内容与映射 | 章节、原页和内容身份，对应题目档案、任务实例、解法、知识及目标的已确认和未决关系 | 尚无首批实际内容；识别完成与正式模型审核须分开 |
| Target 与 Task | 学习目标的成功标准、支持和责任条件；任务族的要求、边界、实例与反例 | 需基于真实任务共同设计，不能机械由目录或每道题生成一个族 |
| Solution 与 KC | 可用策略、必要任务分解、不同策略的知识支撑与适用条件；必要 KC 的定义、区别与来源 | 按 [Learning Space Design](../../concept-design/DeerMind_Learning_Space_Design_v1.1.md)组织，未建关系允许 UNKNOWN；候选与正式对象分别管理 |
| Claim 与评价依据 | 哪个正式对象在何种任务、帮助、质量和观察条件下可被支持或反驳，何时必须未决 | 与 Evaluation 合同对齐；一题做对不自动支持广泛掌握，模型新增不等于学生新增能力 |
| 验证材料与发布说明 | 可复核解法、区分性正反例、相关旧案例、参考判断、版本、审查结果、适用限制及批准范围 | 实际样本与独立参考尚待建立，不以本文件的说明例充当正式评测集 |

初次教材建设从内容和领域建模需要出发，复用候选、审查和发布能力；不为每次新增对象虚构旧模型失败。已有模型的扩展或修正则说明维护依据及影响。两种入口可以共享后台工作台，不能为了界面统一而伪造问题、原因或运行效果。

## 4. 管理员的基础领域演化工作台

### 4.1 从待处理材料进入

管理员可从教材章节、题目档案、具体反馈或保存的覆盖线索进入，也可主动提出明确的建模需要。运行时保留线索不等于自动启动整套 Evolution；首版由管理员选择处理。事项首先显示空间、原材料、当前正式版本、实际发生了什么、预期应当怎样，以及哪些材料尚缺。

一项事项集中呈现“材料与问题、修改候选、验证、审核发布、使用与影响”即可，无须为每个概念建立独立页面或服务。下面的结果是分别可查看的记录，不是必须把所有事项硬塞进的单一线性状态机。无须修改、转交和未决都是合法结果。

| 环节 | 系统与管理员具体操作 | 进入下一步需要的材料或结果 |
| --- | --- | --- |
| 评估问题 | AI 对照原材料和当前模型检查现有对象能否表达该题，排查识别、匹配和本次推理错误；管理员核对有关依据 | 限定范围的问题描述或不改模型结论；相关替代解释及支持、反对和缺失证据。问题描述不直接写成指定解决办法 |
| 准备候选 | AI 起草复用、新增或局部修订方案；管理员查看完整定义与差异，必要时修改 | 精确基础版本、候选定义、条件、来源、例子、关系、预期作用及依赖影响；人工修改部分可追溯 |
| 准备并执行验证 | 在看结果之前明确要区分的原因、要检查的修改、参考与相关旧案例，以及有限停止条件；执行后保留实际输入输出 | 原因得到何种支持与候选达到什么效果分别报告；失败、未决和人工介入不被隐藏，不能只给一个总 PASS |
| 审核 | 管理员检查候选差异、验证、未决、使用范围、历史影响和恢复条件，可批准、退回或保持未决 | 批准绑定准确候选与范围；批准后的候选若继续修改，原授权不能自动覆盖新差异 |
| 提交与启用 | 相应 owner 检查版本、授权及依赖，提交正式修订；运行系统按授权范围启用 | 审核通过、提交完成和实际生效分别可辨；基础版本已变或任一环节失败时不得声称已发布 |
| 使用与影响检查 | 查看后续实际请求使用了什么版本，检查预定效果、相关旧判断和待修复项 | 能区分尚未被使用、已被采用但未证明改善、有限效果已获支持和需要恢复；生效本身不关闭所有问题 |

没有证据表明需要新 KC 时，允许只补充解法、任务关系或映射；已有对象能承担责任时优先复用。若问题是 Evaluation、Policy 或推理规则，保存依据并转交既有工程维护与受控交付，不将其硬改成领域问题来满足此流程。

### 4.2 管理员批准前要看见什么

审核界面必须把原问题、候选和参考放在同一事项中，便于管理员对照，而不是只显示“AI 建议通过”。候选材料至少解释为什么需要改变、为什么不能直接复用、改动影响哪里、已检查哪些反例和旧案例，以及哪些效果仍未知。数学内容检查、语义关系检查、权限与版本检查分别呈现，不能用某一种通过替代另一种。

例如新增 Task Family 时，要说明新要求与邻近任务族在认知责任、解法空间或能力要求上的区别；新增 KC 时，要说明它表示什么可复用知识、与已有 KC 有何区别，以及哪些表现可能支持或反驳相应解释。有限内容与关系验证允许支撑有条件采用，但不能声称已证实新 KC 的长期诊断效度。

管理员一个人可以修改、审核和发布，不增加第二人会签要求。后台记录其各次操作与依据；AI 原始候选、人工修改以及最后批准版本必须可区分，否则后续无法知道系统实际完成了哪些工作。

## 5. 生效、历史与用户可见结果

新版本仅按授权和一致性边界影响后续解析与判断，不要求打断孩子等待发布。正在处理的请求不得混合不相容版本；具体固定、失效和重取输入规则按 [版本架构](../../system-design/DeerMind_Semantic_Version_Replay_Migration_Design_v1.0.md)及 [Governance Runtime](../../system-design/DeerMind_Evolution_Governance_Runtime_Design_v1.0.md)落实。

发布后分开检查两类工作。第一，后续实际请求是否正确使用新关系并取得预期结果；第二，旧结果中哪些依赖确实受到改变影响。仅排版更正不自动全量重算；语义修订可能需要停止使用受影响判断并由 owner 重算。新增模型没有把历史未知自动改成掌握的权限。若以新模型解释旧材料，必须保留原来作答、帮助条件和版本，形成明确的新解释，不能改写旧事实。

后台应分别显示未来使用是否恢复、相关旧判断的修复完成量、待处理与失败。回退也必须检查旧版本现在是否适用；回退未来使用不代表历史已经全部修复，更不重放旧教学。

模型补齐本身不产生一次必须打扰孩子的教学动作。若维护实质纠正此前展示的讲解、对错或掌握判断，按 A73–A74 主动告知受影响且当前有权查看的用户，说明改了什么及尚未完成什么；不重现学生已删除的原件，不披露其他家长对话。新的复习邀请仍由 Policy 根据当前依据决定，孩子可拒绝。

家长看到的是当前可解释的学习情况、相关依据及必要的更正说明，不是管理员的候选工作区。不能因家长与管理员是同一个人，就把管理数据带入家长会话。

## 6. 一个贯穿流程的说明例

以下为合成说明例，不代表实际教材范围或已完成的验证。假设本课程允许使用百分数描述折扣，现有模型能处理“已知原价求折后价格”，但是否覆盖反向求原价尚待核查。

孩子上传：“书包打八折后是 160 元，原价是多少？”她写了“160 × 80% = 128”，并说“讲讲我哪里弄错了”。系统先核对题面和作答，确认这里的 160 是折后价格。本次解法检查的依据是“原价 × 80% = 160”，因此原价为 200；还须确认解释适合当前课程范围。

当次讲解可以说明：“八折后的价格是原价的 80%。160 元已经是这 80%，所以要用 160 ÷ 80% 找回原价；200 元打八折正好是 160 元。”这是完整讲解的示例；若孩子要求仅提示，应改用相应帮助范围。实际展示后记录系统已指出数量关系和求法，不能再说孩子独立发现了这些内容。

学生这一步不需要等新任务族发布。题目档案保存原题、她的 128、讲解和实际帮助，现有合法依据能支持的当次反馈照常形成；如果没有适用的正式 Claim，就不发布“她不掌握反向百分数问题”这样的能力结论。她随后照着写出 200，也不能单凭这次订正证明独立掌握。

管理员之后打开覆盖线索。AI 与管理员首先检查三种不同可能：原题被误识别为求折后价；已有任务族本来涵盖求原量，只是匹配错了；正式任务族确实只定义了正向求量。前两种应进入记录或匹配问题处理，不因本例自动新增模型。第三种才支持进一步考虑必要的领域扩展；仍不意味着一定需要新 KC，百分数关系知识可能已经存在。

如果最终准备一个反向求量的 Task Family 候选，验证应区分“折后是 160”“优惠了 160”等责任不同的情况，检查合法解法，并检查原有正向题是否被错误吸收。候选的具体族边界、参考答案和用例数量须在实际领域设计中核定，本例不替管理员批准这些定义。

候选检查和审核完成后，由相应 owner 提交并按范围启用。后续请求确实采用新版本，才形成使用证据；孩子过去的受帮助记录保持。若只是补齐一个此前未评价的任务族，不应宣称旧结论已被纠正；若确实发现此前展示的判题错误，则另外按依赖维护与告知流程处理。

## 7. 本流程的验证材料与阶段分工

本流程使用统一的 R、A、V 编号，不新建 Evolution Spike 或独立通过门槛。下表是需要准备的覆盖，尚不是执行记录；实际教材到位后确定案例、独立参考、版本与评分依据，在工程运行前冻结有限参数。

| 检查内容 | Phase 4 应准备的具体材料 | 后续验证及已有覆盖 |
| --- | --- | --- |
| 范围与模型覆盖分开 | 纲内已覆盖、课程内尚未学到、纲内新组合或真实缺口、确定超纲、解法看似超纲但存在纲内方法、范围未决 | 检查实际帮助、合理拒绝及未决，不以进度或题库命中代替范围判断；A75–A76，V01、V10 |
| 帮助与掌握判断分开 | 原始作答、完整讲解、仅提示、未展示及展示未知；模型部分缺口与无适用 Claim | 检查实际帮助归因、正式判断条件和无依据结论；A76，V02、V03、V10 |
| 保存与复用分开 | 上传新题、完整生成候选、修订、未核验解法、未知关系和多次实际使用 | 能追溯每次题面与帮助，未决不会丢失或自动开放；A77，V01、V03、V10 |
| 真正扩展与合理不改 | KC、Task Family、Solution、映射的必要变化；已有模型足够、非领域错误和未决反例 | 真实 AI 辅助评估、候选与有限验证，保留人工贡献；A23、A31、A78，V10–V11 |
| 授权生效与影响恢复 | 已用旧映射、候选错误或证据不足、基础版本变化、未批准、提交或启用失败、后续采用与回退 | 证明有限成功及非成功路径；A18–A25、A78，V03、V11；不以全部拒绝证明能力可用 |
| 体验与权限 | 学生无需等后台发布、跨空间隔离、家长只读、按事项管理访问、已删材料及实质更正 | 检查端到端等待、实际可见性、维护负担及通知；A04、A73–A74、A76，V03、V04、V08、V09 |

Phase 5 的增量工作包含线索到问题的评估、原因与候选区分、有限验证执行、结果与人工修改记录，以及生效后实际使用检查。教材候选编辑、版本差异、批准、提交、启用和依赖维护尽量复用既有必需能力。详细设计需要据此拆分工作并估算，不能因复用而事先承诺整个增量很小。

## 8. 教材导入、审核开放与学生使用

### 8.1 管理员从材料开始准备

管理员在目标课程空间内进入教材管理，上传多页 PDF 或成组扫描图片，可整本导入，也可按章节补充。录入教材名称及能确认的版本信息，保留原文件、页序与来源；答案或解析缺失、未知均可接受，不要求先自行补写答案。首次建模走领域建设入口，已有内容的语义修改再按 §4 的适用维护流程处理。

教材工作台以章节和原页组织材料，供管理员在原件、识别结果、模型候选和使用预览之间对照。内容核对与模型审核在同一工作台内衔接，但分别保留状态与结果。AI 可提前准备候选，审核必须使用明确的材料版本，不能把后续改过的题面套用旧校验结果。

| 环节 | 管理员操作及系统处理 | 输出与异常处置 |
| --- | --- | --- |
| 接收材料 | 确认所属空间与教材，上传文件或章节批次；系统保留文件和页序 | 显示原导入任务及接收状态。服务端接受后可离页，重新进入继续查看原任务；接收未知先核对，不重复建书或导入 |
| 识别与组织 | 系统识别目录、正文、例题、练习、答案、公式及图表，关联同题跨页材料；管理员可核对章节、页序与内容对应 | 形成有来源位置的内容草稿。缺页、图示不清、答案错配或识别失败按受影响范围显示，不能只报整本“成功” |
| 内容核对 | 管理员对照原页更正疑点，并检查代表性未标疑材料；AI 对修改后的相关内容重新检查 | 形成已核对内容及仍待处理部分。原件与修订可追溯，原书答案不是无需核验的真值，局部问题不阻塞其他具备条件的内容 |
| 领域准备 | 系统基于明确内容版本起草或复用 Target、Task、Solution、KC 与映射，列出候选依据、反例和未决；无答案时准备标明来源的候选解法 | 管理员能查看及修改完整候选。已有对象优先复用，不逐题机械新增 KC；准备了候选不表示已经形成正式模型 |
| 审核开放 | 查看实际差异、内容和领域检查、适用功能、未决及影响，批准准确范围；相应 owner 提交，按授权启用 | 内容开放与正式模型生效分别留痕。相同操作入口可以编排这些步骤，不能把整章批准解释为所有未决关系都有效 |
| 使用检查 | 从该章节查看学生使用预览、有效版本及功能条件；后续实际使用与异常进入可追溯记录 | 预览用于检查内容和入口，不写入孩子学习历史或掌握状态。仅有预览不代替后续实际使用及质量验收 |

上传未完成、识别失败、等待核对、候选待审、已批准未生效及已开放是不同情况。任务页给出受影响材料和当前可执行的处理，例如补充缺页、更正局部、重试失败步骤或继续审核；不要求管理员删除整本重来。重试继续关联原任务，技术限额与重试次数在工程方案中明确，不因本流程设计承诺任意大小文件。

### 8.2 按实际能力开放内容

同一章节内不同材料可以处于不同准备程度。后台审核按章节组织，但批准结果需要列出实际开放的内容、可用功能及尚未解决的部分，避免一个整章“已发布”标记造成误用。

| 材料准备情况 | 学生可以做什么 | 系统仍需限制什么 |
| --- | --- | --- |
| 原材料和对应内容已经核对，解法尚未可靠核验 | 浏览已开放的原题或正文，按正常入口提出问题 | 未决解法不作为系统认可的讲解、判分或掌握依据；原材料中出现的答案与系统确认正确分别表达 |
| 解释依据、解法和当题判定条件有效，部分 KC 映射未决 | 获得讲解及有依据的当次反馈 | 不基于未决关系更新相应 KC 判断，也不把整个章节锁住等待图谱补全 |
| 相应正式对象、Claim、评价规则及合格题目已准备 | 从教材范围发起相应自测，查看有依据的检测计划 | 检测覆盖必须说明真实范围；未覆盖内容不冒充已检查，首批题量仍按目标和证据决定 |
| 个别已用内容后来确认有误 | 继续使用不受影响内容，受影响处得到明确说明及合法的替代或恢复处理 | 停止使用失效依据，处理依赖判断；不能只改教材原文而保留错误的当前结论 |

尚未核验的教材解法不进入日常求助上下文作为可信依据。如果孩子明确请求解释某道题，可以按 §2 取得清晰题目并重新核验本次帮助；成功回应不自动批准那份教材草稿，也不免除其后续审核。具体处理失败仍如实说明，不能把“教材待准备”或“她尚未学到”改称超纲。

### 8.3 从教材进入学习

学生在当前课程空间中进入教材，按已开放目录选择章节，查看原材料和相应内容。章节内容中可选择具体题目或知识疑问求助，不必先输入 KC 名称；有适用条件时可以作答练习。章节自测沿用选择范围、展示题单覆盖和参考用时、学生决定开始的流程，不因打开章节而自动安排学习任务。

页面说明应对应孩子能做的事，例如“可以查看原题”“这道题的解答还在核对”“本次检测覆盖这些内容”。不向孩子显示“KC 未映射”作为不能学习的解释，也不把内容准备进度称作她的学习进度。模型或教材覆盖不足时，掌握结果可以保持未决，不能显示为能力不足。

教材中实际展示的例解、答案和图示属于已发生的内容接触，按与当前任务有关的条件记录；页面打开不证明孩子已阅读或理解所有内容。独立自测的任务呈现不提前泄露相关解答，如果不能可靠提供不含答案的题面，就不能把该材料用作无帮助检测。历史原题仍允许重测，选题与证据解释要考虑已有接触和实际帮助，不能靠换一个题号清除。

家长通过孩子的概况和相关依据查看所用教材位置、题目及必要说明，对内容只读；本流程不额外授予家长教材编辑或后台审核权。管理员查看学生使用预览时仍是管理操作，不能假冒一次真实学习者作答。

### 8.4 这条流程的验收交接

准备材料须覆盖多页 PDF、图片批次、同题跨页、公式和图表、无答案教材、识别疑点及未标疑错误、局部解法未决、部分 KC 未决，以及已用内容的修订。对应 A16–A17、A23、A26–A27、A42、A45、A69；按 V01、V03、V04、V09–V11 分别检查可用性、质量、角色边界与维护。

验收不能只检查教材“导入完成”：管理员应能查到原页和候选依据、批准限定内容，学生应实际进入已开放章节并完成适用学习动作；剩余材料及未决功能仍可定位。学习进度不得成为拒绝课程内讲解的原因，新增覆盖按 A75 检查。具体扫描样本、首批章节、文件与页数边界及审查抽样须在真实材料到位后完成，不把此处流程表当成已测能力。

## 9. 学生端五个核心场景

### 9.1 页面组织与共同操作

学生 App 围绕当前课程空间组织求助、资料、教材和学习情况。首页首先让孩子知道正在使用哪个课程，并可直接拍题、导入资料或提出问题；其余区域提供上次未完成活动和有依据的复习建议。没有建议或学习记录时，仍能直接开始使用，不用虚构薄弱点填满页面。页面名称和布局是交互草案，最终视觉与手写布局需在指定平板上验证。

五场景共用题目、作答和帮助的工作区，保留不同活动的反馈规则。平板题目区域应可回看原图与关键条件；作答区域以手写为主，兼容文字、语音及纸上作答照片；反馈区域在适用时机展开。不能让讲解覆盖正在写的内容，也不能因为共用组件，在独立检测中自动展开历史答案、对错或解法。

| 页面或区域 | 首屏需要表达的信息 | 主要操作与结果 |
| --- | --- | --- |
| 当前课程首页 | 课程名称、继续中的活动、可选建议及必要的用时信息 | 直接求助、导入错题或试卷，进入教材、自己的资料及学习情况；课程切换后按对应空间取得内容 |
| 我的资料 | 错题与试卷的可辨入口，题面摘要、来源、日期及必要处理状态 | 找到并打开资料，按现有教材关联、来源和日期筛选；可检索题目内容，未确定教材归属仍可找到 |
| 题目与作答工作区 | 原题、当前活动是练习还是检测、已有输入和提交状态 | 书写、拍照补充、提交、求助、核对原件或提出更正；实际活动与每次作答分别保留 |
| 试卷回顾 | 已处理及未决范围、题目列表、卷面批改和系统复核的必要区别 | 按题查看原件、讲解或更正，进入错题再学习；局部失败不使其余结果不可见 |
| 学习情况与检测计划 | 对什么内容能作何种判断、依据及限制；开测前的范围、题数与参考用时 | 查看相关依据，从教材选择章节自测，接受或暂缓有依据的复习与验证邀请 |
| 检测结果 | 本次表现、适用历史支持、未检测或未决内容，以及可选后续动作 | 查看相关题目、求讲解或自愿另做检查；离开不被记为能力反证 |

资料列表呈现“原来做过什么”和“现在有什么依据”时须可区分。例如“上次做错”是历史表现，“后来在提示下完成”是另一次表现，二者不能被一次订正覆盖成“已经掌握”。不新增手动填写掌握程度、清空能力历史或一键消灭错题的入口。

共享操作保持一致：发送或提交才触发学习分析，手写过程不被实时批改；语音预览尚未发送不当作正式回答；同会话请求严格串行，后续输入保留次序。界面显示接收与处理情况，不凭一个加载动画暗示已经评价或保存到服务器。

### 9.2 错题保存与再学习

孩子可以从首页导入错题，也可在资料中重新打开原有题目。上传时保留题面、原始作答及能取得的批改，关键内容清晰时直接处理，不让孩子逐题命名 KC、填错因或确认每个字。把一题作为错题资料保存，表达的是整理意图；正式复核仍可能发现它原本答对或无法判断，不能把入口名称当作错误事实。

| 操作 | 页面应如何响应 | 留下的结果 |
| --- | --- | --- |
| 导入并保存 | 显示所属空间及提交状态，材料可处理后进入题目详情；不确定处只定位局部 | 原件、识别与原作答分别保留；没有过程不补造过程，后台处理未完成不冒称已判断 |
| 重新找到题目 | 列表显示题面摘要、来源与日期，详情能返回原试卷或教材位置；未映射题仍可访问 | 找回的是同一题目档案及对应使用历史，不重新导入为新学习表现 |
| 请求讲解 | 保留原题和原作答，针对当前问题给解释；明确只要提示时遵守提示范围 | 本次实际帮助与原来的答错事实分开，讲完可以离开 |
| 再练一次 | 以练习目的进入新的作答区，提交后反馈；不覆盖原始答案 | 形成新的作答与帮助记录，已经看过的材料仍作为接触条件保留 |
| 检查是否掌握 | 进入复测准备，依据目标及现有证据选择适用原题、变式或原生题，再说明题量与参考用时 | 不要求先选章节；检测时不自动展示原答案，是否独立仍要结合此前实际帮助解释 |
| 核对或提出异议 | 可对照原件指出识别、题目归属或判断问题，系统按 R12 复核 | 原始记录、异议、核实更正与依赖修复分开；用户说“我会了”不直接改写掌握结论 |

错题可以保留在资料中而不被反复推荐。是否需要复习由当前 Belief、Evidence 和目标决定；曾答错不意味着永远薄弱，做过一次也不意味着不再值得检查。界面删除按既有 R24 执行，不能用删除资料代替纠正错误判断。

试卷分析中经系统确认答错的题自动归入错题本，保留原卷来源，孩子无需逐题再次收藏。试卷原题、错题入口与每次作答关联同一来源，不能因多一个入口把同一表现重复累计为两条独立证据。复核后不再成立的错误标签须更新，不能继续作为当前错题推荐的依据；原始作答、更正与实际帮助仍保留。已界面删除条目的限制继续有效，重处理或重新归集不能恢复原条目。

### 9.3 整份试卷回顾

孩子选择导入试卷，提交照片、图片或 PDF，可包含正确与错误作答及老师批改。接收后进入任务页，显示处理中、待补充、部分完成或失败的具体范围；服务端已接受的任务可以离页，稍后从资料中返回查看。无需守着处理，也不为重新查看另建一次考试记录。

完成范围足够时，回顾页先说明“已看到哪些题、哪些能判断、哪些还缺材料”，再呈现题目。统计只针对明确的题目范围，不把漏页当成学生空白，不把未作答或读不清混入答错数量。卷面分数、批改与系统复核结果保留来源区别；缺少完整评分依据时不编造考试总分，系统结论有异议时不覆盖老师在原卷上的标记。

点开一题后进入共用工作区，可看原题与作答、请求讲解或更正。判对只说明该次结果得到支持；只有答案而缺少理由时，可以保留对理解深度的疑问，但不能自动判“蒙对了”。已批改试卷也不天然等于无帮助证据，已知作答条件随材料保留，必要条件未知时限制相应评价。

回顾结果不自动对全卷逐题讲解，也不要求孩子处理完所有错题才能离开。确认错题自动归集；未作答、材料不清和复核争议各有可见状态，不混入已确认错题。补拍或更正后只处理相关部分，同步更新相关错题状态，结果和必要通知按有效性更新，原考试表现不被订正后的答案替换。

### 9.4 主动题目与知识讲解

孩子可以直接说“讲讲分数除法”，从教材选择一段内容求助，也可以在题目中指出卡住的位置。对象清楚时直接给简明解释；确有歧义时只询问解决当前问题所需的信息，不把固定诊断问卷放在每次求助之前。

首段解释应回应当前疑问，说明关键理由，按内容需要采用算式、文字或图示，随后可选择“讲详细些”“这一步为什么”或继续用自然语言追问。只有必要的实际内容才能作为讲解依据；不能用声音自然、排版漂亮或模型自信来代替数学和教学检查。

文字或手写求助默认显示讲解，可选择播放；语音求助默认播放并保留可读内容。停止播放不会撤销已经展示的文字帮助，重听也不是一次新的独立学习表现。请求提示后再要求完整讲解，按两个实际发生的帮助步骤记录。

讲解后不把“我明白了”按钮作为掌握证明，也不强制孩子立即做题。合适时可在反馈区域给出可选择的检查建议，孩子可以继续学习或离开。课程范围内尚未学到的内容仍可讲解；当前基础不足可能需要解释相关前提，但不能擅自扩大课程边界或开启整套自动教学计划。

### 9.5 学习情况与主动自测

学习情况页按本空间教材及相应学习要求组织，展示当前有依据的认识和限制。优先使用孩子能理解的具体说明，例如“这些题能独立完成”“换一种条件还需要检查”，同时说明对应范围和根据。例句不是新的固定能力等级；正式结论仍由 Evaluation 提供。不能按答对题数直接显示全章掌握百分比，也不能把证据不足放进薄弱项排名。

孩子可以展开相关题目与依据，看到当时的任务和帮助条件。当前判断失效或正在复核时如实说明，不继续把旧结论展示为现状；受当前权限和界面删除限制的原件不因查看依据重新出现。具备支持条件的判断和仍待了解的部分可以同时存在。

| 自测阶段 | 页面与操作 | 必须保持的边界 |
| --- | --- | --- |
| 选择范围 | 在本空间教材选择章、节及组合，确认想检查的范围 | 父子目录去重；不以学习进度锁定已确认课程内容，不把所有关联 KC 机械视为必测 |
| 准备检测 | 系统依据目标、正式关系、适用历史和题目条件形成计划 | 页面说明在准备题单；无可用题或条件缺失时给出具体缺口，不无限加载或随意编出题数 |
| 开始前确认 | 展示实际覆盖、题数、参考用时，区分本次检查、历史支持及未覆盖部分；范围过大时提出缩小或分次方案 | 孩子决定开始；参考用时不是强制倒计时，没有全部覆盖不能仅显示“本章自测”而隐去限制 |
| 独立作答 | 显示题面、作答区、当前题序与提交状态；提交后确认收到，不透露对错 | 不自动展开旧答案、判分和讲解，不随表现自动加题；尚未提交的输入与已提交作答版本分别保护 |
| 完成或主动结束 | 显示已完成范围，结束后统一反馈；主动结束保留尚未检测的部分 | 技术失败不触发“主动结束”，也不把未做题判为不会；已提交但未处理完的题仍显示处理中 |
| 查看结果 | 对照本次表现、历史依据和剩余不确定性，查看相关题目、解释或可选建议 | 受帮助后完成与独立完成分别说明；答对题单不等于全面掌握，补测只能另行邀请 |

复测与疑点验证可以直接从具体问题进入，不要求重新选择章节。已看过原题不自动禁止重测，但检测页不能再主动展开答案并仍宣称无帮助。回看、输入修改或恢复原提交均不制造额外独立作答，相关版本和发生次序保留。

多题自测或复测中途明确请求提示、讲解等教学帮助时，结束本次独立检测并转入教学。检测开始说明和求助入口应清楚表达这一后果，不让孩子在点击之后才发现测验已结束。保留此前实际作答，已完成部分按原条件形成结果，未做题标为未检测；当前有未完成作答时保留其真实状态，不伪装提交或完成。孩子可在之后自愿另开检测，但新活动不能抹除已经发生的相关帮助。

转入教学后直接回应当前求助，不强迫孩子先翻完全部结果。测试结果仍可回看，正常反馈与请求的讲解均按实际展示记录。输入确认、识别更正和网络恢复本身不等于请求教学帮助，不能机械触发结束；求助后若讲解未实际展示，也不能仅因活动已结束就记录为已获得提示。

### 9.6 理解疑点与系统邀请

系统需要有具体依据才提出验证邀请。例如一次计算答对却没有足够材料判断关键理由，可以说明“这道题做对了，我还想了解你为什么这样算”，并邀请一道针对该疑点的任务；不能把没有解释直接说成不理解。

邀请放在相关结果或首页建议区域，说明验证对象、为什么值得检查、预计任务量与参考用时，提供开始和暂缓选择。它不遮挡书写，也不在独立检测中通过弹窗提前透露对错。不要求每次讲解后都邀请；具体邀请生成及节制规则由 Policy 在后续工程设计中形成，不能用固定频率取代实际价值判断。

接受后进入适用检测或解释性任务，而不是一份泛化知识问卷。作答可使用语言、算式或图示，语音识别和表达不流畅不能单独当成数学能力不足。验证后分别说明疑点得到支持、被削弱或仍缺什么；不能先断言不会，再只选择能够证明该断言的题目。

暂缓或离开保留邀请处理记录，不降低能力判断、不形成欠交任务，也不由后台自动给孩子布置必做题。以后是否再次建议仍取决于当时依据和负担，不将此前拒绝解释为需要加强干预。

### 9.7 跨场景的纠错、恢复与时间安排

题目、讲解和结果中提供返回原件及提出问题的入口。孩子可说明“识别不对”或“这个判断有疑问”，通过局部选择、文字或语音附上有关内容；这些入口帮助定位请求，不用关键词直接裁定错误原因。系统先按既定规则复核，能确认且获准的更正由对应 owner 处理，未决或涉及正式模型时转后台。

| 情况 | 学生应看到和能做的事 | 不应产生的结果 |
| --- | --- | --- |
| 本地已保存，尚未确认接收 | 保留输入，说明尚未完成提交；恢复后先查询原提交 | 不显示已经判题，不让孩子为网络问题重写相同作答 |
| 已接收，处理尚未完成 | 显示原任务状态，允许按相应活动规则离开后返回 | 不重置体验等待计时，不重复评价或因离页自动宣布完成 |
| 显示或播放状态未知 | 核对原结果与发生记录，保持帮助条件的未知部分 | 不自动重播，也不补写“没有得到帮助” |
| 关键内容需要确认 | 在原材料上定位疑点，允许补充或更正；其他可靠结果继续可用 | 不强制重新确认整卷，不把无法识别当作答错 |
| 异议尚在复核 | 说明处理范围及当前状态，不将学生反馈冒充已确认错误 | 不直接修改 Belief，不因有人提出异议就宣告此前结果必然错误 |
| 已确认错误但修复未完成 | 停止把失效结论当现状，说明已改及仍待处理部分 | 不说全部修好，不重置无关判断；必要的实质更正告知仍按 R12 执行 |
| 从当前课程切换到另一课程 | 将原活动与输入留在原空间，新页面读取新空间内容 | 不把原题或聊天材料带入另一空间作依据；切回来不复制一次新活动 |

种子阶段每天全部 DeerMind 活动共用 30 分钟，包括学习、材料录入、纠错、需要孩子等待的时间及纸上完成系统任务。采用 App 自动记录与离页学习少量补记，具体流程见 §12.6；开始新检测时结合剩余安排建议缩小或分次，接近上限提醒，到点保存进度并提示结束。家长监督执行，不增加强制锁屏、学习配额打卡或独立暂停平台；后台任务耗时不能冒充孩子实际投入。

资料删除沿用已经确定的不可恢复界面删除规则，操作前说明将从自己的界面移除的对象、关联影响及内部历史仍用于获准分析。上传资料按原始资料处理，独立题可单独删，试卷按整卷删，详见 §12.3。删除不作为“已掌握”或“清除错误”的按钮，也不能仅在列表隐藏而由搜索、旧链接或新回复重新展示原条目。

## 10. 家长端了解、咨询与更正告知

### 10.1 进入与页面组织

家长使用独立 Android App，以后台创建的家长账号登录。选择当前有权查看的孩子及课程空间后进入概况；即使首批只有一个孩子、两个课程，也明确显示当前对象。没有有效关联时说明尚无可访问对象并指向管理员处理，不提供搜索任意孩子或直接输入学生标识读取数据的入口。

概况、依据、咨询和更正事项都保留孩子及课程的上下文。切换孩子或空间后，新的请求读取所选范围；此前页面和咨询仍属于原对象，不能把原会话材料带入新的孩子或课程。家长可以查看自己的历史咨询，但进入时应清楚显示原对象及当前访问条件。

| 页面或区域 | 家长需要看到的信息 | 可以完成的操作 |
| --- | --- | --- |
| 学习概况 | 当前孩子和课程、结果更新状态、有依据的表现与困难、尚需了解的范围，以及与这些情况有关的支持建议 | 打开具体判断及依据，针对情况询问；选择其他获授权孩子或课程 |
| 判断与依据详情 | 判断对象和适用条件、相关题目与作答、实际帮助、结论限制及是否已更正 | 只读核查必要材料、展开有关来源、从该判断发起咨询；普通资料更正仍到学生端 |
| 我的咨询 | 自己在相应孩子和空间中的问题、回复及获准引用，能够分清咨询解释和正式判断 | 追问、回看或删除自己的交流；不进入其他家长的会话 |
| 更正与处理事项 | 对自己有实质影响的更正说明，既有提报事项的处理状态和当前可看结果 | 查看变化、剩余影响及说明；依现有权限访问相关依据，不直接执行资料修改或模型发布 |
| 账号与关联信息 | 当前账号及有效亲子关联，登录与恢复的必要入口 | 查看关系、退出；需要建立、调整关联或恢复凭据时按后台核实流程处理 |

界面首先提供按需查看和与具体问题有关的解释。是否采用定期摘要、默认时间范围或固定更新提示频率，需要在完整三端信息安排中确定，不能因概况页存在就自动增加日报、周报或产品外推送。实质更正的主动告知已经属于必需功能，按 §10.5 实现，不等待这些可选形式决定。

### 10.2 概况应回答的问题

家长打开概况时，需要知道孩子在什么范围内有怎样的表现，哪些判断可信到什么程度，以及自己可以怎样支持。概况以有效的学习事实和评价为依据，不从“最近错题很多”直接推断能力下降、态度差或校外辅导无效。

每条需要解释的判断至少说明对象、适用条件及可访问的依据。例如“在没有提示时完成了这些同类题，但换一种条件还缺检查”，比脱离条件的“掌握度 80%”更接近系统能证明的内容。例句不建立新的固定能力等级，具体结论仍由 Evaluation 产生，家长端只是按权限呈现和解释。

概况中的近期活动与当前学习判断分别表达。选取一段近期活动用于查看，不意味着只用这段记录重算全部能力；当前判断可依赖更早且仍适用的证据。页面分别标明材料发生时间与判断更新时间。没有近期活动时如实说明，不能把“未使用 DeerMind”当作现实中没有学习或能力退步。

优势、困难和未决可以同时存在。答对与答错是某次作答结果，提示后完成反映当时支持条件，缺少过程可能只意味着无法解释原因。系统正在复核或已知失效的结果须明确区分，不能以旧结论填满概况；只影响一部分判断时，其他有效部分继续可用。

家长可获得与当前情况有关的支持建议，例如如何倾听孩子解释理由、是否值得鼓励她自愿检查某类问题。建议不是已经执行的教学行动，也不保证效果。首版不从家长端向孩子派发必做题、改变学习目标或增加每日学习时长；孩子的全部使用仍受已定安排约束。

### 10.3 从判断回到必要依据

从概况点开一项判断后，详情先说明“判断是什么、在什么条件下成立、有哪些局限”，再列出支撑或挑战它的相关表现。家长可展开原题、有关作答、当时的提示或讲解，以及来源时间；需要原图或录音核实时，在现有相关依据权限内只读访问。

详情不是全部历史档案的入口。题目需要前后页、图表或相关帮助才能理解时，取得这些必要材料；没有关联的试卷、全部聊天、连续录音和另一空间材料不会因一次展开全部开放。哪些来源与当前判断相关仍须按语义规则与授权检查，不能仅因同属一个孩子就把所有数据装入模型上下文。

同一题的原始作答、订正、后来复测及实际帮助分别标明；老师批改、系统复核和家长自己的疑问也不混为同一种结论。管理员模型候选、失败提示词或内部日志不作为家长判断依据页面的默认内容，正式解释仍须引用实际来源，而非展示模型内部思维过程。

学生界面已删除的材料，家长仍可按已确认权限在相关依据中查看，但不能恢复学生条目，也没有通用“已删除资料库”。对该材料的后台纠错不使其重返学生列表；需要告知学生的判断变化可说明结果，而不重新展示其已删除原件。

### 10.4 围绕具体问题咨询

家长可以从某项判断进入咨询，也可在当前孩子和课程内提出问题。前一种入口带入明确的判断引用；后一种在必要时澄清所指题目或范围。系统只使用当前授权且与问题有关的资料解释，材料不足时说明限制，不为给出流畅回答虚构孩子做过什么。

“为什么认为她还需要检查”应回答实际依据和不确定性；“我可以怎么帮”应给适合当前情况的建议。“她其实已经会了”“给她布置十道题”“把这个数字改成 7”不因出现在咨询中成为直接写 Belief、派题或修改资料的授权。普通资料问题指向学生端原材料入口；家长端保持只读，识别替换或图片重传不从家长聊天执行。

对于学生端已删资料的维护例外，家长可从相关依据进入提报，指定对象、问题位置及必要说明，发送前能看清将交给后台的内容。该提报是维护线索，不是已经确认的错误或待执行的修改指令。只关联本事项所需材料，不自动转交整段私人咨询；后台仍按当前事项授权复核，正式更正由相应 owner 完成。提交、已受理、复核中、未决、已修复及部分修复是不同结果，不能把“已提交”显示为“已解决”。

管理员与家长恰好是同一个人时，仍需在管理电脑中用管理账号进入相应事项；家长账号不因此取得模型编辑或后台数据访问权。普通咨询不静默升级为管理员事项，也不自动把家长私人文字转发给孩子或另一家长。

家长在聊天中补充的线下表现，首版只作为家长陈述用于咨询，不进入更新孩子掌握判断的正式学习证据。系统可说明“如果情况如你描述，可以先这样支持”，不能据此对孩子作出已经核实的能力诊断。保存、摘要和后续检索仍保留家长陈述的来源与用途，不能转化为学生在系统中的实际作答。对已有系统记录或判断提出异议仍可按既定路径核查原材料，合法纠错不受影响。

### 10.5 实质更正的告知与后续查看

当讲解、判题或掌握结论被实质更正，应查明哪些已展示结果受到影响，并在产品内向受影响且当前有权访问的用户主动说明。家长概况中的可见提示与事项入口需能到达该说明；仅更新后台记录不算完成告知，也不要求家长主动猜测旧结果是否变化。

| 告知内容 | 必须说清楚的事实 | 不能暗示的结果 |
| --- | --- | --- |
| 涉及对象 | 当前孩子、课程及受影响的原判断或结果；必要的来源时间 | 不披露另一家长的提问，不把所有关联家长当作同一接收者 |
| 原因与变化 | 原来哪部分不准确，依据什么更正，当前可成立的结果是什么 | 不把原来尚未展示的错误说成家长曾见，也不为解释方便编造确定原因 |
| 处理范围 | 哪些记录已更正，哪些相关判断仍在更新或尚未解决 | 不把改对一个识别数字说成所有历史评价都已修复 |
| 下一步 | 可查看当前结果、有关依据或处理状态；必要时继续询问 | 不要求家长重做孩子的作答，不自动播放旧教学或给孩子派发补做任务 |

例如系统曾因把手写的 7 识别为 1 而形成错误反馈，后来已确认识别错误，但相关学习判断仍在重算。家长应看到“原记录已更正，相关学习判断还在更新”，并能查看目前可用依据，而不是马上得到“孩子已经掌握”的保证。该例是说明界面行为，不是本项目已发生的案例。

纯排版调整、未展示候选修正及未实质影响理解的措辞修改不生成学习结果纠错告知。告知形成、实际呈现与用户是否理解分别记录，不用点击或停留时间证明理解。再次进入事项时既保留这次更正说明，也能辨认当前结果，后续修复失败或完成不得隐藏在一个过时的“处理中”标记后。

通知和历史引用都受当前访问权限约束。已撤销关联时，不通过通知摘要、旧链接或新回复继续披露该孩子的资料。家长咨询中曾引用的判断后来失效，也不能被当作当前依据复述；需要回看历史时保留其当时语境及适用的状态说明，而不把旧回复静默改成从未发生过错误。

### 10.6 私人咨询与异常恢复

每位家长的咨询在各自身份与相应对象范围内保存，孩子和其他家长默认不可见。共同有权查看一项学习事实，不代表能看到对方的问题、措辞或聊天摘要。两个家长依据同一获准事实得到相似回答不等于串用，验证应核对实际检索、来源和模型上下文。

家长按整段会话删除自己的咨询，首版不支持删除单条消息，无需管理员审批，无回收站或恢复入口。确认后提问、回复及相关展示一并移除，列表、搜索、旧链接、摘要和新回复不得重现被删交流。内部保留不冒充物理销毁，也不因删除咨询撤销孩子已有事实、当前有效判断或已提交的独立后台事项；事项可以继续处理和告知结果，但不能借此恢复私人咨询，具体见 §12.3。

页面加载失败、引用失效和权限变化需要分别说明。网络断开时保留尚未发送的问题，恢复后核对原请求，避免重复提交咨询或后台事项；不能以查询失败为理由重用已知失效判断。正在显示的内容应能标识其更新时间，后续请求和刷新继续检查有效授权。

家长账号退出或失效后重新认证，恢复凭据不新建孩子档案，不合并自己与其他家长的交流。关系解除后停止相应读取与新回复中的引用；其他仍有效的亲子关系按各自授权继续可用。客户端缓存及历史引用的技术清理、会话期限与重连实现由 Phase 5 在这些可见性要求内设计，不能以本地已有副本绕过撤权。

### 10.7 验收与剩余交接

| 路径 | 必须检查的用户结果与边界 | 已有验收依据 |
| --- | --- | --- |
| 概况到依据再到咨询 | 能理解有条件的判断，找到相关原题、作答及帮助；家长线下转述不经咨询、摘要或检索变成孩子的正式学习证据，已有错误复核仍可用 | P01–P02、A11、A72；V03、V04、V09 |
| 孩子、课程与家长身份变化 | 切换后对象明确，另一空间或另一家长会话不进入上下文，撤销关联后阻止相应访问 | A04、A46、A49、A51–A52、A70；V03、V09 |
| 只读与后台维护例外 | 家长请求不能修改普通资料；已删资料按具体事项提报、复核并处理，不恢复学生条目、不直接改 Belief | A13–A14、A59、A61–A64、A71–A72；V03、V09、V11 |

家长开户、关联可见及恢复流程见 §12.1–§12.2，首次告知与确认见 §12.4，整段咨询删除见 §12.3。概况时间范围与信息更新安排仍需确定，并在实际手机上检查显示与可用性；数据使用授权撤回功能留后续。线下转述的证据边界已按 §10.4 确定；教材、领域参考与 G4 条件不因家长端草案完成而省略。

## 11. 管理员处理反馈、故障与模型配置

### 11.1 后台工作入口

唯一管理员通过电脑 Web 和独立管理账号进入后台。教材与领域维护分别沿用 §8 和 §4；运行与质量事项、模型连接和用量提供独立入口，避免将服务配置与正式领域模型编辑混为一谈。后台提供完成既定任务所需的工作台，不要求建设通用运维平台或所有语义模型的在线编辑器。

| 工作入口 | 列表中需要的信息 | 打开后完成的任务 |
| --- | --- | --- |
| 内容与领域维护 | 所属空间、教材或对象、准备及审核状态、未决范围 | 按 §4、§8 核查材料、准备候选、验证及限定发布 |
| 反馈与质量事项 | 具体问题、来源、对象、处理状态及影响是否已确认 | 核对授权范围内的来源和判断，区分记录问题、模型问题或仍需了解的情况，执行适用维护 |
| 失败任务 | 原任务、失败步骤与时间、尝试记录、是否已有提交或展示结果 | 核对状态，重试合法的未完成步骤，或转交相应维护；不重建学习事实 |
| 模型连接与能力配置 | 已保存和当前生效配置、用途、可用性检查、适用能力及失败状态 | 更新配置、检查连接与合同适用性，在允许范围启用或恢复配置 |
| 用量与费用 | 期间、用途、调用及失败重试、可得用量、费用依据和未知项 | 判断成本来自何处，回到相关任务检查异常，区分日常使用、内容准备和内部检查 |

事项列表显示处理所需摘要，不因管理员身份直接展示所有孩子的题面、录音或私人交流。进入具体事项后再取得相关材料，并记录访问目的、对象与操作。管理员主动发起质量复核也要明确对象和问题，不能用一个空泛的“检查质量”事项长期取得无关数据。

### 11.2 反馈与质量复核

学生提出的异议先经过已批准的自动复核；未决、冲突、需要正式模型修改及已删资料维护进入后台。系统运行留下的失败或覆盖线索可由管理员选择处理。进入列表并不表示已确认错误，更不直接成为 Evolution 的 System Issue；家长转述的线下表现也不能借后台登记绕过 §10.4 的咨询用途限制。

事项详情先给出原问题及对象，再呈现相关材料和处理轨迹。管理员应能从原题或实际作答查看对应 Observation、Evidence、Belief 与所用模型版本，核查实际帮助、检验结果及当前有效性；缺少某一步就如实显示，不能用推测日志拼成一条已成功的链路。这里展示可审计输入输出与说明，不要求读取模型内部思维过程。

| 核查结果 | 处理路径 | 完成时必须能辨认的结果 |
| --- | --- | --- |
| 原始材料能够确认识别或记录错误，且属于现有规则与授权范围 | 由相应 owner 更正记录，处理实际依赖；管理员核查结果，不直接改掌握标签 | 原记录、更正依据及替代结果可追溯，失效状态已处理，未完成或失败部分可见 |
| 题意、解法、映射或正式领域定义有问题 | 进入 §4 的领域维护与基础演化，必要时先停止使用已确认失效的依据 | 候选、验证、批准、生效和历史影响分开；未批准候选不进入当前评价 |
| 评价、交互或推理规则需要修订 | 形成具体问题及工程维护材料，经 §11.5 的受控版本交付处理 | 不用修改 Task/KC 或直接填 Belief 掩盖其他模型问题，工程修订仍有验证与作用范围 |
| 调用、格式、任务执行或存储处理失败 | 转入 §11.3 的运行恢复或工程修复 | 保留真实失败及重试，不把故障计作语义错误、正常未决或孩子能力不足 |
| 未发现错误、材料仍不足或存在冲突 | 保留依据，分别记录无须更正、待补充或未决，并说明影响 | 不为关闭事项编造原因、强制改结论或宣布全部解决；将来有新材料仍可关联处理 |

具体按钮应说明作用，例如核对来源、提交记录更正、进入领域维护、登记规则问题、查看受影响结果；不使用一个包揽所有含义的“修复成功”。相关语义原因由规则与 LLM 辅助判断并保留依据，不能仅凭错误码、关键词或管理员选择的分类证明根因。

维护结果同时检查记录、依赖判断及用户告知。更正已经完成但部分评价尚未恢复时，事项不能显示“全部处理完成”；实质改变已展示结果时按 §10.5 及 R12 告知受影响用户。没有实质变化、不需要改动或仍待材料也可以结束当前处理，但结束处理不代表问题已被证实解决。

### 11.3 故障核对与有限重试

管理员从原失败任务查看提交、执行尝试、正式提交与展示记录。一次用户输入可能有多次技术尝试，不能在列表里把它们显示成多次学习作答。先检查上一步究竟完成到哪里，再决定恢复方式；调用无响应不等于服务端未接受，展示回执丢失也不等于没有发生帮助。

可重试的处理仍关联原任务，只执行获准且尚未完成的步骤。依赖或权限已经变化时，先按当前合同检查并重新取得适用输入；不能偷偷使用失效旧状态。原来已经提交的结果不重复提交，原题不重复归集为新的独立证据。教材导入恢复后继续其审核流程，不因重试成功直接发布。

已结束、中断或不再具备执行资格的学习活动不能由管理员的重试按钮恢复教学派发。仍需补做的后台维护可以按自身授权继续，但不能向孩子自动重放旧讲解。外部动作或显示是否发生尚不明确时，保留未知并按执行合同核对，不盲目重复。

每次尝试记录结果、失败类别、配置与必要版本、投入和剩余处理范围。允许的自动或人工重试需有有限次数、时间或其他停止条件，由 Phase 5 按具体任务冻结；到达上限后说明失败及下一步，管理员不能通过重新建同一任务掩盖无限重试。当前不预选所有任务共用的超时数字。

### 11.4 模型连接与能力配置

配置页面允许管理员维护服务标识、端点、模型标识、凭据和允许承担的用途，并查看当前生效配置。文本推理、图片理解或语音处理是否由同一服务承担，按工程方案决定；不能仅因一个模型能回答文字问题就把所有入口都标为可用。

凭据只在必要输入中提供，日常列表和错误说明不回显完整密钥，也不进入学生或家长界面。未修改凭据时引用已有配置，不因表单掩码被保存而覆盖为假的密钥；具体安全存储由工程设计完成。服务配置记录变更及作用范围，学习历史引用实际采用的配置，不因更新配置改写过去。

| 检查或状态 | 管理员能确认什么 | 不能据此宣称什么 |
| --- | --- | --- |
| 配置已保存 | 必需配置项已记录，格式满足接收条件 | 不表示网络、凭据或模型调用已经可用 |
| 连接与鉴权检查 | 指定服务在所记时间和条件下能够访问 | 不表示支持所需图像、结构化输出、工具或其他执行合同 |
| 任务能力检查 | 所选配置能满足指定用途的必要输入输出及协议条件 | 不表示数学、解释、判题或 Evidence 推断的语义质量已通过 |
| 已有质量验证资料 | 可查对应模型、规则、范围与样本的实际验证结果及限制 | 不把其他模型或旧配置的通过结论挪用为本配置保证 |
| 限定启用与恢复 | 哪个配置在什么用途和范围已实际生效，或恢复到了哪个适用配置 | 不表示自动重算全部历史，也不允许未检查的备用服务静默接管 |

连接与能力检查使用明确的合成检查材料，保存检查结果、配置和用量，不默认发送真实儿童学习资料试接口。更换外部模型服务也是改变数据处理目的地，仍受既有用途、数据类别和授权约束，见 [AI Runtime §7.9](../../system-design/DeerMind_AI_Reasoning_Runtime_Design_v1.0.md#79-外部模型-provider-是-data-processing-destination)；管理身份及连接成功不产生额外数据披露权限。

管理员能区分测试配置与实际使用配置，保存改动不静默替换正在执行请求的依赖。启用或恢复遵守适用合同和一致性边界；不能为保证调用成功而降低原协议要求，或暗中换用另一模型承担原语义任务。具体配置版本、请求绑定、适配器和检查接口在 Phase 5 设计，本节不预先锁定供应商、框架或数据库。

### 11.5 其他语义模型的受控交付

评价、交互和推理规则的修改从工程维护形成候选交付资料。后台可以接收并查看候选版本、来源、准确基础版本、变化说明、适用范围、验证结果、依赖影响和恢复条件；不要求管理员在网页里编辑任意语义规则。候选资料的文件或登记接口由工程设计确定，不能用“后续手工改库”代替交付入口。

管理员在同一审核流程中对照当前与候选版本，确认验证覆盖及未决后批准明确范围；对应 owner 检查并提交，再按授权启用。若基础已改变、授权不匹配或必需检查未通过，应展示具体冲突并保持候选未生效。发布后的实际采用与历史影响沿用 §5；同一个人可以完成管理步骤，不要求第二位管理员。

此入口与领域维护共享版本差异、审核记录、生效及影响查看能力，但保留不同模型的语义 owner。更换 API 地址不等于发布新的评价规则，发布评价规则也不直接改写某个孩子的掌握程度。需要历史重算时必须说明受影响范围、依据与实际结果，不设未经检查的一键全量“变好”操作。

### 11.6 用量、费用与验收

用量页面按所选时间、任务用途及模型配置查看实际调用、处理耗时和可获得的 token 或其他计费单位。日常学习、教材准备、配置检查、重试和维护分别可追溯；管理员能从异常费用回到相关任务，而非默认打开其全部原始学习内容。金额如依据价格计算，应标为估算并保留计价依据；服务未返回用量或计费口径不明确时显示未知，不填零或把不同配置的价格混算。

当前用户未设固定预算金额，因此本设计不自行增加预算阈值或自动停服规则；实际费用与管理员投入继续记录，工程实验和重试仍须有限。具体验证样本、价格来源、计费精度和用量同步由对应阶段落实，连接检查与失败调用的投入不从账目中消失。

| 验收路径 | 应有的实际证据 | 已有覆盖 |
| --- | --- | --- |
| 反馈定位到适用维护 | 可回查原材料、判断、版本与帮助，区分记录错误、模型问题、运行故障及未决；更正与残余影响真实可见 | M02、M05，A05、A24–A25、A62、A71、A73–A74；V03、V09、V11 |
| 失败任务恢复 | 原任务及多次尝试可追溯，不重复事实、展示、归集或发布；权限及依赖变化后合法停止或重新取材 | A12、A65–A69；V03、V08–V09 |
| 配置保存到有限启用 | 无效凭据、服务不可达、能力不匹配和可用配置分别表达；检查与实际启用可区分，不隐式降级合同 | M03、A15；V03、V08–V09 |
| 其他模型版本交付 | 实际候选与验证资料进入审核、owner 提交、生效及影响检查，覆盖基础冲突和未授权拒绝 | M06、A19–A22；V11 |
| 用量及访问边界 | 失败和检查成本不遗漏，未知费用如实呈现；任务追查不能绕过具体事项、角色和对象授权 | M03、M05、A14–A15、A71；V03、V08–V09 |

以上交互用于准备工程实现和内部验收，不代表已经建立后台服务或完成运行测试。账号开户、亲子关联、系统外人工核实及恢复见 §12.1–§12.2；首次确认方式已定，数据使用授权撤回功能留后续，不新增后台代办。Phase 4 不因已有事项页面草案而提前通过 G4。

## 12. 开户、关联、数据管理与使用时间

本节把已确认的角色权限落实到三端之间的操作，区分可直接细化的流程与仍需讨论的产品取舍。账号开通、亲子关联、数据使用授权和设备权限分别表达；其中一项成立，不自动使其他项成立。学生与家长只使用各自 App，管理员在后台完成已经纳入范围的维护。

### 12.1 开户与亲子关联

管理员从“账号与关联”进入，先核对目标人员、已有账号和学习者档案，再创建缺失部分。恢复旧账号、增加另一位家长或更换设备都不建立第二份学习者档案。首批两个课程空间分别配置与开放，账号创建成功不表示教材或学习功能已经准备完成。

| 操作 | 页面需要的输入与检查 | 可见结果 |
| --- | --- | --- |
| 创建学生账号 | 对应学习者档案、账号名及登录凭据设置；若已有档案，明确关联原档案 | 后台区分账号已建、课程已准备与可开始学习；孩子无需手机号，不开放自助注册 |
| 创建家长账号 | 家长本人及账号信息，不能借用管理员账号 | 家长 App 登录身份独立；账号尚无有效亲子关联时，不显示任何孩子的数据 |
| 建立或调整关联 | 明确是哪位家长、哪个孩子、允许的查看范围及核实结果；操作前能核对对象 | 生效后家长可选择该孩子，双方账号页可查看当前关联；不是向家长开放全部学习历史或赋予资料编辑权 |
| 解除一段关联 | 明确目标关系及受影响范围，提示其他关系和学习档案不随之删除 | 显示解除是否已经生效；此后相关读取、检索与模型引用停止，另一段有效关联照常工作 |
| 查看当前关系 | 孩子看到哪些家长与自己关联；家长看到自己可访问哪些孩子 | 关系是当前状态，不以旧通知代替；双方可发现错绑并联系管理员核对 |

家长首次进入无关联、内容尚未开放或请求失败时，应分别说明原因，不能统一显示为孩子没有学习记录。关联变更后仍停留在原页面的家长，也不能继续通过刷新、旧链接或新提问取得已撤权范围内容。是否已经完成生效核对应可查，不以点击成功代替权限实际变化。

首批身份、亲子关系及找回账号采用已确认的简化方式：项目发起人以管理员身份在系统外人工核实本人和关系，在后台记录对象、核实方式、结果、操作范围及时间，再执行开户、关联或重置。记录用于追溯本次操作依据，不新增证件上传、自动身份认证或第二人审批。尚未核实不能仅凭知道孩子姓名执行绑定；系统外核实也不代替后台实际生效及结果检查。

### 12.2 凭据恢复与关联解除

学生或家长无法登录时，从各自登录页取得找回说明，向管理员说明原账号；管理员在后台找到目标账号和既有档案，按 §12.1 在系统外核实本人，记录结果后重置凭据并查看是否成功。重新登录继续原有、仍有效的权限与记录，界面已删材料保持隐藏，家长私人咨询不与他人合并。核实未完成或对象有歧义时保留待处理，不另建一份账号和历史来绕过问题。

管理员自身无法登录时使用独立的管理恢复方式。该方式在部署时必须准备并在内部验收中实际验证，具体凭据、安全存储和失效处理由 Phase 5 设计。家长账号、亲子关系或能说出孩子资料，都不是恢复管理权的替代凭证；首版不要求第二位管理员才能恢复。

| 变化 | 应处理的范围 | 不应被误解成的结果 |
| --- | --- | --- |
| 退出或凭据失效 | 停止当前登录会话的访问，按相应身份重新认证 | 不删除档案，不撤销实际发生的学习或帮助 |
| 亲子关系解除 | 停止该关系授权的读取、相关上下文及新回复引用；保留关系变更记录 | 不解除其他家长的有效关系，不删除孩子的档案与学习历史 |
| 学生删除上传资料 | 按 §12.3 移除学生端相应资料及关联展示 | 不因删除自动解绑家长、清空能力判断或撤回内部获准使用 |

关系解除后，服务端访问检查和后续检索、模型上下文及回复呈现必须按当前关系执行，不能只隐藏孩子入口而继续用旧关联读取。学习数据使用授权撤回按 §12.4 留待后续，不属于本节的首版账号与关联操作。

### 12.3 学习资料与家长咨询的删除

**已确认按原始资料删除。** 一道独立上传题是一个删除对象；作为整份试卷上传并管理的资料是一个删除对象，无论包含多少页、多少道题。整卷中的题在错题本里有独立入口，也不因此取得独立删除粒度。此规则不限制日常识别更正和判题复核，更正一题无需删除整卷。

| 起点 | 确认前应说明什么 | 完成后的学生端结果 |
| --- | --- | --- |
| 独立上传题 | 题目身份及其原作答等关联材料；删除后自己不能恢复 | 题目和本次原作答不再从列表、详情、搜索、旧链接或新回复取得 |
| 整份试卷 | 试卷身份、所属课程，整卷及关联错题和原作答一并移除 | 试卷入口和由它归集的错题入口同时消失，卷内题不能经其他页面重新打开 |
| 从卷内错题发起 | 先说明该题属于哪份试卷，首版只能删除所属整卷，再进入明确的整卷确认 | 取消则无变化；不能以“删一道错题”的确认实际删除整卷，也不能只隐藏错题入口而留下同题原卷入口 |

确认页简明说明：“删除后，你不能再从自己的界面查看这些资料，也不能恢复。系统内部仍保留学习记录，用于获准的学习分析；已关联家长仍可能在相关学习依据中查看。”这里的家长权限没有增加，只把已定规则在执行前说清楚。因当前操作可能影响整卷，不采用无提示的一键删除。

讲解、作答回顾和掌握依据中的原资料引用同步遵守删除结果，不能留下缩略图、题面摘录或可打开的旧链接来恢复原件。删除期间尚未完成的分析、错题归集和后续重处理，也须保持这一限制。请求是否已被服务端接受不明时，界面显示处理中或待核对；恢复后核对原删除操作，不能先宣称完成后又把条目显示回来。

整卷删除不连带删除其他独立上传资料或之后独立发生的练习，但这些记录同样不能重新展示被删原件。内部仍可按有效性和当前授权使用原有 Evidence 与 Belief，在同一知识范围提供其他适用任务；不能把删除转化为“已经学会”“从未求助”或“需要重新做一遍”。家长相关依据查看和管理员按事项纠错继续遵守 §10–§11。

家长咨询已确认以整段会话为删除单位，不支持单条消息删除。家长从自己的咨询列表或会话详情选择删除，确认页明确所选会话及“全部提问与回复将从你的界面移除，不能恢复”，并说明不影响孩子资料或已提交的独立后台事项。确认后删除限制同时覆盖搜索、旧链接、摘要和新回复，正在生成的回复不能在删除后重建该会话；接收未知时核对原删除操作。

独立事项保留自己的状态及处理结果，可以按原有权限继续办理和告知。事项页不再提供恢复已删会话的链接或整段转录；后台为该事项已经合法取得的必要材料仍按具体事项和用途使用，不因会话删除扩大读取范围，也不把删除咨询当成撤回事项。学生其他独立会话或系统出题活动的删除对象仍需各自确定，不能自动套用家长会话规则。

### 12.4 首次告知与数据授权

首次使用方式已确认：首批由项目发起人以家长身份确认孩子学习数据的用途、可见范围、保留方式及实际使用的外部模型服务；孩子端提供简明说明，并由孩子确认愿意使用。管理员核实、家长授权与孩子的参与确认分别留痕，同一个人兼任家长和管理员也不合并身份。必要确认完成前不启动真实学习资料的接收与分析，不能先上传、先调用再补授权。

家长确认页显示对应孩子、实际课程范围、数据类别与用途、哪些角色在何种条件下能看、保留及界面删除规则、实际外部模型服务和相关用途。确认记录绑定当时的说明版本和范围，账号页可回看。家长确认完成但孩子尚未愿意使用时，保留待确认状态；孩子不愿意不作为学习能力反证，也不以默认勾选、一次登录或家长代点声称孩子已经同意参与。

| 时点与对象 | 必须说明的实际内容 | 可继续操作的依据 |
| --- | --- | --- |
| 孩子首次进入 | 可以怎样求助和退出；系统会出错、可以更正；谁能看相关学习资料；已提交内容会保留；界面删除并非内部销毁 | 家长必要授权已完成，孩子得到简明说明并确认愿意使用；缺少任一项时说明尚待谁确认，不处理真实学习资料 |
| 家长首次进入 | 对应孩子和课程、数据用途与类别、相关依据可见性、保留方式及实际模型服务，另说明自身咨询边界 | 首批由项目发起人的家长账号明确确认并留痕；关联家长查看权不自动扩张为替孩子作出数据授权，确认也不取得管理身份 |
| 首次使用照片或录音 | 当前用途、提交前可检查或取消、发送后的保存与访问规则 | 设备权限与产品数据授权分别满足；取得麦克风权限不表示可以持续录音 |
| 管理员准备实际模型服务 | 哪些用途会向哪些实际服务传送何种材料、适用授权及当前配置 | 不能把“可能使用外部 AI”当作向任何目的地发送儿童资料的授权；合成连接检查与真实资料使用分开 |
| 数据用途或接收范围变化 | 明确发生了什么变化、影响哪类数据和功能、当前尚未取得的授权 | 依实际授权合同重新检查，不凭既有登录、配置保存或一次旧确认自动扩展 |

面向孩子的说明应使用具体语言，例如：“你点提交后，题目、作答和发出的录音会被保存，用来帮助你学习。和你关联的家长可以查看相关学习依据。删除后你不能再从自己的界面找回，但内部记录还会保留。讲解可能有错，你可以提出问题；不想继续时可以结束，也可以不接受自测邀请。”实际界面需分段结合当前操作呈现，后续仍可从账号与说明入口查看，不要求每天重复确认。

以后每次打开 App 不重复首次确认，保持登录仍检查授权是否有效。用途、可见范围或实际服务范围改变时，比较是否超出已经确认的范围；新增部分需要相应授权，尚未取得前不按新范围处理数据，不能仅因配置连通而静默切换。说明版本、确认与生效范围分别可查；单纯重登或在获准范围内重试不要求再点一遍确认。

**MVP 不提供学习数据使用授权撤回功能，留待后续阶段设计与实现。** 首版不建设家长端撤回入口、管理员代办或配套撤回处理流程，也不把它留作 G4 待决项或 MVP 验收项。首次告知、实际范围确认、当前权限检查及亲子关系解除继续执行；资料界面删除仍按 §12.3 处理。这一产品范围调整不改写 Core 的通用权限有效性与失效处理合同，但不要求本次实例化完整的数据授权撤回场景。

首批授权角色已定，不能据此给全部关联家长相同权限。外部服务的具体选择随工程方案确定，必须在真实数据处理前填入实际说明和确认范围，说明中不承诺首版尚未提供的撤回功能。这一产品流程不等于已经完成实现、真实家庭确认或 Pilot 准入，实际使用仍按既定阶段核对。

### 12.5 Product Context 的权限来源

按 [Interaction Space §4.5](../../concept-design/DeerMind_Interaction_Space_Design_v1.1.md#45-外部输入requestconstraintobligation-与-authority-directive)，以下把首版已定行为映射为 Request、Constraint、Obligation 与 Authority Directive 的来源和范围。表格只说明当前产品授予的能力，不创建一个通用权限编辑器；首批数据授权主体按 §12.4 单独确定，不从一般家长查看关系自动推导。

| 来源与输入 | 当前允许的作用 | 范围、终止与责任边界 |
| --- | --- | --- |
| 学生提交题目、求解释、自测或复习请求 | Request，由相应处理与 Policy 判断如何回应 | 当前孩子、当前课程和具体活动；结束活动不抹去已发生事实，也不授权新的自动教学 |
| 学生选择仅提示、结束活动或拒绝邀请 | 收紧当前帮助及活动范围，保留其继续学习的选择 | 后续请求可以明确改变帮助方式；拒绝不作为能力反证，不要求完成额外检测才能离开 |
| 家长查看与咨询 | 当前关系授权内的只读 Request，线下转述只用于咨询 | 不直接写 Evidence/Belief，不派任务、不改学习目标；关系解除后不能继续引用该范围资料 |
| 每天全部 DeerMind 活动最多 30 分钟 | 已确认的产品使用 Constraint，影响学习安排与剩余时间说明 | 跨课程和会话累计；不是必须用满的 Obligation，不把时间限制改写为孩子的学习目标 |
| 管理员开户、关联、故障处理与正式模型维护 | 已授予范围内的管理操作；正式模型候选按 Governance 授权和 owner 提交 | 对象、事项、范围与结果可追溯；不能直接写能力结论，不能绕过 Policy 自动派发学习活动 |
| 首批由项目发起人以家长身份作出的数据授权 | 在其实际有效范围内约束读取、处理与披露，孩子的知情参与另行确认 | 保留对应孩子、用途、类别、接收范围及说明版本；配置成功、管理员身份和普通聊天都不替代它，数据使用授权撤回功能留后续 |
| 学校或辅导班的作业、进度和考试要求 | 在已知来源下作为相关学习背景，必要时澄清 | 首版没有教师客户端或任务指派入口；上传试卷或提到老师要求，不自动建立可强制执行的外部 Obligation 或 Directive |

所有外部输入保持来源可见。具备管理或其他合法 authority 可以收紧允许范围，但不替代 Evaluation 的认识责任，不使管理员、家长或外部要求取得无限教学控制权。学习内容与判断仍按两个课程空间隔离；仅为执行共同用时上限累计活动时长，不取得跨空间使用学习证据的权限。

### 12.6 每日使用时间

已确认上限是孩子当天全部 DeerMind 活动合计 30 分钟，正常求助、复习、自测、录入、纠错、占用孩子的等待及纸上完成系统任务都在内。后台独自处理、家长咨询和管理员维护不计入孩子用时；不要求每天用满，不为补齐验证样本加时。显示用时、安排下一项活动及保留进度必须采用同一口径，不能分别给两个空间各 30 分钟。

**已确认采用 App 自动记录与少量补记。** 系统记录学生 App 内使用区间，包括看题、思考、作答、听讲及占用孩子的等待，不能把短暂没有触摸直接算成休息。离开 App 后继续在纸上完成 DeerMind 任务的时间，在返回时简短确认并补记；家长监督总量，不需要每天另填一份重复台账。

| 情况 | 记录与交互 | 对总量的影响 |
| --- | --- | --- |
| App 内学习、录入、纠错或需要等待 | 自动记录使用区间，正常看题思考不要求持续操作来证明活跃 | 按实际记录累计，不能只统计模型运行或笔迹输入时间 |
| 离页后继续纸上学习 | 返回相关活动时可确认刚才是否继续学习及大约用时；无需逐题补记 | 补记标明来源，只有未被自动记录的部分加入总量；未确认不默认为零 |
| 只等后台处理，孩子已经离开 | 任务照常保留状态，处理完成后再查看 | 后台独自处理时长不计入孩子用时；孩子回来查看或纠错的时间计入 |
| 离页期间已有可记录的学习活动，例如继续播放讲解 | 结合实际活动记录核对区间，补记时说明已经计入的部分 | 与补记去重，不把同一段听讲和纸上作答时间相加；播放记录不证明听懂 |
| 用时缺失、来源有重叠或同步未完成 | 区分已记录、补记和待核对，不虚构精确总量 | 缺失不能计为零；重复提交同一补记或重连不重复累计 |
| 接近或达到 30 分钟 | 提醒剩余安排；到点保存进度并提示今天结束，由家长监督 | 不强制锁屏，也不新建另一空间的额度；实际超时如实保留，不截断成 30 分钟 |

学生端提供当日总量及必要的补记核对，家长可结合学习概况监督，不借计时取得修改孩子学习资料的权限。补记是用时陈述，不是某道题已完成或已独立掌握的证据；不据此补造作答、帮助或参与结果。提醒、补记本身的操作负担也在体验观察内，不能为求计量精度要求孩子反复报时。

时间到点后的输入保留、尚未完成检测的部分结果和后台任务继续状态沿用既有恢复规则，没有完成的题不标为答错或不会。记录方式明确后，由 Phase 5 确定计时事件、去重同步、异常恢复及提醒配置；内部验收覆盖离页、重连、跨空间累计和补记，不将提醒功能通过写成每天使用一定不超时。

### 12.7 跨角色验收与待定事项

| 流程 | 必查结果 | 既有验收覆盖 |
| --- | --- | --- |
| 开户、关联与解除 | 账号、稳定档案及关系分开；多对多切换不串用，双方可见当前关系，旧登录不能绕过撤权 | A47–A53；V03、V09 |
| 恢复凭据 | 核实对象后恢复原身份及有效权限；管理员恢复独立，历史与界面删除状态保留 | A47、A50、A53；V03、V09 |
| 独立题与整卷删除 | 确认实际对象及影响；卷内题不单独删除，关联错题、原作答、旧链接与新回复遵守删除；后台处理不恢复 | A60–A62、A64、A74；V03 |
| 家长整段咨询删除 | 不支持单条消息删除；摘要、新回复及事项页不恢复会话，孩子资料及独立事项不受连带删除 | A63、A70；V03、V09 |
| 首次告知与实际授权 | 系统外核实及后台记录可查；家长范围确认与孩子愿意参与分别记录，缺少必要确认不处理真实学习资料；登录、关系与授权不互相替代 | R17–R18、R24、A48–A50、A59–A64；V03–V04、V09，不含已延后的数据使用授权撤回功能 |
| 当日时间与未完成活动 | 自动记录、离页补记、重复提交、跨空间累计及未知可核对；提醒、进度保留与实际超时如实呈现，不伪造能力结果 | R13、R16；V04、V08 |

家长咨询粒度、每日记录方式、首批身份核实和首次确认已确定，数据使用授权撤回功能已明确移出 MVP。当前待讨论的是其他学生资料的删除对象，以及 §10.1 的家长概况时间范围和信息更新安排。它们影响实际体验或权限，不能统一标为“工程自行决定”；数据库字段、密码机制、缓存处理和计时实现则在产品合同确定后进入 Phase 5。

## 13. 决定状态与 Phase 4 交付安排

**已确认：课程范围内尚未学到的内容允许求助。** 超纲依据已确认课程范围判断，学习进度不锁定章节讲解；已有基础用于调整解释和建议。此决定已纳入 Definition §6 与 A75，不免除内容质量和具体求助的必要条件，也不意味着支持范围自动扩展到所有小学数学。

**已确认：试卷确认错题自动归集，多题自测求助结束本次检测。** 前者保留原卷来源及判题依据，未作答、识别不清和争议题不混作已确认错误；后者保留已有表现，将未做题标为未检测，再回应讲解。之后可以另开检测，仍考虑实际帮助。两项决定落入 R01–R02、R04、A08、A35、A69，具体交互见 §9.2、§9.3、§9.5。

**已确认：家长咨询中的线下表现转述仅用于家长咨询。** 首版不将其纳入更新孩子掌握判断的正式学习证据；对系统既有记录或判断提出异议仍走已定复核路径。陈述的保存、摘要与检索不得改变其来源和用途，不把私人咨询变成间接的学习表现录入入口。决定落入 Definition §4、需求规格 §6、A72 与 V09，见 §10.4。

**已确认：上传资料按原始资料删除。** 独立上传题可单独删除，试卷按整卷删除并同步隐藏关联错题及原作答，不支持卷内单题删除。删除前明确范围，引用及后台重处理不能恢复学生端原件；有效获准的内部依据和家长相关依据权限保留。决定落入 Definition §4、R24、A61 与 V03，交互见 §12.3。其他对象的粒度不因此自动确定。

**已确认：家长咨询整段删除，每日时间自动记录并少量补记。** 咨询删除不撤销独立后台事项，也不允许借事项或新回复恢复会话；用时跨空间累计，区分自动、补记与未知，提醒并保存进度，由家长监督，不强制锁屏。决定落入 R16、R24、A63、V08–V09，流程见 §12.3、§12.6。

**已确认：首批人工核实，家长授权与孩子参与确认分开。** 管理员在系统外核实本人和关系、后台留痕，不增加证件上传或自动认证；项目发起人以家长身份确认实际数据用途、范围和服务，孩子确认愿意使用。必要确认前不处理真实学习资料，不要求每次打开重复确认；范围变化重新检查授权，见 §12.1–§12.4。

**已确认：MVP 不提供学习数据使用授权撤回功能，留后续优化。** 家长端入口、管理员代办及配套处理均不进入本次设计和验收；已确认的首次授权、亲子解绑和资料界面删除各自保留。该项不再列为 Phase 4 待讨论或阻塞项，已同步至 Definition §4、D04、R18、需求规格 §6 及验证方案 §1。
