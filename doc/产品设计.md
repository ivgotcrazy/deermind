## 2. 产品定位与设计原则

### 2.1 产品定位

- **形态**：私人工具，唯一核心用户是创始人的女儿（2026 秋季升入六年级）。
- **MVP 主线**：数学错题闭环（拍照 → OCR → 归因 → 讲解 → 变式验收 → 间隔复习）+ 读题训练（应用题专项）。
- **使用场景**：每天放学后 15–30 分钟，单次闭环 1–2 个知识点，可中断恢复。

### 2.2 设计原则（继承概念文档四条红线）

1. **家长零强制投入**：产品默认零录入、零操作即可良好运转；家长录入为可选增值（老师评语、观察、补充教材）。
2. **教育结论必须严谨**：禁止"一次做对 = 已掌握"；掌握度必须是时间维度上的状态机；讲解绑定教材来源。
3. **低风险技术优先**：MVP 不深度评判孩子的讲解（软性验收），深度评判推迟 V1。
4. **产品自己跑**：家长参与度分三档，任何一档都能独立运转。

### 2.3 本版已确认的关键决策

| 决策项 | 结论 |
|---|---|
| 教材版本 | 多版本支持：人教版 + 北师大版（学校教材）+ 辅导班教材（学而思/奥数/思维） |
| 知识点建模 | 版本无关的知识点本体 + 教材目录映射（人教/北师大/辅导班专题） |
| 起步范围 | 六年级上册第 1 章（人教版：分数乘法；北师大版：圆），实际学校版本在"一次性配置"时确认 |
| MVP 交互 | 文字 + 语音输入（ASR）+ 讲解朗读（TTS） |
| 部署方式 | 轻量云服务器（约 2C4G），数据上云 |
| 家长端 | 与孩子端同一 Flutter App（双角色：孩子端 / 家长模式，PIN 保护），Android 侧载 APK；微信小程序因需备案推迟到后期 |
| 题目来源 | 预置少量题库（基础练习）+ LLM 按"三不变一变"生成变式 |
| 学习空间（基础模型） | 每学期/任务创建"学习空间"，空间内绑定教材、维护进度、录入材料，系统在该空间内辅导；报辅导班可另建空间（v1.2） |
| 范围护栏 | 知识点存在性必须来自空间教材；讲解以教材为权威、可生成式多角度展开；超进度走软提醒+分支引导，不硬阻断（v1.2） |
| 记忆体系 | 所有对话全量持久化，定期提炼为结构化记忆（事实/偏好/状态），支撑"越用越懂"（v1.2） |

## 3. 用户与使用场景

### 3.1 用户

| 角色 | 说明 | 参与度 |
|---|---|---|
| 女儿（核心） | 六年级，放学后 15–30 分钟 | 每日使用 |
| 妈妈/爸爸（间接） | 低参与：只看周报；中参与：日报+告警；高参与：录入+错题详情 | 按档位 |

### 3.2 一次闭环主流程（孩子端）

```
女儿拍照（作业/试卷/练习册）
  → OCR 识别 → 题目归类到知识点
  → 归因对话（2–3 问）→ 判定：粗心/概念不清/审题失误/思路混乱
  → 针对性处理：
      概念不清 → 讲解（文字+TTS）→ 3–5 道基础练习
      粗心     → 检查习惯提示 → 直接进变式
      审题/读题失误 → 读题训练（圈信息→复述→数量关系）
  → 变式验收（三不变一变）：做对 + 一句话思路（语音/文字）→ 短期掌握
  → 间隔复习（1/3/7/14 天）→ 长期掌握
  → 错题画像沉淀
```

#### J1 家长创建学习空间（一次性配置）

- **用户**：妈妈/爸爸
- **目标**：为女儿建立"六年级上学期数学"学习空间，绑定教材，让系统拥有学习范围
- **主流程（用户视角）**：
  1. 打开家长模式（PIN）→ 进入"学习空间"
  2. 新建空间：填写名称"学校·六年级上册数学"、选择类型（学校/辅导班）、学期
  3. 选择教材：从系统内置列表选择（人教版/北师大版），或上传辅导班教材（PDF/图片 → OCR 提取目录）
  4. 确认知识点清单与当前进度（可选：不确定则留给 J2 摸底）
  5. 完成 → 孩子端出现该空间入口，系统可在其内辅导
- **关键界面要素**：空间列表卡片、新建空间表单、教材选择器、上传导入进度条、知识点清单确认页
- **涉及功能**：US-15、US-16（部分）、§5.10
- **分支/异常**：上传 OCR 识别失败 → 手动上传目录；同一空间可绑多本教材；学期中报辅导班 → 再建一个空间

#### J2 学生首次进入学习空间（摸底/冷启动）

- **用户**：女儿
- **目标**：让 Agent 知道她学到哪、水平如何，建立初始画像
- **主流程（用户视角）**：
  1. 首页出现"学校·六上数学"空间 → 点击进入
  2. 小鹿打招呼 + 摸底对话："这学期我们学分数乘法，你学到哪了？先做两道题试试？"
  3. 完成 3–5 道摸底题 → 生成初始薄弱点画像（三色）
  4. 小鹿建议："要不要把上周的错题拍给我看看？"
- **关键界面要素**：空间切换、小鹿形象对话、摸底进度、初始画像页
- **涉及功能**：US-16、US-18、§5.10
- **分支/异常**：女儿不想测 → 跳过摸底，从日常错题逐步积累；进度不确定 → 标记"待摸底"

#### J3 学生每日学习闭环（核心旅程）

- **用户**：女儿
- **目标**：放学后 15–30 分钟，把一个错题/新知识点真正学会
- **主流程（用户视角）**：
  1. 打开 App → 首页"今日任务"卡片（待复习 + 待学知识点）
  2. 小鹿自然问："今天数学课上到哪了？"（女儿回答或拍课本目录）
  3. 拍错题 → 识别 → 确认题目 → 归因对话（2–3 问）
  4. 按归因分支处理：概念不清 → 讲解（可朗读）→ 3–5 道练习；粗心 → 检查提示 → 直接变式；审题失误 → 读题训练
  5. 变式验收：做对 + 一句话讲思路（语音/文字）→ 短期掌握
  6. 25 分钟到时 → 休息 5 分钟；今日任务完成 → 小结页
- **关键界面要素**：今日任务卡片、拍照/裁剪、识别确认、对话气泡（归因）、讲解卡（含朗读按钮）、答题卡、变式页、一句话思路输入、休息引导
- **涉及功能**：US-1~7、US-16、US-17、§5.1–5.6、§8
- **分支/异常**：超进度题 → 软提醒"提前学/先放着"；OCR 失败 → 手动输入；中途中断 → 下次进入恢复未完成任务

#### J4 学生完成间隔复习（掌握度推进）

- **用户**：女儿
- **目标**：按遗忘曲线 1/3/7/14 天复习，把"短期掌握"推进为"长期掌握"
- **主流程（用户视角）**：
  1. 收到复习提醒（放学时段）→ 进入"复习"
  2. 逐题作答 → 判定通过/失败
  3. 1/3/7 三次间隔全部通过 → 该知识点变"长期掌握"（画像黄→绿）
  4. 失败 → 回到讲解换角度，重排复习计划
- **关键界面要素**：复习任务列表、答题页、掌握度变化反馈（鼓励）
- **涉及功能**：US-7、§5.6
- **分支/异常**：错过复习日 → 顺延并保留记录；不打扰（家长零强制投入）

#### J5 家长日常跟进（日报/周报）

- **用户**：妈妈/爸爸
- **目标**：用最少时间了解孩子学情，收到异常提醒
- **主流程（用户视角）**：
  1. 打开家长模式 → "今日"：今天学了什么、完成几个知识点、有无异常
  2. 异常告警（如同一知识点连续失败）→ 点开看建议
  3. 周日 → 周报：掌握率变化、重点错因、下周建议
  4. 低参与家长：只需每周看一次周报，其余零操作
- **关键界面要素**：今日卡片、异常列表、周报图表页
- **涉及功能**：US-8、US-9、US-13、§5.8
- **分支/异常**：家长升档/降档切换参与度（默认低参与）

#### J6 家长高参与——录入与深度查看

- **用户**：妈妈/爸爸
- **目标**：补充系统不知道的信息（评语/观察/教材），让辅导更精准
- **主流程（用户视角）**：
  1. 家长模式 → "家长录入"
  2. 录老师评语（孩子不可见）："老师说女儿分数应用题常漏条件"
  3. 录观察："她口算还行，一到大题就慌"
  4. 上传补充教材（辅导班讲义）
  5. 系统纳入记忆与画像 → 后续辅导体现（如多鼓励、多练读题）
  6. 高参与档可查看错题详情与归因
- **关键界面要素**：录入表单（评语/观察/教材）、上传页、记忆列表（可查看/删除）
- **涉及功能**：US-10、US-13、US-18、§5.8、§8.8
- **分支/异常**：不录入不影响产品运转（红线）；记忆可删

#### J7 家长设置与数据管理

- **用户**：妈妈/爸爸
- **目标**：控制防沉迷、参与度档位、数据主权
- **主流程（用户视角）**：设置每日时长 → 切换参与度档位 → 查看/删除记忆 → 一键导出/删除全部数据
- **关键界面要素**：设置页、档位选择、导出/删除确认弹窗
- **涉及功能**：US-11、US-12、§5.9、§8.8（家长控制）
- **分支/异常**：删除为不可逆操作（二次确认）

## 4. 信息架构与导航

### 4.1 孩子端（Flutter App）

```
┌─ 首页（今日学习卡片）
│    · 今日目标（1–2 个知识点闭环 / 复习任务）
│    · 快捷入口：拍错题、复习、读题训练
│
├─ 拍错题 → 拍照 → 识别中 → 确认题目 → 归因对话 → 处理分支
├─ 讲解页（文字 + TTS 朗读 + 教材来源）
├─ 练习页（3–5 道基础题）
├─ 变式验收页（变式题 + 一句话思路）
├─ 读题训练页（圈信息 → 复述 → 数量关系）
├─ 复习页（间隔复习题目）
└─ 设置（朗读开关、音量、防沉迷提示）
```

- 全局：小鹿虚拟形象与鼓励式话术贯穿；支持会话中断后恢复（下次进入回到未完成任务）。

### 4.2 家长端（Flutter App · 家长模式）

```
┌─ 今日（日报）：今日学习、完成知识点、有无异常
├─ 周报：本周学习、掌握率变化、重点错因、下周建议
├─ 薄弱点清单（三色：已掌握/攻克中/需关注）
├─ 错题详情（高参与档开启）
├─ 家长录入（老师评语 / 家长观察 / 补充教材）
└─ 设置（参与度档位、时长、推送订阅、数据导出/删除）
```

- 家长模式入口：孩子端"设置"中的家长入口，受家长 PIN 保护，进入后为家长界面（防止孩子误入）。
- 默认克制：仅展示三色区域，不主动打扰；升档后开放更多信息。

## 5. 核心功能需求

### 5.1 错题拍照与 OCR（P0）

- **功能描述**：女儿拍摄错题照片（或从相册选择），OCR 识别题目文本，自动归类到知识点，留存原图。
- **输入/输出**：
  - 输入：单张或多张照片（≤3 张），支持裁剪。
  - 输出：题目文本（可编辑）、识别置信度、归属知识点（可修正）、原图 URL。
- **交互**：拍照 → "识别中…" → 展示识别文本与题目预览 → 女儿确认或修正 → 进入归因对话。
- **去重**：相同题图/相近文本重复录入时，提示"这道题之前录过"，可选"作为新错题"或"回到原记录"。
- **验收标准**：
  - 打印体/手写体（工整）错题识别文字准确率 ≥ 90%（可编辑兜底）；
  - 从拍照到进入归因对话 ≤ 5s；
  - 识别失败（低置信度）时提供"手动输入题目"兜底。

### 5.2 归因对话引擎（P0，核心创新）

- **错误类型（四分类）**：
  | 类型 | 定义 | 典型信号 |
  |---|---|---|
  | 粗心（程序性失误） | 概念/方法对，仅计算、抄写、符号、步骤跳跃错误 | 能说出正确思路；换数字会做；错在"最后一步" |
  | 概念不清 | 知识点本身未掌握 | 说不清考什么；换数字仍错；方法不对 |
  | 审题失误 | 漏条件、看错单位/要求/数字 | 复述题意有遗漏；圈不出关键条件 |
  | 思路混乱 | 知道概念但不知从何下手、步骤逻辑断裂 | 卡在中间；讲不清为什么这么做 |
- **追问规则**：最多 3 个追问，采用决策树（见 §8.2），命中任一判定即停止并给出归因。
- **验收标准**：
  - 归因对话 ≤ 5 轮完成；
  - 验证期（家长每周抽查 5 道）归因一致率 ≥ 80%；
  - 每次归因写入错题记录，供家长高参与档复核。

### 5.3 讲解模块（P0）

- **触发**：归因 = 概念不清（或思路混乱中涉及概念部分）。
- **内容要求**：
  - 绑定教材/教辅原文来源（RAG 引用，展示"来源：人教版六上 Pxx"）；
  - 苏格拉底式、用孩子能听懂的语言；
  - 支持多角度讲解（同一概念至少 2 种讲法，供换角度回溯）；
  - 篇幅控制：单次讲解正文 ≤ 300 字或 ≤ 3 分钟朗读（适配儿童注意力）。
- **TTS**：默认朗读（柔和女声/童声），可静音切换为文字；朗读失败自动降级为文字。
- **验收标准**：讲解后基础练习首答正确率 ≥ 70%；讲解内容必须带教材来源引用；无来源的内容标记"补充说明"。

### 5.4 基础练习与变式验收（P0）

- **基础练习**：
  - 来源：预置题库（每知识点 5–10 道基础题，人工录入+校验）；
  - 数量：3–5 道；全对 → 进入变式；有错 → 返回讲解（换角度）后再练，最多 2 轮。
- **变式验收**：
  - 变式题由 LLM 按"三不变一变"生成：不变 = 核心知识点、解题逻辑、难度；一变 = 情境/数字/表述。
  - 生成后自检（规则校验 + LLM 自评，见 §8.4），不合格重生成（≤2 次）。
  - 判定：做对 + 一句话思路（语音或文字）→ **短期掌握**；任一项不达标 → 回到讲解换角度。
- **验收标准**：
  - 变式题与知识点绑定一致率 100%（规则校验）；
  - 变式验收后进入间隔复习闭环的转化率 ≥ 90%；
  - 进入变式的知识点最终"长期掌握"比例 ≥ 70%。

### 5.5 读题训练（应用题专项，P0）

- **触发**：归因 = 审题失误，或题目为应用题且归因存在"读题"嫌疑。
- **三步流程**：
  1. **圈关键信息**：Agent 引导女儿在题干中圈出已知条件、隐藏条件、所求目标；
  2. **复述题意**：女儿用自己的话复述"求什么、给了哪些条件"（Agent 只确认、不评判）；
  3. **数量关系建模**：Agent 引导说出"条件与问题的关系"（如总价=单价×数量），再重做原题。
- **判读逻辑**：训练后重做原题或变式，连续 2 次通过 → 确认"读题类"并进入变式验收；仍失败 → 切换检查"概念不清"。
- **验收标准**：读题类错题训练后重做通过率 ≥ 80%。

### 5.6 间隔复习调度（P0）

- **计划**：知识点达到"短期掌握"后自动生成复习计划：第 1 / 3 / 7 / 14 天。
- **判定**：
  - 通过第 1、3、7 天三次复习 → **长期掌握**；
  - 任一次失败 → 回退"学习中"，重新讲解并重排复习计划；
  - 长期掌握后，第 14 天巩固抽查；30 天抽查失败 → 回退"学习中"（疑似遗忘）。
- **提醒**：孩子端 App 内通知（放学时段）；不强制、不打扰（家长零强制投入）。
- **验收标准**：间隔复习通过率 ≥ 80%；复习计划生成正确率 100%（自动校验）。

### 5.7 错题画像与知识图谱（P0）

- **错题画像维度**：知识点分布、错误类型分布、时间趋势、反复错知识点 Top N。
- **知识图谱（MVP 简化版）**：版本无关知识点本体 + 前置依赖关系 + 教材目录映射。
- **应用**：诊断到薄弱点时先查前置；前置弱则先补前置（避免治标不治本）。
- **验收标准**：知识点可正确归属到人教/北师大目录；前置依赖在诊断时生效（有测试用例）。

### 5.8 家长端（Flutter App · 家长模式，P0）

- **参与度三档**：
  | 档位 | 内容 |
  |---|---|
  | 低参与（默认） | 只看周报 |
  | 中参与 | + 日报 + 异常告警 |
  | 高参与 | + 错题详情 + 家长录入 |
- **日报**：当天学习了什么、完成几个知识点、有无异常（如同一知识点连续失败）。
- **周报**：本周学习、掌握率变化、重点错因、下周建议（周日生成）。
- **家长录入入口**：老师评语（孩子不可见）、家长观察与感受、补充教材资料。
- **推送（P1）**：App 本地通知（日报/周报提醒）；微信推送（订阅消息/服务号）推迟到小程序阶段（需备案/认证，见 §13 R1）。
- **验收标准**：日报/周报生成及时（每日 21:00 前 / 每周日）；家长零操作即可查看；录入不影响孩子端运转。

### 5.9 防沉迷与家长控制（P0）

- 单次会话最长 25 分钟强制休息 5 分钟（倒计时 + 休息引导页）；
- 每日总时长可由家长设置（默认 30 分钟）；
- 达到阈值后孩子端锁定，需家长解锁或次日恢复；
- 家长端可随时查看/调整。

### 5.10 学习空间与进度对齐（基础模型，P0，v1.2）

**学习空间（Learning Space）是产品的基础模型元素**——一个按学期/任务隔离的上下文容器，系统在该空间内进行辅导。

- **创建**：家长（一次性配置）创建"学习空间"，如"学校·六年级上册数学"；学期中报辅导班可再建"辅导班·学而思数学"等空间。一个空间包含：绑定教材（系统内置或上传导入，可多个）、当前进度、录入材料。
- **教材绑定**：教材库 = 系统内置（人教版/北师大版等）+ 家长上传（辅导班教辅）。空间内至少绑定 1 本教材。
- **进度维护（学生为主）**：
  - Agent 每次会话自然询问"今天学到哪了？"（10 秒级）；
  - 拍照测验/错题时自动推断进度；
  - 家长仅在异常时一次性校准（如换教材）。
- **范围护栏（核心约束）**：
  - **知识点的存在性必须来自空间内教材的范围**（系统不能凭空教教材外知识点）；
  - **讲解内容以教材为权威、可生成式多角度展开**（因材施教，不拘泥原文）；
  - 超出当前进度 → **软提醒 + 分支引导**，不硬阻断：分支 A「提前学」（更新进度）/ 分支 B「先放着」（挂起）。
- **进度与掌握度的关系**：进度范围按空间隔离（学校空间未学到≠辅导班空间未学到）；知识点掌握度全局统一（跨空间共享）。
- **验收标准**：
  - 创建空间、绑定/上传教材流程可用（一次性配置）；
  - 超进度题必触发软提醒（可测）；软提醒不阻断操作（可测）；
  - 讲解内容不越出知识点边界（人工抽检）。

## 6. 教育模型与状态机

### 6.1 掌握度状态机

```
未接触 → 学习中 → 短期掌握 → 长期掌握
            ↑         │         │
            └─────────┴─────────┘（复习失败 → 回退学习中）
```

| 状态 | 进入条件 | 离开条件 |
|---|---|---|
| 未接触 | 知识点首次纳入 | 进入讲解或练习 |
| 学习中 | 进入讲解/练习/复习失败 | 变式验收通过（做对+一句话思路） |
| 短期掌握 | 变式验收通过（当天） | 1/3/7 天三次复习全部通过 → 长期掌握；任一失败 → 回退学习中 |
| 长期掌握 | 1/3/7 复习通过 | 14/30 天巩固抽查失败 → 回退学习中（疑似遗忘） |

- **掌握度分值**（用于画像）：长期掌握=1.0；短期掌握=0.7；学习中=0.3~0.6（按通过练习比例）；未接触=0。

### 6.2 归因分类判定标准

见 §5.2 表格；归因必须可追溯（记录追问问答，供复核）。

### 6.3 知识点与前置依赖

- **本体**：知识点 = 领域（算术/代数/几何/应用）+ 年级 + 名称 + 描述 + 前置依赖列表。
- **教材映射**：知识点 ↔ 人教版目录 ↔ 北师大版目录 ↔ 辅导班专题（多对多）。
- **前置依赖规则**：A 是 B 的前置（如"分数意义" → "分数乘法"）；诊断 B 薄弱时检查 A。

### 6.4 学习空间 × 进度 × 掌握度（v1.2）

- **进度（scope）**：按空间隔离——每个学习空间有自己的教材集与"当前进度"（学到哪章哪节）。
- **掌握度（mastery）**：全局统一——同一知识点跨空间共享掌握度（学校空间学过分数乘法，辅导班空间也视为已学）。
- **超进度判定**：基于"当前对话所在空间"的进度范围；知识点"是否学过"基于全局掌握度记录。
- **范围冲突处理**：辅导班超前教"分数除法"而学校空间未到——辅导班空间进度覆盖该知识点，学校空间不覆盖；两空间均可辅导，掌握度共享。

## 8. Agent 行为设计

### 8.1 系统提示词框架（孩子端）

```
角色：小鹿，一位耐心的六年级数学老师
语气：鼓励、不评判、儿童友好
核心原则：
1. 先归因后讲解，不直接给答案
2. 讲解绑定教材来源；无来源内容标注"补充说明"
3. 苏格拉底式引导，让孩子自己说出思路
4. 每次讲解 ≤300 字或 ≤3 分钟朗读
5. 孩子回答错误时："没关系，我们来看看哪里卡住了"
禁止：贬低、打击、一次性抛出大量概念、直接报答案
```

- 提示词版本化存储（便于迭代回归测试）。

### 8.2 归因追问决策树（2–3 问）

```
Q1（判概念）: "这道题考的是哪个知识点？/ 你能先讲讲你当时是怎么想的吗？"
   → 说不出/说错 → 概念不清
   → 能说对思路 → 进 Q2
Q2（判读题）: "你能把题目里给了哪些条件、要求什么，用自己的话说一遍吗？"
   → 复述遗漏/错 → 审题失误
   → 复述正确 → 进 Q3
Q3（判粗心/思路）: "如果数字换成小数/分数，你还知道怎么做吗？"
   → 会做 → 粗心（程序性失误）
   → 不会/不确定 → 思路混乱
```

### 8.3 讲解规则

- 先给出"这个问题考什么"，再讲方法，最后给 1 个例子；
- 多角度：至少准备 2 种讲法（例：分数的意义用"分饼"与"数轴"两种讲法）；
- 讲解结束引导："现在你能试着做一道类似的题吗？"

### 8.4 变式生成规则（三不变一变 + 自检）

```
约束：
· 不变：核心知识点、解题逻辑、难度层级
· 一变：情境 / 数字 / 表述方式（至少改变两处以上，避免仅换数字）
自检清单（LLM 生成后执行，全部通过才下发）：
1. 是否仍考核同一知识点？
2. 解题逻辑是否与原型一致？
3. 难度是否相当（步数、计算量相近）？
4. 是否有两处以上变化（情境/数字/表述）？
5. 答案是否唯一且可校验？
不合格 → 重生成（≤2 次），仍不合格 → 使用预置变式或标记人工待审
```

### 8.5 软性讲思路规则

- 场景：变式验收后"用一句话说说你怎么想的"。
- 处理：语音录入（ASR 转写）或文字；**不深度评判对错**，仅做记录 + 简单鼓励（"思路不错/我们再练练"）；
- 目的：自我解释训练（self-explanation），培养元认知；深度评判推迟 V1（"小老师模式"）。

### 8.6 读题训练规则

- 圈信息：Agent 逐句引导，"这句话里哪个是条件？哪个是要我们求的？"
- 复述：女儿用自己的话说一遍题目（Agent 只确认、纠偏、不评判）；
- 数量关系："这些条件和问题之间是什么关系？能写成算式吗？"
- 完成后再重做原题，按 §5.5 判读。

### 8.7 学习空间与进度对齐规则（v1.2）

- **上下文注入**：每次会话注入"当前空间"信息（教材、当前进度、已学知识点范围）。
- **进度询问**：会话开场自然询问"今天学到哪了？"；拍照错题时按题目知识点推断进度并请确认。
- **范围判定**：题目 → 知识点 → 判定其是否在当前空间进度范围内。
- **超进度软提醒（不硬阻断）**：
  - 分支 A「提前学」→ 将该知识点纳入空间进度（标记超前学习），正常进入闭环；
  - 分支 B「先放着」→ 题目挂起到"待学清单"，不进入闭环。
- **讲解范围约束**：知识点存在性必须来自空间教材；讲解内容可多角度展开，但不得越出该知识点边界。
- **记忆注入**：系统提示词携带当前用户相关记忆（偏好/状态/事实），支撑个性化。

### 8.8 记忆提炼规则（v1.2）

- **全量留存**：所有对话（含 ASR 文本）持久化保存，作为事实数据，不删减（家长可一键删除全部）。
- **提炼节奏**：每日定时 + 会话结束触发，从新增对话中提炼记忆条目。
- **记忆分层**：
  - 事实型（factive）：学过哪些章节、错题归因、测验结果、进度变化；
  - 偏好型（preference）：讲解风格偏好、激励方式、畏难点（如应用题）、兴趣点；
  - 状态型（state）：当前进度、当前薄弱点、近期情绪/信心。
- **质量控制**：每条记忆带来源（session）、置信度与时间；低置信度不进提示词上下文；记忆可去重、可过期（时间衰减）。
- **家长控制**：家长可查看全部记忆并删除（与数据导出/删除一致）。
- **验收**：每日提炼任务成功执行；记忆在后续会话中被引用（抽样验证）。

## 9. 非功能需求

### 9.1 性能

| 场景 | 目标 |
|---|---|
| 拍照→OCR 完成 | ≤ 3s |
| 归因对话响应（单条） | ≤ 3s |
| 讲解生成（首字） | ≤ 5s（建议流式输出） |
| 变式题生成 | ≤ 8s（含自检） |
| TTS 返回首段音频 | ≤ 3s |
| 日报/周报生成 | 每日 21:00 前 / 每周日 |

### 9.2 防沉迷

- 单次 25 分钟强制休息 5 分钟；每日总时长家长可设（默认 30 分钟）；超时锁定，家长解锁或次日恢复。

### 9.3 隐私与安全

- 数据加密传输（HTTPS/TLS）与存储（敏感字段加密）；
- 最小必要收集：仅收集女儿学习所需数据；语音仅用于 ASR，按需留存，支持删除；
- 未成年人保护：监护人（家长）知情同意；数据导出/删除一键完成；
- 孩子端不可见家长录入的老师评语/观察。

### 9.4 成本控制

- 模型：DeepSeek API（低成本优先）；
- OCR/ASR/TTS：按量付费，设月度预算上限（建议首月 ≤ ¥50），超限熔断降级（关闭 TTS/ASR，改文字）；
- 图片/音频：对象存储，定期清理非必要副本。

### 9.5 兼容性与可用性

- 孩子端：Android 8.0+（MVP 仅 Android 侧载 APK），主流分辨率；iOS 后续（TestFlight）；
- 家长端：同一 Flutter App 的家长模式（Android 侧载 APK；iOS 后续 TestFlight）；
- 弱网/断网：文字为主流程可降级，语音/朗读降级为文字。

### 9.6 可维护性

- 提示词版本化 + 规则可配置化（归因决策树、变式自检清单、复习排期）；
- 模块化：拍照/OCR、归因、讲解、变式、复习、家长端各自独立模块；
- 埋点完整（见 §12），便于验证期迭代。

## 10. 技术架构

### 10.1 总览

```
[Flutter App：孩子端 / 家长模式（PIN 保护）]（同一 App 双角色）
                        │
       └─────────── 后端 API（轻量云服务器 2C4G）──────────┘
                        │
      ┌─────────────────┼─────────────────┐
  DeepSeek API      OCR / ASR / TTS      PostgreSQL + 对象存储
   （LLM 引擎）        （腾讯云/讯飞）        （业务数据 / 图片音频）
        │
   轻量 RAG（BM25 检索教材/教辅片段，MVP 不引入向量库）
```

### 10.2 前端（Flutter）

- 跨端独立 App，Android 侧载 APK 起步；**单 App 双角色**：孩子端与家长端（家长模式受 PIN 保护，防止孩子误入）；
- 关键依赖：相机拍照（`camera`）、录音（`record`）、音频播放（`just_audio`/`audioplayers`）、状态管理（`Riverpod` 或 `Provider`）、本地缓存（`drift`/`sqflite`）、本地通知（`flutter_local_notifications`）；
- 本地重运算（端上推理/知识追踪）预留平台通道（MethodChannel）。

### 10.3 后端（轻量云）

- 轻量云服务器（2C4G，约 ¥50–80/月）；
- API 框架：FastAPI（Python）或 Node.js；REST + 少量流式（SSE）接口；
- 鉴权：孩子端设备绑定 + 家长端 PIN（家长模式）；微信登录/openid 推迟到小程序阶段（R1）。

### 10.4 OCR / ASR / TTS

- OCR：腾讯云 OCR（错题识别）；
- ASR：腾讯云/讯飞语音识别（普通话，儿童友好设置）；
- TTS：腾讯云/讯飞 TTS（柔和女声/童声）；
- 全部按量付费，带月度熔断（§9.4）。

### 10.5 RAG 与知识库

- MVP：轻量 RAG（BM25/关键词检索教材、教辅片段），绑定讲解来源；
- 不引入向量数据库（避免过度设计）；数据量增大后再评估。

### 10.6 数据库

- PostgreSQL 或 MySQL；对象存储（COS/OSS）存图片音频；
- 日报/周报与记忆提炼由每日定时任务聚合生成。

## 11. 里程碑与迭代计划

| 阶段 | 周期 | 目标 | 交付物 |
|---|---|---|---|
| 0 原型 | 第 1–2 周 | 最小对话原型 | 学习空间创建+教材绑定；拍照→OCR→LLM 归因+讲解（文字）跑通 |
| 1 闭环 MVP | 第 3–6 周 | 单知识点闭环 | 错题库 + 归因 + 讲解 + 变式验收（空间内，先 1 个知识点）；进度对齐 |
| 2 模型补齐 | 第 7–10 周 | 模型与数据 | 掌握度状态机 + 间隔复习 + 前置依赖图谱（六上第 1 章） |
| 3 交互增强 | 第 11–12 周 | 语音与读题 | 语音输入（ASR）+ 讲解朗读（TTS）+ 读题训练分支 |
| 4 家长端 | 第 13–14 周 | 家长模式（App 内） | 日报/周报/设置/录入入口（低+中参与档）；PIN 保护 |
| 5 实学验证 | 第 15–20 周 | 真实使用迭代 | 女儿真实使用 ≥ 6 周，迭代归因准确率与讲解质量 |
| 6 扩展 | 之后 | 能力扩展 | 更多知识点 → 错题详情/推送（P1）→ 英语 → 评估商业化 |

> 注：相比概念文档，本计划将"语音/读题"与"家长端"拆为独立阶段（第 3、4 阶段），以便闭环核心先验证。

## 13. 风险与开放问题

| # | 风险/问题 | 说明 | 应对/决策 |
|---|---|---|---|
| R1 | 微信小程序需备案 | 小程序发布必须完成备案（2023 年起强制），个人主体周期长；服务号推送另需企业认证（约 ¥300/年） | MVP 家长端用 App 家长模式（PIN 保护）查看日报/周报，无需微信；小程序与微信推送推迟到后期（P2） |
| R2 | 学校实际教材版本待确认 | 已支持人教/北师大双版本，但女儿学校实际用哪个需在"一次性配置"时确认 | 知识点版本无关 + 目录映射，配置时选定 |
| R3 | ASR/TTS 增加成本与网络依赖 | 语音方案比纯文字贵、且依赖网络 | 设月度熔断；弱网降级为文字 |
| R4 | LLM 讲解/变式幻觉 | 讲解错误被孩子内化；变式不合规 | 讲解绑定教材来源；变式自检清单 + 预置兜底；间隔复习暴露错误 |
| R5 | 归因准确率不足 | 影响辅导方向 | 验证期家长抽查校准；归因可追溯 |
| R6 | 孩子不愿主动使用 | 产品依赖孩子每日使用 | 小鹿形象 + 短节奏 + 可中断；验证期观察并快速迭代 |
| R7 | 成本超支 | LLM+OCR+ASR+TTS 按量计费 | 月度预算 + 熔断降级 |
| R8 | 数据隐私（未成年人） | 语音、错题、画像均为敏感数据 | 最小收集、加密、家长控制导出删除、监护人同意 |
| R9 | 讲出思路的深度评判（V1） | 儿童 ASR + 评判准确率 | MVP 软性版本，V1 再上"小老师模式" |
| R10 | 大陆轻量云域名需 ICP 备案 | 大陆云厂商对未备案域名默认不放行 80/443 访问；个人主体备案约 1–2 周 | MVP 后端若用大陆云，尽早提交域名 ICP 备案；或改用香港/海外轻量服务器（免备案，延迟略高）跳过备案 |
| R11 | 记忆/对话数据规模与隐私 | 全量对话+记忆包含大量个人信息，随时间增长 | 文本为主（成本可控）；家长可查看/删除；记忆最小化进入上下文；符合未成年人数据保护 |
