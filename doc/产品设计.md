## 2. 全局定位与设计原则

### 2.1 产品定位

- **形态**：私人工具，唯一核心用户是创始人的女儿（2026 秋季升入六年级）。
- **本质**：**掌握度驱动的 AI 高效辅导助手**——以"输入 → 模型 → 输出 → 反馈"学习引擎为骨架，**以聊天为核心互动**；错题闭环只是最重要的技能之一，而非唯一主线。
- **核心价值（减负）**：掌握即止、能不用就不用——用最少时间把不牢的知识点学牢，把时间还给孩子。
- **使用场景**：每天放学后 15–30 分钟，随时可插入提问，可中断恢复。

### 2.2 设计原则（继承概念文档五条红线）

1. **减负（红线〇）**：掌握即止——模型判定已掌握就不再安排，主动提示"这个已经会了，不用再花时间"；产品成功 = 帮孩子用最少时间达到掌握，而非占用更多时间。
2. **家长零强制投入**：默认零录入、零操作即可良好运转；家长各项功能独立开关、想看就看、想录入就录入，全凭自愿（不做参与度分档）。
3. **教育结论必须严谨**：禁止"一次做对 = 已掌握"；掌握度必须是时间维度上的状态机；讲解绑定教材来源。
4. **低风险技术优先**：费曼用"结构化自述 + 要点核对"，不赌 LLM 主观评判；变式用"三不变一变 + 自检清单"。
5. **信任输入假设（有效运行的基础）**：充分信任所有输入都是真实的——孩子如实作答与反馈、错题真实、家长录入可靠；不设防作弊机制；若输入失真，由归因对话/检验/间隔复习交叉验证逐步自我修正。

## 3. 共享底座（三端共用的模型与规则）

> 本章内容不归属于任何单一端，三端均依赖。各端章节会引用本处的模型与规则编号（如 §3.5 状态机、§3.6 教育规则）。

### 3.1 账号模型与三端关系

| 端 | 账号方式 | 说明 |
|---|---|---|
| 孩子端 `app_child` | **账号 + 密码登录**（账号由家长端创建并告知） | 不绑定设备：任意设备登录同一账号即同一档案；登录态本地保持，可登出；保护数据安全 |
| 家长端 `app_parent` | **自行注册 + 账号密码登录**（用户名+密码） | 家长身份代表"家庭"；先注册家长账号再登录；**负责创建与管理学生账号（生命周期全权掌控，一个家长对应多个孩子）** |
| 管理员端 `admin_web` | 独立账号登录（MVP 单账号，创始人本人） | 强密码 + HTTPS + 登录日志；与学生/家长端物理隔离；对学生账号仅只读查看 |

- **三端共享同一后端与数据**：学习空间、错题、掌握度、记忆、会话（均按学生账号隔离）。
- **账号生命周期归属家长**：创建 / 改密（重置）/ 改名 / 换头像 / 删除均由家长端完成（见 §5.6）；**账号密码不绑定设备**，孩子换设备直接登录同一账号即可。
- **家庭模型（MVP 简化）**：一个家长账号可对应**多个孩子**（学生账号），数量不限制；多家长 / 多孩子家庭（引入 `family` 实体）为后续扩展（P2，见 R16）。
- **数据模型层级（三级，核心）**：**家长（`parent`）→ 学生账号（`user`，`user.parent_id`，1:N）→ 学习空间（`learning_space`，`learning_space.user_id`，1:N）**。一个家长可有多个孩子（多个学生账号）；一个学生账号可有多个学习空间。家长端**先创建学生账号，再在学生账号下创建学习空间**（空间归属于该学生）。
- **数据安全**：学生端账号密码登录，保护未成年人数据；密码由家长设置并告知孩子，家长可随时重置。
- **家长账号来源**：家长端**自行注册**（用户名+密码），首启进入注册页；MVP 一个家长账号即一个家庭入口（多家长共管家庭为后续扩展）；忘记密码由管理员端协助重置（预留邮箱找回 P2）。

### 3.2 权限矩阵（谁读谁写）

| 数据域 | 孩子端 | 家长端 | 管理员端 |
|---|---|---|---|
| 学习空间（创建/绑定教材/进度校准） | 只读（切换、使用） | **读写**（创建/绑定/校准） | 只读（可在看板查看） |
| 会话与聊天记录 | 读（自己的历史对话） | 读（依赖"错题详情"开关；不展示完整聊天） | 读写（治理用，修正留痕） |
| 掌握度/薄弱点 | 不直接展示（见 D6） | 读（薄弱点清单/周报） | 读 + 手动校正（留审计） |
| 错题记录 | 读（自己拍照产生的记录） | 读（"错题详情"开关开启时） | 读写（治理） |
| 记忆（底层模型数据） | 不可见 | **不可见**（"删除全部数据"=逻辑删除，物理保留） | 读写（治理，可修正/逻辑删除/彻底删除，留痕） |
| 家长录入（评语/观察） | **不可见**（隐私隔离） | 读写 | 读 |
| 学生账号生命周期（创建/改密/改名/删除） | 不管理（仅登录） | **全权**（创建/改密/改名/删除） | 只读（查看数量/状态） |
| 功能开关/时长 | 只读（在设置里可看防沉迷提示） | 读写 | 读（+默认值配置） |
| 配置与规则（归因/变式/提示词/熔断） | 不可见 | 不可见 | **读写**（版本化） |
| 成本与用量 | 不可见 | 不可见 | 读 |

### 3.3 基础资产：知识点库 / 教材库 / 映射 / 知识点集

> **平台级共享内容资产**，由管理员端维护（§6.5）；三端共用——孩子端辅导、家长端建空间、管理员端管理。本节定义"是什么/规则"，管理操作在后台。

**四级模型（平台级 → 空间级）**：

- **知识点库（平台级，版本无关，纯概念本体）**：知识点 = `{ 领域(算术/代数/几何/应用), 名称, 描述, 前置依赖列表, 重要标记(触发费曼) }`；**无教材/年级绑定（去年级化）**——知识点是独立概念（"分数乘法"不依赖任何教材/年级）；id 全局唯一；是全局"总库"。
- **教材库（平台级，组织形态）**：教材 = `{ 版本(人教/北师大/辅导班), 书名, 册(年级学期), 章-节目录, 原文片段 }`；教材是知识的"组织形态"，是**讲解权威来源**（RAG 锚点，§7.5）。
- **映射（平台级，多对多）**：教材目录条目（教材+章+节）↔ 知识点；**年级/册信息在映射中**（知识点本身无年级）；决定"某教材能导出哪些知识点"。
- **知识点集（空间级，派生）**：学习空间绑定教材后，经映射**自动**从知识点库取出子集（多教材取并集、去重）= 该空间的"能教什么"（**范围护栏**）；**派生、不单独维护**（MVP 不落表，绑定变化即重算；量大再物化为 `space_knowledge` 缓存）。追踪集 ⊆ 知识点集（§3.5）。

**生成管线（如何定义与生成）**：

| 资产 | 定义方式 | 生成方式 |
|---|---|---|
| 知识点 | 人工定义本体（后台录入） | MVP 以"六年级上册第 1 章"为核心起步；先建库再建映射；重要标记用于费曼触发（§3.6-5） |
| 教材 | 系统内置预置入库（人工整理目录+原文） | 家长上传教材走解析管线：PDF → OCR → 章节目录识别 → 人工校验 → 入库（上传入口在家长端 §5.6，校验在后台 §6.5 A-4） |
| 映射 | 人工维护为主（后台把"人教版六上 P6"映射到知识点"分数乘法"） | 上传教材解析后提示"待映射"清单；可批量；完整性可校验（每节都应映射，未映射标"待映射"） |
| 知识点集 | 自动派生 | 绑定教材变化即重算，无需人工维护 |

**其他共享内容资产（同类处理，管理在后台）**：

- **题库**（`question`）：基础/变式/复习/检验客观题，绑定知识点（§6.5 A-5）；
- **费曼要点清单**（`feynman_checklist`）：重要知识点的要点清单与核对结果（§6.5 A-6）。

### 3.4 学习空间与进度

#### 学习空间（Learning Space）—— 学习的完整上下文容器

**学习空间是产品的基础模型元素**：一个孩子在某个主题/学期下的**学习完整上下文容器**，系统在该空间内进行全部辅导。空间里装的不只是"教材 + 进度 + 录入材料"，而是该主题下**与学习相关的一切**：

**空间内包含的内容**

| 内容 | 说明 | 对应数据表 |
|---|---|---|
| 教材（textbook） | 系统内置（人教/北师大）+ 家长上传（辅导班教辅），可多本 | `space_textbook` |
| 知识点范围 | 即该空间的**知识点集**（§3.3）：由绑定教材经映射从知识点库派生，决定"能教什么" | `knowledge_point` / `textbook` / `textbook_mapping` |
| 学习进度 | 学到哪章哪节，随会话推进 | `space_progress` |
| 聊天记录 | 空间内全部会话与消息（归属空间） | `session` / `chat_message` |
| 考察记录 | 检验/练习/变式/间隔复习的作答与结果 | `question`（作答）/ `review_schedule` |
| 错题记录 | 拍照错题及归因（归属空间） | `error_record` |
| 材料录入 | 家长录入的老师评语/观察/补充材料 | `parent_note` |
| 掌握度模型 | **被追踪**（有介入证据）知识点的掌握度状态（追踪集 ⊆ 知识点集，全局统一；未追踪无记录、默认信任） | `mastery` |
| 记忆 | 从空间内对话提炼的记忆（全局画像共用） | `memory_item` |
| 生成物 | 复习计划、日报/周报、薄弱点清单等 | `daily_summary` / `weekly_report` 等 |

**空间是"隔离 + 共享"的边界**：

- **隔离（原始数据按空间归属）**：教材、知识点范围、进度、聊天/考察/错题记录——按空间隔离（学校空间未学到 ≠ 辅导班空间未学到）；
- **共享（派生认知按孩子统一）**：
  - **掌握度全局统一**：同一知识点跨空间共享（在学校空间学过分数乘法，辅导班空间也视为已学）；
  - **记忆全局共享（学生级）**：学生级记忆（`scope=student`）描述"孩子"这一主体（偏好、畏难点、习惯、情绪、状态），不属于某个空间——在任一空间提炼到的记忆，在所有空间的辅导中都生效，让 AI 跨空间前后一致（如"对应用题畏难"在学校与辅导班空间都会体现）；另有**空间级记忆**（`scope=space`）绑定特定空间、生命周期随该空间（§3.6-7）；
  - **画像全局共享**：孩子的整体画像（掌握度分布、薄弱点、偏好、风格）为"孩子级"视图，跨空间一致；家长端/后台展示的是孩子整体画像，而非单空间画像。
- **原始数据隔离 ≠ 派生认知共享**：原始聊天/考察/错题按空间隔离存储（数据归属清晰），但从这些数据**提炼出的掌握度、记忆、画像属于孩子主体、全局共享**——两者不矛盾；进度类信息走 `space_progress`（按空间），不进入全局记忆。

**创建与生命周期（仅家长端，D4）**：

- **创建顺序**：家长端**先创建学生账号**，再**在该学生账号下创建学习空间**（空间归属于该学生，`learning_space.user_id`）；一个学生可有多个空间；
- 家长为学生创建"学校·六年级上册数学"；学期中报辅导班可再建"辅导班·学而思数学"等空间；
- 空间内至少绑定 1 本教材（系统内置或家长上传）；
- 空间是**长期存在的上下文容器**，不随单次会话结束而消失。

**进度维护（学生为主）**：

- Agent 每次会话自然询问"今天学到哪了？"（10 秒级）；拍照测验/错题时自动推断进度；家长仅在异常时一次性校准（如换教材）。

**范围护栏（核心约束）**：

- 知识点的存在性必须来自空间内教材的范围（系统不能凭空教教材外知识点）；
- 讲解内容以教材为权威、可生成式多角度展开（因材施教，不拘泥原文）；
- 超出当前进度 → **软提醒 + 分支引导**，不硬阻断：分支 A「提前学」（更新进度）/ 分支 B「先放着」（挂起）。

**进度与掌握度的关系**：进度范围按空间隔离；知识点掌握度全局统一（跨空间共享）。

### 3.5 掌握度状态机

**掌握度状态机只作用于"被追踪的知识点"，而不是空间内的全部知识点。**

- **知识点全集（范围护栏）**：来自该空间的**知识点集**（§3.3，由教材经映射派生），决定"能教什么"，不作为"要验证什么"的清单。
- **未追踪（状态机之外，默认）**：无掌握度记录、软件不介入，**逻辑上可视为已掌握（默认信任）**——孩子无需向软件"证明"自己会；与"信任输入假设"（红线五）自洽，是减负的基础。
- **进入追踪（出现"反证/介入证据"即进入"学习中"，无"未接触"过渡态）**：
  1. 错题：拍照错题归因到该知识点；
  2. 摸底 / 检验暴露薄弱：摸底题或"考考我"答错；
  3. 孩子主动要求：说"我不懂 X / 讲讲 X"；
  4. 前置薄弱：诊断依赖知识点时发现前置不牢。

```
学习中 → 短期掌握 → 长期掌握
   ↑         │         │
   └─────────┴─────────┘（复习失败 / 遗忘 → 回退学习中）
```

| 状态 | 进入条件 | 离开条件 |
|---|---|---|
| 学习中 | 进入追踪（出现反证/介入证据），或复习失败回退 | 变式验收通过（做对+一句话思路） |
| 短期掌握 | 变式验收通过（当天） | 1/3/7 天三次复习全部通过 → 长期掌握；任一失败 → 回退学习中 |
| 长期掌握 | 1/3/7 复习通过 | 14/30 天巩固抽查失败 → 回退学习中（疑似遗忘） |

- **掌握度分值**（用于画像，仅追踪集内）：长期掌握=1.0；短期掌握=0.7；学习中=0.3~0.6（按通过练习比例）；**未追踪无记录（默认信任，不入评分、不列薄弱点）**。
- **减负语义**：长期掌握 = 真正学会，不再安排学习与复习；已掌握知识点再次出现时，Agent 主动提示"这个已经会了，不用再花时间"（见 §4.6）。
- **反证即追踪**：未追踪知识点一旦出现反证（错题/摸底或检验答错/主动要求/前置薄弱）→ 直接进入"学习中"，无需先经过"未接触"。

### 3.6 教育规则

**（1）归因四分类与追问决策树（2–3 问）**

| 类型 | 定义 | 典型信号 |
|---|---|---|
| 粗心（程序性失误） | 概念/方法对，仅计算、抄写、符号、步骤跳跃错误 | 能说出正确思路；换数字会做；错在"最后一步" |
| 概念不清 | 知识点本身未掌握 | 说不清考什么；换数字仍错；方法不对 |
| 审题失误 | 漏条件、看错单位/要求/数字 | 复述题意有遗漏；圈不出关键条件 |
| 思路混乱 | 知道概念但不知从何下手、步骤逻辑断裂 | 卡在中间；讲不清为什么这么做 |

```
Q1（判概念）: "这道题考的是哪个知识点？/ 你能先讲讲你当时是怎么想的吗？"
   → 说不出/说错 → 概念不清
   → 能说对思路 → 进 Q2
Q2（判读题）: "你能把题目里给了哪些条件、要求什么，用自己的话说一遍吗？"
   → 复述遗漏/错 → 审题失误
   → 复述正确 → 进 Q3
Q3（判粗心/思路）: "如果数字换成小数/分数，你还知道怎么做吗？"
   → 会做 → 粗心（程序性失误）
   → 不会/不确定 → 思路混乱
```

**（2）变式生成规则（三不变一变 + 自检）**

```
约束：
· 不变：核心知识点、解题逻辑、难度层级
· 一变：情境 / 数字 / 表述方式（至少改变两处以上，避免仅换数字）
自检清单（LLM 生成后执行，全部通过才下发）：
1. 是否仍考核同一知识点？
2. 解题逻辑是否与原型一致？
3. 难度是否相当（步数、计算量相近）？
4. 是否有两处以上变化（情境/数字/表述）？
5. 答案是否唯一且可校验？
不合格 → 重生成（≤2 次），仍不合格 → 使用预置变式或标记人工待审
```

**（3）间隔复习调度**

- 计划：知识点达到"短期掌握"后自动生成复习计划：第 1 / 3 / 7 / 14 天。
- 判定：通过第 1、3、7 天三次复习 → **长期掌握**；任一次失败 → 回退"学习中"，重新讲解并重排复习计划；长期掌握后，第 14 天巩固抽查；30 天抽查失败 → 回退"学习中"（疑似遗忘）。
- 减负语义：长期掌握后不再安排（见 §3.5）。

**（4）读题训练（应用题专项，三步）**

1. **圈关键信息**：Agent 引导女儿在题干中圈出已知条件、隐藏条件、所求目标；
2. **复述题意**：女儿用自己的话复述"求什么、给了哪些条件"（Agent 只确认、不评判）；
3. **数量关系建模**：Agent 引导说出"条件与问题的关系"（如总价=单价×数量），再重做原题。

判读逻辑：训练后重做原题或变式，连续 2 次通过 → 确认"读题类"并进入变式验收；仍失败 → 切换检查"概念不清"。

**（5）费曼要点核对（替代主观评判）**

- 每个重要知识点维护一份**关键要点清单**（人工编写，进 `feynman_checklist`，后台维护见 §6.5）；
- Agent 把孩子的自述与要点逐条比对：覆盖 → 该条打勾；遗漏/错误 → 记缺失；
- 全部覆盖 → "通过，这个知识点你已经会了，不用再花时间啦"（可触发掌握即止）；
- 有缺失 → 只指出缺哪条 + 补讲，不展开自由深度评判；
- 不强求：孩子不想讲 → 改为客观检验；每次自述 ≤ 3 分钟。

**（6）软性讲思路规则**

- 场景：变式验收后"用一句话说说你怎么想的"。
- 处理：语音录入（ASR 转写）或文字；**不深度评判对错**，仅做记录 + 简单鼓励（"思路不错/我们再练练"）；目的：自我解释训练，培养元认知；深度评判推迟 V1（"小老师模式"）。

**（7）记忆提炼规则**

- **全量留存**：所有对话（含 ASR 文本）持久化保存，作为事实数据，不删减。
- **提炼节奏**：每日定时 + 会话结束触发，从新增对话中提炼记忆条目。
- **记忆分层**：事实型（学过章节/错题归因/测验结果/进度）；偏好型（讲解风格偏好/激励方式/畏难点/兴趣点）；状态型（当前进度/当前薄弱点/近期情绪信心）。
- **记忆分域（生命周期来源）**：
  - **空间级记忆（`scope=space`，绑定 `space_id`）**：与特定学习空间相关的记忆（如某空间内的考察情况、空间特有材料相关记忆）——**生命周期随学习空间**：空间删除 → 其空间级记忆一并删除；空间长期存在 → 记忆长期存在；
  - **学生级记忆（`scope=student`）**：与"孩子"主体相关的记忆（偏好、畏难点、习惯、情绪、状态及跨空间事实）——**生命周期随学生账号**：学生账号删除 → 学生级记忆一并删除；学生存在 → 记忆长期存在。
- **删除语义（逻辑删除）**：家长"删除全部数据"对记忆执行**逻辑删除（软删）**——界面不可见、不再注入模型上下文，但**物理保留**，便于后续数据挖掘与诊断；物理清除由管理员端治理或按保留期策略执行（P2），并提供"彻底删除"以满足监护人删除权（未成年人数据保护）。
- **质量控制**：每条记忆带来源（session）、置信度与时间；低置信度不进提示词上下文；记忆可去重、可过期（时间衰减）。
- **可见性（底层模型数据）**：记忆为内部模型数据，孩子端/家长端**均不可见**（无记忆列表入口）；家长仅能通过"删除全部数据"整体清除（数据主权，逻辑删除）；记忆的查看/修正/彻底删除由管理员端治理完成（§6.7）。

| `daily_summary` / `weekly_report` | user_id, date, stats_json, content | 日报/周报 |

- **家庭模型**：MVP 以 `parent`（家长账号）直接拥有多个 `user`（学生账号，`user.parent_id`）；多家长 / 多孩子家庭（引入 `family` 实体，家长↔家庭、孩子↔家庭多对多）为后续扩展（P2，见 R16）。

**（5）可维护性**

- 提示词版本化 + 规则可配置化（归因决策树、变式自检清单、复习排期、熔断阈值）——配置统一收敛到后台（§6.6）；

- 埋点完整（§9.2），便于验证期迭代。

- **意图分类**（6 项技能 + 兜底）：

| 意图 | 示例 | 落地形态 |
|---|---|---|

| 讲题 | "这题不会" / 拍题 | 跳讲题流程页（重） |

**对话脚本样例 1 — 讲知识点 + 掌握即止（黄金路径）**

```

女儿：（选）1/2
小鹿：对啦！[变式卡] 再来一道：5/6 × 2/5 = ?
女儿：（选）1/3
小鹿：全对！而且你已经能说出思路了。这个知识点你已经会了，今天不用再花时间啦。[掌握即止提示卡]
      [状态机：学习中 → 短期掌握；进入 1/3/7/14 间隔复习]
```

### 4.5 技能流程逐项（落地形态汇总）

| 技能 | 形态 | 流程要点（详见引用） |
|---|---|---|
| 讲知识点 | 对话内讲解卡 | 意图路由 → 锚点取教材片段（§7.5）→ 讲解卡（来源+TTS+多角度）→ 引导检验 |
| 讲题 | 跳讲题流程页 | 拍照/描述 → 归因（§3.6-1）→ 分支处理 → 练习 → 变式（§3.6-2）→ 短期掌握 |
| 检验 | 对话内答题卡 | 3–5 道客观题 → 判定 → 更新掌握度；重要知识点触发费曼 |
| 费曼 | 对话内卡片 | 分步引导 → 自述（语音）→ 要点逐条打勾（§3.6-5）→ 通过/缺哪条 |
| 错题闭环 | 跳错题拍照/识别确认页 → 讲题流程 | 拍照 → OCR → 归因 → 处理 → 变式 → 复习（重点技能，非唯一主线） |

### 4.6 系统主动能力

- **摸底（冷启动）**：首次进入（或无进度时）小鹿打招呼 + 摸底对话，3–5 道摸底题**探测薄弱（找反证）**——答错的知识点进入追踪（学习中），答对的不追踪（默认信任，减负）；女儿不想测 → 跳过，从日常错题逐步积累。
- **今日规划**：**只从追踪集生成**（§3.5）——待复习（追踪集内间隔到期）+ 待学薄弱点（追踪集内学习中，≤2 个）+ 已掌握减负提示；**未追踪知识点不推送**（默认信任，逻辑上视为已掌握）。
- **主动提醒**：间隔复习到点、异常薄弱提醒——孩子端 App 内通知（放学时段）；不强制、不打扰；**提醒只针对追踪集内知识点**。
- **掌握即止提示**：状态机判定已掌握（短期/长期）→ 主动提示"这个已经会了，不用再花时间"，不再安排学习任务；孩子仍想巩固 → 尊重，给一道轻量检验即可。

### 4.7 会话中断恢复 + 防沉迷

- **中断与恢复（D7）**：见 §4.4；会话上下文（对话历史、进行中技能）保留。
- **防沉迷（D5）**：**仅记录时长，不打断**——不强制休息、不锁定；使用时长写入 `usage_stat`，进入家长端日报/周报（§5.4）供家长参考；孩子端设置页只展示本周使用时长（不阻断使用）。
- **登录态（D3）**：账号密码登录；登录态本地保持（token）；登出后需重新登录；不绑定设备。

### 4.8 孩子端数据与埋点

### 4.9 孩子端验收标准

| 维度 | 验收 |
|---|---|

## 5. 家长端（第二端 · 功能可开关）

### 5.1 定位与目标用户

- **学习类**：今日会话数、平均会话时长（目标 15–30 分钟）、本周掌握率（长期掌握/全部已接触）、薄弱点 Top N（按 `mastery` 状态 + 连续失败）、每周使用天数。
- **成本类**：本月各服务用量与金额、月度预算进度、熔断触发状态与次数（`circuit_breaker_triggered`）。
- **质量类**：归因一致率（验证期家长抽查）、意图路由正确率、费曼要点核对通过率。

### 6.5 内容管理（字段级规格）

- 见 A-3 ~ A-6；所有内容发布后孩子端生效，发布动作埋点 `admin_config_update`。
- 教材解析管线：PDF → 章节目录 → 知识点映射（与 §7.5 离线建库共用）。

### 6.6 规则配置（版本化与生效机制）

- **D11**：配置版本化，草稿可预览；发布后对"新会话/下一条消息"生效；支持回滚。
- 提示词版本：`prompt_version` 表维护 active/draft，切换即时生效于新会话。

### 6.7 数据治理（与信任输入的边界）

- **D12**：治理仅针对技术性错误与系统误判（OCR/归因/状态机异常）；**不质疑孩子作答本身**（守护"信任输入假设"，红线五）。
- 手动校正掌握度 = 异常兜底（如系统误判导致状态错乱），校正写审计（`operation_log`），可在看板回查。

### 6.8 系统设置与安全

- 单管理员账号（MVP）；强密码 + HTTPS + 登录日志 + 失败锁定（A-1）。
- 月度预算与熔断阈值（§3.8-3）；操作日志完整留痕（§3.7 `operation_log`）。

### 6.9 后台数据与埋点

- 数据读写：全部业务表（读；治理时修正并留痕）+ 配置表（`sys_config`、`prompt_version`、`admin_user`、`operation_log`）。
- 埋点：`admin_login`、`admin_dashboard_view`、`admin_config_update`、`admin_data_fix`、`cost_usage_query`、`circuit_breaker_triggered`、`admin_settings_view`。

## 7. 技术架构

### 7.1 总览

```
[孩子端 Flutter App（平板优先，聊天优先）]   [家长端 Flutter App（手机优先）]   [管理员 Web 后台（PC 浏览器）]
        （三端共享后端）
                        │
       └─────────── 后端 API（轻量云服务器 2C4G）──────────┘
                        │
      ┌─────────────────┼─────────────────┐
  DeepSeek API      OCR / ASR / TTS      PostgreSQL + 对象存储
   （LLM 引擎）        （腾讯云/讯飞）        （业务数据 / 图片音频）
        │
   核心运行时：意图路由 / 技能调度 + 掌握度引擎（状态机/图谱/记忆）
        │
   轻量 RAG（教材，知识点锚定查找 + BM25 兜底，不引入向量库）
```

### 7.2 前端（三端）

- **孩子端 `app_child` + 家长端 `app_parent`（Flutter）**：单仓双入口，共享 core 包与主题令牌；Android 侧载 APK 起步，不上应用商店；关键依赖：相机拍照（`camera`）、录音（`record`）、音频播放（`just_audio`/`audioplayers`）、状态管理（`Riverpod` 或 `Provider`）、本地缓存（`drift`/`sqflite`）、本地通知（`flutter_local_notifications`）；本地重运算预留 MethodChannel。
- **管理员后台 `admin_web`（Web）**：Vue3 + Vite + TypeScript + Element Plus（沿用原型技术栈），PC 浏览器访问；提供看板、内容管理、规则配置、数据治理页面。

### 7.3 后端（轻量云）

- 轻量云服务器（2C4G，约 ¥50–80/月）；
- API 框架：FastAPI（Python）或 Node.js；REST + 少量流式（SSE）接口；
- 鉴权：孩子端**账号密码登录**（家长创建账号，不绑定设备，token 会话，D3）；家长端独立 App **自行注册 + 账号密码登录**（token 会话）；管理员后台独立账号登录（单账号，强密码 + HTTPS + 登录日志）；微信登录/openid 推迟到小程序阶段（R1）。

### 7.4 OCR / ASR / TTS

- OCR：腾讯云 OCR（错题识别）；
- ASR：腾讯云/讯飞语音识别（普通话，儿童友好设置）——孩子端**主要输入**（D2）；
- TTS：腾讯云/讯飞 TTS（柔和女声/童声）；
- 全部按量付费，带月度熔断（§3.8-3）。

### 7.5 RAG 与知识库（无向量库的落地实现）

**结论：MVP 不引入向量数据库**——因为语义层由 LLM 意图路由承担，检索退化为"知识点锚定的结构化查找 + BM25 兜底"，不需要向量检索。具体实现：

- **离线建库（一次性）**：
  - 教材解析：人教/北师大/教辅 PDF → 按"章-节-知识点"切分为教材片段（chunk），每片段挂元数据：知识点 ID、教材版本、章节、页码、标题（与后台 §6.5 共用管线）；
  - 建两类索引：**知识点锚点表**（知识点 ID → 片段列表，结构化主路径）+ **BM25 倒排索引**（片段全文，关键词兜底，`rank_bm25` / PG 全文检索）；
  - 片段存 PostgreSQL，BM25 索引内存加载（单教材几十万字符，2C4G 毫秒级）。
- **查询链路（每次讲解/讲题）**：
  1. 意图路由（LLM）把问句归一为 技能 + 知识点 ID（结构化输出）；
  2. **主路径**：知识点锚点表直接取该知识点教材片段（含页码）→ 注入提示词 → 讲解标注"来源：人教版六上 Pxx"；
  3. **兜底路径**：路由置信度低或未命中锚点 → 问句关键词跑 BM25 召回 top-3 → LLM 结合上下文选用（LLM 即重排器）；
  4. 每次检索 1–3 个片段、低频率，延迟可忽略（远小于 LLM 生成时间）。
- **同义词问题的处理**：中文"同义不同词"（孩子说"分数除法咋做"，教材写"除以一个数等于乘它的倒数"）——语义匹配放在"问句→知识点"这一跳（LLM 意图路由），而非"问句→原文"；辅以小型同义词/术语词典（人工维护，几十条）。
- **可选增强（不引入向量库基础设施）**：离线把教材片段向量化（几千片段 × 几百维 ≈ 几十 MB，numpy/文件存储），查询时问句向量化后内存余弦 top-k——自托管伪向量检索，毫秒级；后期可平滑迁移到真向量库。
- **升级阈值**：语料 > 100 万字符 / 需跨学科跨文档语义召回 / 多用户规模化时，再引入向量数据库（PG `pgvector` 扩展或独立向量库）。

### 7.6 数据库

- PostgreSQL 或 MySQL；对象存储（COS/OSS）存图片音频；
- 日报/周报、记忆提炼、使用时长统计由每日定时任务聚合生成。

## 10. 风险与开放问题

| # | 风险/问题 | 说明 | 应对/决策 |
|---|---|---|---|
| R1 | 微信小程序需备案 | 小程序发布必须完成备案（2023 年起强制），个人主体周期长；服务号推送另需企业认证（约 ¥300/年） | MVP 家长端用独立家长端 App 查看日报/周报（自行注册登录），无需微信；小程序与微信推送推迟到后期（P2） |
| R2 | 学校实际教材版本待确认 | 已支持人教/北师大双版本，但女儿学校实际用哪个需在"一次性配置"时确认 | 知识点版本无关 + 目录映射，配置时选定 |
| R3 | ASR/TTS 增加成本与网络依赖 | 语音方案比纯文字贵、且依赖网络；且语音为主要输入（D2）更依赖 | 设月度熔断；弱网降级为文字；验证期观察 ASR 成本 |
| R4 | LLM 讲解/变式幻觉 | 讲解错误被孩子内化；变式不合规 | 讲解绑定教材来源；变式自检清单 + 预置兜底；间隔复习暴露错误 |
| R5 | 归因准确率不足 | 影响辅导方向 | 验证期家长抽查校准；归因可追溯 |
| R6 | 孩子不愿主动使用 / 不知道问什么 | 产品依赖孩子每日使用 | 小鹿形象 + 短节奏 + 可中断；Agent 主动发起（建议/检验/提醒）+ 今日任务卡引导；验证期观察并快速迭代 |
| R7 | 成本超支 | LLM+OCR+ASR+TTS 按量计费 | 月度预算 + 熔断降级（后台可配阈值） |
| R8 | 数据隐私（未成年人） | 语音、错题、画像、记忆均为敏感数据 | 最小收集、加密、家长控制导出删除（删除=逻辑删除）；管理员端提供"彻底删除"以满足监护人删除权；监护人同意 |
| R9 | 讲出思路的深度评判（V1） | 儿童 ASR + 评判准确率 | MVP 软性版本，V1 再上"小老师模式" |

| R12 | 聊天被当"答案机器"或越界闲聊 | 影响学习效果与减负 | 先归因后讲解、限制直接给答案；意图路由 + 聊天边界规则（友好拉回）；验证期观察话术 |
| R13 | 费曼自述评判不可靠 | 影响掌握度判定 | 结构化自述 + 要点清单核对（客观比对），不赌 LLM 主观深度评判；要点清单人工维护 |
| R14 | 管理员后台安全与误操作 | 后台可改数据，误操作影响孩子端 | MVP 单管理员账号 + 强密码 + HTTPS + 登录/操作日志；数据修正留痕；删除二次确认；配置版本化可回滚 |
| R15 | 学生账号密码安全 | 家长设置的密码可能过弱/被遗忘；多设备登录管理 | 创建/重置时密码强度校验；登录失败限速；忘记密码由家长端重置（不设自助找回，保护未成年人数据） |
| R16 | 家庭模型扩展 | 一个家长对应多个孩子已支持；多家长/多孩子家庭需引入 `family` 实体 | MVP 简化模型：一个家长账号 ↔ 多个学生账号（`user.parent_id` 隔离）；后续扩展：`family` 表 + 家长↔家庭、孩子↔家庭多对多，再评估商业化数量限制与订阅（P2，§3.1） |
| R17 | 家长账号丢失/忘记密码 | 家长账号是学生账号生命周期的管理者，丢失影响数据管理 | 注册密码强度校验；忘记密码由管理员端协助重置（MVP，管理员=创始人）；预留邮箱找回（P2）；登录失败限速 |
