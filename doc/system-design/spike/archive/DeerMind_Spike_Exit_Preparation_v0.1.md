# DeerMind Spike 有界退出验证准备 v0.1

日期：2026-10-07。本文件对应[剩余八项退出清单与预算](DeerMind_Spike_Exit_Checklist_and_Budget_v0.1.md)，说明本轮实际入口、版本接入、离线证据与执行条件。准备与模型验证分别记账；准备通过不增加 9/17，不修改 A2 的 DENIED，也不关闭 Gate E/F。

## 1. 本轮入口与冻结范围

配置为 `src/spike/fixtures/spike-exit-v1.json`，离线准备入口为 `src/spike/prepare_spike_exit.py`，真实执行入口为 `src/spike/run_spike_exit.py`。冻结包保存于 `src/spike/review-packages/spike-exit-v1`，真实记录使用唯一目录 `src/spike/runs/spike-exit-v1`。两个目录均拒绝覆盖；旧配置、包和批次没有重新运行或改写。准备期间的可修改接线检查使用忽略目录中的临时输出，不是新增的真实验证轮次。

本轮固定 66 次执行及四个派生效果边界，最多 375 次模型调用。固定语义对照在前，随后为 A1/E1 正常场景、九条机制缺口和 X5。单次预算、共享 60 分钟期限、零传输重试和零替补沿用退出计划。九条机制补证使用原 DeepSeek Flash/beta 配置，输出上限 2048；新增质量路径上限 4096，均关闭 thinking、temperature 为 0、单次 timeout 不超过 60 秒且受剩余总时间限制。

执行前核对准备包的源文件及产物 SHA256。冻结范围包含实际代码、协议、fixture、设计文档，以及复用的下游消息证据；API key 不进入包或日志。真实执行逐次留存出站消息、动态 schema、原始返回、运行时快照、实际调用数和失败原因。出站审计只判断测试标签或精确测试标记是否泄漏，不执行自然语言语义分类。

## 3. 旧证据适用性与本地检查

原 E2/F2/X1/X2 的 46 条已完成路径在当前共享机制上做离线回放。回放读取原逐次输入、schema、模型配置和原始返回，核对当前同一场景的请求与结果。原协议与场景文件保持相同；回放不发网络请求，不生成新 LLM 判断，不重写原证据。

38 条路径的请求可完全比较相等。八条包含实际行动记录的路径需要显式、一一对应地映射该记录及其 Intent/acknowledgement 的运行时 UUID，并记录模拟渲染时钟的变化；候选中的精确结构化引用沿同一映射重绑定。原文含义、数值、披露内容、来源种类、固定 canonical 版本、schema 和模型配置均必须相等，任何其他差异都使适用性不获证明。所有差异、原文件 SHA256、回放请求和运行时检查保留在 `historical-compatibility.json` 及逐条 JSONL。该证明限于保留的 46 条机制路径，不证明旧代码逐字重建或新协议的语义可靠性。

离线完整接线使用显式 SCRIPTED 返回来验证真实共享 Context、候选、必需检查、提交、串行收束与 mock 效果。脚本可以故意为无语义价值的文本返回 PASS，因此这类结果绝不用于支持 A1/A2/E1 的语义质量。实际出站请求必须没有预期标签，消息长度不超过已有 16000 字符合同。准备包的 `summary.json`、`scripted-results.json`、`actual-requests.json` 和测试日志记录最终结果；只有 status 为 OFFLINE_READY 且哈希再次核对成功，才能进入真实执行。

新增测试直接验证首个错误 PASS 阻止后续评分/调用、传输失败不重试、缺少作者复核不能继续、逐项与总时间预算生效、剩余 timeout 缩短、标签不能外发、X5 schema 扩展不改语义规则，以及旧证据回放不能改写披露内容。错误规则/Context 和不可信校验 execution 的补充注入检查正式提交仍被拒绝。其余机械义务复用既有实际测试；下游义务另绑定已保存的实际 ContextManifest、生成和校验消息，不能只引用某个函数返回。

## 4. 真实执行的停止与复核

任何固定对照未识别目标缺陷、正常场景不满足要求、运行失败或机械检查失败，都立即结束本轮，后续为 NOT_RUN。一次对照的目标判断已失败时，不再为该对照追加测试评分来寻求抵消。每个完成的模型结果须由本会话作者检查原始候选及返回；模型测试评分本身不能打开下一项执行。

真实入口完成一项后写入 `review-request.json`，等待与该项记录 SHA256 绑定的作者 ACCEPT/REJECT 和具体说明。等待包含在同一个 60 分钟期限内；缺少、错误绑定或拒绝的复核都会停止。该文件接口只是运行控制，不新增模型 reviewer，也不要求用户逐条审批。预期标签和作者复核来自同一会话，不能称为独立人员盲评；原要求若采用独立人员含义，该独立性缺口在 Completion 评审中继续保留。

本轮先作出固定范围的能力和可执行性结论，再按原 §17 与 Gate E/F 评审。无论失败或证据不足，均交付八项处置、原始证据索引、预算使用、版本映射和具体阻塞，不自动开下一批、不调 prompt、不换案例、不增加仲裁调用。
