# DeerMind Spike 阶段收口决定草案 v0.1

日期：2026-10-06。状态：待评审的阶段决定草案。建议结束本轮追加模型调优，转入证据评审和设计修订；当前不能宣告原 Spike Completion、Gate E/F 或 System Design v1.0 完成。所有固定批次及其失败、未决、未运行记录保留。12 项架构假设和 5 项组合均有评估，完整验收仍为 9/17。

## 1. 收口决定与理由

选择证据收口，不继续以“把每个反例改到通过”为默认工作路径。已有反证足以否定 AA-A02 的原承诺；A1/E1/X5 的语义与合同问题已形成[整合修订](DeerMind_Validation_and_Interaction_Closure_Revision_v0.1.md)；E2/F2/X1/X2 未完成路径已[逐项归因](../../../../src/spike/reports/remaining-mechanism-review-20261006.json)。这些结果应先改变设计依据，再决定是否存在必须补取的证据。

持续调优可能改善局部表现，但没有固定质量目标和失败后的决策分支，就不能限定完成时间。直接将未决改为通过，或仅把它移到“后续开发”，都会使文档与证据不一致。本草案不采用这两种方式，也不以本地测试数量衡量阶段退出。

## 3. 可以继续的工作与功能范围

当前可以继续文档证据评审、设计修订和已有局部机制的整合准备；这不等于已经正式进入 Architecture Validation Build。Gate 通过前不发布 v1.0，也不把现有 Harness 宣传为完成产品闭环。

后续受控范围建议限定为一个任务族、当前作答或请求、明确登记并获准的行动，以及可追溯的候选、校验、提交和实际效果。权限、版本、依赖、串行和失败处理仍是基础要求，不能作为后续可选能力。Observation 对能力的猜测和 Policy 对独立性的自述，不成为能力事实。

建议暂缓完整自动诊断转教学链和未经验证的自主能力更新。原有 Evidence/Belief 的架构责任与支持机制保留，不能用脚本评分或缺省值冒充真实 Evaluation。若当前范围仍需要某项能力，就必须定义并验证它，不能一边延后一边继续依赖。

## 4. 正式退出与停止条件

[路线图 Gate E](../../../../src/spike/reports/source-baseline-design-review-20261008/originals/DeerMind_System_Design_Roadmap_v0.5.md.txt)允许四种处置：验证支持；证据否定后完成设计修订或 ADR；充分证据证明无需试验；明确阶段化能力且证明延后不破坏 Invariant。INCONCLUSIVE 本身不是其中一项。每项未决必须明确采用哪条路径及依据；基础约束不能被包装成可延后能力。

[原 Spike §17](../DeerMind_Consolidated_Architecture_Spike_Design_v0.1.md)要求完整场景执行；范围移交不补造缺失覆盖。若采用阶段化范围，必须正式说明哪些原要求保持、哪些调整及其理由，保留旧 9/17 和新范围的映射。完成设计修订后还须按 Gate E/F 分别评审，不以接受本草案代替 Gate 判定。

下一步先形成上述映射及正式设计修订清单。若某项取舍仍缺少决定性证据，才提出新的固定验证计划，声明输入、范围、调用上限和成功、失败、未决各自的后续决定。新计划不替换旧批次，不因失败自动扩容或再次调优。本草案不授权新模型调用，也不自定误放容忍阈值。

## 5. 重新打开本决定的条件

若保留范围出现越权效果、已知失效依据继续执行、失败候选被当作正式输入、活动未成功切换却按新活动执行，必须重新审查相应合同。若移交能力实际被当前范围依赖，必须撤销该范围声明并补齐设计或验证。语义指标、成本或可用性无法满足已确定的要求时，重新选择方案；不能为了维持阶段进度修改历史结果。

本草案完成的是阶段决定的具体表达。A2 正式假设修订、A1/E1 最低要求以及阶段化不破坏基础约束的论证仍须完成；它们是当前真实阻塞，不能继续用新增版本或测试数代替。
