# DeerMind Observation Validation Profile v0.1

日期：2026-10-05。状态：条件规则与分项审计的实验性实现；尚未完成真实模型语义验收，不替换既有架构结论。

## 1. 目的与适用性

本合同落实[校验与轮次关闭修订草案](DeerMind_Observation_Validation_Turn_Closure_Revision_v0.1.md)中的内容成立、必要含义与校验执行区分，并衔接[算术表达合同](DeerMind_Arithmetic_Expression_Contract_v0.1.md)。A1 原协议已有完整、正确与不完整作答的条件规则；本次以独立 [v13 实验协议](../../../../src/spike/protocols/observation-validation-v13.json)整合这些规则及未求值表达表示，保留旧版本和原始失败。

协议在候选生成前固定，不在失败后改选更容易通过的范围。同一协议同时要求 method、division、final_result、grounding、boundary、arithmetic_mapping、attribution 七项判据，没有可选项，也没有 NOT_APPLICABLE 的语义判据结果。可见现象不同，满足必要含义的方式可以不同；这一适用性判断由规则约束下的 LLM 读取原始材料完成，不能通过关键词、标点或候选自称“未完成”决定。

完整与不完整不是让全部判据一起切换的二元标签。方法是否明确、局部算术是否给出结果、最终答案是否提交，应分别按材料理解。只写答案也可能需要判断答案正确性；缺少商或中间步骤不免除对已提交最终答案的判断。候选遗漏的内容不能成为缩小检查范围的依据。

## 2. 必要含义的满足条件

| 判据 | 原材料提供相应内容时 | 原材料未提供或确实有歧义时 |
| --- | --- | --- |
| method | 候选解释可见的“总价除以已知数量、再乘目标数量”结构及其单位量含义；不要求出现固定术语，但不能只留下无内容的全局歧义标签 | 保留已见部分，并限定哪些环节缺失或含义不明。仅有最终答案不能证明使用了何种方法 |
| division | 对可见局部计算作正确判断：指出实际错误及正确局部值，或保留正确计算而不捏造错误 | 商未知时保留原表达和未给出的结果；没有局部计算时明确这一限制。不能替学习者补出已提交的数值 |
| final_result | 候选独立判断已提交答案是否符合原始任务，不能仅判断它与前一步是否一致 | 没有最终答案时明确其缺失；只有后续步骤确实缺失时才这样描述，不能把“没有答案”扩大成“没有步骤” |

上述含义必须体现在候选自身，并通过候选引用和原材料来源接受审查。来源有某段内容或 reviewer 能推导出正确答案，都不能代替候选缺失的判断。原始现象存在局部不确定性，与 reviewer 无法完成检查是两回事：忠实表达前者可以通过，后者必须保留 UNRESOLVED。

内容成立要求独立检查来源、归属、局部含义和责任边界，包含既有独立职责准入与精确算术检查。完整覆盖必要含义不能抵消错误来源、系统能力推断或教学决策。数值结果正确也不能证明学习者实际写过该结果。

九个[设计样例](../../../../src/spike/fixtures/validation-required-meaning-v1.json)覆盖完整错误、只指出局部错误、完整正确、保留未完成、捏造完成、仅有答案、未完成步骤但已有答案、局部方法歧义与追加能力结论。样例标签是开发者的预期，尚未用于真实模型验证，不计为通过证据，也不作为运行时文本分类器。

## 3. 分项记录与准入

每项检查记录 execution_status、conclusion 和其实际来源记录。执行状态为 NOT_RUN、COMPLETED 或 FAILED；只有 COMPLETED 才有 PASS、FAIL 或 UNRESOLVED 结论。NOT_RUN 和 FAILED 的结论为 null，不能把超时、断连、错误字段或结构违约伪装成一次已完成的语义判断。失败来源记录保留失败类型和原因；前面已完成的检查与后面未执行的检查分别保留。

content_validity 汇总 grounding、boundary、arithmetic_mapping、attribution，以及独立职责与计算检查；required_meaning 汇总 method、division、final_result。汇总仅在其全部检查完成后给出结论。“内容检查 FAIL”表示该维度至少一项检查未通过，不等于已证明整个候选所述事实为假。例如映射不忠实时，可以记录映射判据 FAIL，而原组合审查仍按已有规则保持 UNRESOLVED。

聚合执行状态另允许 INCOMPLETE，表示已有检查完成、其他检查尚未完成，避免把部分执行写成全部未执行。必要来源复核失败单独保留 SemanticRecheckFailed 引用，先前完整返回的判据不被抹掉；整体执行失败也不能用先前结果产生新的通过。

实现以 ValidationAttemptStarted、ValidationAttemptFailed 和 ValidationAssessment 执行记录保存这些信息。Assessment 是对既有检查记录的审计汇总，不是新的 authoritative model，也不取得准入权限。正式提交仍核验 exact candidate、全部必要语义判断、职责、算术、权限、版本、依赖及当前轮次资格。伪造汇总为 PASS 不能覆盖必要判断的失败。正常路径不新增模型调用，依旧由职责分类、算术提取和综合审查完成；已有的有界来源复核规则不变。

与失败关闭的接口使用同一 exact candidate 和 Context。ValidationAttemptFailed 可以作为该轮次的失败依据，不需要虚构一次 Policy 决策；实际效果停止与队列释放仍服从原关闭条件。

## 4. 验收范围与后续设计

本地验证针对记录及提交机制：开始前未执行、内容通过但必要含义缺失、必要含义满足但责任越界、已完成的未决判断、各阶段失败及后续未执行、字段错误、复核失败、缓存读取、部分执行、伪造汇总和失败轮次关闭。所有语义结果由显式本地 fixture 注入，不能据此证明条件规则被真实模型正确理解。

后续真实语义验证必须同时检查适用性判断和候选内容，特别是完整作答被误当作不完整、缺少步骤导致跳过实际答案、真实局部歧义被误拒，以及模型把候选遗漏当成来源缺失。当前完整验收数和 Gate 状态不因本合同改变。A2 的错误内容下游准入与 E1 的评分责任仍需要单独设计后果，不能由分项记录修复，也不应以反复增加模型批次替代设计决策。
