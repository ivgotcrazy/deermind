# DeerMind 单任务原型第一轮工程验证 v0.1

日期：2026-10-07。本轮承接已关闭的[可行性审查](DeerMind_Spike_Issue_Disposition_and_Feasibility_Decision_v0.1.md)，将已修订的 Observation 与 Policy 协议接入完整两回合会话，回答修复是否在实际链路中生效、剩余失败首先发生在哪里。它是受限原型工程验证，不重新开启旧 Spike 的语义准确率验收。

本轮固定一个苹果单价问题、AskSelfCheck 和 HintCheckStep 两种已登记提示，以及 NoIntervention / Defer。维持严格串行、必需审查、精确引用与授权检查，使用模拟显示执行器。禁止自动活动切换、新题和正式 Evidence / Belief 写入；这轮不会证明真实用户已看见或使用帮助。

## 输入与版本

Observation 使用 observation-feasibility-v1，明确局部答案判断不等于正式 Evidence 评价，并支持 criterion 引用同字段内多个独立原文片段。Policy 使用 policy-feasibility-v1，允许引用实际提供的 execution 空间 AssistanceContext，引用仍须属于当前上下文。其余语义策略与运行时保持不变。本轮不增加审查器、不跳过失败、不在运行中修改提示词。

从原单任务样本中每类选择一个会话，原输入不改动，每个会话执行一次、每次两回合。原始样本与本轮结构化计划见 [engineering fixture](../../../../src/spike/fixtures/single-task-engineering-v1.json)。

| 会话 | 场景 | 主要核对内容 |
| --- | --- | --- |
| T01 | 正确作答 | 不制造错误和不必要提示，不推断稳定掌握。 |
| T03 | 定位帮助 | 提示检查除法，不给正确商或答案；下一回合保留实际帮助。 |
| T05 | 尚未完成 | 保留已有正确除法与尚无最终结果的区别，遵守等待请求。 |
| T07 | 方法与结果 | 判断完整表达式结果有误但不凭空定位除法；只给整体自查提示。 |
| T09 | 请求限制 | 即使看到错误也遵守本次不要提示的请求。 |
| T12 | 实际帮助 | 区分已发生的定位帮助、学习者重新计算和学习者自称独立发现的陈述。 |

这些是已见的开发者样本，不称为独立盲测，不估计总体准确率。样本标签、期待动作和验收文字只用于离线核对，不传给被测模型。每个独立会话从空帮助历史开始；第二回合只继承本次第一回合实际发生的结果。即使预写的第二回合感谢提示，第一回合失败时也不能据感谢伪造系统帮助。

## 调用预算与停止条件

模型为 deepseek-flash，beta 结构化输出端点，temperature 0、thinking disabled，单次输出最多 4096 tokens、输入最多 64,000 字符、请求超时最多 60 秒。12 个回合每回合最多 7 次逻辑调用，正常上限为 84 次。沿用已验证的网络重试适配器，每个请求最多 3 次传输尝试，间隔 2 秒和 5 秒；全轮实际 API 调用仍以 100 次为硬上限，总调用阶段以 600 秒为硬上限。所有传输尝试使用完全相同的请求并保留记录；schema、契约、语义失败不得重试。

程序机制违例立即停止整个批次；普通语义或输出失败只结束对应回合，收束后可以处理下一回合或独立会话。预算耗尽、结果未收束分别记为未运行和阻塞，不补样本。没有第二批和自动调参。执行前固定源文件指纹，输出目录拒绝覆盖，执行后保留原始记录。

## 结果判断与交付

先报告完整执行的会话和回合、网络未完成、协议或契约失败、语义拒绝；再人工核对每个已生成的 Observation 与 Policy。允许的局部观察被职责分类拒绝属于误拒；候选本身确实遗漏必需判断而被拒绝属于生成缺陷，不能算审查误拒。候选有缺陷却被正式提交，则单列漏判。算术提取、职责分类和最终准入分别报告，不能只看最终 PASS。

已执行提示须与期待动作、当前请求及实际帮助历史一致。流程完成只表示运行到终点，内容或动作不符合预期的会话不能计为有效会话。人工核对由实现者完成，单列判断依据与争议，不冒称独立审查。

本轮完成的条件是：固定版本已接入并通过相关本地检查，12 个回合均有结果或明确未运行原因，所有候选与失败有离线复核和下一步处置。若完整路径仍不能建立，应指出最早的共同阻塞及一项优先修复；若已能建立，则列出可用路径与剩余质量问题。本轮不会因未达到全通过而无限追加调用，也不会因此否定已经形成的有限可行性结论。原合同的 9/17、A2 DENIED 和正式 Gate 状态保持不变。
