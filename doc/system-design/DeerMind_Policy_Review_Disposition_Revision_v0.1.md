# DeerMind Policy Review Disposition Revision v0.1

日期：2026-10-06。状态：基于已关闭真实批次的具体合同修订设计；尚未实现、集成或验证。本文补充[Policy 语义与评分合同](DeerMind_Policy_Semantic_Utility_Contract_v0.1.md)，不重写冻结的 v2 协议，也不自动启动第三轮模型验证。

## 1. 已观察的问题及设计选择

[固定真实评审](../../src/spike/reports/policy-v2-real-review-20261006.md)中，定位反例同时包含“没有替代任何定位工作”和“帮助定位但不提供商”，语义校验与评分都给出 PASS。评分解释已经注意到前一句偏强，却用另一字段的正确描述为它解围。问题不只是遗漏规则，也在于当前输出只有总体状态和自由理由，无法机械检查评审承认的缺陷是否与其裁决一致。

同一批次将“原作答在形成候选时可用、当前评审被隐去”判为候选无依据，混淆了评审信息缺口与可确认的内容缺陷。四个旧候选的新 PASS 则继续容许假设语气充当依据，并将受助定位与独立重算合并。这些原始评分保留；本文给出后续机制选择，不把设计交付计作语义问题已经解决。

当前选择是在已有的一次 Policy 语义校验中，返回固定义务的状态、精确证据位置和失败原因；由确定性代码核对引用、覆盖和裁决的一致性。保持生成一次、语义校验一次以及测试场景单独评分的调用结构，不增加默认仲裁模型，不要求第二次重审上游全文。继续严格串行，当前轮次未收束前不处理下一正常轮次。

这项设计只改善显式结果的可核查性。若 LLM 根本未抽取错误断言，或将冲突误判为可以并存，机械代码仍无法凭空知道真实含义。因而应分别验收“已声明缺陷不得绕过准入”和“模型能否识别缺陷”，不能把前者包装成原 A2 普遍语义隔离命题恢复成立。

## 2. 同一次校验的最小结果合同

拟新增 opt-in 的 Policy 校验格式 `policy-disposition-v1`，继续使用 S1–S5 义务，不给每种教学情景建立硬编码分支。校验结果绑定原 candidate digest、冻结 ContextManifest 和精确规则版本；模型返回简短裁决证据，详细内部推理过程不属于合同。

| 结果部分 | 必要内容与用途 |
| --- | --- |
| checks | S1–S5 各一项且不可重复；每项包含 PASS/FAIL/UNRESOLVED、reason_code、findings 引用和简短理由 |
| findings | 本次判定依赖的断言、关系及材料位置；使用精确候选字段片段和 Context 中的 exact ref、字段片段，不采用自由引用标题 |
| review_material_gaps | 对所需但当前不可见材料的引用或来源角色、为何影响此义务，以及对应受信可用性记录；不允许候选自行声明“材料丢失”免除依据义务 |
| reviewed_fields | 明确已读的全部生成合同字段；机械检查集合覆盖，只证明声明覆盖，不证明 LLM 实际理解完整 |
| status | 模型提出的整体裁决；与固定义务和 findings 的确定性约束核对，不从自由理由中猜测状态 |

findings 只保留影响裁决的证据，不要求把自然语言拆成无限细的断言图。语义边界最低覆盖当前决定的事实依据、重要假设、责任替代、预期与实际披露、跨字段一致性。定位与重算是本轮反例中的语义责任，不升格为所有任务都必须套用的固定责任等级。

候选片段可以表示为 `field`、`start`、`end`、`quote`，起止按解码后字符串的 Unicode code point 计数，左闭右开；来源片段另有 exact ref 和字段路径。机械校验必须验证切片等于 quote，并限制在本次许可的投影内容中。精确子串命中只证明位置真实，不能证明引用支持断言。模型报告“没有发现冲突”也不是可靠隔离证据。

每条 finding 声明其关系：SUPPORTED、CONTRADICTED、REQUIRED_BASIS_ABSENT 或 UNDETERMINED，并关联受影响义务。关系的含义由规则和 LLM 判断；机械代码只处理声明的一致性。例如，checks 声称 S3 PASS，但其所引用或关联的 finding 是 S3 CONTRADICTED，必须拒绝该评审输出，不能无视 finding 后继续提交。

## 3. 矛盾不能靠另一句正确话自动抵消

评审对象是不可变的完整候选。对相同对象、时间、条件和责任范围的断言，若一句说“没有定位帮助”，另一句说“定位受到帮助”，不能因为第二句正确，就把第一句改读成“只是重算独立”。明确的范围限定、引用他人主张、描述不同时间或明确撤回前文，可以改变是否冲突的语义判断；应引用该限定的准确位置，而不能由评审者替候选补写限定。

CONTRADICTED 在任一必需义务下形成内容 FAIL，其他义务的 PASS 不抵消它。若是否同一责任或条件无法确定，应记录 UNDETERMINED 并使相关义务 UNRESOLVED，而非为了得到完整答案将其解释为通过。修正候选必须形成新的候选身份和重新校验，不能修改原候选、静默去掉矛盾句或让评分输出改写行动。

这不要求固定介入行动。定位提示本身可以合法且合理，失败的是候选声称未发生定位替代的解释；允许对照必须包括承认定位帮助、保留独立重算的合格说明。完整讲解也可在当前请求和已生效活动允许时独立选择，上游 Observation 建议不取得行动权限。

## 4. 材料可用性与候选依据分开记录

材料可用性属于受信上下文组装及权限层，而不是 LLM 对材料含义的结论。优先复用 ContextManifest 的 included、excluded、来源引用、版本、权限决定及候选形成时的 Context 绑定；历史离线评审若主动删去来源，应由评审包的受信配置注明删去的是哪个 exact record 或哪个材料角色。无需新增第二套权威世界状态或让候选带一张自证材料清单。

拟将相关可用性原因为 AVAILABLE、WITHHELD_FOR_REVIEW、ACCESS_DENIED、RETRIEVAL_FAILED、NOT_PROVIDED_TO_FORMATION、UNKNOWN。它们只描述能够证实的材料状态。评审者不得把缺少的来源补写成不存在，也不得自动扩大权限去取回 ACCESS_DENIED 材料。是否为某个断言所必需、是否仍可依据其他获准材料判断，由 LLM 按规则解释。

| 已知条件 | 内容/校验处理 | 生产准入 |
| --- | --- | --- |
| 获准材料足以确认候选与事实或自身相矛盾 | 对应义务 FAIL，即使其他材料缺失也保留这个已证实缺陷 | 拒绝 |
| 完整候选在其形成时获准材料范围内缺少必要依据，评审信息足以确认该义务未满足 | REQUIRED_BASIS_ABSENT，对应义务 FAIL；不声称证明潜在心理过程绝不可能 | 拒绝 |
| 候选形成时的确切来源已知，但当前评审被隐去或无权读取；其他材料不足以判断断言 | 对应义务 UNRESOLVED，并记录材料缺口；不称其断言已被事实反驳 | 拒绝，保留未决原因 |
| 既不能确认材料来源历史，也不能据当前材料裁决 | UNRESOLVED/UNKNOWN，不替候选猜测来源 | 拒绝 |
| 原必需 Context 获取或授权失败，尚不能开始有效语义校验 | 由运行时记录上下文/执行失败，不制造一条模型内容 FAIL 或 PASS | 拒绝并走原失败收束 |

可用性不会自动决定所有内容状态。即使某来源缺失，候选内部已有足够信息证明冲突，仍可判 FAIL；即使某材料可读，也不保证它能支持候选。在独立的多个义务中，已确认的 FAIL 优先于内容层的 UNRESOLVED；但执行未完成时仍记录执行状态，不得伪装成一次完成的有效语义裁决。所有必需校验完成且全部 PASS 才有语义准入资格，仍须通过原机械权限及精确行动检查。

一个未被上下文支持的假设，也不能只因使用“可能”而转为 WITHHELD 或 UNRESOLVED。假设的实际问题来源、决策关联和区分路径仍是 S2 义务；系统不知道心理过程不等于每个猜测都可以充当介入依据。

## 5. 运行接入、成本和剩余风险

新格式需要在现有语义校验解析路径中显式选择。先校验 schema、固定义务及字段覆盖，再核对精确片段与可用性依据，最后核对 findings、checks 和 status 的关系；校验器不能仅仅读取模型顶层 PASS。无效引用、缺少必需行、重复义务或自相矛盾的评审结果属于合同/执行失败，不能注册为有效 ValidationResult。有效的内容 FAIL 与有效的 UNRESOLVED 则按各自原因保留，均不得准入。

Policy 生产校验与测试 utility 仍有不同职责。utility 可以引用自己的结构化判据，不能复用生产 PASS 当作其内容必然正确的证明；任一 utility FAIL 不能撤销已经发生的合法效果。生产 Evidence 仍依据实际效果历史与 Claim 形成独立责任内的候选，不把 Policy 对“独立性”的自述升级为学习者事实。

工程成本是一次语义调用中更长的输出、更多引用核对、Context 可用性元数据和版本适配，而非默认更多调用。优先试验小型 S1–S5 结果，不引入通用论证图、递归反思或批量自动修补。全部拒绝也不构成成功，必须保留合法假设、有限帮助、当前允许讲解以及材料确实不足的对照。

本合同不能保证语义抽取不遗漏、同义判断正确或两个评审不产生相关错误；不能给出未经验证的误放率。是否满足产品要求仍需原 Evidence Review、ADR/Reopen 与 Gate 评审。当前不接受一个自定误放容忍阈值来关闭 Gate。

## 6. 一次局部实现应完成的交付

下一步将该格式作为 opt-in 接入同一次语义校验，完整交付结构化输出、受信可用性绑定、确定性裁决核对和有限本地故障注入，不再分成反复的纯提示增补。最小本地用例应证明：声明矛盾仍顶层 PASS 被拒绝；正确的显式限定不被词法误拒；已声明材料缺口且顶层 PASS 被拒绝；材料缺失不覆盖已知矛盾；引用越过字段投影或候选被替换时拒绝；有效 FAIL/UNRESOLVED 均不能提交；全部合格的脚本正例能够通过。

上述局部用例只验证模型明确返回内容的机械处理，不能把脚本注入的 finding 称为 LLM 已识别矛盾。真实语义验证需另作范围决定，已关闭的三十六次批次不重启。本轮无实现、运行测试或真实模型调用，A2 DENIED、E1 INCONCLUSIVE、9/17 及 Gate E/F OPEN 均保持。
