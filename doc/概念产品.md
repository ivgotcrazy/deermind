## 1. 产品概述

### 1.1 一句话定义

呦鹿智伴是一款**先为女儿（六年级）量身打造**的 AI 数学学伴，以"错题拍照 → 自动归因 → 针对性讲解 → 变式验收 → 间隔复习"闭环为核心，让女儿把错过的题真正吃透，把"粗心"与"概念不清"分清楚，并逐步学会讲出解题思路。

### 1.2 产品定位（本阶段）

- **当前：私人工具。** 唯一用户是创始人的女儿，目标是把"数学错题闭环"这一件事做到足够好。
- **远期（非本阶段）：** 若验证有效，再评估是否产品化。商业化、监管合规、竞品策略均不在本阶段做决策。

### 1.3 产品愿景（私人版）

让女儿拥有一位懂她、陪她、帮她把错题真正吃透的 AI 学伴。

### 1.4 Slogan

"呦鹿智伴，知你所短，伴你所长。"

## 2. 目标用户（本阶段）

- **唯一核心用户：创始人女儿**（2026 秋季升入六年级）
- **间接用户：创始人夫妇**——只承担"一次性配置"与"每周看一次周报"，日常零投入
- 本阶段不做任何其他用户假设；扩展用户（小学 4–6 年级、初中、英语、语文）全部写入"远期展望"，不进入本阶段设计

## 3. 核心痛点与范围决策

### 3.1 痛点优先级（本阶段）——表层痛点 × 根因 × 应对

| 表层痛点 | 根因 | 产品应对 | 优先级 |
|---|---|---|---|
| 数学粗心算错 | 熟练度不足、步骤监控缺失（真正的"粗心"很少） | 归因对话区分"粗心/概念不清" → 检查习惯训练 | P0（MVP 主线） |
| 应用题/读题失分 | 阅读理解弱、抓不住数量关系、审题丢条件 | 读题训练：圈关键信息 → 复述题意 → 数量关系建模 | P0（MVP 主线，v0.2.2 新增） |
| 会做但讲不出所以然 | 概念理解浅、缺乏元认知与自我解释 | 归因追问 + 讲出思路（软性验收，V1 强化） | P0 |
| 错题本效率低 | 抄答案式订正、不复盘 | 错题闭环：自动归因/间隔复习/变式 | P0（闭环载体） |
| 家长没时间/没能力辅导 | 家长陪伴时间稀缺 | 设计红线：家长零日常录入 + 周报 | P0（§4） |
| 数学焦虑/畏难（观察项） | 情绪占用工作记忆，恶性循环 | MVP 仅用鼓励式话术表达，不做专门功能 | 远期（V1+ 情感设计） |
| 刷题不总结/应试技巧 | 低效刷题替代题型归纳 | 主动放弃（非 AI 学伴核心价值） | ✖ 不做 |
| 英语语法错误多 | — | — | P1（远期） |
| 语文 | — | — | P1（远期，验证期后再决策） |

### 3.2 为什么 MVP 只做"数学错题闭环"

- 痛点最集中、最可量化：错题 → 归因 → 验收 → 复习是完整可度量的闭环
- 闭环验收机制在数学上最容易设计（变式生成、判定明确）
- 应用题/读题失分已确认为女儿的真实高频痛点（创始人确认），读题训练作为闭环内分支纳入 MVP（§5.4）
- 女儿每天放学后可用 15–30 分钟，单科闭环节奏最匹配
- 独立开发、业余时间，范围必须收缩到"一件事做透"

## 4. 设计红线（v0.2 确立，重构的基石）

**红线一：家长零强制投入（默认零录入，可选增强）**
- 家长只承担一次性配置（约 1–2 小时：导入教材目录、确认当前进度与知识点清单）
- 日常所有数据由"女儿拍照 + Agent 自动处理"，或 Agent 在对话中自然采集——**产品默认流程不依赖任何家长日常录入**
- 同时开放"家长录入入口"作为**可选增值输入**：有条件的家长可补充老师评语（孩子不宜看到）、家长自己的观察与感受、希望引入的教材资料等；录入后提升个性化质量，不录入也不影响产品运转
- 原则：录入是"锦上添花"而非"必需"；任何"不录入就退化"的功能都是设计缺陷

**红线二：教育结论必须严谨**
- 禁止"一次做对 = 已掌握"；掌握度必须是时间维度上的状态机（§6.1）
- 讲解绑定教材/教辅原文来源，降低错误内化风险

**红线三：低风险技术优先**
- MVP 不依赖"LLM 深度评判孩子讲解"（高风险卡点），先用低风险方案跑通闭环

**红线四：把"家长没时间"转化为"产品自己跑"，同时满足"有时间"的家长**
- 家长端按**参与度三档**设计，默认按"低参与"运转，家长可随时升档（详见 §10.2）：
  - 低参与（默认）：只收周报，零操作
  - 中参与：加开日报 + 异常告警，每天约 5 分钟查看
  - 高参与：在低/中基础上，开放家长录入入口与错题详情查看
- 原则：任何一档都能独立良好运转；日报/周报/告警均可订阅或关闭

## 5. 核心场景：数学错题闭环（MVP 唯一主线）

### 5.1 一次闭环流程

```
① 女儿拍错题照（作业/试卷/练习册）
        ↓
② OCR 识别 → Agent 自动归类到知识点
        ↓
③ 归因对话（Agent 追问 2–3 问）
   判断：粗心 / 概念不清 / 审题失误 / 思路混乱
        ↓
④ 针对性处理：
   - 概念不清 → 知识点讲解（绑定教材）+ 3–5 道基础练习
   - 粗心     → 检查习惯训练 + 变式验收
   - 审题/读题失误 → 读题训练（圈关键信息 → 复述题意 → 数量关系建模，见 §5.4）
        ↓
⑤ 变式验收（三不变一变）
   - 做对 + 一句话说思路 → 标记【短期掌握】
   - 未做对 → 回到 ④ 换讲解角度
        ↓
⑥ 间隔复习（1 / 3 / 7 / 14 天推送）
   - 连续通过 → 标记【长期掌握】，移出错题待办
   - 未通过   → 回退【学习中】，重新归因
        ↓
⑦ 错题画像沉淀：反复错的知识点、错误类型分布、进步趋势
```

### 5.2 "讲出所以然"的处理（v0.2 决策）

- **MVP 软性版**：变式做对后，要求女儿"用一句话说说你怎么想的"。作为自我解释训练，**不强制 LLM 深度评判对错**，只记录与简单提示——避开儿童语音识别与评判的技术风险。
- **V1 强化版**："小老师模式"，让女儿把题讲给小鹿听，LLM 深度评判逻辑（需先解决儿童语音识别与评判准确率）。

### 5.3 归因对话（最核心的创新点）

"粗心 vs 概念不清"家长最容易误判、也最影响辅导方向。Agent 用 2–3 个追问区分：

- "这道题你是没看懂题目，还是看懂了算错的？"
- "如果数字换成小数/分数，你还知道怎么做吗？"
- "你先告诉我，这道题考的是哪个知识点？"

归因结果沉淀进错题画像，验证期由家长抽样校准（§9.1）。

### 5.4 读题训练（应用题专项，v0.2.2 新增）

针对"应用题/读题失分"这一女儿的高频真实痛点（创始人确认），当归因判定为审题/读题失误时进入专项训练，分三步：

1. **圈关键信息**：Agent 引导女儿在题干中圈出已知条件、隐藏条件、所求目标
2. **复述题意**：让女儿用自己的话复述"这道题让我求什么、给了哪些条件"（Agent 只确认、不评判）
3. **数量关系建模**：Agent 引导女儿说出"条件与问题之间是什么关系"（如"总价 = 单价 × 数量"），再重做原题

判读逻辑：读题训练后重做原题或变式，连续 2 次通过 → 确认为"读题类"并进入变式验收（§5.1 ⑤）；若仍失败 → 切换检查是否为"概念不清"（知识点本身未掌握，而非读题问题）。

## 6. 教育模型（v0.2 严谨化）

### 6.1 掌握度状态机

```
未接触 → 学习中 → 短期掌握 → 长期掌握
              ↑        │
              └────────┘（变式/复习未通过 → 回退学习中）
```

- **短期掌握**：变式验收当天通过
- **长期掌握**：至少一次间隔复习通过（1/3/7/14 天后仍通过）——**只有长期掌握才算真正学会**

### 6.2 前置依赖知识图谱（MVP 简化版）

- 只为女儿当前年级数学核心章节建立前置依赖（如 分数乘法 ← 分数意义 ← 整数乘法）
- 诊断到薄弱点先查前置；前置弱则先补前置，避免治标不治本
- 不做全学科图谱，控制在当前学习范围 1–2 章逐步扩充

### 6.3 讲解质量保障

- 讲解绑定教材/教辅原文来源（RAG 引用）
- 关键概念"多角度讲解"；间隔复习失败自动更换角度

## 7. 数据来源设计（"家长零录入"落地）

| 数据类型 | 采集方式 | 负担 |
|---|---|---|
| 教材/教辅目录 | 一次性导入（PDF/图片 OCR → 核对知识点清单） | 家长一次性 1–2 小时 |
| 当前学习进度 | Agent 对话自然询问 + 家长一次性确认 | 零日常负担 |
| 错题/作业错误 | 女儿拍照 → OCR → 自动归类 | 女儿约 10 秒/道 |
| 测验结果 | 拍照成绩单（可选） | 女儿约 10 秒/次 |
| 归因与掌握度 | Agent 自动生成 | 零负担 |
| 家长补充资料（可选增值） | 家长录入入口：老师评语、家长观察与感受、补充教材资料 | 按家长意愿，可零可多 |

## 8. 技术架构（MVP 务实版）

### 8.1 组件选择

- **前端（孩子端）**：**跨端独立 App（Flutter）**——Android + iOS 一套代码；后续的本地重运算（端上推理、知识追踪）与音视频交互（讲解语音、对话回放）都能在 Flutter 内接原生能力实现。**平板优先响应式**（手机/Pad 均可用，导航按断点切换）。**不上应用商店**：Android 直接侧载 APK 安装；如需 iOS，走 TestFlight 分发（需 Apple 开发者账号，约 ¥688/年）
- **前端（家长端）**：独立家长端 App（Flutter，家长手机安装，手机优先响应式，查看日报/周报/录入/设置，打开即用无 PIN 门禁）；微信小程序因需备案推迟到后期
- **大模型**：DeepSeek API（低成本优先）
- **OCR**：成熟 SDK（如腾讯云 OCR）识别错题拍照
- **知识库**：轻量 RAG，MVP 先存少量章节
- **结构化数据**：错题库、掌握度状态机、知识点图谱 → 常规数据库（SQLite/MySQL + KV），**MVP 不引入向量数据库**（避免过度设计）
- **选型说明（孩子端为何选 Flutter 独立 App、不用微信小程序）**：产品后续必有本地重运算（端上推理、知识追踪）与音视频交互（讲解语音、对话回放），独立 App 才能完整承载，且推送自主可控、本地存储充裕、可后台常驻；Flutter 一套代码出 Android/iOS 两端，不上商店、侧载分发即可。不用微信小程序的原因：① 家长常以微信"青少年模式"或系统级时长限制管控微信，孩子端依赖微信即受制于人；② 小程序推送走"订阅消息"、需用户逐次授权，间隔复习提醒做不牢；③ 小程序包体积（约 2M/20M）与本地存储（约 10MB）装不下讲解音频/动画/错题库；④ 无法跑端上本地运算与后台任务；⑤ 未来商业化时"学科培训"类目审核是坎。行业 K6 学习产品（作业帮/猿辅导/斑马AI/洪恩/叫叫等）核心学习体验均为独立 App，小程序仅用于家长端或轻量工具

### 8.2 数据流

```
女儿拍照（Flutter App）
  → OCR 解析题目
  → LLM：归类 + 归因对话
  → 更新错题库 & 掌握度状态机
  → 生成讲解/练习/变式（RAG 引用教材）
  → 验收 & 间隔复习调度
  → 错题画像 & 周报（自动）
```

## 9. 成功指标（以学习成效为核心）

### 9.1 核心指标（学习成效）

| 指标 | 目标 | 度量方式 |
|---|---|---|
| 同知识点再犯率下降 | 间隔复习通过率 ≥ 80% | 状态机自动统计 |
| 闭环完成率 | 进入变式的知识点 ≥ 70% 最终"长期掌握" | 状态机自动统计 |
| 归因准确率 | 家长抽样复核一致率 ≥ 80% | 仅验证期家长每周抽查 5 道（约 5 分钟），校准后免抽 |
| 讲解有效性 | 讲解后基础练习首答正确率 ≥ 70% | 自动统计 |
| 读题训练有效性 | 读题类错题训练后重做通过率 ≥ 80% | 自动统计 |

### 9.2 辅助指标（参与度/体验）

- 每周使用天数 ≥ 4 天
- 单次会话 15–30 分钟（配合防沉迷，不追求更长）
- 家长每周查看一次周报（低参与档基线；中参与档可订阅日报）

## 10. 交互设计

### 10.1 孩子端

- 小鹿虚拟形象，鼓励式、不评判："没关系，我们来看看哪里卡住了"
- 防沉迷：单次最长 25 分钟强制休息 5 分钟；时长家长设定
- 节奏匹配"放学后 15–30 分钟"：每次会话只做 1–2 个知识点闭环，可中断恢复

### 10.2 家长端（按参与度分档，默认克制）

- **低参与（默认）**：每周日自动推送周报——本周学了什么、掌握率变化、重点错因、下周建议；零操作
- **中参与（可选）**：加开每日日报——当天学了什么、完成几个知识点、有无异常；异常告警（如同一知识点连续多天失败）主动打扰
- **高参与（可选）**：开放"家长录入入口"（老师评语、家长观察、补充教材）+ 可查看错题详情
- 默认只展示"已掌握/正在攻克/需关注"三色区域，不展示错题细节（家长升档后可查看）
- 支持一键导出/删除全部数据

## 11. 里程碑（独立开发、业余时间、周期拉长）

| 阶段 | 周期 | 目标 |
|---|---|---|
| 0 原型 | 第 1–2 周 | 拍照 → OCR → LLM 归因+讲解的最小对话原型 |
| 1 闭环 MVP | 第 3–6 周 | 错题库 + 归因对话 + 讲解 + 变式验收（先做 1 个知识点） |
| 2 模型补齐 | 第 7–10 周 | 掌握度状态机 + 间隔复习 + 前置依赖图谱（当前章节） |
| 3 实学验证 | 第 11–16 周 | 女儿真实使用 ≥ 4 周，迭代归因准确率与讲解质量 |
| 4 扩展 | 之后 | 扩展知识点覆盖 → 讲出思路强化版 → 英语 → 评估是否商业化 |

## 12. 风险与应对

| 风险 | 应对 |
|---|---|
| 孩子把 AI 当答案机器、产生依赖 | 先归因后讲解；限制"直接给答案"比例；鼓励先自己讲 |
| LLM 讲解错误被孩子内化 | 讲解绑定教材来源；多角度讲解；间隔复习暴露并纠正 |
| 儿童语音识别/讲解评判不可靠 | MVP 用软性版本（一句话思路），深度评判推迟 V1 |
| 持续成本失控（LLM+OCR） | 低成本模型优先、按需调用、设定月成本上限 |
| 孩子使用意愿不足 | 小鹿形象 + 轻量激励（避免过度游戏化）；节奏短、可中断 |
| 未成年人数据隐私 | 最小必要收集；家长知情同意；数据可导出可删除 |
| 防沉迷失效 | 内置 25+5 机制；时长家长设定 |
| 孩子端被微信管控/受限 | 孩子端用独立 App（Flutter），不依赖微信；防沉迷在应用内自控 |

## 13. 关键成功要素

1. **归因准确**：能否分清"粗心/概念不清"决定辅导方向，是本产品区别于普通题库的核心
2. **讲解质量**：绑定教材来源 + 多角度讲解，是孩子信任与安全的前提
3. **掌握度判定严谨**：间隔重复的"长期掌握"定义，是产品承诺"真的学会了"的可信度来源
4. **使用习惯**：15–30 分钟节奏 + 可中断 + 防沉迷，是孩子长期愿意用的前提
5. **家长零负担（默认）+ 参与度可升降**：默认零录入、零操作，产品自己跑；同时为有条件的家长提供日报、家长录入入口等升档能力——不同参与度的家长都能被满足
6. **女儿真实参与**：产品必须让孩子觉得"有用、不累、不被监控"
7. **读题训练有效**：应用题/读题是女儿的高频失分点，读题训练必须真正改善它（而非只归因、不训练）
