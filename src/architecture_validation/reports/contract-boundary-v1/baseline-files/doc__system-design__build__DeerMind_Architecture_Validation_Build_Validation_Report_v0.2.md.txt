## 1. 阶段判断

R1 修复了模型侧引用合同，并取得了此前缺少的局部真实证据：定位提示实际展示后，新的作答能够经过 Evidence、Belief 和 Policy；新的单位量说明也能够使 Belief 从 UNKNOWN 更新为有限的 DIRECTIONAL。这些是开发样本上的真实执行结果，说明相应链路可以运行。它们不替代六段保留会话、四项 Evaluation 专项和原定 G2 验收。

最后一轮开发联调完成4/6个轮次，两个三轮会话均未全部完成。一轮 Observation 被误拒；另一轮已经转入 Teaching，模型却再次选择 Control，被后端拒绝。已知的“提示已提供定位，理由却否认提供定位”反例也再次被审查器误放。两轮开发上限已经用完，没有达到预先声明的正式复验准入条件，因此没有启动新的24轮正式会话和12个正式探针，也没有追加第三轮修复。

本轮结论不能写成“正式复验再次失败”，因为正式复验没有发生；也不能根据未执行的保留样本推测其通过率。准确的阶段判断是：首次 G2 HOLD 保持，R1 消除了一部分工程阻断、增加了有限组合证据，但尚不足以解除 HOLD。当前仍在 Development Phase 2，不进入 MVP Definition。

剩余结果不足以否定整体设计。引用、状态转换和提交限制可以执行，模型生成及审查仍会给出与输入或规则矛盾的结果。当前这套 DeepSeek Flash 非思考配置、上下文表达和生成/审查合同尚未达到选定场景要求；这不是对所有模型或所有实现的否定，也不能把尚未取得的 Evaluation 验收无限归入未来优化。

## 3. 修复内容及机制证据

模型现在只看到本次上下文允许选择的短 ID 及字段枚举。后端将短 ID 解析成精确对象、版本、修订和 hash，不再根据字符串相似度或拼接格式猜对象。dev2让同一数据库中的短编号保持稳定，避免历史解释中的编号随下一轮排列变化而误指；每次可引用范围仍限于获准 Context。正式记录保留精确引用，原始候选和每次模型编号绑定也保留。

上下文明确区分当前已确认活动、推理职责、学习者原文和实际渲染记录。文本中实际写出的算式及数量关系说明是可观察表现；“我已掌握”“我看过提示”等对能力或历史经历的自述不自动成为确认事实。实际渲染仍不证明学习者读懂；空展示列表在 COMPLETE 范围内只说明受控通道未记录到相关帮助，不证明没有外部帮助。测试驱动的后续输入以目标轮真实 occurrence 为条件选择分支，避免前轮失败后仍声称看过提示。

dev2增加的 Claim依据索引由正式 Claim 引用机械分组，不替模型选择 Evidence 意义。审查输出必须包含四项指定规则；恢复生成可以读取上次失败类型和失败项诊断，但审查新候选时不把上次意见当作事实。每轮至多一个恢复生成/校验对；必需评价失败继续阻断 Policy，没有默认 NoIntervention、旧 Belief 回退或自动绕过审查。

原定24条机制路径与补充检查在R1首轮修复后共38项通过；加入分支检查及dev2修改后，完整离线检查40/40通过，其中仍包含原24条机制路径。32K准入变更后相关5项容量与预算检查另行通过。见[dev2完整离线结果](../../../src/architecture_validation/reports/revalidation-r1/offline-dev2.xml)、[容量及预算检查](../../../src/architecture_validation/reports/revalidation-r1/admission-capacity-dev2.xml)。首个局部检查曾因旧测试仍要求逻辑ID别名而失败，原[失败记录](../../../src/architecture_validation/reports/revalidation-r1/offline-first.xml)保留；该测试已按新合同改为检查短ID精确绑定，并增加错误类型、旧格式和未知编号不得提交的反例。

这些离线检查验证事务、权限、串行、失效、去重、持久化恢复和展示记录等机制，不计为模型质量证据。此前中断迟返、恢复配额调度和本地预算持久化修复得到保留；R1没有再次出现这三类故障，也没有重复初次引用格式失败。一次 Belief schema 错误通过允许的恢复完成，不能据此宣称所有输出格式问题已经消失。

| D1.1 独立错误作答 | Observation两次审查未过，未提交 | 原定初始观察及其后更正对照缺失 |

D1.1的第一次候选写 `current_purpose=IndependentDiagnosis`，运行时也提供 `current_activity=IndependentDiagnosis`。审查理由却先承认两者取值，再把同一取值判成擅自转换。第二次拒绝又把“无法确认学习者后续是否检查”的不确定性说明判成越界。这里有明确的审查误拒。它不说明学科推断本身不可实现，但说明同一模型作为必经审查器时会凭空增加约束。把状态字段的相等性再次交给语义审查，也扩大了产生这类误拒的机会。

D2.3首先正确生成Control，后端实际记录活动转为Teaching。下一次Policy的上下文明示 `current_activity=Teaching`、允许动作只有Hint和Explanation；模型却再次输出Control，并在理由中声称当前仍是IndependentDiagnosis。后端以 `ActionNotAdmissible` 拒绝，没有派发未获准动作。旧Observation确实保存了观察时的诊断活动；模型采用过时活动是输出中已确认的问题，旧元数据造成混淆属于基于上下文的推断，不是可观察的模型内部原因。当前通用候选schema仍列出所有动作，动作选择在物化时才校验；将当前允许集合前移至生成schema是后续可单独处理的工程项，本轮没有在结束后改动再追测。

P06仍给出同一类关键反例：提示点名“检查84÷7”，理由却说没有替代任何定位工作。dev2审查判PASS，并解释“仅点名算式、未提供定位结论”与理由一致。这是明确误放；这次发生在独立开发探针中，没有进入真实决策提交或展示路径，但说明审查器未稳定识别已知语义矛盾。dev1识别正确、dev2又误放，支持“当前修正不能稳定解除已知问题”的判断，不能用前一轮成功覆盖后一轮失败。

## 7. 剩余工作应如何定性

引用合同、中断收尾、预算调度和落盘属于已有处理办法的工程问题。R1消除了此次开发中的引用格式阻断，机制检查通过；不能因此宣布所有模型输出错误都消失。当前动作集合前移到生成schema、减少模型重新填写权威状态，属于可以单独验证的剩余工程项。

合法表现被误拒、定位理由不实被误放，属于当前模型与审查合同的语义质量问题。两轮都保留了明确例子，继续加长整段提示词没有在批准范围内解决它们。现有证据不能区分问题分别有多少来自模型能力、提示与材料组织、角色配置及单模型审查相关性，所以不把全部责任归给供应商模型，也不宣称已经证明无解。

真实Evaluation的完整验收仍是当前Build必须回答的核心未知，不能用开发部分成功替代。下一次若继续，应先决定生成及审查的职责边界：精确状态和值域交给程序，LLM专注含义判断；再为审查组件安排独立、有预算的验证，必要时比较模型或推理配置。若要修改原支持范围或验收条件，须作为新决定提出，不能追溯改写本次成绩。当前没有证据要求推翻七份v1.0设计，也没有依据把G2改为PASS。

本轮已经完成被批准的修复、两轮开发联调和报告收口，按既定停止条件结束。它没有完成G2验收；没有自动安排第三轮开发、第二次正式测量或进入MVP Definition。
