## 2. 本轮范围、修复与版本

R2按Plan §7.4使用此前已准备但未运行的六段四轮样本和十二个正负探针。每段独立数据库，使用相同代码、规范、模型与规则；后续自称看见帮助的输入仅在目标轮实际展示后启用。Observation探针去除已由后端负责的活动字段，其他候选含义不变。样本、参数、评分标准及77项源码/文档hash在[v2冻结清单](../../../src/architecture_validation/reports/g2-r2/v2/freeze.json)保存；执行期间未修改这些文件。

模型为deepseek-flash，thinking=disabled、temperature=0、JSON对象输出、单请求最多8192输出tokens、60秒超时。本地输入准入32K估算tokens、200K封装字符，采用官方离线分词器加25%及512 tokens余量。实际最高准入估算16,067，没有容量阻断或静默截断。供应商别名没有固定到不可变模型权重，temperature=0也不保证重复输出。

最初v1在S1.3被格式问题阻断：Belief额外写出合同未定义的assessment_kind_note:null，恢复时又写epistemic_status_note:""。立即增加按schema移除无内容额外字段的适配，保留原文和修改位置；非空未知字段、布尔、数值及容器继续拒绝，已知字段和语义内容不自动补写。错误消息也明确指出不符合的规则及字段。原来的同值重复JSON字段合并继续保留，冲突值仍拒绝，供应商响应封装继续严格解析。

两个真实失败返回固化为回归夹具；[29项针对性检查](../../../src/architecture_validation/reports/g2-r2/format-fix-tests.xml)和[完整75项检查](../../../src/architecture_validation/reports/g2-r2/v2-offline-tests.xml)通过。v2从S1第一轮重新执行全套，未拼接v1的成功轮次。v2真实运行规范化了18处同值重复字段和9处空额外字段，均继续经过原schema、语义审查和owner提交。这说明修复确实处理了再次出现的格式问题。

v1共23次HTTP尝试、2轮正常完成及1轮格式失败，单独保存在[v1结果](../../../src/architecture_validation/reports/g2-r2/S1.json)、[修复说明](../../../src/architecture_validation/reports/g2-r2/implementation-repair.json)和[v1证据包](../../../src/architecture_validation/reports/g2-r2/v1-evidence.zip)。v2的24轮才是本次G2评分对象；两个版本的全部费用仍共用R2账本。

## 4. 剩余问题的具体原因与处理级别

**缺少说明被当成反证。** S3.1学习者只写“44÷4＝10，10×9＝90”。Evidence正确识别除法错误，却进一步认为“商算错且没有解释数量关系”对单位量理解构成反证。Belief采用了这条Evidence；两层语义审查都放行。S3.2的新Evidence已经写出“缺少解释不等于理解错误”，Belief仍把旧条目作为有限反向依据保留。S4出现相同类型。已有Claim和EvidenceSemantics要求区分材料缺失与不能说明，输入也包含这些规范；不是后端漏传规范或格式解析失败。问题在于生成、审查和后续聚合没有一致执行这条语义区别，并且错误一旦入库会持续影响后续判断。

**换题后误判独立性。** S6.1系统实际提示“先用总量除以份数求每份价格”。S6.3换成新数值后，模型以“旧提示只针对上一题”为由把整题记为独立完成的正向证据，并据此更新Belief。S6.4学习者明确说“新题也用了先前提示的方法”，模型仍支持整题独立完成。新商是学习者算出的，可以支持相应计算责任；方法识别已受帮助，不能因换题自动归为无帮助整题完成。上下文保留了原提示和实际发生引用，所以这是相关性解释错误，不是帮助记录丢失。

**审查器仍会误放自相矛盾的理由。** 十二探针全部取得可判定返回，11/12符合预期：六个正例全部接受，六个负例中RP06被接受，误放1/6，误拒0/6，无UNRESOLVED或格式失败。RP06拟展示“请重新检查132÷11这一步”，理由却称完全未提供定位；审查器仍PASS，并把这段理由误读为承认有限定位。提示是否合法与理由是否真实是两个检查点。此探针本身没有进入学习者会话，不单独作为整个架构失败的依据，但明确说明审查PASS不能消除前两类风险。[原始探针结果](../../../src/architecture_validation/reports/g2-r2/v2/probes.json)保留完整返回。

R1未准入与R2已执行是不同批次，不能继续将当前状态写成“正式验收尚未开始”。Spike已完成，A2 DENIED、E1/X5 INCONCLUSIVE及七份v1.0系统设计保持原有身份；当前仍在Development Phase 2，尚未进入MVP Definition。

人工复测继续使用仓库根目录的`deermind.cmd start`启动后台并打开前端，`deermind.cmd status`查询，`deermind.cmd stop`停止；参数和离线模式见[实现README](../../../src/architecture_validation/README.md)。人工实例使用独立数据库和预算，不写入已关闭实验结果。真实模式使用已配置的密钥，无需因本轮网络重试重新配置。

本实现仅验证单进程、本地持久化、受控浏览器和合成文本学习者。渲染确认不代表学习者看见或理解；没有真实儿童、长期学习收益、校准掌握概率、多租户或分布式可靠性的结论。B5已完成本轮证据整理与G2判断；下一步针对明确的语义缺口制定受限修复验证，不继续无边界的全量测试。


## 7. R3专项修复、失败边界与默认配置回退

R3按Plan §7.5执行一次语义修订：进一步区分缺失说明与反向表现，明确方法帮助的跨题影响，要求Belief检查旧Evidence是否存在解释错误，并将三项Claim共享四项总评改为每个Claim各四项。没有改变正式Claim、认识对象、owner或G2门槛，也没有引入关键词语义判断。调用前冻结16个原始上下文重放、10轮专项会话和条件准入后才可执行的正式样本，配置仍为DeepSeek Flash非思考。执行期间82项冻结文件未变更。

**专项没有达到准入，正式复验调用为0。** 原始10个Evaluation审查正反例仅5个标签符合预期；其中两项属于分项全PASS而总评FAIL的机械汇总问题，按正确的确定性汇总离线重算为7/10，仍有两项误放和一项误拒。这个7/10是同一批分项的离线核对，不是新模型测量，也没有改变原来的事务结果。另有一个拒绝标签虽然符合预期，其理由却错误要求重复解释不能形成修订，说明标签命中不等于理由可靠。两个Policy理由诊断分别接受合法提示、误放否认定位的理由，后者仍存在。

四个重新生成中，两项在目标边界上改善：缺少单位量说明不再被当反证；原先错误的单位量反证也能被Belief明确排除。但其他问题保留：一项输出承认方法责任受到替代，却仍支持无帮助整题Claim；另一项去掉新的错误支持，却保留具有相同错误前提的旧支持。因此不能把局部改善当作传播问题已解决。一次Belief返回存在值不同的重复conflicts键，严格解析正确拒绝；按原有一次格式恢复重新生成后schema通过，但语义仍错误，原失败与恢复分开保存。

十轮真实专项有5轮正常完成，按同一四维尺度只有3轮内容可用；两个四轮场景均未完整完成。原讲解场景D3没有实际显示讲解，方法提示场景D6的提示也被审查误拒，后续按“没有看到提示”的冻结分支继续。因此本轮真实链路没有覆盖帮助之后的原关键对照，不能把后续计算成功算作帮助问题已修复。两个相邻对照中，“按6份平均分得到一份”的解释取得有限支持；“把总价当单位价”的明确错误两次分项全PASS，却被错误总评阻断。

| 发现 | 定性与处理 |
| --- | --- |
| 分项全部PASS，总评却FAIL | 可确定的实现问题。最终总评改由程序根据所有必需分项汇总；模型原始总评留作审计。六份真实异常回放通过，未改任何分项语义判断。 |
| 重复JSON键有不同值 | 不能擅自取首值或末值。保留拒绝，通过一次重新生成恢复格式；不把格式恢复当语义通过。 |
| 缺失与反证、方法帮助延续仍误放 | 当前语义Profile未解决根因，准入失败；不追加第二轮调词，也不启动正式G2。 |
| 新的误拒和依据误排除 | 同一评审先要求不许REVISE，恢复后又要求必须REVISE；还出现仅因换题排除同Task Family旧Evidence。属于该候选Profile的副作用。 |

本次实验的语义改动和逐Claim审查结构已从默认运行路径撤回，原代码保存在[source.zip](../../../src/architecture_validation/reports/evaluation-repair-r3/source.zip)，[回退记录](../../../src/architecture_validation/reports/evaluation-repair-r3/rollback.json)指向R2基线。当前默认Profile是R2语义规则加确定性审查汇总：任一必需分项FAIL则总评FAIL，有未决则不通过，所有必需分项完整且PASS才通过。缺项、空理由、错误引用及schema失败仍不能提交；不会用程序替换任何LLM分项语义判断。Validation同时记录原模型总评与汇总规则。此改动经过实际异常输出回放和owner提交路径检查，最终完整81项离线检查通过；当前组合尚未重新进行完整真实G2测量，不回填R3已失败的会话成绩。

R3共104次HTTP尝试、94个逻辑请求，含一次格式恢复；10次传输失败全部按原规则恢复，没有形成未覆盖或语义扣分。已确认输入418,578 tokens、输出59,196 tokens，按冻结单价估算1.310724元；连同无usage尝试的保守预留为2.082098元。账本活跃450.94秒，约7.52分钟，不含编码、评阅和文档整理；10轮中位33.57秒、样本P95为51.26秒。均未触及本批资源上限，停止原因是准入条件不满足，不是额度耗尽。

[专项结论](../../../src/architecture_validation/reports/evaluation-repair-r3/assessment.json)、[逐例评阅](../../../src/architecture_validation/reports/evaluation-repair-r3/quality-review.json)、[准入决定](../../../src/architecture_validation/reports/evaluation-repair-r3/admission.json)、[最终离线检查](../../../src/architecture_validation/reports/evaluation-repair-r3/final-offline.xml)及[证据包](../../../src/architecture_validation/reports/evaluation-repair-r3/evidence.zip)保存完整依据。准入守卫已离线确认拒绝正式执行，没有额外API调用。529条记录、1,739处精确引用和四个数据库完整性核对无误；这些检查不证明语义准确。评阅仍为作者/Codex，不是独立人工盲评。

本次得到的明确结论是：这套规则细化与审查拆分没有在当前配置上解决问题，不能默认启用，也不支持解除G2 HOLD。它没有证明所有规则组织方式都无效，更没有否定Evaluation的架构责任。下一步应做控制变量的推理配置或审查模型对照，固定原失败及合法对照，比较实际纠错与误拒，而不是默认再进行一轮同类规则微调。模型选择、能力支持和费用需要在该对照开始前核验；本报告不把更换配置写成已经验证有效的解法。R3已关闭，剩余预算不自动转为后续调用。


## 8. R4固定输入的推理配置对照

R4按Plan §7.6比较现有deepseek-flash的非思考与思考high。两组每例一次主请求，输入为10个Evaluation审查正反例、2个Policy理由诊断和4个生成任务，共32个；原始上下文来自R2，恢复R2四项审查schema，没有沿用R3逐Claim实验结构。按案例交替执行先后顺序。实际发送的16对messages和schema逐字一致，87项冻结源码/文档在执行期间未变更。两组均为JSON输出、max_tokens=32768、timeout=120秒；非思考temperature=0，思考模式不支持该参数，因此不发送。参数依据[官方说明](https://api-docs.deepseek.com/guides/thinking_mode/)，[运行前冻结清单](../../../src/architecture_validation/reports/reasoning-comparison-r4/freeze.json)保存完整范围和筛选条件。

**没有一组达到下一次真实链路实验的筛选条件，本批关闭，不进入完整G2。** 这不是因格式或网络阻断：32个主请求均取得schema合格结果，未使用格式恢复；3次传输失败全部重试恢复。以下全部是本次主结果，不使用R2/R3成绩补齐。

| 指标 | 非思考 | 思考high |
| --- | --- | --- |
| Evaluation审查标签符合预期 | 5/10 | 7/10 |
| 错误候选被放行 | 5/5 | 3/5 |
| 合法候选被误拒 | 0/5 | 0/5 |
| 标签及全部拒绝/接受理由均成立 | 5/10 | 6/10 |
| Policy理由诊断符合预期 | 1/2 | 2/2 |
| 重新生成满足预定核心边界 / 整体可用 | 1/4 / 1/4 | 0/4 / 0/4 |
| 单次成功请求API耗时中位数 | 2.62秒 | 25.05秒 |
| 单次成功请求API耗时样本P95 / 最大值 | 5.25秒 / 5.25秒 | 63.13秒 / 63.13秒 |

思考组新增识别了R02的“商错不等于关系解释错”、R04的“方法提示可能延续到同族新题”，以及R12的“提示已定位，理由却否认定位”。但R02同时提出了不成立的额外拒绝理由：把本已有错误商支持的除法反证也归为过度推断。因此7/10只表示标签匹配，不等于七项理由全部正确。两组均放行R01、R03、R05，五个合法对照均接受；本小样本没有观察到新增误拒，不代表误拒风险已消失。

重新生成揭示了更直接的不一致。非思考R13能正确写出“没有数量意义说明，所以单位量Claim为NonInformative”，但同组R01审查错误候选时却认可反向证据。思考R04能拒绝“旧提示只属于旧题”的理由，同组R15生成时却仍称新题独立完成，并把先前方法对后续新题的影响误称为倒灌。两组R14/R16继续采纳原错误Evidence，限定为“有限方向性”并没有纠正依据。思考R13还将只有算式、没有数量意义说明的材料写为Supports；这不符合运行前冻结的说明责任和NonInformative准则。这里缺的不是“已证明掌握”，而是该Claim要求的说明行为。

这些是观察到的输出差异，不足以单独证明模型内部成因。较合理的工程假设是，当前合并任务和候选导向审查容易接受已有解释，已提交Evidence又持续影响聚合；但R4没有比较不同的任务拆分、候选隐藏或owner纠错方案，不能把该假设写成已经确证的根因。尤其，R13至R16分别重放原始上下文，R14/R16刻意包含旧错误Evidence；没有把新生成结果接成真实会话，也没有测试“非思考生成＋思考审查”的组合。因此既不能宣布这种混合组合有效，也不能据此宣布它永远无效。

当前能够关闭的结论是：**只把现有配置开启思考high，不足以作为本实现的G2修复方案。** 局部审查有改善，生成与旧证据传播仍失败，且单次成功API请求的中位耗时约为非思考的9.6倍。R4不再增加第三档配置、不换模型继续抽样，默认服务维持原非思考参数；实验的32768输出额度和120秒超时只用于这次显式对照，默认仍为8192和60秒。90项离线检查包含新增参数、费用预留和默认兼容性检查，不把这些检查当语义正确率。

后续工作应转到Evaluation的具体实现组织与纠错流程，先形成可审阅的方案，再决定是否值得运行：分别约束每个Claim可由哪些观察支持，区分独立解释材料与核对候选；对已识别的错误Evidence，由Evaluation owner更正并使下游按有效依据重算，不能只让Belief用谨慎措辞沿用原错误。原设计已经要求owner correction/replacement及下游重判，见[证据评审§1.1](../DeerMind_System_Design_Evidence_Review_v1.0.md#11-adr-001-语义校验的保证范围)；当前实现已有失效传播和重算入口，仍需明确语义错误如何被识别、送回原owner、修订并验证。此建议不是已经验证的解法，也不授权降低G2、使用关键词替代语义判断或要求每次下游无条件复审全部上游。R2完整验收、R3规则修订和R4配置对照已给出各自明确结论，应停止把现有方案视为只需再调一次参数即可通过。

资源共35次HTTP尝试、32个逻辑请求；非思考18次尝试含2次传输失败，思考17次含1次失败，全部恢复。已确认输入156,126 tokens、输出96,272 tokens；其中思考组输出88,925 tokens，包含推理输出。按冻结的缓存未命中/高峰单价估算，已确认usage费用1.082428元，含未知usage尝试预留的保守费用1.890798元；实际供应商账单可能因缓存和时段优惠更低。账本适配器活跃498.91秒，约8.32分钟，不含编码、离线测试和作者评阅，未触及96次、15元或30分钟上限。两组单独资源及完整时延口径见[结论与指标](../../../src/architecture_validation/reports/reasoning-comparison-r4/assessment.json)，计价依据见[核验记录](../../../src/architecture_validation/reports/reasoning-comparison-r4/pricing.json)。
