# 集成设计候选与阶段范围评审（2026-10-07）

本次评审完成的是三个修订候选的合同核对和阶段取舍建议，未批准正式基线、修改原 Completion 或关闭 Gate。依据现有文件进行作者复核，没有独立盲评、模型调用或测试运行。原 9/17、A2 DENIED 及全部 INCONCLUSIVE 保留。

## 1. A2：撤回过强承诺，保留执行约束

建议采用总体设计 v0.3 的修订方向。上位 [AI-native 原则 §5.3–5.4](../../../doc/top/DeerMind_AI_Native_Architecture_Principles_v0.2.md)已经区分确定性提交与可出错的语义判断，并允许派生语义追溯、更正和重算。原 AA-A02 将这些机制进一步假设为足以隔离开放文本中的越界语义；两次错误正式提交否定了这个工程假设，不等于证据已经否定 SI-04 或 SI-13 本身。

替代原承诺应分成两项，不能合成一个新的“可靠通过率”。第一项是可检查的提交义务：每个必需校验均完成且通过，绑定 exact candidate、Context、规则和执行；权限、版本、依赖及生命周期也成立，否则不提交。第二项是声明范围内的内容质量义务：Observation 不产生能力认定或 Policy 决定，合法局部描述及归属明确的请求仍须可用。语义规则和 LLM 负责后者；确定性机制不被宣称为开放语义证明。

第一项有局部实现证据，第二项有已知失败和未决，不能相互抵消。下游按自己的职责判断输出，不继承上游权限，不假定第二次判断必然纠错；发现误提交仍更正并保留历史。仅保留 PASS 的局限说明尚不足以完成修订验收：必须在正式基线采用替代命题，声明其适用 Profile 和证据，并按原 Spike §17.3 保留受影响验证要求。

结论是设计修订方向合理，不需要因本反例立即重开 Concept Architecture，也没有证据支持“所有语义越界已解决”。原 AA-A02 仍 DENIED，不建立未经证明的后继 SUPPORTED。

## 2. A1/E1：最低要求已经可以固定

| 对象 | 最低义务 | 如何判定缺陷 |
|---|---|---|
| 完整作答 Observation | 有来源的方法解释、可见计算判断、已提交最终答案的独立判断；不读取 Learner Belief | 只定位一步但漏掉所需方法或最终答案，仍不完整；不能因已有片段正确而放行 |
| 未完成作答 Observation | 保留实际表达与确实未知；不补造已提交值；已有答案仍判断 | 将未求值表达补为学生的计算结果，或以步骤缺失免除已有答案判断，均不满足合同 |
| 请求 Observation | 保留请求归属、对象、限制；按生成前声明目的处理混合材料 | 请求不是活动切换、权限授予、稳定偏好或能力事实；不能失败后改用较窄合同补救旧候选 |
| Policy | 事实或假设有来源，行动符合当前请求和活动；理由如实描述帮助与剩余责任，字段间无明确冲突 | “再检查 42÷6”已经帮助定位；仍由学生重算不能支持“未帮助定位”。另一字段的正确说明也不能抵消错误断言 |
| 评审材料不足 | 分开执行失败、可判断的不合格、无法完成判断 | 当前评审看不到依据，不自动证明生成时没有依据；必要依据无法核实则不得补记 PASS |

上述合同已在三份候选中一致表达。责任相关的硬缺陷不能以总体 utility 分数补偿；grounding、responsiveness、responsibility_cost、consistency 是逐维可审阅问题，不是额外四个生产 reviewer。开放含义判断仍使用规则与 LLM，文档复核不能变成关键词准入规则。

验收时先检查单项是否执行完整，再对照来源与声明义务判断内容。执行失败不计语义成功；模型 PASS 不自动裁决已知内容争议。作者标签、具体异议、原始输出及未决都保留，不能把本次同一作者复核称为独立准确率验证。最低要求已经明确，但当前没有批准模型质量阈值，也没有足够证据证明选定实现达到稳定质量。因此本次不启动新批次；如果随后需要补证，必须先固定判据与成功、失败、未决的终止处置。

## 3. 可以延后的能力及适用条件

建议延后 X5 的完整自动诊断转教学，而不是延后失败收束或活动权限。拟保留的最小交互范围是：活动开始时明确登记目的与获准动作；在同一活动内完成单任务作答或请求、Observation 和 Policy，执行获准的局部 Hint / AskForExplanation 类动作并记录实际披露。不启动自动活动切换或跨轮计划；原活动不允许的讲解明确不执行，请求仍可以得到合法的失败、等待或不行动处理。

这个范围在合同上不依赖自动转换：没有切换 Intent，就没有必须消费的成功转换事件；没有实际转换，就始终按原活动约束判断；发生帮助仍进入实际披露历史；下一普通轮次仍须等待前轮收束。因此延后的是新增交互能力，不是撤去提交、串行、权限和帮助历史义务。

但这只是设计层的依赖论证，不能冒充现有默认实现已禁用该能力。正式采用前必须有版本化范围配置及其执行入口限制，并核实无旁路派发、Context 不预先读取新活动条件、失败 Control 不开启教学。现有局部 mock 证据不覆盖全部真实边界。原 X5 缺失路径继续保留，当前不将它记为已获批准的 STAGED。

基础 Evidence / Learner Belief 不能从最小闭环中全部删除。[路线图 §7.2](source-baseline-design-review-20261008/originals/DeerMind_System_Design_Roadmap_v0.5.md.txt)明确保留它们；可以延后未经验证的自主能力更新方式，但保留范围仍需真实、Claim-relative 的 Evaluation，不得用脚本输出或 Policy 自述代替。远端停止、未知效果对账和崩溃恢复可以作为另行限定的运行能力研究；在这些能力未成立时，存在无法确认的在途 effect 就不得释放串行队列。

E2/F2/X1/X2 的 46/55 有限结果足以建议保留已观察到的机制方向，不足以取消九条缺失真实路径。网络失败和多结果拒绝属于有效失败记录，不是已完成成功链路。原权限、纠正失效、执行前复核等基础约束继续保留，不能因为缩小功能范围而延后。

## 4. 一致性检查与退出结论

核对了[总体设计 v0.3](../../../doc/system-design/DeerMind_System_Design_v0.3.md) §3.2、§7.7、附录 A/B，[AI 推理运行时 v0.2](../../../doc/system-design/DeerMind_AI_Reasoning_Runtime_Design_v0.2.md) §6.6、§8.5，以及[交互决策运行时 v0.2](../../../doc/system-design/DeerMind_Interaction_Decision_Runtime_Design_v0.2.md) §7.13、§8.10 和附录。三份修订的必需校验、失败旧候选禁用、实际 Control 条件及真实披露责任一致；历史原假设明确作为旧输入保留。未发现这些修订之间的合同冲突，这不等于完整基线或实现验收通过。

发现一项尚未整合的状态问题：路线图 v0.5 §8 仍写 Phase 4 IN PROGRESS / Spike NOT STARTED，新总体设计已记录固定实验执行结束。该段是旧路线图快照，不能再作为当前进度说明；正式基线采用时应更新为证据评审状态并保留历史版本。其他专项仍引用旧总体版本，因此三份候选不能单独宣告整个 Baseline Set 一致冻结。

原 Spike §17.1 要求完整场景及重复执行，§17.3 要求否定后修订和受影响验证，未决需后续验证。Gate E 虽允许修订或有依据的阶段化，也不能自动废除这些执行要求。当前可以结束无界调优并完成本次合同评审，不能宣布原 Spike 验收完成、Gate E/F 通过或直接进入 Build。

剩余工作现在限定为三件：采用明确的替代假设和最低合同，并同步基线引用及状态；决定是否采用上述不依赖 X5 的功能范围，并给出实现限制证据；按保留或明确修订的 Completion 条件列出最少补证项及终止决定。若坚持原条件，就必须补齐原缺口；若改变阶段要求，必须明确记录改变和理由，旧 9/17 不变。后续不再用增加版本、测试数或相同候选的新 PASS 代替这些决定。
