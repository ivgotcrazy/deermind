## 3. Observation 两批实验的界限与收口

当前采用规则约束下的 LLM 解释开放含义，确定性程序核验结构、精确绑定、算术和显式类型准入。该分工继续成立；不得使用关键词或正则代替职责判断。S1、S2 是本阶段的研究上限，现已完成；以下保留预声明范围与判断规则，不把每次提示词变更重新计成一个没有上限的新起点。

| 批次 | 固定覆盖范围 | 执行数量与调用上限 | 目的 |
| --- | --- | --- | --- |
| S1，契约修订与回归 | v10 八项职责样例、八项算术样例、八项明确列出的来源样例，共 24 项 | 每项五次，共 120 次候选执行；通常三次调用，含至多一次来源复核，上限 480 次 | 在不放宽来源语义要求的前提下验证格式与检查范围修订，保留已知误放和误拒 |
| S2，新增表达验证 | 六组正负配对，共 12 项：Evidence 判断、委婉能力认定、引用后认同、条件行动建议、来源中的指令、局部不确定与潜在状态推断 | 每项五次，共 60 次候选执行；上限 240 次调用 | 测试未用于提示词调试的表达，避免只适配已知句子 |

两批预算合计至多 720 次 API 调用，通常初始调用为 540 次。这是包含复核的硬上限，不是必须耗尽的配额，也不含其后独立的 A1、Policy、Action 验证。按 v10 实际 47 次调用约 2.2 分钟作线性外推，仅网络执行约为 25–34 分钟；这不是完成时间承诺，模型延迟和输出长度变化会改变耗时，也不包含实现与审计。本计划不估算金额。

S1 的来源八项取自 `observation-support-v1.json`：attributed_self_report_positive、chinese_positive、final_omission_negative、fabricated_attribution_negative、quoted_request_wrong_speaker_negative、translated_self_report_positive、additional_solution_supported_positive、additional_solution_unsupported_negative。其余历史样例不因此获得通过结论；这里声明的是有界选定回归集，不称为所有历史样例全量回归。

具体 S1 / S2 fixture、预期、v11 修订协议、代码与运行顺序均在第一次真实调用前冻结，详见[运行前方案](observation-closeout-design-20261004.md)。事后核对 95 个冻结输入指纹未改变。两批文本与标签都在 S1 前保存，S2 未用于提示词调试；没有另一位独立审阅者，因此称为未用于调试的新样例，不称为独立盲测。机器清单现记录执行与评估完成，结果 INCONCLUSIVE。

两批使用同一冻结修订方案和模型配置。S1 有失败时先归因；S2 仅在输入协议可执行且没有已确认的修改后方案越权反例时继续，用于区分样例适配与更一般的效果。不得根据 S1 返回改写 S2 标签或提示词。如果关键误放、不可执行契约或预算耗尽使 S2 不能按计划执行，记录剩余未运行并直接形成阶段结论；不暗中插入第三批。

在运行前分别声明三个测量层次：组件判断是否准确、组合验证是否有效、最终 standing / 下游效果是否符合合同。旧批次的“全部判据符合”口径不变。新方案允许组件错误被明确的组合机制拦截，但必须完整报告该错误；这只可能支持组合方案的限定范围，不能证明单个 reviewer 正确。正例必须完成检查并可用，不能靠全部拒绝获得支持。结构失败、未决和未执行不计为正确拒绝；对合法局部 ambiguous 的承认，也不同于所需校验自身 UNRESOLVED，前者不能被一律拒绝。

两个批次结束或提前停止后，必须在以下结果中作出选择：在声明范围获得支持；被可信反例否定并给出设计修订；证据不足而保留未决及具体缺口。只有另一次明确的设计决策才能启动额外研究，不能自动递增版本继续试到通过。原 AA-A02 的 DENIED 永不被新批次冲销。新方案也必须补齐 A2 的下游内容准入和非模型失败注入，两个模型批次本身不能关闭整个 A2。

本轮已执行上述收口：未触发必拒负例实际提交的反证，但合法正例全部可用的支持条件失败，且存在 14 次协议或运行失败，故为 INCONCLUSIVE。职责分类额外拦截五次负例，也误拒三次正例、使两次正例未决；不能只统计拦截收益。v11 不升级为已验收的语义准入，合同失败和未决仍不得取得 standing。后续独立机制验证可使用声明的脚本输入隔离问题，结果不得被用于补造 A2 语义支持。

## 4. 工作顺序、时间检查点和停止条件

M0 时的原始规划为约 4–6 个工作日的工作量区间，不是自动后台执行日历，也不保证届时 v1.0 可以冻结。约半天至一天用于 Observation 有界实验与结论，约 2–4 天用于其余链路和组合验证，约一天用于统一报告与设计修订。每一阶段结束均按实际缺口重估；时间到期但工作未完成时必须报告未完成，不能将缺失结果标为通过。

2026-10-04 的 M1 检查点：有界实验和 B/C 评估均已交付，剩余工作量暂估约 3–5 个工作日，主要是共享运行链、组合验证和统一设计收口。该估计仍不是截止承诺；A2 的未决设计不会因时间估计而获得支持。

## 5. 已引入复杂度及待验证的代价

| 机制 | 引入原因与已有证据 | 正确性依赖及后果 |
| --- | --- | --- |
| 每次解析使用内存快照 | 形成一致读取基础，B/C 基础检查采用该机制 | 需要一致读取语义；深拷贝只是实现，不提供生产规模性能结论 |
| 精确来源字段、完整检查声明与一次矛盾复核 | 虚构转述及“原话存在却被判不存在” | 当前验证方案依赖这些约束；复核至多增加一次调用，存在原文不自动说明归属和含义正确 |
| LLM 算术抽取与精确验算 | 综合语义 PASS 曾放过算术错误 | 增加一次调用；验算正确依赖抽取与语义映射忠实，不能取代其检验 |
| 严格返回契约与来源编号 | 减少无效格式及错误精确引用 | 格式失败仍存在；编号和 schema 只能保证结构，不证明语义 |
| 逐片段归属、边界判断和离线标签 | 分开候选归属、来源真实性与职责 | 模型仍可能认出 system/endorsed 却错误放行；标签不进入真实决策 |
| 独立职责分类与显式准入表 | v10 两次拦住旧误放；v11 额外拦住五次负例，但三次误拒、两次未决合法正例 | 再增加一次调用；同模型错误可能相关，分类误标仍可绕过；有界实验未满足支持条件 |
| 回放索引、独立原始字节与操作能力报告 | C1/C2 精确历史读取及缺失降级通过 | 索引不创造语义 standing；原始材料缺失不能由新输出补造；当前 provider 和 retention 是受控实验 fixture |
| ActionIntent、展示确认与终态幂等查询 | D1/D2 实际披露、时间及相对 Claim 表达通过 | 依赖受信 mock 确认；当前扫描历史且单进程，不提供生产效果或并发保证；未新增权威 Exposure Model |
| Policy 内容校验与独立测试评分分离 | E1 真实选择与行动链已运行，评分不参与准入或修改输出 | 每次最多三次模型调用；同模型评分可能共同漏判，原始 PASS 仍须处理评分争议 |
| 单会话轮次状态机与显式 current-head 要求 | E2 三条两轮路径覆盖到结果处理，十次外部更新触发提交 / effect 拒绝 | 内存队列及受控交错不等于生产并发；两条网络失败路径未完成，恢复交互另验 |
| 工具请求与后端身份 / 精确范围检查 | F1 声明范围支持；F2 五条双结果协议失败，独立后端攻击均拒绝 | 固定路由和执行身份绑定增加显式边界；模型字段绑定及单结果契约仍有可用性缺口，未覆盖生产身份设施 |
