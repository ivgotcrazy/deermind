## 串行与失效证据

SerialSession 将一个活动轮次限制在单个 conversation 内，保留 InputQueued、TurnStarted、TurnContextBound、TurnPolicyResult、TurnIntentBound、ActionResultProcessed、TurnSettled 事件。A 的普通 T2 输入在 T1 Policy 调用开始后到达，事实和排队记录立即保存，但没有进入 T1 的冻结 Context。reasoning、Intent 待执行、effect 已返回但结果尚未处理、结果处理完但轮次尚未收束四个位置，启动同会话下一轮均被拒绝。

完整 A 路径的受控时钟关系为：T1 实际展示在 38，结果处理在 39，T1 收束在 40，T2 启动在 41，T2 的正式 Observation 提交在 42，新 Context 绑定在 43。T2 的 Context 包含其当前输入、正式 Observation 和 T1 已发生的实际披露，随后才调用真实 Policy。该证据验证串行边界覆盖了行动结果处理，而不只限制 LLM 调用顺序。

断连的两条路径没有 Policy 正式提交、ActionIntent 或实际展示，T2 也没有启动。对应 T1 保持未收束，保存的排队事实不丢失。本轮没有测试如何从异常中恢复或向用户解释失败，因此不将“没有提前启动 T2”夸大为完整的恢复能力。

B/C 的外部变化来自明确的 `C-external` / Evaluation owner stimulus，通过 Context、Candidate、脚本校验和正式 Commit 形成 LearnerBelief:r2。十次更新均真实提交，没有直接安装派生 r2，也没有把同会话排队输入当作已处理的新依据。旧 r1 保留不变；当前 Context 对它明确声明 CURRENT + require_head，因新 head 已存在而失去这一使用资格。Context assembler、提交及 effect 路径都可检查该要求，不把任何新 revision 普遍等同于对历史的撤销。

B 中原始模型请求、候选和校验仍绑定 r1；r2 在提交前已存在，五次原候选均因 RequiredHeadChanged 拒绝，没有静默换用 r2。C 中原 Policy 已提交、Intent 已形成，外部 r2 随后提交；执行器在实际展示前再次检查依据并拒绝，之后按 NotOccurred 处理结果、收束当前轮次。不存在用 Intent 充当已经发生帮助的记录。

本实现是单进程可控交错。注入点位于 adapter 已记录模型调用开始、请求已构造之后，具体发生在 transport 向真实 provider 转交之前；它验证冻结 Context 到提交之间的外部更新窗口，不声称模拟了远端模型计算时的真实线程竞争。独立 owner 在 C 活动期间可以提交，其他 conversation 也可独立启动；没有引入跨会话 learner-wide lock。生产线程、分布式事务和崩溃恢复仍在本轮范围之外。

## 审计、结论与后续

调用前 188 项本地测试通过，其中六项新增检查覆盖完整交错路径、提前收束 / 重入拒绝、旧 head 的新 Context 拒绝、其他 conversation 独立启动、重复输入及错绑 Context，以及真实 Policy 未选择 Execute 时不得伪造 effect 覆盖。

[离线审计](serial-e2-audit-20261004.json)核对 112 个冻结输入、十五个一致的初始快照和十五份结束快照、原始汇总及所有调用。逐条核对十一次真实 Policy 正式提交、五次 stale 拒绝、十次独立 owner 的 Belief:r2 正式提交、旧 r1 保留、CURRENT / require_head 声明、模型上下文未重绑，以及三个完整两轮时序。原始目录与结果不覆盖，正式结论另存于 [AA-E02 评估](assumption-e2-20261004.json)。

这些证据支持继续沿用“单会话完整轮次串行 + 关键依赖重验”的实现方向，尚未发现需要 learner-wide lock、普通输入重叠处理或 silent rebase 的必要性。但 A 只有三次完成，按预声明条件本轮不把 AA-E02 升为 SUPPORTED，也没有观察到足以将其判为 DENIED 的架构反证。后续若需要补足模型路径，应另作明确的有界决定；当前不自动重试或修改提示词。

总体完整验收仍为 6/17。E2 的实现、固定执行与未决评估已交付，接下来推进 F1/F2：把语言自授权限、范围越界和委托凭据攻击接入真实模型与后端执行边界。A2 的 DENIED、E1 的评分未决以及 Gate E/F 的 OPEN 均保持不变。
