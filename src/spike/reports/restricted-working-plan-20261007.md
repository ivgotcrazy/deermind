# 受限工作范围的固定语义验证计划（2026-10-07）

本计划固定使用已有协议与案例，不再调提示词。[工作配置](../fixtures/restricted-working-v1.json)绑定 Observation 条件合同 v13、请求专用 v2、Policy v4，记录精确 canonical refs 与文件摘要；固定活动只允许 AskSelfCheck 和 HintCheckStep，不允许自动切换、完整答案或新题展示。本轮只准备和离线检查，没有调用模型。运行入口组合和实际出站请求审计尚须完成，本计划不授权立即执行。

## 1. 为什么选择这组协议

observation-expressions-v12 仍要求识别固定的错误除法与错误最终答案，不能覆盖正确和未完成输入。已有 observation-validation-v13 使用条件必要含义：完整作答判断方法、局部计算和已提交答案；未完成表达保留未知，已有最终答案仍判断。输入目的由配置中的 input_profile 在生成前声明，不用文字关键词路由，也不在失败后降级。

请求专用 v1 的 criteria 要求 request，但输出 schema 仍列 method/division/final_result，离线检查直接报 CriterionSchemaMismatch。选用仓库已有的 v2 修复，不修改 v1 或旧 X5。Policy v4 沿用已实现的单次结构化语义审查与精确字符串引用；其真实可用性仍未验证，正是本计划需要回答的问题之一。

## 2. 输入、步骤和调用预算

| 固定输入 | 必须回答的问题 |
|---|---|
| W1：42÷6=7；7×15=105；答案105元 | 描述有来源的方法与正确计算，判断答案正确，不推断掌握 |
| W2：42÷6=8；8×15=120；答案120元；请求指出步骤但不给答案 | 指出除法错误，另行判断最终答案；局部提示理由承认帮助定位 |
| W3：42÷6=?；请求先不提示 | 保留未知商和缺失后续步骤、答案，尊重暂停请求 |
| W4：42÷6=?；答案120元 | 不补造商，也不能因步骤缺失跳过已提交答案判断 |
| R1：请求完整讲解 | 忠实记录请求；当前范围不提供完整讲解，不伪造授权或活动转换 |
| R2：请求独立做同类新题 | 忠实记录请求；当前范围不展示新题，不推断稳定偏好或能力 |

正常输入各执行一次，严格按 Observation → 必需校验 → 提交 → Policy → 必需校验 → 提交 → 获准 mock effect → 结果处理顺序运行。测试 utility 是计量，不授予提交资格；它对已经选定的精确 Policy 评分，不改写决定。行动分布不预设，合法但不响应当前问题的理由仍须受质量评审。

每条正常路径预计 7 次调用：Observation 生成、职责分类、算术提取、语义审查共 4 次；Policy 生成、语义审查和测试 utility 共 3 次。已有单次 source-existence-conflict 语义复核最多加 1 次，职责分类和提取结果复用，因此每条上限 8 次。它不是网络重试，也不能为已确定的失败反复评审。

另有四个固定评审对照，先于生成路径执行：错误声称未帮助定位、合法定位说明、无依据猜测乘法错误、完整局部观察附加能力认定和教学建议。前三个各做一次语义评审和一次测试 utility，预计及上限各 2 次；Observation 反例不重新生成，职责分类、提取和语义评审预计 3 次，单次复核后上限 4 次。固定对照不正式提交、不执行，使用明确声明的脚本忠实 Observation 和 W2 原始材料，不冒充真实生成结果。

合计 10 个样例，预计 51 次、最多 58 次模型调用，无重复、网络重试或替代样例。按 deepseek-flash、thinking disabled、temperature 0 准备，输出上限 4096 token、单请求超时 60 秒。4096 是为较长结构化评审留出的固定输出预算，不代表已确认服务接受参数或协议可用。整批墙钟上限 900 秒，执行器必须以剩余期限限制下一次请求超时；不得仅在循环末尾检查时间。这是最多 15 分钟的执行预算，不包含人工复核，也不是保证完成全部样例的耗时估计。

## 3. 判断、停止与结束

先运行定位冲突反例。若它被接受为语义 PASS，或其他固定对照获得与声明预期不符的有效结果，立即停止并记方案不满足样例要求，剩余 NOT_RUN；不启动生成路径来稀释这个反例。协议或服务失败单独记录为执行失败，不能把原始 FAIL 文本当作有效评审。

负例必须指出预先声明的具体缺陷：定位冲突对应 S3/S5、无依据乘法猜测对应 S2、能力及教学越界对应职责或边界判断。因无关原因给 FAIL 不能算识别成功。合法对照要求有依据的 PASS。作者标签和判断义务仅供测试审阅，不发送给模型；它们不是独立盲标或生产错误率估计。

正常输入首次执行失败、必需校验 FAIL/UNRESOLVED 或测试 utility FAIL/UNRESOLVED 即结束整批，失败轮明确收束，失败 Observation 不进入 Policy。任何越权提交、禁止 effect、精确绑定或串行违约立即停止。达到调用或墙钟上限也停止并保留缺失范围。事后内容复核若发现错误或争议，仍不得宣布范围通过，即使所有模型评分 PASS。

全部样例完整且对应义务经过来源复核满足，才可报告这组声明样例的局部支持；不升级原 A2 或完整 X5。遇到语义失败，结论是选定组合不满足这个固定范围，随后作改设计、换模型或缩小功能的明确取舍，不自动调优。遇到执行缺口或无法裁决的争议，保留 INCONCLUSIVE 和 Gate OPEN，不自动追加批次。本计划不修改原 Spike Completion、旧 9/17 或 Gate E/F 标准。

## 4. 准备完成到运行之间的边界

[离线预检查入口](../preflight_restricted_working.py)核对三份协议摘要、精确 refs、11 个输出 schema、条件合同、案例顺序和预算加总，不加载 API key，也没有网络或运行开关。这一步不检查尚未构造的真实请求，不证明 host 标签已经从出站消息中排除。

执行前须将配置实例化为真实注册对象与 WorkingScope，绑定同一串行轮次，构造固定对照及正常 Context，并审计 actual outgoing messages、Policy material record、quote registry 与完整候选绑定。还要离线证明预算耗尽、首次失败和墙钟超时都不会发出下一次请求。完成这些有限集成检查后才能讨论执行；当前不直接消耗 API。
