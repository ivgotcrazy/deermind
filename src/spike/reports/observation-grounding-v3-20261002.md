## 已确认的误拒

合法自述样例的两次实际 `messages` 完全相同。原始 `work:1` 内容都包含：

> The learner also wrote: "I cannot do division; please explain it."

候选准确引用了这句话，并说明它是学习者自述，不是独立确立的能力判断。第一次校验引用了实际来源并通过；第二次却在 grounding 中断言：

> The quoted learner statement appears only inside the candidate's own description, not in the original submitted work, so the attribution is unsupported.

第二次把引语及后续归属说明都判为 FAIL，sources 留空，因此提交被拒绝。已核对保存的真实请求，原话确实存在；不是丢失上下文、混入负例或候选不同。

两次响应 ID 分别为 `01cae82a-783d-488a-ab23-802dd7130364` 和 `5710dfb2-2a4c-4227-9ac4-7a5031d0fb6d`。相同输入与 temperature 0 在本次没有产生相同判断，不可用重复次数推导独立同分布的错误概率。

v3 对直接引语 PASS 要求引用真实来源，但对“未找到来源”的 FAIL 允许空来源，这是本次错误否定能够进入校验记录的结构位置。模型为什么漏看来源无法从可见响应确证；不能把这一推断写成已知内部机制。

## 传输问题与证据限制

7 次失败发生在得到可用响应前。无 API key 的独立 HEAD 检查中，沙箱内 curl 因 Windows TLS 凭据错误失败，沙箱外 curl 与 Python 均可连到服务并收到预期的未认证 401。正式批次本身已在沙箱外运行，后续有成功响应，因此这不足以把其 7 次失败归因于同一个沙箱问题。

当前适配器把未分类异常统一记为 `ProviderTransportFailure`，没有保留底层异常类型；本批不能进一步确定是连接重置、代理还是服务端断开。没有自动重试，没有把缺失响应算作通过。跨语言自述正例两次都没有响应，其语义效果仍缺少证据。
