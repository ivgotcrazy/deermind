# 失败轮次关闭机制：本地实现与验证 v1

日期：2026-10-05。范围：单进程 Spike、受信串行协调器、脚本认知和同步 mock 执行器。

## 1. 已实现的行为

[合同修订草案](../../../doc/system-design/DeerMind_Observation_Validation_Turn_Closure_Revision_v0.1.md)中的最小失败关闭机制已实现，并在限定的本地范围通过验证。一次固定离线运行完成 236 项测试，失败、错误、跳过均为零，其中新增关闭边界测试 18 项。运行阻断网络连接，实际网络尝试与真实模型调用均为零；150 个冻结输入在运行后指纹一致。本结果不验证真实语义质量，不改变 9/17 的完整验收数、A2 的原始 DENIED、X5 的 INCONCLUSIVE 或 Gate E/F 的 OPEN。

失败轮次首先进入 CLOSING。共享生成、校验、正式提交、ActionIntent 准入和实际执行入口检查该轮次是否仍开放；新 Context 不能仅凭重复使用已关闭的交互输入绕过检查。正在返回的生成或综合校验结果保留为明确的审计记录，不能重新进入正式提交。正式提交追加前和效果分发前均有关闭检查，正常轮次仍按原有顺序串行处理。

关闭不改写历史事实。已经成功提交的 Policy 保留，关闭后不能据此创建新的行动；已经发生的完整展示、部分展示、未知结果和成功活动切换也保留。尚未分发的 Intent 以 NotOccurred 结束。已分发但尚未返回的执行器使轮次继续停留在 CLOSING，队列不能释放，重复执行也不能伪造一个 NotOccurred 来解除阻塞。本地同步执行器返回后，协调器处理其真实终态，才允许结束旧轮次并开始排队请求。

Observation 校验失败可以直接走失败关闭，无须伪造一次 Policy 决策。随后学习请求使用自己的输入形成新的 Observation，不依赖失败候选，也不提前混入旧轮次。该路径的含义由显式测试 fixture 给定，没有用脚本证明模型能够正确理解学习请求。失败的 Policy 提交已接入关闭状态；其他异常由受信编排者提供同一轮次的失败记录，显式调用关闭接口。本次提供关闭能力，不声称已有覆盖所有异常的生产调度器。

## 2. 验证及证据

固定运行目录为 [turn-closure-v1](../runs/turn-closure-v1/summary.json)，包含[冻结清单](../runs/turn-closure-v1/manifest.json)、[完整测试输出](../runs/turn-closure-v1/unit-tests.txt)及 18 份新增测试的事件和最终历史快照。结果解释和离线指纹核对见[限定评估](turn-closure-assessment-20261005.json)。入口 [run_turn_closure_validation.py](../run_turn_closure_validation.py)拒绝覆盖已有目录，不读取项目 API 配置；实际认知调用使用本地显式 transport。

| 检查范围 | 已核实的边界 |
| --- | --- |
| 失败及队列 | Observation 失败后释放下一请求；排队输入不能提前生成；失败 Policy 提交进入关闭；其他会话仍可独立推进 |
| 晚到认知及提交 | 晚到生成与综合校验仅审计；关闭后不能新发校验调用；提交追加前关闭会拒绝 standing |
| Intent 与分发 | Policy 已提交后阻止新 Intent；已准入但尚未绑定的 Intent 也纳入关闭；分发前关闭得到 NotOccurred |
| 实际效果与停止依据 | 完整、部分、未知终态不变；确认过程中关闭须等待同步执行器返回；无返回的分发继续阻塞且不可重复执行 |
| 活动与绑定 | 未执行的 Control 被阻止；成功切换 Teaching 后的后续失败不回滚活动；复用旧输入、更换协调器及错轮次失败引用不能绕过约束 |

五个实现文件修改前的原始字节保存在 [source-baseline-turn-closure-20261005](source-baseline-turn-closure-20261005/index.json)。旧来源指纹、当前来源指纹和保存位置由统一证据清单关联。历史真实批次、manifest 和评估保持原样；旧批次针对旧源码的结论不能无说明地迁移为对新源码的验证。

## 3. 尚未实现的范围及设计后果

本次停止依据是同步 mock 执行器已经返回，并不代表真实网络超时已经停止远端效果。真实远端停止确认、晚到效果的事实对账、进程崩溃恢复、分布式并发和经认证的用户主动中断均未实现。仅剩远端效果不明时不得直接套用本地返回证明。Context 由受信编排者绑定到轮次；不包含已知交互输入的 Observation 必须显式绑定，X5 的工作事实入口已接入该绑定。

草案中“内容成立、必要含义、校验执行状态”的分开表示和未求值表达式类型仍未实现；required checks 和所有语义协议保持原样。原草案继续作为修订提案，实施状态由本报告和清单记录为“本地关闭机制部分实现”，不将整份提案标为已验收。

下一步应落实未求值表达式及精确字段映射合同，明确 `?`、未完成算式和数值断言的区别，并以有界离线契约检查确认结构，不用关键字判断含义，也不降低必要检查。之后再处理 A2 下游准入与 E1 评分责任的设计后果。本次没有启动或授权追加 A1/X5 真实批次，不能用这 18 项本地检查填补其未执行的真实路径。
