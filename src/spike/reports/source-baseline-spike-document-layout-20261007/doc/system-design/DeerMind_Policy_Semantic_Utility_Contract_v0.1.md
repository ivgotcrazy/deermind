# DeerMind Policy Semantic & Utility Contract v0.1

日期：2026-10-06。状态：版本化规则草案；已形成独立 v2 协议和设计样例，尚未接入运行、独立审阅或取得真实模型验证。本合同细化[下游内容准入与 Policy 责任提案](DeerMind_Downstream_Admission_Policy_Responsibility_Revision_v0.1.md)，不替换旧 E1 证据及其结论。

## 1. 责任和判定对象

Policy 在当前材料、活动约束与授权范围内选择 Execute、NoIntervention 或 Defer。行动合法性检查精确参数与权限；语义校验判断候选的表述是否有依据、归属正确且内部一致；测试专用 utility review 衡量选择的解释质量。这三个判断不能相互替代。合法行动可能理由不合格，解释合格也不证明最佳教学选择；utility 分数不能授予权限、改变候选或参与生产提交。

开放语义由明确规则和 LLM 判断。机械代码可以检查字段形状、精确引用、版本、权限与执行记录，不据关键词判断“独立”“可能”或教学帮助程度。消费者必须在自己的职责内形成结论，不因源记录具有 Observation standing 就继承其中每句话，更不继承其中的教学决定。

本合同的可执行提示草案为 [policy-e1-v2.json](../../src/spike/protocols/policy-e1-v2.json)。保留原输出结构、合法性 profile 和四个评分维度，不引入额外模型调用或新的领域状态。S1–S5 写入生成、语义校验和测试评分提示；列出的 rule ID 用于简短可核对的理由，不要求模型输出内部推理过程。

## 2. 语义义务

| 规则 | 校验义务 | 边界 |
| --- | --- | --- |
| S1 自身责任与来源 | 根据实际材料、当前请求、已生效活动及精确行动说明本次选择 | 原始请求不是授权；上游建议不是既定决定；活动仅由获准且确认的 Control 改变 |
| S2 不确定性依据 | 对影响决定的不确定性，交代材料缺口、与本次选择的关系和可区分解释的后续证据 | “可能”不免除依据义务，也不要求证明不可见心理过程绝不可能；不强迫凭空制造不确定性 |
| S3 责任范围 | 对照精确提示和帮助历史，说明定位、计算或其他具体责任中哪些获得帮助、哪些仍由学习者承担 | 指出应检查的算式已帮助定位，即使商仍由学习者重算；明确限定的“独立重算”可以成立 |
| S4 预期与实际 | 行动尚未发生时只说明预期披露；实际效果须有受信发生记录，部分或未知效果保留其范围 | 展示不证明注意、利用或掌握；理由不得扩大行动 payload；不为 Evidence 自动赋数值强度 |
| S5 一致性与选择自由 | 核对 outcome、参数、理由、不确定性、披露及 Defer 条件是否一致 | 不能因评审者偏好另一行动而拒绝；Defer 是新的决策机会，不自动安排执行 |

S2 的三个要素可以在 rationale 与 uncertainty 中合并、简洁说明，不增加固定句式或每句逐字引用要求。明确错误及当前请求已足够支持一个决定时，可以不提出额外假设。只确认除法失配、保留笔误与其他原因未分辨、让后续自行检查提供材料，是可以审查的理由；它不意味着所有场景都应选择自行检查。

S3 必须结合完整语境解释。如果候选明确承认提示帮助定位，并把独立限定为尚未代做的重新计算，不能因使用“独立”一词拒绝。相反，精确提示已指出待查算式，候选仍声称完全保留独立定位，则构成冲突。已帮助定位不意味着所有策略或重算证据都无效，后续 Evaluation 仍须相对于 Claim、时间和实际帮助解释。

## 3. 状态与评分合同

语义 PASS 表示给定材料足以支持适用义务；FAIL 表示完整候选与所给材料已足以确认义务违反；UNRESOLVED 表示必要评审材料缺失或解释确实未能消解。完整候选没有给出所需依据，不能仅因使用假设语气就一律降为未决。评审源材料根本缺失时，也不能直接把候选判成编造。网络、输出结构或模型执行故障属于执行失败，不伪装成语义未决。

测试评分继续逐项输出 grounding、responsiveness、responsibility_cost、consistency。grounding 检查来源与不确定性的依据；responsiveness 检查对当前请求、目的及等待机会的回应；responsibility_cost 检查具体收益、成本和责任替代；consistency 检查各字段与精确行动的关系。每项提供简短的规则与材料依据。缺失或矛盾的必要理由判 FAIL，真实评分歧义保留 UNRESOLVED；同一缺陷可以影响多个维度，不需要人为拆成互斥类别。

沿用测试工具的汇总：任一 FAIL 则整体 FAIL，没有 FAIL 但存在 UNRESOLVED 则整体 UNRESOLVED，四项均 PASS 才为评分 PASS。这个汇总只描述评分结果，不能覆盖语义失败、执行故障或行动拒绝。评审角色单独运行不等于独立人工审阅，也不证明两个模型判断的错误独立。

## 4. 旧争议与参考样例

[原始来源复核](../../src/spike/reports/a2-e1-design-consequence-review-20261005.json)保留四个精确候选：一次无额外依据的乘法错误猜测，以及三次在定位提示后仍声称保留独立诊断的理由。旧自动评分 PASS 和争议标记保持；本合同并未对这四个候选完成新规则下的重评。后续必须读取完整候选与当时的精确 Context，不能仅按争议摘录重判旧运行。

[版本化样例](../../src/spike/fixtures/policy-e1-rules-v2.json)包含十四个聚焦片段，覆盖无依据猜测与有依据缺口、无需制造不确定性、评审材料缺失、定位责任被抹去及明确保留、限定的独立重算、预期冒充实际、未知展示、展示冒充掌握、上游建议冒充授权、消费方独立选择同一行动、回应等待与 Defer 新机会。

这些样例的预期由本轮规则作者给出，尚未独立审阅或模型执行。每项只对所列义务和评分维度提出预期，不构成完整 PolicyOutcome、整体评分或生产准入结果。四个历史候选另列为来源回归项，不附自动生成的新判决。未来评审输入必须排除预期标签；正反例与未决例均应保留，不能以全部拒绝取得可靠性支持。

## 5. 集成及验收边界

现有 PolicyWorld 在运行中固定绑定 v1 协议、语义规则和 utility 规则引用。直接把 v2 JSON 传给这个入口会产生版本身份不一致，因此本轮没有更换入口或宣称可直接启动。后续应在独立入口中绑定 v2 的三个 canonical ref、对应兼容性依据和 VersionContext，同时核查实际模型消息确实使用新版规则；旧 v1 入口及历史 manifest 保持不变。既有字段投影也不会因新规则文件存在而自动启用，必须另外声明每个输入的用途合同并验证来源链。
