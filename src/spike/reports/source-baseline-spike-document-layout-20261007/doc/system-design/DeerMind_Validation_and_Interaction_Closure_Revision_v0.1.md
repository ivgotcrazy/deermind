# DeerMind 校验保证与交互收束整合修订 v0.1

日期：2026-10-06。状态：整合合同修订草案。本文收敛 A2 校验保证、A1 必要含义和 X5 失败后请求处理的讨论方向，供合入总体设计与专项合同前审阅。旧协议、实验结果、完整验收 9/17 和 Gate E/F OPEN 保留；本修订不表示原假设重新成立或完整交互链已经验证。

## 1. 校验通过意味着什么

语义校验是提交前的必需检查。只有每项 required check 已完成、结果为 PASS，并且绑定当前候选、规则、上下文和获准执行，候选才可以继续原有提交路径；随后仍须满足权限、版本、依赖、生命周期和预期版本等条件。缺失、失败、未决或绑定不一致的检查不得被补记为通过。

PASS 表示该次获准评审按声明规则给出了通过意见，不是内容必然正确的证明。正式 standing 表示对象经过规定流程取得对应职责下的正式资格，不能扩展为每句话都正确、跨职责成立或获得行动权限。Observation 中的能力结论或教学建议仍是违规内容；即使误放后没有实际行动，这次提交也仍是错误。发现错误后由对应 owner 按已有更正和新版本流程处理，保留旧记录及实际效果历史。

下游消费正式内容时，在自己的既有生成与校验合同中判断输出是否有依据、归属是否正确、是否属于自己的职责。上游通过意见不能替代下游的这些判断，不默认增加一次重新评审上游全文的调用。Policy 不把 Observation 中的教学建议当成决定或授权；Evaluation 不把 Policy 的独立性说明当成能力事实。下游也可能误判，职责分工不能被宣称为必然纠错机制。

AA-A02 的原命题与 DENIED 保留。后继验证应分别判断机械提交是否拒绝缺失或无效校验，以及声明范围内的模型语义表现。两者不能互相代替，也不能据有限样例承诺开放文本的普遍隔离。

## 2. Observation 按当前目的完成必要判断

版本化 Protocol 在生成候选前声明本轮目的、允许材料和全部必要检查。开放含义仍由规则与 LLM 判断，不能用关键词路由，也不能因候选遗漏而改选较容易通过的合同。任务方法、局部计算和最终答案分别判断，不以一个“完整或不完整”标签统一免除要求。

| 当前处理内容 | 必要判断 |
| --- | --- |
| 完整作答 | 解释有过程依据的方法，判断可见局部计算，独立判断已提交答案是否符合题目。只指出除法错误不能代替最终答案判断。 |
| 未完成或有歧义的作答 | 保留实际表达、已知内容和确实缺失或含义不明的部分；不能补造学生已经提交的结果。若仍有最终答案，不能因步骤缺失而跳过答案判断。 |
| 学习请求 | 准确记录请求的提出者、对象和限制；不推断稳定偏好、能力或系统已经作出决定。不能仅因上下文包含旧作答，就把本轮请求合同变成旧作答的完整重评。 |

同一输入兼有作答和请求时，由预先声明的处理目的和规则确定必要含义，不能借“请求”免除本轮已要求的作答判断。材料不足以完成必要理解时保留未决。来源正确、已写部分有用和完成本轮合同是不同结论；所有必需检查仍须通过。失败后不自动把完整观察降级为局部观察，也不修改旧候选沿用原校验记录。

## 3. 失败轮次结束后处理新的请求

同一会话的常规处理严格串行。普通新输入可以先记录收到事实并排队，不提前理解、不进入在途上下文，也不替代旧轮次。候选不合格或检查失败时，记录绑定该轮和候选的失败依据，关闭该轮提交及后续派发资格；迟到结果只能审计，不能恢复资格。

释放队列前必须完成该轮的失败收束。若尚无动作派发，可以明确结束该轮；若已有动作在途，须按执行合同处理其结果或确认执行已经结束，保留发生、部分发生和未知范围。不能把未知写成未发生，也不能因等待时间足够长就认定执行停止。当前局部实现只证明同步 mock 返回后的处理，远程停止确认和生产恢复仍未验证。

旧轮次结束后，新的学习请求进入自己的轮次和合同。它可以重新读取获准的原题、原始作答及其他符合用途的材料，但不能把失败 Observation 或原始模型附言作为正式现象依据。必需材料缺失时明确返回无法完成；可选材料按协议排除。新请求能够处理，不意味着旧作答分析已经成功。

## 4. X5 的活动转换与后续证据

学生请求讲解后，新的请求 Observation 先完成自己的校验和提交。Policy 再依据当前请求、活动约束、获准材料和权限判断是否采取行动；请求本身不授予权限，也不使活动转换生效。若选择获准 Control，必须经过新候选校验、提交、Intent 和执行确认。只有实际成功的 ActivityTransitionOccurred 被处理后，才按已经生效的活动条件继续同轮决策。

继续决策时重新组装符合当前活动和权限的上下文，形成新的讲解候选并完成其 required checks，不能沿用转换前的 Policy 结果直接展示讲解。Control 失败或结果未知时，不得按“已经转入教学”继续。普通展示也不能冒充活动转换；旧活动、旧候选和先前决策历史保持原样。

实际讲解展示由受信执行确认记录，预期披露不能代替实际披露。后续新题作答在自己的轮次中处理，Evaluation 按具体 Claim、实际帮助历史和作答材料形成判断。换题、答对或 Policy 声称独立，都不自动证明独立掌握；当前没有新的能力评分或数值权重规则。

## 5. 修订落位与结束条件

本合同复用已有字段用途投影、条件必要含义、失败轮次收束和成功 Control 后继续决策的局部机制，不新增 reviewer、通用论证图或并行轮次。总体设计应明确 PASS 的保证范围并保留 AA-A02 反证；AI Reasoning Runtime 应承载 purpose-specific 必要检查与失败记录；Interaction Decision Runtime 应承载失败收束、队列释放和活动转换条件。具体字段和输出协议由既有专项定义，本文不替换它们的默认版本。

本轮设计分析在这些责任、失败处理和后续缺口获得明确决定后可以收口；正式 Spike Completion 和阶段准入仍依据原退出条件处理。A1 未运行与质量争议、A2 原错误提交和下游缺口、E1 语义与评分争议、X5 全部真实完整路径及效果边界缺口仍在。阶段移交不计作通过；若调整验收范围，必须保留原假设、结果与新要求的对应关系。

后续仅在某项设计取舍缺少决定性证据时提出有界验证，先声明命题、范围、预算，以及成功、失败、未决各自的结束方式。不能以继续增加本地测试或获得新的模型 PASS 代替原假设的证据评审。本文不启动真实批次，不选择未经讨论的误放容忍阈值，不冻结 v1.0。
