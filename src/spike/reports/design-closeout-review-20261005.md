# Spike 证据审查与设计收口清单（2026-10-05）

当前可以从逐项补充实验转入设计收口，但不能宣布 Spike 完成。12 个架构假设均已形成分类，5 个组合均有评估；完整验收仍为 9/17。原 AA-A02 DENIED 和所有 INCONCLUSIVE 保留。本文给出待评审的设计后果和后续验收范围，不改写 System Design 的正式责任合同，不关闭 Gate E/F，也不批准或启动额外模型批次。

## 优先处理的三项合同

第一项是 Observation 的语义成立、最低有用性和校验执行状态。X5 的前三个候选说对了局部除法错误，却漏掉该合同要求的最终结果判断；A1 又出现模型评分认可、内容复核仍认为策略解释不足的情况。这些都不能简单归入“语义越界”。建议明确记录来源与职责检查、有用性检查及执行完整性各自的结果，正式提交继续遵守该类型声明的 required checks，不由运行时自行放宽。是否允许一份合同完整、范围更小的局部 Observation，需要作为新的类型或 profile 决策审查；不能直接把当前失败候选当作合格观察交给 Policy。

第二项是模型输出与确定性检查之间的表达合同。字段名称只允许候选实际字段，是精确绑定问题，可提前声明为 schema 枚举。`42÷6=?` 是可见但未求值的作答，不能强制放进有数值结果的算术断言。建议将原始表达保留与“可验算的数值断言”明确分开，由规则约束下的 LLM 决定其含义及映射，确定性工具只验算完整数值断言并检查精确结构。任何新结构仍须验证未决数字没有被补造、错误算术没有因类型选择绕过检查。已有断连、多个结果、来源片段覆盖等失败也不得用静默重试掩盖。

第三项是失败轮次的收束与后续请求。普通会话严格串行的决定保持；新输入先接收后排队，不抢占在途理解。当前 X5 在观察失败后停在未完成路径，新学习请求不能被悄悄解释成教学已获授权。需要另行明确校验失败、服务失败或用户主动中断时，如何记录该轮终止或等待、如何向用户表达，以及何时释放队列。成功 Control 后才开放下一轮内决策的机制保持。异常路径的设计不能被普通消息自动改写，也不能让“未确认发生”变成“确认没有帮助”。

## 复杂度审查与执行约束

当前 Observation 典型路径已包含生成、职责分类、算术提取和语义审查四次模型调用。额外协议使来源、归属和算术更可追踪，也增加了精确字段、片段覆盖、数值表达和多次服务调用的失败机会。A1 的 7 次尝试出现 4 次协议/运行失败，不能据此估计生产失败率，但足以阻止把“多重校验”等同于已证实可靠。下一轮设计应说明保留每个检查的作用、不可替代性与代价，不能继续无上限叠加提示词或审查模型。

本地内存快照、历史线性扫描、显式 grants、脚本 Evaluation、受控交错和 mock effect 都已进入统一报告的复杂度登记。它们是验证手段，不应未经性能、授权或恢复设计就移植成产品实现。A1 新增的 schema/判据一致性预检查只检查机器合同，保留；它不能判断提示词语义一致性或模型返回内容是否正确。

下一步先形成上述三项合同的具体设计修订草案及对原 Assumption 的映射，再审查 A2 的否定后果与 E1 的评分合同。完成设计决定后，才提出一次有范围、预算和停止条件的受影响用例验证计划。当前不预约批次、不耗用 API、不保证通过、不把剩余 8 个未完成场景按同一次数机械补齐。

按原 Spike 文档 §17，未决项需要修订实验或设计并保留后续验证要求；完整场景覆盖、Hidden Complexity Review、逐项 design consequence 和统一报告完成后，仍须 Evidence Review、必要 ADR / Reopen 判断、Gate E、Gate F，才能冻结 System Design v1.0。本文完成的是证据到设计问题的整理；设计取舍、修订实现和相关验收仍未完成。
