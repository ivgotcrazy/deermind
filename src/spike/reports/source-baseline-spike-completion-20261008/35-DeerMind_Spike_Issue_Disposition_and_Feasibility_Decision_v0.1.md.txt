# DeerMind Spike 问题定性与可行性决定 v0.1

日期：2026-10-07。依据本次讨论，当前阶段以验证技术路径是否初步可行为目标，不再以消除全部语义误判或补齐旧批次的全部重复次数为退出条件。结论是：**核心执行机制在受控场景下可行，语义处理具有有限的真实模型可行性证据，可以进入受限工程验证；当前冻结原型仍未达到可用标准，完整自动教学闭环尚未证实。**

本决定取代旧退出清单作为后续工作的排序依据，不改写旧实验结果。原 A2 的 DENIED、原型验收的 NO_GO、旧合同的 9/17 以及 Gate E/F OPEN 均保留。9/17 是旧合同完成度，不再作为本次可行性工作的待办进度；它不能被改成“17/17 已通过”，也不能继续要求在同一处无限调优。当前允许的是实验性质的受限工程验证，不代表正式 Build Gate 或发布验收已经通过。

## 当前必须作出的机制决定

语义审查的 PASS 是一个可能出错的模型判断，不能作为内容绝对正确或职责绝对纯净的保证。原反例确实否定了旧强保证：模型认为用户要求讲解，因此“系统应当讲解”是合理内容，进而将 Policy 建议放进了 Observation。后续职责分类能够在有限样例中拦截这种内容，说明存在可实施的改进路径；它没有恢复绝对保证。当前保留明确语义规则和 LLM 分类，并以程序检查精确输入、协议版本、授权、提交条件和实际执行结果。程序不以关键词代替语义判断，也不凭另一个模型的 PASS 授予执行权限。

必须同时消除 Observation 与 Evaluation 之间的规则冲突。“这次提交的 120 元不符合题意”是局部作答判断，属于 Observation；“该表现对能力命题构成强反对证据，应降低可信度”是在赋予 Evidence 意义或更新 Belief，属于 Evaluation。原职责规则把任何“learner claim”都包含进去，会误拒协议同时要求的局部正确性判断。新协议明确区分这两种工作；这属于本阶段必须解决的定义问题，不能归咎于模型准确率。

活动切换也必须有机制结论。学习者请求讲解，表示原先保持独立诊断的交互条件发生变化，但请求和 Policy 建议本身不能伪造活动切换已经执行。受信 Control 的实际结果决定后续活动约束，显示确认决定哪些帮助确实发生；失败、部分显示和结果未知分别保留。此次已重新走通该机制及四个执行边界。真实 LLM 完成整条 X5 路径仍未验证，不能据模拟路径宣称自动教学已经可用。

## 问题逐项处置

“后续优化”只用于已有技术路径、尚欠质量或稳定性的事项。另列“能力尚未验证”，避免把没有证据的能力说成普通优化。下表中的“本次关闭”仅表示该问题已有当前阶段处置，不表示生产质量验收通过。

| 问题 | 定性与证据 | 当前处理及后续边界 |
| --- | --- | --- |
| 1. 越界建议被审查为 PASS 并提交 | 核心假设问题。原 v9 两次误提交，旧绝对语义隔离承诺不成立。 | 明确否定旧强保证。后续采用可错语义审查与确定性执行约束，不再尝试证明“永不误判”。新 v10 拦截旧反例，v11 有有限正负例证据；误放率、误拒率留工程评估。 |
| 2. 正常局部判断被认作 Evidence | 核心规则冲突，不能只算实现质量问题。 | 已在新 Observation 协议澄清局部正确性与正式 Evidence 评价的职责；固定 8 例真实模型检查已完成。此次关闭规则矛盾，不承诺所有表达都能正确分类。 |
| 3. 缺审查、错绑定、旧依赖或伪授权是否仍可提交和执行 | 核心程序机制，必须现在检查。 | 相关提交、上下文投影、失效、串行、授权与执行边界回归通过。必需审查缺失、失败、未决仍阻止提交；保留提交时复核，不以停止语义调优为由放松。 |
| 4. 活动切换或讲解未实际发生却被记为发生 | 核心机制问题。 | 模拟语义输出下走通 X5，控制未发生、讲解未发生、部分发生、结果未知四种分支通过。实际发生事实不从 Policy 理由或计划中推断。 |
| 5. criterion 引用不连续而整次校验失败 | 简单表示契约问题。四个保存返回选择了有间隔的有效引用。 | 已新增显式版本：支持同字段有序选择，展开为若干独立原文引用，不拼接跨间隔句子。未知、重复、逆序和跨字段选择仍拒绝；claim、职责分段和算术锚点仍要求连续。四个旧返回可离线准确表达。 |
| 6. Policy 引用实际提供的 AssistanceContext 被 schema 拒绝 | 简单接口不一致。输入来自 execution 空间，输出 enum 却不允许 execution。 | 新 Policy 接口允许引用该空间；仍要求引用确实在当前上下文中。旧失败返回通过新 schema，新增负例证明伪造引用不能提交；引用记录不增加权限。 |
| 7. 本地消息长度限制阻止发送 | 已解决的简单工程问题。 | 已有 64,000 字符容量修订，不再列为待办。仍保留有界输入与成本预算，实际更大场景在工程阶段测量。 |
| 8. 单独数值、未完成算式无法表达 | 已解决的表示问题，剩余为抽取质量。 | 既有 ScalarValue、UnevaluatedExpression 保留，不编造算式或结果来满足 schema。类型选择和语义映射准确率留工程优化。 |
| 9. 重试日志中的 session 参数重复导致运行器中断 | 已解决的简单工程问题。 | 日志元数据已移入 retry_context，原中断及其调用量保留；后续 18 回合正常完成执行记录。不是语义失败。 |
| 10. 本次探针启动时端点不匹配 | 简单运行器配置问题；首目录 0 次外部调用。 | 显式采用协议声明的 beta 端点后，固定 8 次调用完成。保留首次启动结果，不计为模型失败，不占用语义重试机会。 |
| 11. 网络断连 | 运行条件问题，不构成语义或设计反证。 | 前次专项重跑 77 次调用、18 回合无传输失败；已能单独看清非网络失败。旧断连保持未完成；本次 8 次调用也无断连，不再专为补齐重复次数重跑。 |
| 12. 多工具返回、缺字段、缺来源及内部汇总不一致 | 协议遵循和可用性问题；任取一个返回或自动补来源可能改变含义。 | 保持整次返回显式失败，不在本轮做通用自动修复。结构化返回、有限重试和失败恢复留工程验证，重试不能掩盖原失败。 |
| 13. 职责误拒、转述的错误等式被当作系统认可 | 已有可行路径的模型准确率问题。 | 固定职责定义后移交独立样本评估；算术程序只对模型给出的结构验算，不能证明 speaker/stance 正确。不得用关键词推断“转述”或自动改为 reported_only。 |
| 14. 未判断最终答案，审查却给 PASS | 生成和审查漏检；需求本身已明确。 | 保留失败事实和必需语义项，不为提高完成率删掉该要求。覆盖率、误放、漏检关联及审查策略留工程验证，不要求在 Spike 消除所有漏检。 |
| 15. 提示已定位错误，理由却称完全独立；或虚构不确定性 | Policy 生成与审查质量问题，动作权限与实际披露机制另有证据。 | 明确“定位受到帮助，重新计算仍由学习者完成”的规则。后续评估理由与实际动作的一致性，不因措辞质量争议否定已验证的执行机制，也不忽略会误导下游的内容。 |
| 16. 调用链过长、成本与延迟偏高 | 后续工程优化问题。 | 以完整会话完成率、成本、延迟和失败恢复评估；本轮不继续堆叠审查器。不得用本次 8 个短分类请求的耗时估计产品延迟。 |
| 17. 完整真实 X5 及真实 Evaluation / Belief 更新 | 能力尚未验证，不可直接说成简单优化。 | 当前受限工程范围只允许固定单任务、已登记局部提示、NoIntervention / Defer，不启用自动转教学、自动新题、正式 Evidence / Belief 写入。相关能力启用前须有独立可行性结论，不能拿 scripted Evaluation 当证据。 |

## 剩余八项的当前阶段结论

原测试合同和结果逐项保留；以下回答的是这些项目是否仍阻止技术路线的初步判断。

| 项目 | 已有证据与本次补充 | 当前阶段处置 |
| --- | --- | --- |
| A1 Observation 形成 | 旧批次有真实生成与提交，最新网络重跑有 3 次 Observation 提交；质量失败很多。 | 有有限形成路径证据；完成率与内容质量进入工程验证。原 INCONCLUSIVE 保留。 |
| A2 语义与正式准入 | 旧强保证被否定；v11 的 90 个正例尝试中 77 次提交，90 个负例尝试中 84 次有效拒绝、6 次未完成、0 次误提交。提交与下游输入边界另有程序证据。 | 对旧保证给出否定结论，对修订后的概率性语义方案保留有限可行性判断；不再等“语义零错误”才能退出。 |
| E1 Policy | 15/15 条真实 Policy 路径完成，10 次局部提示、4 次不干预、1 次延后；输入 Observation 为模拟，另有 4 个评分争议。 | 决策与执行技术路径可继续，语义理由与教学价值留工程评估，不宣称完整学习链路通过。 |
| E2 严格串行 | 13/15 条旧真实路径完成，2 次断连；本次代表队列路径通过。 | 串行机制已有证据，不为补齐重复次数继续卡住。远端取消、持久化恢复留生产实现。 |
| F2 工具授权 | 20/25 条旧真实路径完成，5 次输出封装失败；25 次受控攻击拒绝，本次三类代表路径通过。 | 后端授权机制保留；模型合法调用的稳定性留工程验证。 |
| X1 更正与失效 | 4/5 条旧真实路径完成，1 次断连；本次更正后失效与新决策路径通过。 | 在声明范围内保留可行性，不再依赖 A2 达到完美准确率。 |
| X2 版本变化与撤销 | 9/10 条旧真实路径完成，1 次断连；本次撤销代表路径通过。 | 未来版本启用与即时撤销分别处理的机制保留。 |
| X5 诊断转教学组合 | 旧真实整链 0/5；本次模拟语义路径与四个实际效果边界通过。 | 核心生命周期可继续，真实自动组合能力仍未验证；禁用该能力后不阻止固定任务原型工程。不能报为真实 X5 PASS。 |

这些项目存在不同类型的依赖。旧语义强保证被否定，需要修订承诺和下游消费规则；它不阻止使用明确标注的受控认知输出来验证队列、权限、版本失效和执行事实。反过来，只有这些机制通过，也不足以证明真实模型能完成整个教学过程。后续按需要启用的能力安排验证，避免让一个语义质量问题成为所有工作的共同前置条件。

## 本次修复与验证结果

接口修订为 [Observation 可行性协议](../../../src/spike/protocols/observation-feasibility-v1.json) 和 [Policy 可行性协议](../../../src/spike/protocols/policy-feasibility-v1.json)，显式选择后生效，不覆盖冻结的 v14 / Policy v2。职责和算术含义继续由 LLM 判断；连续性、原文引用、精确引用绑定和授权由程序检查。

[本地验证](../../../src/spike/runs/feasibility-triage-offline-v1/summary.json)完成 104 项相关检查，7 条代表机制路径、4 个执行边界全部通过；41 次调用为模拟返回，外部模型调用为 0。X5 中 Evaluation 和 Belief 仍为明确标记的测试输入，显示与 Control 为模拟执行器。保存的四个不连续 criterion 引用与一个 Policy 引用失败已通过新表示契约检查，未重新执行提交，也未据此推断语义正确或会话可用。

[职责规则检查](../../../src/spike/runs/feasibility-responsibility-v2/summary.json)使用 deepseek-flash，temperature 0、thinking disabled，每例一次，最多 8 次调用、总上限 300 秒、单次超时 30 秒、输出上限 2048 tokens、输入上限 64,000 字符，无重试。实际 8 次完成，约 7.84 秒；放行或拒绝的状态与预期均一致，原角色集合标签严格匹配 7/8。样例标签没有传给模型。

未完全匹配的一例是“学习者写了42÷6＝8，这个等式不正确”。原标注只列 local_observation，模型将前半句标为 attributed_report、后半句标为 local_observation，符合该协议要求的职责分段。因此这是预设标签过粗，不能报告为模型误判；同时不能回改标签使原统计变成 8/8。原结果保持 7/8，本次人工解释另记于处置报告。这八例是开发者编写的规则检查，并非独立盲测，也不是模型准确率估计。

此次修复前的相关代码、目录入口和台账已留存；首次探针启动因端点配置被本地拒绝，0 次外部调用，其记录也保留。修正运行器配置后才执行上述固定八例，没有因此扩大语义实验范围。

## 退出条件与后续工作

当前可行性工作的机制结论、接口修复和未验证能力均已列明，本轮关闭，不再开启另一批“直到全部通过”的语义测试。下一步进入受限单任务原型的工程验证，首先解决正例误拒、必需内容漏判和有效会话完成率；每轮预先限定修改项、样本和预算，并将语义失败、协议失败与网络失败分别报告。通过标准应按原型目标事先制定，不能沿用“所有开放语义都必须正确”的隐含标准。

工程验证不得绕开必需审查、精确绑定或后端授权；在这些条件未满足时，回合应明确失败。完整真实 X5 和真实 Evaluation 另立能力验证，启用前仍保持关闭。如果发现缺审查也能取得正式状态、跨主体越权、旧决策仍能执行，或仅有计划就生成实际发生记录，应立即重开相应机制问题；一般措辞误判、漏检和延迟则进入既定工程问题清单。若一个拟启用能力连最小真实路径也无法建立，应对该能力给出收缩或否定结论，不无限追加模型调用。

机器可读的问题分类、阶段决定、人工复核和证据指纹见 [处置报告](../../../src/spike/reports/feasibility-triage-20261007.json)。旧版完整实验评估继续保留在台账中，后续报告必须同时说明当前允许的范围与尚未验证的能力。
