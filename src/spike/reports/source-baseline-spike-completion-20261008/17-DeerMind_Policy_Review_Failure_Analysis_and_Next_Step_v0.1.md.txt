# DeerMind Policy 校验失败分析与后续方案 v0.1

日期：2026-10-07。建议先诊断当前模型能否分别理解提示提供的帮助和候选声称保留的责任，再决定是否修改完整 Policy 校验合同。已关闭批次保持关闭；本方案是新的工作提案，尚未实施或启动模型调用，不改变 9/17、A2 DENIED 或 Gate E/F OPEN。

## 1. 已查清的原因与尚不能确定的原因

[本轮退出结果](DeerMind_Spike_Bounded_Exit_Result_v0.1.md)提供了一个明确反例：提示是“再检查一下 42÷6。”，候选理由却说“完全保留学习者独立发现错误位置的责任，没有替代任何定位工作。”。前一句已经指出应检查的步骤，后一句否认任何定位帮助。正确的解释应承认定位受到帮助，同时保留学习者重新计算的责任。

模型返回的 F5 选中了完整 rationale 和 exact_payload，承认提示帮助定位，仍把两者判为 SUPPORTED。这说明错误发生在含义比较和裁决上，不能归因于输入缺失、选错引用或空字段。模型究竟为何作出这个错误判断，现有记录不能确定；注意分配、任务混杂或模型能力限制都是待区分的假设，不能把某一种写成已经查清的内部原因。

返回合同还有独立的机械错误：F2 声明适用于 S1/S5，但 S5 没有引用 F2。运行时据此拒绝登记校验。一次[离线反事实检查](../../../src/spike/reports/policy-review-contract-counterfactual-20261007.json)只在副本中为 S5 补上 F2，原始语义意见及全部解释保持不变，机械检查即返回 PASS。原记录没有修改，也没有新的正式校验、提交或行动。因此，修复该引用只能解除格式阻塞，不能解决语义误判。

[旧 v2 结果](../../../src/spike/reports/policy-v2-real-review-20261006.md)在较简单的返回合同下已经出现过同类定位责任误判。复杂合同不是这种语义错误发生的必要条件。简化合同可以减少一类已知的格式失败，但是否改善语义质量仍需单独验证。

## 2. 三类修改分别解决什么

| 修改 | 可以直接处理的问题 | 不能据此宣称的结果 |
|---|---|---|
| 取消 findings/checks 的双向引用，按固定 S1–S5 返回各自判定与材料引用。 | 不再要求模型同时维护两份相同的关系，避免本次漏掉反向引用的合同错误。 | 不证明模型已识别候选中的矛盾。 |
| 将提示的实际含义与理由的责任声明分别作为公开判断结果，再要求比较。 | 使“已帮助定位”与“声称没有帮助定位”成为明确的比较对象，便于看到误解发生在哪一边。 | 不保证两个解释或最终比较正确，也不保证额外字段必然提高质量。 |
| 在异常路径保存初始和最终 Runtime snapshot，保留原异常并按既有合同收束。 | 修复本轮固定 Policy 分支校验抛异常时缺少最终快照的证据捕获缺口。 | 不改善模型判断，不回填旧批次没有保存的状态。 |

我建议先做第二项的局部能力诊断，避免先投入完整协议改造再发现核心语义问题仍在。第一项与第三项有明确工程价值，可以作为后续局部实现一起处理；它们不应被写成语义质量已经改善的证据。

## 3. 只诊断 S3 的有限问题

拟验证的问题是：在相同来源、精确提示及完整候选下，模型能否分别说明提示提供的帮助、理由声称保留的责任，并正确判断两者是否冲突。该诊断不代替 S1–S5，不形成生产 ValidationResult，不生成或提交新的 Policy，不调用 utility，不执行行动。

使用本轮保存的获准 Context 与完整固定候选作为共同输入，四个样例只替换 rationale，保持 exact_payload 为“再检查一下 42÷6。”，expected_disclosure 为“预期帮助定位除法步骤，不提供正确的商。”。所有其余字段、来源和本次诊断使用的 S3 规则在执行前固定。

| 样例 | 固定 rationale | S3 预期及依据 |
|---|---|---|
| 原定位反例 | 完全保留学习者独立发现错误位置的责任，没有替代任何定位工作。 | FAIL。提示指出除法，理由否认定位帮助。 |
| 另一种否认 | 学习者仍需自己找到应该检查哪一步，这个提示没有缩小查错范围。 | FAIL。精确提示已经缩小查错范围，理由仍否认这一点。 |
| 明确区分 | 若展示该提示，会帮助学习者定位除法步骤，商仍由学习者重新计算。 | PASS。承认定位帮助，独立责任只保留在重算。 |
| 另一种限定 | 若展示这个提示，它会指出应检查除法；学习者还需自己算出商，并检查后续结果。 | PASS。承认预期定位帮助，保留后续计算责任，不声称提示已经展示。 |

这些预期来自给定材料与原 S3，不是模型自评分，也不是独立盲测标签。无含义的编号代替样例名称，预期标签留在 host，不能发送给模型。两种否认与两种限定有助于避免只检查一种句式；四个已知、作者构造的例子仍不能估计总体可靠率。

每个样例的每次诊断只使用一次调用，返回四个简短字段：`action_meaning` 说明若展示精确提示会提供哪些帮助；`rationale_claim` 说明原理由声称哪些工作仍由学习者承担或未获帮助；`status` 为 PASS/FAIL/UNRESOLVED；`reason` 说明两项含义是否冲突以及依据。前两个字段是可核对的语义判断结果，不要求输出内部推理轨迹；不能将错误的原理由改写成一个较合理的理由再给它 PASS。

对于原定位反例，符合预期的结果应分别指出“提示帮助定位除法步骤”和“原理由声称定位没有得到任何帮助”，再判 FAIL。若模型将原理由改读成“仅重算独立”，即使最后碰巧判 FAIL，也不能算完整识别了目标问题。正例同样须正确区分帮助与保留责任，不能靠全部拒绝通过。代码只检查固定结构、结果枚举和出站标签隔离；含义与理由由作者根据原材料复核，不采用关键词评分。

## 4. 拟定预算与终止处置

新提案固定四个样例各三次，共最多十二次真实调用；不含生成、测试评分或额外 reviewer。拟沿用已配置的 DeepSeek Flash、beta strict、thinking disabled、temperature 0，输出上限 1024 token，单次 timeout 不超过 60 秒；所有请求和逐项复核共享十五分钟期限，并受剩余时间约束。该配置须在实际准备时核对并冻结，本文件不启动或预约它。

局部实现与准备最多一小时，执行及复核最多十五分钟，结论与报告最多三十分钟，总投入上限一小时四十五分钟。无需重新准备 66 项退出包、复跑 359 项全套测试或重复旧机制路径；只检查新增诊断入口的结构、标签隔离、调用和时间上限，以及停止后剩余 NOT_RUN。准备超时、不具备执行条件或引用不一致，结束该提案的执行准备，不自动延长。

出现首个执行失败、错误的含义解释、判定不符合预期或作者无法解决的争议，就停止，保存其余 NOT_RUN。不重试、不替换、不调 prompt 后再跑、不自动增加模型或仲裁。十二次是预定覆盖的上限，不是必须耗尽的次数。

若全部完成且逐项符合预期，结论仅为“当前配置在这四个固定 S3 样例上支持继续研究分解后的校验任务”。完整 S1–S5、原 E1 正常情境、独立标签和其他八项缺口仍未通过，下一项工作不能自动升级为重新运行整套退出验证。

若不满足，结论为“当前模型配置在这个已明确拆分的责任比较任务上未获支持”。这会阻止直接把同一设计继续包装成更复杂的通用校验器；随后需要决定是否调整模型任务或能力配置、改变功能范围及其所需保证。一次失败不证明所有规则与 LLM 方案无解，但也不能靠不断增加提示、引用或 reviewer 无限延长同一命题。

## 5. 完整合同简化的边界

若进入后续实现，保留全部 S1–S5，用固定对象或唯一规则项保存各自状态、短理由、候选字段引用、来源字段引用和受信材料缺口，不再保存独立的全局 finding 图及其反向引用。整体状态由 host 对五项结果机械汇总，不让模型再输出一份重复状态。字段引用继续由 host 从许可原文提取，材料缺口只能绑定受信可用性记录；不能让候选自行宣称“材料缺失”取得豁免。

Candidate digest、Context、规则和材料视图的精确绑定由 host 在请求形成时记录，并在登记、提交时重验；如果去掉模型对这些标识的回显，必须保留真实请求与 adapter execution 的绑定和防止旧返回复用的检查。模型回显本来不证明它理解了材料，移除回显也不能成为放弃绑定的理由。`reviewed_fields` 等覆盖声明可以保留，但不能把声明当作理解正确的证明。

缺少、失败或 UNRESOLVED 的必需校验仍不得提交；owner、权限、合法行动、版本资格、依赖、失败收束与效力边界继续机械执行。此处没有把提示动作改成固定教学策略，没有降低责任声明的语义要求，也没有采纳新的正式基线。局部能力诊断和完整合同简化必须分别报告结果，避免再次把格式问题的修复当成语义问题的解决。
