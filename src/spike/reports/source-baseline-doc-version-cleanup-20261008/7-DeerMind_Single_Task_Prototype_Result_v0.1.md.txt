# DeerMind 单题受限原型实现与验收结果 v0.1

日期：2026-10-07。结论：**本轮关闭，当前配置 NO_GO。** 新的受限入口已经实现并通过规定范围内的机械检查，但 DeepSeek Flash 与 Observation v13 组成的处理链未完成任何一个正常交互会话。十二个固定会话全部执行过，没有通过、替换或补跑；不把本结果留在等待修补的进行中状态。

本次按[整合修订与验收表](DeerMind_Single_Task_Prototype_Revision_and_Acceptance_v0.1.md)实施。结论针对这一个具体配置。已有机械能力可以保留；本轮没有取得 Policy 真实选择质量、真实提示后第二次作答处理或生产可靠性的支持证据。

## 1. 已经完成的实现

[受限入口](../../../../src/spike/foundation/single_task.py)直接复用现有 BoundaryRuntime、SecurityRuntime、SerialSession 和 ActionRuntime，重新登记本题所需的协议、动作及权限。它没有继承历史场景初始化时写入的脚本 Observation，也没有签发 Evaluation 身份或 Evidence、Learner Belief 写入能力。开放含义仍交给规则＋LLM 判断，没有增加关键词分类。

入口支持同题两次原始作答、串行排队、失败收束、准确提示展示和下一轮帮助历史。帮助投影来源于执行记录；Policy 理由与 reviewer 说明不会进入下一轮模型上下文。未展示、部分展示、未知送达分别保留；未知在途效果会阻塞该会话。正常失败显示固定失败回执，不伪装成 NoIntervention。

新入口采用既定的 Observation v13 和 Policy v2，没有实现 v6 校验器，没有修改旧协议或公共 Runtime 文件。Policy 的 test-only utility reviewer 不进入处理流程。固定样本和执行代码见[夹具](../../../../src/spike/fixtures/single-task-prototype-v1.json)与[运行入口](../../../../src/spike/run_single_task_prototype.py)。

## 3. 失败发生在哪里

| 失败点 | 轮数 | 已核实的原因 |
|---|---|---|
| Observation 语义校验请求在本地被拒绝 | 12 | 拼装完成的消息超过旧适配器的 16,000 字符上限，尚未发往模型。 |
| 算术提取把单个答案装入不适用的类型 | 6 | 把“最终答案是 120”等单个数值写成 NumericAssertion，但 operator、left、right 为 null；运行合同要求完整二元运算。 |
| 算术提取的数值为空 | 1 | 把只描述“42 乘 15”的片段写成 NumericAssertion，value 却为 null；数值检查拒绝。 |
| 算术片段引用不成立 | 3 | 指定的表达式在其所属 segment 中不存在，或出现不止一次，不满足准确定位条件。 |
| 职责分段没有逐字覆盖 | 2 | 返回分段改动了候选中的标点，例如把中文句号换为英文句点，导致准确匹配失败。 |

逐会话分布如下。这里是处理失败位置，不是把错误都归咎于模型理解能力。

| 会话 | 第一轮 | 第二轮 |
|---|---|---|
| T01 正确作答 | 请求超长 | 请求超长 |
| T02 等价正确方法 | 请求超长 | NumericAssertion 的 value 为空 |
| T03 定位请求 | 单个答案缺少运算符 | 单个答案缺少运算符 |
| T04 定位请求改述 | 职责分段不完整 | 请求超长 |
| T05 未完成后完成 | 请求超长 | 请求超长 |
| T06 等待后请求提示 | 请求超长 | 表达式不在所属片段内 |
| T07 方法合理而结果错 | 单个答案缺少运算符 | 请求超长 |
| T08 乘法错误 | 请求超长 | 表达式片段定位不成立 |
| T09 明确不提示 | 单个答案缺少运算符 | 请求超长 |
| T10 只要一般提醒 | 单个答案缺少运算符 | 单个答案缺少运算符 |
| T11 帮助历史 | 请求超长 | 职责分段不完整 |
| T12 独立发现自述 | 请求超长 | 表达式片段定位不成立 |

例如 T01 第一轮的作答完全正确：“42÷6＝7，7×15＝105。我做完了，如果没有问题就不要提示。”模型生成了对方法、两个计算和最终结果的正确描述，随后完成职责分类及算术提取。程序再把规则、原文、候选、提取结果和计算结果拼成语义校验请求，消息长度达到 21,200 字符。适配器在发出第四次请求之前发现超过 16,000 字符上限，抛出 InputLimitExceeded。于是 Observation 没有提交，Policy 没有启动，学习者只会得到处理失败回执。

21,200 字符中，system prompt 为 8,930 字符；正文各字段单独序列化后，criteria 为 3,983 字符，算术提取为 1,930 字符，计算结果为 3,292 字符。原始上下文仅 475 字符。字段计数不含相同的外围包装，不能直接相加当作完整消息长度。这个例子的主要体积来自既有校验材料，不是长题目，也不是多轮聊天堆积。

十二条超长请求的重建长度为 18,363–23,928 字符。原适配器在拒绝超长请求前尚未保存其消息，因此这些精确长度来自[离线重建](../../../../src/spike/reports/single-task-prototype-offline-analysis-20261007.json)，不是原始网络抓取。重建只重放已记录的 70 个返回，没有新模型调用；实际发送过的 70 份消息在只映射随机 execution 引用标识后逐项一致，schema 与消息长度一致，二十四轮的失败结果也一致。[分析脚本](../../../../src/spike/analyze_single_task_prototype.py)保留了这一检查。

T03 第一轮说明另一个独立问题。Observation 已经写出“最终答案是 120，和本题正确结果不一致”。算术提取器将“最终答案是 120”标为 NumericAssertion，保留 value＝120，却没有运算符或操作数。返回符合外层 JSON schema 中允许 null 的结构，但不符合该类型的运行约束。这是表示合同与模型映射的适配问题，不能解释为模型不知道 42÷6 等于多少。

同时，原始候选确实出现了内容错误。T04 第一轮和 T11 第一轮把已给出 120 的作答说成“没有最终答案”；T11、T12 的第二轮在同一段描述中先把 42÷6＝7 说成错误，随后又改称正确。这些候选均未提交。它们说明只修复消息容量或表示问题，仍不能推定内容质量已经合格。

## 4. 为什么机械检查通过却全部交互失败

准备阶段的脚本 Observation 是一个很短的英文描述，没有真实的数学判断；算术提取响应使用空 expressions。它适合检验调用顺序、提交条件和失败边界，但没有代表真实模型生成后会展开的算术材料。离线最大消息只有 15,548 字符，因此通过了旧上限。

我把这份机械就绪结果用于进入真实评估时，没有另外用有代表性的完整计算候选检查消息容量。这是准备覆盖的遗漏。它不推翻已验证的串行和权限行为，但会直接影响整条正常流程能否执行，应在结果中明确记账，不能以“模型很难”解释。

本轮也没有复现过去“首个错误让所有无依赖测试停止”的推进方式。十二个会话都取得了终局结果，错误没有消失或被重试替换；这使当前配置不可用的结论可以立即关闭，而不再等待某个校验器先变得完美。

## 5. 处置决定

保留新受限入口、其机械测试和事实帮助投影实现。停止将“DeepSeek Flash＋Observation v13 的生成、职责分段、算术提取、全文语义校验”作为这类单题提示原型的默认前置处理链。当前入口可以支持后续明确变更后的配置，但本配置不能作为可用原型交付。

不在本轮追加放大输入上限、调整表达式 schema 或修改 prompt 的实验。容量上限属于明确可修的工程问题；但在保持本次原始返回不变、只解除容量限制的假设下，也仅 T01、T05 两个会话没有其他已经发生的失败，其余十个会话仍有更早的合同错误。这个推断不预测新一次模型调用，只说明单独修容量不足以支持本轮验收。

后续方向建议明确改成另一种能力配置：对于只选择两个登记提示、又不产生学习者评价状态的原型，直接以原始作答、当前请求、活动约束和实际帮助历史为 Policy 输入，由 Policy 承担本次受限选择责任；需要正式 Observation 的评价流程另行限定职责和质量合同。该方案会改变本原型“先正式提交 Observation”的前提，必须先作显式设计修订，不能在失败后临时旁路必需校验。这里没有实现或安排这条后续路线，也没有为它承诺通过率。

这种处置保留规则＋LLM 的语义职责，减少让一个简单提示选择依赖多个复杂文本映射的条件。它不重新提出通用语义保真保证，不实现已搁置的 v6 reviewer，也不要求继续填旧 17 个案例。

本轮质量结果为 NO_GO，原综合 Spike 仍为 TERMINATED_NOT_ACCEPTED，历史覆盖仍为 9/17，A2 仍 DENIED，Gate E/F 仍 OPEN。正式语义校验没有执行，因此本轮语义误放率、误拒率和 Policy 质量均为不可估计；没有到达的路径不记为通过。
