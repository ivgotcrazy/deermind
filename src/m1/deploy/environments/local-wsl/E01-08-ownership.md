## 1. 变更范围

事件保存不再自动调用投影器。所属业务决定采用哪些事件、如何生成查询数据；公共底座只提供事件保存、授权读取、可靠交付及通用收据、进度记录。

| 位置 | 职责 |
| :--- | :--- |
| `foundation/system/events/store.py` | 追加并校验事件，返回完整事实，登记待发安排；不生成业务投影 |
| `product/accounts/projections.py` | 账号五表的转换、顺序及写入；同一事件可生成多行、多表，多事件可更新同一当前值 |
| `product/accounts/rebuild.py` | 选择维护范围、建立副本、核对完整行集合及依赖、原子替换 |
| `foundation/system/projections/receipts.py` | 按生成器、代次、事件防重；成功后登记，不解释业务数据 |
| `foundation/system/projections/records.py` | 保存固定上界、检查点和维护结果，只操作runtime控制记录 |
| `bootstrap/projections.py` | 装配账号维护入口及实现摘要，不定义业务表或转换规则 |

生产者在一个事务内完成事件追加、显式调用业务生成器、保存请求收据；任一步失败全部回滚。订阅处理器可以调用同一生成器；本次用已保存事实模拟该业务入口，不新增账号生产订阅。消息可靠交接与后续业务处理仍分开。

文件登记是文件服务自己的控制记录，改为由文件服务显式保存。登录、执行、交接及维护审计移除空投影回调，不再制造没有业务写入的投影完成收据。

## 2. 重建边界

- `product.account_views.v2`覆盖账号、监护人、监护关系、使用确认、当前使用条件五表。原ID、修订、时间和来源保持，条件取历史中最后一个已保存快照，不重新判断同意。
- 扫描但未采用的事件不生成应用收据。关系及确认的多行都保存，不能用“每事件一行”核对数量。
- 共享监护人来源不在授权范围时失败，操作人重新批准包含来源账号的范围；不自动扩大读取权限。其他学生的关系、确认及条件不变。
- 重建只清理所选学生从表中无事实依据的行，不删除账号、凭据或共享监护人。最终核对失败，正式表保持原样。
- 临时连接或可重试数据库故障保留断点；事实缺失、结构或关联错误保留旧投影及失败记录。不调用AI、不发通知、不创建业务任务。

迁移`0009_projection_ownership`只为维护记录增加`target_relations`，不改变历史迁移、事实正文及事件Schema。旧单表记录仍可查询，但不能用新实现继续执行，也不能解释成五表已恢复。旧应用收据保留；历史事实需要按v2重建时通过维护流程建立新代次，不直接重投到在线表。

维护命令仍为`deermind-rebuild prepare/resume/status`，参数及授权要求沿用[首批命令](E01-08-rebuild.md#3-维护命令)。必须先停止相关写入；NOWAIT只检查取锁当时，后续写入仍受已定锁超时保护。
