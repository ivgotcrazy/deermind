# M1 工程约束

遵循[编程规范](../../doc/mvp/m1/engineering/Coding_Standard.md)。目录和模块边界以工程设计为准。

- 只实现当前获准增量；关键业务、架构或授权取舍先确认。
- 不导入旧原型、试验或`.tmp`代码；不创建后续功能占位。
- 以简单实现为先；输入校验、错误处理、权限、事务和幂等不能省略。
- 不手改生成合同，不绕过模块公开边界，不提交凭据或真实学习材料。
- `bash scripts/check.sh`只检查不改文件；`bash scripts/test.sh local`运行本地测试。
- 真实集群测试须显式选择`target`或`components`及目标环境；组件测试会重启测试release。
- 按逻辑分段、合理换行；文件及复杂函数说明职责、关键约束和副作用，不压缩成一坨。
- 工具通过后逐文件人工review命名、流程、注释、异常及测试断言，记录具体结论。
- 修复检查失败的原因；局部豁免必须说明理由，禁止整文件关闭检查掩盖问题。
- 交付前保存检查与测试证据，说明未覆盖项；用户评审通过才标记增量完成。
