本目录接收按[M1业务工作包](../README.md#2-六个产品设计工作包)共同核对的[PRD](../PRD.md)、[详细设计](../design/README.md)与原型，不把PRD正文写完作为唯一开工条件。工程负责接口、数据存储、真实AI与识别服务、串行处理、权限实施、定义采用、持久化和恢复、启动工具及交付，不替产品决定学习流程和评价含义。

## 1. 按需要建立的输出

- `Engineering_Design.md`：系统如何实现。包括服务／模块、接口输入输出、存储与Schema、LLM和识别调用、上下文与串行处理、权限、版本、失败恢复及部署配置。以教材导入为例，要写清文件怎样保存、后台任务怎样推进、哪些模型调用生成候选、失败怎样重试；不重新定义谁可以应用教材。
- `Delivery_Plan.md`：按什么顺序实现。说明工作项、依赖、复用部分、每步交付与验收；围绕一条真实路径逐步打通，不按菜单数量排工期。
- `Delivery_Report.md`：实际交付了什么。给出版本、配置、安装启动和复测方法、内容清单、验证报告引用及限制；有真实软件后才创建，不复制验证报告的结果正文。

以上文件尚未创建。源码继续位于`src/`，不随文档归档移动。各Space的责任可以在一个简单部署中实现，不据目录划分增加服务或通用平台。

## 2. 进入工程的条件

按拟接收范围核对业务规则、详细规格、原型和对应截图，记录准确版本、输入输出、依赖及未决项。可对已明确部分提前分析技术可行性；正式实现须满足对应范围的G3／G4责任和接收记录，不因某份文档或一个包自检通过而自动开工。受产品未决项影响的部分继续设计，工程反馈可返回产品修订。

M1最终须通过真实工具完成整册建模及教学闭环；开发可按章联调，不要求在产品设计阶段手工完成全书模型。整册实物内容与软件的最终验收，不与代表性设计样例混为一谈。

## 3. 本轮必须承接的实现与复测要求

当前输入为[PRD v0.20](../PRD.md)、[内容规格v0.19](../design/Content_and_Model_Reference.md)、[交互规格v0.18](../design/Interaction_Design.md)和[验证计划v0.1](../validation/Validation_Plan.md)。正式接收按范围固定文件及资产哈希；本节不是完整工程设计，也不宣布已开始实现。原型只承担交互说明，缺少真实引擎不等于要先把原型做成生产系统。

| 实现项 | 必须接收的产品合同 | 工程输出与核对 |
| --- | --- | --- |
| 教材导入Agent | 原件与对话上下文、受限工具动作、候选检查／渲染、采用与继续；无手工内容编辑器 | 工具协议、范围约束、结构化输出、编号引用、调用及失败记录；原型单次重解析不是已实现Agent |
| 模型适配 | KC Task／复合Task、子Task及方法依赖；跨章节方法汇总并保留适用来源 | 适配旧Task角色和`allowedMethods()`；不能仅改字段名或对所有章节无条件开放方法 |
| 求助与教学机会 | 内容§4.9／4.18的分类、实际展示、稳定机会身份、资格与去重 | 明确程序字段和合法转移；语义解释不明不提供轮内帮助、不加L；同一机会拆消息／恢复不重复更新 |
| 数值核心 | 既定观测更新、转移公式和参数；未决不作负证，迁移／保持不加L | 纯函数与参数校验，使用相同实现核对§4.19和对应fixture，覆盖边界、重复、跳过与纠正重算；不把仅grep到公式视为引擎验收 |
| 评价接线 | 先检查归因、帮助、版本、条件、重复来源，再调用数值函数 | 无资格项显式跳过；事件→Evidence→Belief→目标输入输出可追溯；禁止后验回灌 |
| 分步启用 | 可以先实现公式并用结构化案例验证，再接LLM解释和真实事件 | L仅在机会资格和去重通过后调用；真实校准和教学效果另验，不将mock数值对上视为校准 |
