## 1. 验证什么、由什么证据回答

本计划服务于M1从教材准备到教学与评价的主流程。产品规则是否明确、原型是否展示、程序是否按规则执行、模型解释是否可靠、学生是否受益是不同问题，分别记录结果。文档自检和mock走查不能替代后面三类验证；局部样例通过不能表示整册可用。

| 对象 | 本轮规定的验证方式 | 通过后能够说明什么 |
| --- | --- | --- |
| 教材解析与纠错 | 固定原件、管理员对话、Agent实际候选和核对结果 | 指定样例及操作是否完成，不等于全册提取正确 |
| 领域补建和章节采用 | 已有与缺失定义分别处理，检查Task／Solution／KC引用和实例关系 | 内容能够按模型约束入库并采用，不等于抽象粒度对所有领域有效 |
| Evidence资格与帮助判断 | 预先核对的正例、反例和未决例，独立复核语义与引用 | 哪些表现能够用于哪个分项，哪些必须跳过 |
| 概率计算和事件更新 | 调用实际计算与提交函数，覆盖去重、顺序、版本和失败重试 | 实现符合已采用算法，不等于参数已校准 |
| 概率预测与学习效果 | 保留验证样本的前向预测及后续实际表现，另行观察教学结果 | 指定人群、范围和条件内的预测质量与效果，不证明潜在能力真值 |

质量门槛仍以[PRD§7.2](../PRD.md#72-质量目标与证据责任)为准：MET-002针对支持范围内清晰材料的整题关键内容，初次自动结果和纠错后结果分开；MET-003／004分别核对当题与掌握判断，不能全部输出未知规避错误。这些比例不直接充当概率校准标准。样本分母、参考答案、未知与失败的计数规则必须在执行前固定，不能只统计成功提交的结果。

## 2. 教材导入Agent与整册建模验证

本轮纠错验证仍限于既有四例C02、C03、C05和C06，不再扩大样例范围。历史输入、输出与人工修正保留在[内容表达试验](Content_Representation_Trial.md)所链接资产中；它们是问题来源及对照材料，不是新的Agent成功记录。管理员只能通过对话描述问题、提供原件或补充材料，不使用结构化结果编辑器。

| 样例 | 管理员对话要解决的问题 | 对最终候选的检查 |
| --- | --- | --- |
| C02 | 同一道题包含两种解法，应分别提取 | 保留一个题目实例和两个解法实例，各自过程完整，均指向该题；不重复生成题目 |
| C03 | 核对公式运算结合次序，并区分教材用于辨错的错误 | 正确保留原式结构和原书意图；不把教材故意给出的错误擅自改成正确答案 |
| C05 | 原页三张统计图有遗漏，请回看并补齐 | 各图数据、轴、图例、单位和题目归属可核对；无关内容不变，不能凭印象补数 |
| C06 | 图形、标记与附页材料的可见范围不清楚 | 提取可见事实；缺失附页保持待补，要求补材料，不猜测隐藏关系或尺寸 |

每次执行保留原件及版本、初次自动候选、完整管理员对话、Agent工具调用与中间候选、采用或取消结果。最终结果必须可回到原页核对。管理员直接告知一个正确数值可以计为人工指导后的修正，但必须与Agent自行从原页恢复区分；预先提供修好的JSON不能算对话纠错验证。模型、提示词、工具版本、重试上限和预算在执行前固定，网络重试与语义纠错轮数分别统计。

内容参考答案由核对人员基于原页建立，争议先记录并复核，不能由被测Agent自行判自己通过。每例同时检查目标问题是否修正、其他事实是否保持、内容归属是否正确、编号引用是否由程序维持，以及取消候选是否保留此前结果。旧版本候选不得覆盖更新后的内容；Agent不能直接改已入库领域定义或章节采用关系。所有未完成和失败样例保留，网络故障、结构错误、语义错误、资料不足分别计数。

四例不覆盖从新内容抽象出新KC、TaskTemplate和SolutionTemplate的全部能力。工程必须另外验证已存在定义的复用和确实缺失定义的补建：实例先有来源，再确定模板，解法实例同时指向题目实例和方法模板；KC Task与复合Task的依赖遵循内容规格。评审模板是否遗漏条件、过宽、过窄或与已有定义重复，不能只检查JSON合法。该项使用整册逐章建模中实际出现的缺口，按预先固定的范围验收，不在本轮四例纠错中追加无限样例。

整册完成另按[内容规格§5](../design/Content_and_Model_Reference.md#5-如何从代表样例扩展到整册)逐章核对：原件覆盖、提取结果、未解决问题、领域定义、章节采用、目标与行为可用条件均须有记录。四例或“分数的应用”通过不能代替整册交付，版权页待补也不能被试验结论隐去。

人工成本分开记录实际核对时间、主动输入／纠正时间、等待时间、对话轮数、仍需补充的材料以及可取得的调用费用。先报告各例与各章的真实分布；没有整册样本前，不按四例平均值宣称整册成本已受控。

## 3. Evidence、学习机会与算法实现验证

语义资格先于数值更新。固定输入应包含原始事件、当前检测轮及帮助事实、Task／方法／判据版本和已有记录，参考结果明确哪些分项可更新、哪些保留未决。语义参考不能只写一个正确／错误标签。

| 必验情况 | 预期结果 |
| --- | --- |
| 两种方法中只展示方法A的过程 | 只更新有直接表现的A分项，不把B标成掌握 |
| 只有答案、步骤无解释、完整解释 | 分别处理方法不可识别、求解有依据但理解不足以判断、解释可核对；不一律更新四方面 |
| 当前题请求提示或讲解 | 必须先结束当前检测轮并记录帮助，再给内容；之后不能把受助表现认定为原轮独立通过 |
| 提交失败、显示问题、含糊的“没懂” | 技术确认不等于帮助；含糊请求先澄清，不在澄清时泄露思路；实际给过帮助不能抹去 |
| 明确错误、来源不清、解释失败 | 明确且合格的负表现可更新；来源不明或处理失败保持未决，不能当作学生错误 |
| 父Task完成、子Task过程有或没有证据 | 只递归更新有明确依据的子Task方法及方面，不沿依赖关系复制成功 |
| 同一事件重试、同一作答拆成多段 | 同一分项只处理一次；不同方面共享依据不等于多个独立样本，不合成为总掌握率 |
| 教学拆消息、暂停恢复、同一输出重试 | 沿用同一学习机会身份；达到资格时同一分项最多应用一次L，生成未展示不计 |
| 父层讲解或子方法实际教学 | 父层讲解不自动给所有子Task加L；明确教到的子责任须有自己的内容依据 |
| 普通讲解后没有新作答 | 独立／理解仅在机会资格明确时可用L；迁移／保持L为0，不增加成功题数或最近验证时间 |
| 迁移经历未知、未到七天、遇到反证 | 不虚构新颖情境或保持证据；按本例目标条件处理未知、待检与反证，概率高也不能越过条件 |
| 参数或解释版本改变、更新失败后重试 | 不以换版本制造新证据或新机会；事件追加记录，失败不能产生部分状态或重复更新 |

确定性检查要调用工程实现的计算、资格过滤及提交函数，验证无非法更新、无重复处理、无跨空间归因及可复算结果；这类规则必须全部符合，不能以平均准确率容忍错误写入。原型固定数值检查只说明mock示例彼此一致。测试入口及当前未接入脚本的用例见[工程说明§3](../engineering/README.md#3-本轮必须承接的实现与复测要求)，本轮没有执行这些浏览器用例。

学习机会语义核对与去重未通过前，不启用不合格输入的学习转移；保留已采用L初值，不另造一套参数。依据、资格、实际处理结果分别留痕，无法确定是否足够完整的教学机会先跳过，而不是按消息数补一个L。

## 4. 参数校准、过度自信与停止条件

当前p0=0.50、S=0.15、G=0.25、L=0.05仍为共享试用假设，迁移／保持有效L为0。不得把文档升版解释为参数已验证。参数来源和计算以[内容规格§4.18](../design/Content_and_Model_Reference.md#418-概率计算学习转移与共享参数)为准，本计划不新增逐Task、逐方法的调参界面。

验证对象首先是下一次符合条件的表现预测，不是不可直接观测的“真实掌握概率”。在获得下一次作答之前固定当前分项概率p，依已采用测量模型得到通过预测`p × (1 − S) + (1 − p) × G`，再与后续合格表现对照。不能用更新后概率回头预测同一条证据；不同条件的独立、理解、迁移和保持分开说明，缺少后续表现不能当作失败。

| 环节 | 运行前固定的做法 |
| --- | --- |
| 样本单位 | 记录学生数、唯一作答数、方法与方面、正负表现和未知数量；同一次作答拆成多方面不能充当多个独立学生样本 |
| 划分 | 区分参数探索与保留验证，按学生分组并遵守时间先后；若验证同一学生的后续预测，可使用其此前记录，但不能用未来记录选参数或阈值 |
| 预测指标 | 记录Brier分数、预测区间内的实际通过率及不确定性；与只用探索样本确定的简单通过率基线比较，按学生聚类处理重复观测 |
| 过度自信检查 | 单列高预测但失败、重复近似题、提示暴露和来源不明案例；不能只看总平均掩盖特定方法或方面失效 |
| 参数调整 | 先核对资格、去重和测量条件；确需调参时先用探索样本，固定新版本后验证。数据不足不据少量个例增设逐方法参数 |

正式校准的最低样本量、预测区间划分、估计精度、相对基线的允许差异及判断门槛，必须在查看验证集结果之前写入运行协议。依据是预期误差、学生内重复观测和需要单列的方面，不能随意约定“几十题足够”。当前尚无真实样本分布，以上数值没有被确认，因此本计划不宣称已具备概率校准通过条件。工程确定性验证和四例Agent验证可以先开展；试用负责人和执行人员在校准试验开始前补齐协议，实际批准人与版本留痕。

停止与降级按问题所在环节处理：

- 来源、实际方法或帮助条件不清：保留原始事件及未决解释，跳过受影响分项更新，不把未决当负证据。
- 机会粒度、实际交付或去重无法保证：暂不应用学习转移，保留教学记录，不删除历史。
- 出现无效引用、重复更新或部分提交：停止受影响的自动更新链，修复后按既有事件重新核对；不通过改写原始事件掩盖问题。
- 某分项预测明显不可靠：暂停依赖该概率的自动决策，保留有效Evidence及明确目标条件。恢复须有修复或新版本验证记录，不临时挑选对结果有利的算法。
- 样本不足：标明“未验证”，不报通过；未知比例和覆盖量同时报告，不能靠全部拒绝判断取得表面高准确率。

这些处理不自动废弃全部Belief，也不保证目标评价因此已经可靠。目标判断的语义资格、条件和反证处理仍须单独验证；即时、延迟与主动介入的实际价值另按PRD既有指标观察，不由概率拟合结果代替。

执行后才创建`Validation_Report.md`，链接运行输入、输出、完整失败、统计分母和版本，分别给出确定性实现、内容语义、概率预测和学习效果结论。修复后复测须保留旧结果，注明本次改变的对象及影响范围。本轮仅交付计划和文档自检，未新增真实模型调用结果、学生实验结果或截图。
