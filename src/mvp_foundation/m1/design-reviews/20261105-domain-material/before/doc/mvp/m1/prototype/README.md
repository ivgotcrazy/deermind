## 1. 启动与浏览

在仓库根目录双击`m1-prototype.cmd`，或运行：

```powershell
.\m1-prototype.cmd start
.\m1-prototype.cmd status
.\m1-prototype.cmd restart -NoBrowser
.\m1-prototype.cmd stop
```

也可以在本目录运行`prototype.cmd`。首次启动安装锁定依赖并构建，后台窗口隐藏；`-NoBrowser`只启动服务，`-Port 5183`可改端口。需要已安装Node.js及npm，版本要求见package.json。

默认地址是[http://127.0.0.1:5182/admin/#/textbooks](http://127.0.0.1:5182/admin/#/textbooks)。旧5181仍是旧原型，根目录原来的`prototype.cmd`也仍启动旧版，二者不会互相替换。

**走查路径：** 教材管理 → 导入教材 → 载入真实教材书页 → 上传并开始整理。随后在三栏工作区处理图文、跨页及疑点，保存后可返回列表继续或删除草稿。至少确认一个课题后，“查看整理交接”列出准备结果；它不会创建Task、Claim或应用课程。

页面使用构建结果，修改代码后运行restart。开发时可在本目录执行`npm run dev`，须先停止占用5182的预览服务。浏览器mock保存在本目录服务自己的来源下，使用M1专用存储键；更换端口或浏览器不会自动带入草稿。

## 2. 当前迁入范围

| 范围 | 当前结果 |
| --- | --- |
| D01已有操作 | 文件选择与顺序、教材信息、模拟进度及中断、原页对照、编辑、跨页合并、表格与图表、核对、保存继续、删除草稿 |
| D01仍待补齐 | 原件预览与补页、目录与遗漏内容维护、逐页处理及失败部分继续；具体方案见交互规格§4.1，尚未由本次目录授权自动确认 |
| D02–D06 | 建模与题库、应用选用、学生教学、检测评价、主动任务及追溯仍属M1，按包迁入；本轮不显示不可操作的空菜单 |
| M2／M3或无关旧能力 | 没有迁入完整家长端、首页统计、错题日常管理、旧运行大屏及通用后台工具 |

保留V2的配色、侧栏和三栏整理布局。仅复用整理工作区、对话框、内容展示及内容类型、五页样例定义、五张原图，逐文件来源见[复用清单](reuse-manifest.json)。新的入口、D01状态、启动及测试只依赖本目录的代码和npm依赖，不从旧原型运行时导入模块；没有复制旧会话服务、LLM配置或个人数据。

本轮只提供数学领域的教材整理样例，未迁入领域编辑器。普通文件选择可以检查文件类型和顺序，但没有OCR，因此不能把其内容变成整理结果；页面明确提示使用内置样例继续。原页是真实教材，内容、疑点与过程为预设mock，不能视为全册导入验收。

## 3. 代码与检查

```text
prototype/
├── src/App.vue                 M1入口与草稿列表
├── src/components/             导入、图文整理、内容展示及对话框
├── src/model/                  D01数据、状态与五页mock
├── public/materials/bnu6a/     五张真实书页
├── scripts/                    独立构建启动及本地静态服务
├── tests/                      D01浏览回归
├── package.json                独立依赖与命令
└── reuse-manifest.json          按需复用来源
```

在本目录执行`npm run build`及`npm test`。浏览测试使用Playwright Chromium；新机器如缺浏览器，先执行`npx playwright install chromium`。测试在临时浏览器与随机本地端口运行，截图写入test-results，不清除用户草稿、不调用模型API。

本次对应文档的18张截图见[采集清单](../design/assets/d01-v0.2/capture-manifest.json)，范围与检查见[作者记录](../design/assets/d01-v0.2/review.json)。这些证据只证明有限mock可操作，不能证明真实文件处理、教学质量或整册建模完成。
