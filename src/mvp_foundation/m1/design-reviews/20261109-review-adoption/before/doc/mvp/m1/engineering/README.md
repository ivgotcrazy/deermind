本目录接收按[M1业务工作包](../README.md#2-六个产品设计工作包)共同核对的[PRD](../PRD.md)、[详细设计](../design/README.md)与原型，不把PRD正文写完作为唯一开工条件。工程负责接口、数据存储、真实AI与识别服务、串行处理、权限实施、定义采用、持久化和恢复、启动工具及交付，不替产品决定学习流程和评价含义。

## 1. 按需要建立的输出

- `Engineering_Design.md`：系统如何实现。包括服务／模块、接口输入输出、存储与Schema、LLM和识别调用、上下文与串行处理、权限、版本、失败恢复及部署配置。以教材导入为例，要写清文件怎样保存、后台任务怎样推进、哪些模型调用生成候选、失败怎样重试；不重新定义谁可以应用教材。
- `Delivery_Plan.md`：按什么顺序实现。说明工作项、依赖、复用部分、每步交付与验收；围绕一条真实路径逐步打通，不按菜单数量排工期。
- `Delivery_Report.md`：实际交付了什么。给出版本、配置、安装启动和复测方法、内容清单、验证报告引用及限制；有真实软件后才创建，不复制验证报告的结果正文。

以上文件尚未创建。源码继续位于`src/`，不随文档归档移动。各Space的责任可以在一个简单部署中实现，不据目录划分增加服务或通用平台。

## 2. 进入工程的条件

按拟接收范围核对业务规则、详细规格、原型和对应截图，记录准确版本、输入输出、依赖及未决项。可对已明确部分提前分析技术可行性；正式实现须满足对应范围的G3／G4责任和接收记录，不因某份文档或一个包自检通过而自动开工。受产品未决项影响的部分继续设计，工程反馈可返回产品修订。

M1最终须通过真实工具完成整册建模及教学闭环；开发可按章联调，不要求在产品设计阶段手工完成全书模型。整册实物内容与软件的最终验收，不与代表性设计样例混为一谈。
