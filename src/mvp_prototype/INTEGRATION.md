## 1. 目标与边界

在 `mvp_prototype` 内建立统一的构建、启动与服务入口。学生端直接以 V2 的 App、四个页面、对话与输入组件为底稿，保留生成式交互与当前页面并存的组织；管理端采用新版观测与管理工作区；家长端沿用既有页面。原型整合不扩大真实模型的教学范围，不把示例运行轨迹、即时教学反馈转换为正式 Evidence 或 Belief。

`mvp_prototype_v2` 与 `mvp_admin_prototype` 保持原样。新入口为 `structure.html?role=student|parent|admin`；旧结构页面保留为 `legacy-structure.html`，`phase4.html` 与早期 `index.html` 也保留。三个角色入口仍然分开；原型选择角色不等于已实现正式账号权限。

## 2. 实施顺序与交付

| 工作项 | 实施内容 | 完成依据 |
|---|---|---|
| I1：迁移与兼容边界 | 确认来源、旧入口、存储键、模型接口及未接入能力 | 本文及原目录校验 |
| I2：学生端 | 以 V2 学生端源码为底稿，建立独立服务适配层；左侧对话、右侧当前页面，保留搜索、展开和会话上下文 | 新学生入口、浏览器定向检查 |
| I3：管理员端 | 新版观测与管理页面，嵌入旧维护、内容准备、人工复核和账号流程 | 新后台入口及发布、采用检查 |
| I4：三端与运行整合 | 家长端保留，默认启动入口更新，构建包含旧入口 | 启动脚本、角色回归 |
| I5：验证与交付 | 类型、构建、服务、浏览器及视觉检查，记录已知边界 | §5 的实际结果 |

## 3. 数据与功能迁移

| 项目 | 接法与不变量 |
|---|---|
| 实际对话 | 继续使用 `/api/live`、原服务配置、模型适配器和串行命令协议。各页面输入原文转交；附带白名单内的页面名称，不携带预写学习评价，不使用关键词判断教学意图 |
| 会话与草稿 | 保留 `deermind-structure-v1`、会话 ID、`real:*` 草稿与幂等请求 ID；V2 页面偏好及会话页面上下文保存在同一存储的 `v2:*` 键；服务端 `.tmp/mvp-live` 不搬迁、不清空 |
| 旧活动 | 保留原记录及草稿；已有真实会话在新工作区恢复，预写活动可以打开旧入口。预写教学和表现不自动送入模型 |
| 检测过程 | 沿用检测期间收起教学、保留答案、求助先结束检测、取消与重试合同。界面导航不得绕过进行中的检查 |
| 课堂进度 | 首页与学习情况复用原组件和记录，学生更新、家长只读；不把课堂进度当作掌握情况 |
| 题目输入 | 图片和说明保留为待处理输入，保持空间隔离；不声称已执行 OCR、识别或判错 |
| 学习情况 | 继续使用已标注的参考要求状态，移除 V2 百分比阈值推断；采用搜索、分册筛选和分页 |
| 管理观测 | 新版示例目录和示例轨迹只读；“实际会话”单独读取真实对话，先填写查阅用途，不补造正式模型链路 |
| 维护与发布 | 复用原候选字段检查、审核依据、批准失效、发布及指定采用流程，继续保存既有本地维护状态 |
| 家长复核 | 保留家长提交的事项，在新后台记录处理意见；不替家长修改学生资料，不直接改 Belief |
| 账号目录 | 新版用户列表读取旧账号流程的本地合成档案，新增、找回与关联结果可见；学生与家长分开，不引入教师角色 |

学生首页的活动统计使用本空间实际保存的会话与消息；未接入的计时、正式错题判断显示未统计，不使用 V2 固定的分钟数或能力分数。学习要求的预写状态与本轮实际对话明确分开。

## 4. 对新旧差异的处理

- 学生端以 V2 分栏为交互基线：从首页、学习情况、教材或错题本进入时，左侧展开对话，右侧保留该页面；导航可切换右侧页面而不新建会话。收起聊天时页面铺满，输入条保留；平板继续左右布局，窄屏改为上下布局。
- 学生课程采用现有校内、校外两个独立空间；不会只修改课程名称而继续显示另一课程的记录。
- 后台的 KC 只保留领域与教学解释用途，不呈现为独立掌握状态。Task Claim 内部四方面尚未真实推断时，显示“未接入正式判断”。
- 新后台示例数据中的旧单值轨迹作为历史展示参考保留，并明确版本局限；不能据此判断当前多维模型已实现。
- 章节不能仅凭 KC 重叠获得正式 Task/Solution 映射。缺少明确映射和版本时保持待核对。
- 基础 Evolution 维护在 MVP 原型中保留；自动演化、正式失效处理及评价重算仍未实现。
- 新版未接通的新建、编辑、导出等按钮不再表现为有效操作。可操作的维护使用原合成案例，不冒充正在编辑列表里任意一个示例对象。

## 5. 验证与已知边界

### 5.1 第一轮整合的历史结果（2026-10-20）

这些结果只说明当时的功能整合通过，不能证明当时的学生交互符合 V2；2026-10-21 的复审已否定该交互选择，当前结果见 §5.2。

验证分为服务机制、浏览器集成和视觉检查。离线协议响应只用来验证页面是否正确发送、恢复与展示，不作为模型判断质量证据；真实模型检查需单独记录。

本轮结果如下：

| 检查 | 结果与覆盖 |

| 新入口集成 | `npm test -- tests/integrated.spec.ts`：最终 9 项通过，57.5 秒；覆盖真实接口协议、输入安全、草稿、恢复、检测、课堂进度、家长只读、300 章目录、图片输入隔离、维护发布、账号目录及实际会话查看 |

截图与检查摘要保存在本地 `.tmp/integration-review/`、`.tmp/integrated-live-check/` 和 `.tmp/integrated-home-*`、`.tmp/integrated-chat-*`；这些临时检查产物不进入产品数据或正式验证报告。

原型仍不包含正式认证、服务端角色授权、OCR、多维能力推断或真实发布重算。新后台的任意对象编辑也尚未实现。本次交付是三端界面与已有原型能力的整合，不将这些范围外能力标为完成。

### 5.2 以 V2 为底稿的整改（2026-10-21）

上一轮只保留 V2 的视觉，再嵌入旧 `LiveLesson.vue` 整页会话，没有承接 V2 以生成式交互为主、当前页面作为上下文的核心行为。本轮移除该接法，按照“V2 界面 → 服务适配层 → 原有服务和存储”的方向重建学生端。

| V2 交互 | 本轮实现及旧能力的接入位置 |
|---|---|
| 四个页面作为持续上下文 | 直接从 V2 的 HomePage、LearningStatusPage、TextbookPage、ErrorBookPage 派生；保留组件实例、过滤和展开状态，不挂载旧 CatalogPage 或 RecordsPage |
| 左侧生成式对话 | 从 V2 ChatWorkspace、ChatMessage、InputComposer 派生；真实回复、图示、练习与检查由组件承载，不再加载旧 LiveLesson |
| 收起与常驻输入 | 保留 V2 展开／收起关系；收起后继续输入，页面铺满；首次请求失败不清空草稿 |
| 会话协议 | `useConversation.ts` 接入原 `/api/live`，处理轮次串行、轮询、取消、失败、幂等请求与历史恢复，不参与教学语义决策 |
| 页面与对话关系 | 路由为 `#/当前页面?chat=会话ID`；普通导航只换右侧页面。同一页面的过滤和展开状态保留；刷新恢复，旧 `#/lesson?id=...` 兼容原会话，缺少页面来源的旧会话回到首页作为上下文 |
| 独立检查 | 检查中收起讲解及右侧参考内容，并阻止切换空间或另一活动；提交、求助或结束后恢复。页面组件不因此销毁 |
| 课堂进度与题目图片 | 进度复用旧数据规则及选择弹窗；图片仍只保存在本地待处理输入，保持课程隔离，不编造 OCR 或错题判断 |
| 示例与实际数据 | 不迁入 V2 的固定学习时长、百分比阈值、模拟回复和关键词分流。首页采用实际会话计数及待评价；章节和错题的预写参考单独标注 |

仅附带当前页面名称作为模型的定位信息，不等于模型已经读取右侧全部数据。章节讲解、错题讲解等明确动作把对应题目或章节放入当前请求；正式 Evaluation、全页面语义上下文与跨活动规划未在本轮实现。真实教学范围继续限定为校内“分数的应用”。

本轮结果如下：

| 检查 | 结果 |
|---|---|
| 类型与生产构建 | `npm run build` 通过，240 个模块；根启动脚本重新启动 5178 服务 |
| V2 与保留管理流程 | `student-v2.spec.ts` 9 项、`integrated.spec.ts` 3 项，共 12 项通过（1.6 分钟），覆盖四个来源页面、对话与页面联动、筛选／展开保留、收起、旧链接、刷新、幂等恢复、练习与检查、图片与空间隔离，以及管理端维护和追溯 |

| 真实模型 | 1 条合成问题与 1 条回复；DeepSeek Flash 模型调用约 1.936 秒，教材在右侧保留、刷新草稿恢复、后台可追溯，无浏览器异常；这是连通检查，不是教学质量测量 |

## 6. 后续维护入口

- 新版学生 App 与服务适配层位于 `src/integrated/student/`，从 V2 派生的页面及聊天组件位于其 `components/`，新版管理员页面位于 `src/integrated/admin/`；保留的家长与真实对话状态位于 `src/structure/`。
- 真实服务继续由 `scripts/serve.mjs` 和原 `live-*` 模块提供；未新增 API key 配置位置。
- `scripts/build-legacy-styles.mjs` 为原维护流程的样式生成作用域隔离文件。修改原 `style.css` 或 `foundation.css` 后，应运行此脚本并重建，避免影响新版后台外壳。
- 两个独立新版项目继续作为来源和对照，当前使用入口统一在 `mvp_prototype`。未经后续决定，不删除这两个目录。
